入口 signin/page.test.tsx
- 不正な遷移元(%s)で開いた成功では、ラウンド一覧へ遷移する(3組) → 遷移元の許可・外部URL → auth-routes.test の allowedReturnTo / sign-in.test の「成功時にsignedInだけを送って許可された遷移先 %s へ進み」、E2E signin.spec の許可・外部URL
- 認証サービスが認証の拒否を返しても(%s)、…新しいトークンで再送信して遷移できる(2組) → 失敗でトークン消費・チェックのやり直し → sign-in-flow.test の failed、sign-in.test の「拒否では、failedを送ってトークンを消費し…」、signin-form.test の「%sの後の再送信」、E2E signin.spec の「認証に失敗すると…」
- 認証サービスが通信の断を値で返したときは(%s)…(2組) → 同上 + 失敗の種類の写し → supabase-auth.test の通信の断、signin-form.test「通信の断(遷移元付き)の後の再送信」
- 認証サービスへの送信が失敗しても、通信エラーを示し…(1) → 通信断の写し → supabase-auth.test の「呼び出しが投げたときと、接続を得られないときは、届かなかった」
- 追加(移送): 入口から通して、認証の応答待ちで画面を離れたら、成功が戻っても遷移しない ← 画面の同種(下)から移した

- 同 describe の2行(認証の失敗(遷移元付き)・通信の断) → 失敗の種類・遷移元の組合せ → 残した2行(認証の失敗/通信の断(遷移元付き))と supabase-auth.test、auth-routes.test
