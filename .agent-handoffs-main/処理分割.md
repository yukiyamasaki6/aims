# 処理分割

既存の振る舞いの全数検査(過剰な分岐・余計な処理の有無)に向けて、本体コードを検査単位の「処理」へ分割した結果である。
処理ごとのアクティビティ図、意図と必要性の調査、変更は後続の担当が行う。この文書は処理の過不足を判断せず、修正案も含まない。

## 1. 分割の方針と読み方

- 対象は、リポジトリの追跡ファイルのうち、テスト・生成物・依存物・文書・処理を持たない設定の宣言、CI/CD・開発スクリプト(ユーザー判断)を除く全ファイルである(除外は第4節)。
- 1つの処理は、開始から終了までが1枚のアクティビティ図に収まる大きさを目安にし、利用者の操作、画面の読み込み、裏で動く処理、要求ごとの処理、DBのRPCなどの単位で切った。
- どのファイルも、いずれか1つの処理に属する。複数の処理にまたがる大きなファイルは行範囲で分け、全行がちょうど1つの処理に属するように範囲を並べた(第4節)。
- 行範囲は関数の境界を目安にしており、直前のコメント行は前後どちらかに含まれうる。後続の担当は、範囲の両端の数行を読んで境界を確かめること。
- 複数の処理から呼ばれるだけの部品(型、規則、実装)は、独立した処理にはならないため、呼ばれる側として専用の処理を立てた。種別に「共通部品」と記した。
- 「分岐」は、ソースの分岐トークン(if、else、switch、case、catch、for、while、`&&`、`||`、`??`、三項演算子、SQLのIF・CASE・EXCEPTIONなど)の数を数えた目安である。少(10未満)、中(10〜29)、多(30〜79)、非常に多(80以上)に区分した。宣言だけのSQLやCSSは、数が少なくても行数が多い。
- 「外部接点」は、範囲のソースからキーワードで検出した外部との接点の種類と検出数である。
- 「依存」は、各ファイル(行範囲)のimportした名前の定義がどの処理に属するかから機械的に求めた。型だけの依存も含む。実行時の注入先は含まず、DBのRPC名による結び付き(例: SEND-04とDB-06)は含まない。

処理の数は99、対象ファイルは238件(合計20951行)である。

## 5. 留意点

- 検査の単位が1枚の図に収まるかは、行数と分岐の数からの目安である。「非常に多」と「多」の処理は、図にする段階で分けるかを後続の担当が確かめること。
- 依存は静的な参照から求めており、手続き間の呼び出しの順序は含まない。図にする段階で対象ファイルを読んで確かめること。
- DBの関数(DB-05〜DB-14)は、クライアントのRPC呼び出し(SEND-04、SEND-05、RND-06)とは別の処理として切った。呼び出しの関係は、RPC名で結ばれる。
- 型だけの依存も数えるため、型の定義がたまたま属する処理(例: `SessionReader`型はAUTH-05の範囲にある)への依存が現れる。実行時の呼び出し関係とは限らない。
- 分岐の数は、デフォルト値の`||`や型の絞り込みなども含むため、図に現れる分岐の数とは一致しない。
