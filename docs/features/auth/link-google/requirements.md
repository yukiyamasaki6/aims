# auth/link-google

## 目的

サインイン済みの利用者が、設定から、自分のアカウントにGoogleアカウントでのサインインを追加し、不要になれば解除できるようにする。
メールアドレスの認証コードでのサインインは、Googleアカウントの追加・解除によらず、全てのアカウントに残る。

## 要求

### 結び付きを確かめる

- 設定パネルの分類「アカウント」の「Google認証」の行は、Googleアカウントが結び付いているときは、そのGoogleアカウントのメールアドレスと「解除」を表示する。
- 結び付いていないときは、「追加」を表示する。
- 表示は、アカウントをメールアドレスの認証コードとGoogleアカウントのどちらで作ったか、今どちらでサインインしているかによらず、同じ規則に従う。
- Googleアカウントのメールアドレスは、アカウントのメールアドレス(「メールアドレス」の行)と異なることがあり、それぞれの行に、それぞれのアドレスが表示される。

### Googleアカウントを追加する

- 「追加」を押すとGoogleの画面へ移り、Googleでの認証を済ませると、設定パネルの分類「アカウント」の表示へ戻る。
  「Google認証」の行に、そのGoogleアカウントのメールアドレスと「解除」が表示される。
  追加したことを知らせる表示は出さない。
- 追加の後は、そのGoogleアカウントで、このアカウントと記録にサインインできる。
  メールアドレスの認証コードでのサインインも、変わらず使える。
- 追加するGoogleアカウントのメールアドレスは、アカウントのメールアドレスと異なってもよい。
  追加しても、アカウントのメールアドレスは変わらない。
- 「追加」は、セキュリティチェックの完了を要さない。
- 追加したときは、認証サービスの標準の通知メール(「Google認証が追加されました」)が、アカウントのメールアドレスへ届く。
  AIMSは、この通知メールを有効にするだけで、自らは送らない。

### Googleアカウントを解除する

- 「解除」を押すと、「Google認証を解除しますか？」の確認が表示される。
  確認には、この文言のほかに説明文・注意書きを付けない。
- 確認を閉じる(取り消す)と、何も変わらない。
- 確認すると、結び付きが解除され、「Google認証」の行に「追加」が表示される。
  解除したことを知らせる表示は出さない。
- 解除は、Googleアカウントで作ったアカウントを含む、全てのアカウントで行える。
- 解除の後も、メールアドレスの認証コードで、このアカウントと記録にサインインできる。
  この端末と他の端末のサインインは、解除によって終わらない。
- 解除しても、アカウントのメールアドレスと記録は変わらない。
- 解除したGoogleアカウントで、後からGoogleでの認証を済ませたときの扱いは、auth/signinに従う。
  - そのGoogleアカウントのメールアドレスがアカウントのメールアドレスと同じときは、再び自動でこのアカウントに結び付く。
  - 異なるときは、新しいアカウントが作られる。
- 解除したときは、認証サービスの標準の通知メール(「Google認証が解除されました」)が、アカウントのメールアドレスへ届く。
  AIMSは、この通知メールを有効にするだけで、自らは送らない。

### 追加・解除が済まなかったとき

- Googleの画面で利用者が認証を取り消した、または拒否したときは、分類「アカウント」の表示へ戻る。
  結び付きは変わらず、何も知らせない。再度操作できる。
- 選んだGoogleアカウントが、既に別のAIMSのアカウントに結び付いているとき(そのGoogleアカウントで作ったアカウントを含む)は、追加されない。
  一般の失敗(「Googleでの認証に失敗しました。」)とは別に、「このGoogleアカウントは既に使用されています。」が表示される。どちらのアカウントも変わらない。
- 追加が、認証サービスの拒否・制限、通信の失敗で終わったときは、「Googleでの認証に失敗しました。」が表示され、結び付きは変わらず、再試行できる。
- 解除が、認証サービスの拒否・制限、通信の失敗で終わったときは、「Google認証の解除に失敗しました。」が表示され、結び付きは変わらず、再試行できる。
- 失敗の種類(拒否、制限、通信)ごとの文は設けず、認証サービスの文言も表示しない。
- 結果が分からない失敗のときは、成功と表示しない。
  「Google認証」の行は、認証サービスから読み直した結び付きを表示する。
- 追加・解除の処理中に操作を繰り返しても、同じ処理は重複して行われない。

### オフラインのとき

- オフラインでも、設定パネルを開けるときは「Google認証」の行が表示される(結び付きは、最後に確かめたもの)。
- オフラインで「追加」「解除」を押しても、処理は行われず、端末にも保留されず、ネットワークの案内が表示される。
- 通信が戻ると、再び操作できる。

### サインインしていないとき、サインインが切れたとき

- 未認証のとき、サインインが切れたときの移動は、app/settingsに従う。
- Googleから戻ったときにサインインが切れていたときは、サインイン画面へ移動する。

### 処理の途中で画面を離れたとき

- 解除の応答を待つ間に、設定パネルの別の表示へ移った、または設定パネルが閉じた利用者には、その応答による表示は起きない。
  解除自体は、応答が成功なら行われる。

### メールアドレスの手段を直接外そうとしたとき

- 画面を使わない直接の呼び出しで、アカウントを残したままメールアドレスの手段(認証サービスのemailのidentity)を外そうとしても、拒否される。
  メールアドレスの手段も、メールアドレスの認証コードでのサインインも、変わらない。
- アカウント削除、Googleアカウントの解除、メールアドレス変更の完了は、この拒否の影響を受けず、従来どおり行える。
- 画面にはメールアドレスの手段を外す操作が無いため、画面の動作と、利用者から見える結果は変わらない。

## 対象外

- メールアドレスの認証コードでのサインインを、アカウントから取り除くこと。
  全てのアカウントに残る。
- 画面からの、複数のGoogleアカウントの結び付け。画面から結び付けられるGoogleアカウントは1つまでである。
- Google以外の外部の認証の追加・解除。
- 追加の前の本人確認(メールアドレスの認証コードなど)。
  認証サービスは追加の前に本人確認を求めず、画面で求めても、画面を使わない直接の呼び出しには効かない。
  盗まれたサインインでGoogleアカウントを追加されたときは、認証サービスの標準の通知メールで気付く。
  残余リスクとして受け入れ、`docs/security.md`に記録する。
- 本番で追加・解除が動くための、運営者の作業。
  ホスト版の認証サービスでの手動の結合(Manual Linking。認証サービスではbetaの機能)の有効化、認証サービスの標準の通知メール(追加・解除)の有効化、Google Cloudのリダイレクトの設定(auth/signinの対象外に挙げたものと同じ)は、運営者が行う。
  プレビュー環境で、実際のGoogleアカウントを使った確認も、運営者が行う。
