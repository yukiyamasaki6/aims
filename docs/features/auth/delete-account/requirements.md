# auth/delete-account

## 目的

サインイン済みの利用者が、自分の意思で、自分のアカウントと、アカウントに紐づく記録をAIMSから取り除けるようにする。
削除には、利用者の明示的な意思と、削除のたびに画面で行う新しい標準メールOTPのコード確認を要する。
DBは直近60秒以内の標準メールOTP認証を認可の条件とする。

## 要求

### アカウントを削除する

- 設定パネルの分類「アカウント」の「アカウント削除」の行の「削除」から、アカウント削除の画面へ移動できる。
  行は、分類「アカウント」の他の行(メールアドレス、Google認証、サインアウト)と同じ枠に並ぶ(app/settings)。
- 削除の前に、削除が取り消せないこと、削除される内容が伝わる。
  利用者が削除の意思を明示するまで、削除は行われない。
- 削除が完了すると、アカウントは使えなくなり、削除したアカウントの認証情報でサインインできない。
  この端末のサインインは終了し、サインイン画面へ移動する。サインイン画面には、削除前の画面への遷移元は付かない。
- 削除が完了した後は、ホームや点数一覧などの画面を開いてもサインイン画面へ移動し、削除した記録は表示されない。
- 削除したメールアドレスは、新しいアカウントとして改めて登録できる。
  削除前の記録は引き継がれない。
- 削除したアカウントに結び付いていたGoogleアカウントで、改めてGoogleでの認証を済ませると、新しいアカウントが作られる。
  削除前の記録は引き継がれない。
- Googleアカウントで作ったアカウントや、Googleアカウントが結び付いたアカウントも、同じ流れ(現在のメールアドレスへの標準OTPのコード確認)で削除する。
  Googleアカウントでの確認による削除は設けない。
- 他の端末のサインインは、削除により使えなくなる。
  他の端末では、削除の後、認証サービスのセッションの更新と取得が拒否され、削除したアカウントの認証情報でサインインし直せない。
  他の端末は、アクセストークンの期限が切れた後の更新の拒否で検知され、サインイン画面へ移動する(app/navigationに従う)。
  期限が切れるまでの最大約1時間は、他の端末の期限内のアクセストークンが、認証サービス以外への通信で通りうる。
  削除後に同じメールアドレスで登録したアカウントには、その旧アクセストークンは結び付かない。
  残余リスクとして受け入れる(`docs/security.md`)。

### 削除される記録

- 削除により、利用者のプロフィール(名前)と、個人のプリセットは削除される。
- 削除により、利用者のラウンドへの参加(編集者・閲覧者のどちらも)は削除される。
- 利用者を除くと編集者がいなくなるラウンドは、ラウンド・距離・矢・それらの変更履歴の全てが削除される。
  現在、ラウンドの参加者は作成者だけであり、全てのラウンドがこれにあたる。
  進行中・完了・削除済み(論理削除)のラウンドを区別しない。
  閲覧者だけが残るラウンドも、編集者がいなくなるため削除され、閲覧者はそのラウンドを見られなくなる。
- 利用者を除いても編集者が残るラウンドは、ラウンド・距離・矢と、他の参加者の記録は残る。
  そのうち、利用者が射手として記録された矢と、その矢の変更履歴(射手の記録)、利用者が操作した変更履歴(ラウンド・距離・矢の各履歴)は匿名化される。
  匿名化された記録からは、削除した利用者を特定できず、その利用者のアカウントとも結び付かない。
  匿名化の後も、残る参加者のラウンドの表示・集計・同期は、削除の前と同じ形で成り立つ。
  利用者が閲覧者だけだったラウンドには、利用者に由来する矢や履歴がなく、参加の削除だけが行われる。
- 削除の後、利用者のアカウントに紐づく記録は、匿名化されたものと、削除の前に取得したバックアップと、削除の記録を除いて残らない。
- 削除の記録は、復元のときに削除したアカウントを削除の後と同じ状態に戻すため、バックアップの外に、削除から最大31日残る。
  削除の記録が持つのは利用者IDと削除の時刻だけで、メールアドレスなどの個人情報は含まない。
  削除の記録は運営者だけが読め、期間内は消すことも書き換えることもできない(`docs/backup.md`)。
- 削除の前に取得したバックアップには、削除したアカウント(メールアドレス、認証手段)と記録が、取得から最大30日残る。
  バックアップは運営者だけが読め、復元しても削除したアカウントは削除の後と同じ状態に戻る(`docs/backup.md`)。
  残余リスクとして受け入れる(`docs/security.md`)。
- この端末が削除の完了を知ったとき、この端末にある、その利用者の記録(端末内に保存したラウンドなどと、未送信の操作)も消える。
  消えた未送信の操作は、あとから保存されない。
  削除が完了した後に、同じメールアドレスで新しく登録した利用者や、別の利用者がサインインしても、消えた記録は表示も送信もされない。
  削除が行われなかったときは、この端末の記録は消えない。
  削除の結果が不明なときは、この端末の記録は消えず、削除が行われていた場合も、残ることがある。
  残った記録は、表示も送信もされない。
  他の端末にある記録は対象外で、その端末で次に開いたとき、サインインの失効の検知(アクセストークンの期限が切れた後)に従う。

### 標準メールOTPによる本人確認

- 画面は、直近60秒以内にOTPでログインしていても、削除のたびに現在のメールアドレスへ標準OTPを送り、新しいコードを確認してから削除する。ログイン直後であることを理由にコード確認を省略しない。
- 操作の流れは、「アカウントを削除」を押す→コードが送信されコード入力へ進む→コードを入力して「確認して削除」を押す→コード確認と削除、である。画面の段階は意思確認とコード入力の2つだけで、別の「認証コードを送信」ボタンや要求・処理中の別段階は置かない。押下後はそのボタンが処理中表示になるだけである。
- コードの送信・再送・確認の挙動は、ログイン・登録の認証コードと同じである。送付先を入力で受けず、現在のメールへ送る点だけが異なる。
- 削除は、利用者が削除の意思を明示し、その削除のためにコードを確認した場合にだけ実行する。
- DBは、削除対象アカウントの直近60秒以内のメールOTP認証を認可の条件とし、60秒ちょうどを許容する。DBは画面での新しいコード確認と通常ログインのOTP認証を区別しない。
- OTP認証の証跡がない、パスワード認証だけ、またはOTP認証から60秒を超えた場合は、アカウントと記録を残して削除を拒否する。
- 削除が拒否された場合は、他の失敗と同じく意思確認へ戻り、「アカウントを削除」から現在のメールアドレスへ標準OTPを送り直して再試行できる。
- コードの送信・受信・メール閲覧・リンク操作・セッション更新だけでは、OTP確認の60秒の期間を延長しない。
- 再確認前の古い認証情報や別セッションには、新しい確認時刻を引き継がない。
- コード自体の有効期限は15分で、確認後に削除できる60秒とは区別する。
- 削除専用の本人確認、単回許可、削除用途への束縛はDBでは保証しない。画面を介さずに直接RPCを呼ぶ場合は、直近60秒以内のOTP認証だけで削除できる(受け入れる残余リスク。`docs/security.md`)。
- 削除にサービスロールや管理APIを用いない。

### 認証コードの入力中

- 「アカウントを削除」の押下で、現在の送付先へコードを送る。送付先は表示し、変更できない。
- 削除の注意書きは意思確認の画面にだけ表示し、コード入力の段階には表示しない。コード入力の段階は、ログイン・登録と同じ迷惑メールの案内を含むコード入力の部品と「確認して削除」を表示する。
- コード欄はメールコードの自動入力に対応し、再送は送付から60秒待ち、残り秒数が表示される。
- 再送後に古いコードは使えず、未入力・誤り・期限切れ・使用済み・別アカウントのコードでは新しい本人確認が成立せず、再入力・再送で再試行できる。
- コード確認と削除の意思を明示して実行できる。
- 途中で利用者が切り替わっても、元の対象と異なるアカウントを削除しない。

### 設定パネルから開く

- 設定パネルの「アカウント削除」の行の「削除」からの移動と、ハッシュ`#settings/account/delete-account`での表示は、app/settingsに従う。
- ハッシュ`#settings/account/delete-account`を付けた画面を直接開く、または再読み込みしても、設定パネルにアカウント削除の画面が表示される(入力値は残らない)。
- ブラウザの戻る・進むで、設定パネルの分類「アカウント」の表示とアカウント削除の画面の間を移動できる。
- ヘッダーに項目の名称「アカウント削除」と戻るの操作が、段階によらず表示され、戻るを押すと、削除を行わずに設定パネルの分類「アカウント」の表示へ移る。本文には分類「アカウント」へ戻る操作を置かない。
- 削除の処理中は、ヘッダーの戻るの操作は押せない。

### オフラインのとき

- 設定パネルをオフラインで開けるときは、オフラインでもアカウント削除の画面が開き、設定パネルの項目から移動できる。
- オフラインで削除を実行しても、削除は行われず、端末にも保留されず、「ネットワークに接続されていません。接続を確認してから再度お試しください。」が表示される。
- 通信が戻ると、再び実行できる。

### 不備や失敗があるとき

- 未入力コードでは理由を示して確認を送信しない。
- 「アカウントを削除」によるコード送信と再送は、セキュリティチェックを完了してから実行する。未完了の押下では処理中として待ち、完了で自動再開する。
- チェック欄は追加操作・失敗で表示され、完了後も取り直すまで保持する。追加操作中は待機を継続し、チェック失敗や追加操作のない待機上限では理由を示して解除する。
- コード送信・再送で消費したチェックは成否によらず取り直す。再操作では改めて待てる。
- 認証サービスの送信・検証制限を回避せず、制限時は理由を示し、時間を置いて再試行できる。
- 誤ったコードの後は理由を示してコード入力へ留まり、有効なコードで再試行できる。
- 送付の拒否（送信間隔・制限・直近ログインから60秒以内の押下を含む）とチェックの失敗は、意思確認に留まってエラーが表示され、時間を置いて「アカウントを削除」を押し直せる。
- コード確認に成功した後の削除の失敗（削除の拒否、確定失敗、通信エラー、結果不明、オフライン、確認後の現在の利用者の読み直しでの不一致・取得失敗）は全て、意思確認へ戻って同じ「エラーが発生しました。しばらくしてから再度お試しください。」が赤で表示される。利用者・メール・再送待機は保たれ、コードは消える。
- コード確認そのものの失敗（誤り・期限切れ・使用済み・別アカウントのコード）と、確認前の照合の失敗は、コード入力に留まってエラーが表示される。
- 削除が行われなかったことが確実な失敗では、アカウントと記録を維持して理由を表示し、再試行できる。
- 応答がない・結果不明の場合も、他の削除の失敗と同じ表示とし、成功表示や端末記録の消去を行わない。削除済みだった場合の再試行は認証喪失に従いサインインへ移る。
- 削除は完了するか全く行われないかのどちらかで、一部だけ残して終わらない。
- 要求・再送・確認・削除の処理中に連続操作しても、同じ処理を重複開始しない。

### サインインしていないとき、サインインが切れたとき

- 未認証で、ハッシュ`#settings/account/delete-account`を付けた画面を開くと、サインイン画面へ移動し、開こうとした画面がハッシュを含めて遷移元として付く。
  サインインすると、その画面が、設定パネルにアカウント削除の画面を開いた状態で表示される。
- 表示中にサインインが切れたときは、サインイン画面へ移動する。
- サインアウトした後、ブラウザの戻るでアカウント削除の画面を開こうとしても、サインイン画面へ移動する。
- 画面の枠を保存した後でも、未認証または期限切れで開くと、サインイン画面へ移動する。

### 処理の途中で画面を離れたとき

- 削除の応答を待つ間に別の画面へ離れた(ブラウザの戻る・進むでハッシュが変わり、設定パネルの別の表示へ移った、または設定パネルが閉じたときを含む)利用者には、その応答による表示は起きない。
  削除自体は、応答が成功なら行われる。

## 対象外

- アカウントの一時停止、削除の取り消し・猶予期間、削除後の復元。
- 削除前の記録の書き出し(エクスポート)。
- 削除の前に、Googleアカウントの結び付きを解除すること(auth/link-googleで扱う。アカウント削除には不要)。
- 匿名化された記録の表示(現在、射手と操作した利用者は画面に表示されない)。
- 編集者が残らないラウンドの、残る閲覧者への事前の通知。
- アプリ独自のOTP試行回数管理。標準Authの制限とCAPTCHAを利用する。
- 削除の履歴の記録と通知メール。
- 端末へのオフライン中の削除の保留。
- メールアドレス変更・サインアウトの仕様変更。
