# auth/signin 設計

## 概要

`/signin`でメールアドレスへコードを送り、標準メールOTPを確認してサインインする。
送付と再送はTurnstileを使い、確認はAuthの検証制限を通す。
確認成功後は、安全な遷移元またはホームへページ全体を置き換える。

## 画面と状態

| 状態 | 表示・操作 | 次の状態 |
| --- | --- | --- |
| メール入力 | メール、コード送信、チェック。本文に登録・パスワード回復のリンクを置かない | 送信受理でコード入力 |
| チェック待ち | 操作時点の入力を保持し、送信中と同じ表示 | 到着で送信、失敗・上限で解除 |
| コード入力 | 送付先、コード、確認、戻る、再送待機・迷惑メールの案内 | 確認成功で遷移、戻るでメール入力 |
| 処理中 | 送信/確認/再送/戻るを重複開始しない | 失敗は同じ段階へ、成功は遷移まで処理中 |
| 入力不備・オフライン・失敗 | 内側の種類に対応した理由を示す | 入力を保ち再試行 |

コード欄は`autocomplete=one-time-code`、メール欄はメールの自動入力に対応する。
メール入力のEnterはコード送信を実行し、コード入力のEnterは確認を実行する。
送付成功から60秒は再送を拒否して残り秒数を表示し、戻っても待機とメールを保持する。
コードの未入力だけを送信前に検査し、形式・期限・再使用の判定はAuthへ委ねる。
既知の未登録応答でも共通のコード入力案内へ進むが、自動登録しない。制限・CAPTCHA・通信失敗は成功に変換しない。
ヘッダーから登録へ進める。認証済みで開いた場合は有効な遷移元またはホームへ移る。

## 構成とデータの流れ

以下の`src/`は`apps/web/src/`からの相対である。

| ファイル | 責務 |
| --- | --- |
| `src/app/(auth)/signin/page.tsx` | Auth・Clock・Connectivity・PageReplaceを生成し、送信時の遷移元読み出しを画面へ渡す |
| `src/features/auth/application/sign-in.ts` | `createSignIn`が共通OTP処理を生成し、確認後に`destinationOf(from)`へ置換する |
| `src/features/auth/application/email-otp.ts` | 送信・確認・再送待機の共通手続きと認証IOの約束 |
| `src/features/auth/domain/email-otp-flow.ts` | 段階・入力・通信可否・チェック待ち・排他の規則 |
| `src/features/auth/ui/signin-form.tsx` | サインインの文言と未検証の遷移元を共通画面へ渡す |
| `src/features/auth/ui/email-otp-form.tsx` | 2段階の入力画面と、既存OTP部品への接続 |
| `src/features/auth/infrastructure/supabase-auth.ts` | `signInWithOtp`のshouldCreateUser:false、`verifyOtp`のtype:emailと結果の変換 |
| `src/features/auth/domain/auth-routes.ts` | `/rounds`配下のパス・クエリ・ハッシュだけを遷移元に許可する |

遷移元は送信時にURLから読み、returnToがハッシュを持たない場合だけ現在のハッシュを補う。
描画時にはブラウザURLを読まず、静的な事前描画を保つ。
送付時点のメールと確認するメールを一致させ、変更した場合はコード入力をやり直す。
確認後は`window.location.replace`で1回だけページ全体を読み込み、失敗と違い送信中を解除しない。

## 設計判断

| 判断 | 理由 | 見直す条件 |
| --- | --- | --- |
| 未登録アドレスを自動登録しない | 登録とログインの入口を分ける契約を保つため | 入口を統合するとき |
| 既知の未登録応答を共通表示へ写す | 画面から登録有無を知らせないため。サービスの直接API応答の一律秘匿は保証しない | Authの応答契約が変わるとき |
| 遷移元を完了時にも検証する | 外部URLへ送ることを防ぐため | 保護対象の経路が変わるとき |

## 制約と未対応
