# auth/signin テスト設計

## 基準と担当範囲

[要件](requirements.md)・[設計](design.md)と[共通テスト設計](../test-design.md)を基準とする。
共通OTPの組合せは共通側で確認し、本機能では登録不可、安全な完了先、既存の利用者と記録への復帰を確認する。

## 単体・コンポーネント

| 前提・操作 | 期待結果 |
| --- | --- |
| ログイン入口で送信する | shouldCreateUser:falseを指定し、未登録メールを自動作成しない。 |
| 有効な/rounds配下の遷移元を伴って確認を完了する | パス・クエリ・ハッシュを保ち、ページ全体を1回置換する。 |
| 遷移元がない、外部URL、プロトコル相対、/roundsに似た別パスで完了する | ホームへ進む。auth-routes.test.tsの既存境界をOTP完了にも接続する。 |
| 送信時のURLを読む | returnToにハッシュがない場合だけ現在のハッシュを補う。既存ハッシュを上書きせず、描画時にはブラウザURLを読まない。 |
| 未登録ログインの既知の拒否を受ける | コード入力の共通案内へ進み、登録済みとの画面差を作らない。制限・CAPTCHA・通信失敗は成功にしない。 |
| メール/コードの段階で操作する | サインインの文言と共通手続きを接続し、メールとコードの自動入力、未着案内を利用できる。パスワード入力・再設定導線はない。 |

配置は既存sign-in.test.ts・auth-routes.test.ts・signin-form.test.tsxと、共通email-otpの各テストとする。
認証済みの入口転送はproxyの既存単体試験で、安全な遷移先あり/なしを確認する。

## 実Auth結合と主要E2E

既存`apps/web/tests/e2e/auth/signin.spec.ts`を更新する。

| 経路 | 利用者から見える結果 |
| --- | --- |
| 記録を持つ利用者がメールを送りコードを確認する | 元の利用者ID・記録のままホームを使える。送付・閲覧だけではサインインしない。 |
| 保護画面のパス・クエリ・設定ハッシュからログインする | 確認後に目的の画面と設定項目を開く。外部URLの代表1件はホームへ進む。 |
| 未登録メールでログイン送付を要求する | 共通案内を示すが、認証も利用者作成も起こらない。ローカルDBの比較で未作成を確認する。 |
| 認証済みで/signinを開く | 有効な遷移元へ、なければホームへ進む。 |

実コードの無効条件、別端末のメール閲覧、直接password拒否と更新後/回復後のパスワード認証の再開不可（回復コードの確認によるOTPセッションは通常のメールOTPと同等として許容する）、旧セッション維持は共通テスト設計の結合・切替試験で確認する。
再設定URLは一般の未定義ルートと同じ扱いで、専用リダイレクトを期待しない。
ヘッダーの登録リンクは既存の共有リンク試験に任せ、本文の旧登録/回復リンク試験を削除する。
実行条件・データ準備・完了判定は共通テスト設計に従う。
