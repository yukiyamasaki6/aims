# auth/signin テスト設計

## 基準と担当範囲

[要件](requirements.md)・[設計](design.md)と[共通テスト設計](../test-design.md)を基準とする。
`/signin`は新規・既存を区別しない唯一の認証入口である。
共通OTPの入力・待機・失敗・再送・離脱の組合せは共通側で確認し、本機能では次を確認する。

1. 未登録メールで登録でき、既存メールで元の利用者IDと記録へ復帰する(登録可否)。
2. 新規・既存で画面・文言・流れを分けず、登録有無を知らせない。
3. 安全な完了先(有効な遷移元またはホーム)。
4. `/signup`を提供せず、救済を設けない。
5. 未サインイン向けヘッダーを持たず、ロゴだけを置く。
6. 送付ボタンの文言(「メールで続ける」)の使い分け。

固定の寸法・位置・クラスは期待値にしない。ロゴの高さ・配置、見出し撤去後の見た目は手動で確認する。

## 単体・コンポーネント

| 前提・操作 | 期待結果 |
| --- | --- |
| 入口でメールを送信する | 共通手続きを登録可で作り、AuthへshouldCreateUser:trueを渡す。削除の再確認はfalseのままで、既知の拒否の変換を維持する(共通側のアダプター表で確認し、ここで重複させない)。 |
| 未登録・登録済みのどちらへの送付も受理される | どちらも共通のコード入力案内へ進み、登録有無で文言・段階・遷移を分けない。制限・CAPTCHA・通信失敗は成功にしない。 |
| 有効な/rounds配下の遷移元を伴って確認を完了する | パス・クエリ・ハッシュを保ち、ページ全体を1回置換する。 |
| 遷移元がない、外部URL、プロトコル相対、/roundsに似た別パスで完了する | ホームへ進む。auth-routes.test.tsの境界をOTP完了にも接続する。 |
| 送信時のURLを読む | returnToにハッシュがない場合だけ現在のハッシュを補う。既存ハッシュを上書きせず、描画時にはブラウザURLを読まない。 |
| メール入力段階を描画する | 本文の見出しがなく、送付ボタンは専用の「メールで続ける」(`emailContinue`の文言を翻訳ヘルパーで得る)である。ログイン・登録の相互リンクやパスワード入力・再設定導線がない。 |
| コード入力段階を描画する | 本文の見出しがなく、送付先の説明・戻る・確認・再送・迷惑メールの案内がある。確認・再送のボタンに「メールで続ける」を使わない。 |
| 送付成功後にメール入力へ戻る | 同じ送付ボタン(「メールで続ける」)を使い、待機中は既存どおり残り秒数を示す。待機終了後は残り秒数がなく「メールで続ける」になる。 |
| メール/コードの段階で操作する | メールとコードの自動入力、Enterの送信・確認、未着案内を利用できる(共通側で確認済みの接続を再検証しない)。 |
| メール変更の送付を描画する | 従来の「認証コードを送信」(`otpSendCode`)のままで、「メールで続ける」へ波及しない(change-email-form側で確認する)。 |

配置は既存`sign-in.test.ts`・`auth-routes.test.ts`・`signin-form.test.tsx`と、共通email-otpの各テストとする。

### 経路と非提供の単体

| 前提・操作 | 期待結果 |
| --- | --- |
| 認証済みで遷移元のない/signinを開く | ホーム(/rounds)へリダイレクトする。 |
| 認証済みで有効な遷移元付きの/signinを開く | その遷移元へ戻り、パス・クエリ・設定ハッシュを保つ。外部URL・不正値はホームへ進む。 |
| 認証済み・未認証で/signupを開く(クエリ・ハッシュ付きを含む) | 専用のガードに入らず、任意の未定義パスと同じ扱いで素通りする。リダイレクト・別名・遷移元の引継ぎを返さない。 |

配置は`proxy.test.ts`と`auth-routes.test.ts`である。
proxyのmatcherに/signupが残らないこと、`routes.ts`に`SIGN_UP_PATH`、`app/(auth)/signup/`、`sign-up.ts`が残らないことは、定数の写しをテストにせず、差分レビューと`pnpm typecheck`・未使用検査で確認する。

### ロゴとヘッダーの不在

| 前提・操作 | 期待結果 |
| --- | --- |
| 共通のロゴ部品へ表示の高さを指定する(`logo-image.test.tsx`) | 指定した高さで表示され、未指定なら既定の高さで表示される。2つの高さの間で縦横比が保たれ、代替テキストを持つ(`translatorFor("shared")`の`logoAlt`で得る)。24px・48pxの値そのものは期待値にしない。 |
| 紹介画面を描画する(`intro-screen.test.tsx`) | ロゴを表示し、ロゴはリンクの中に置かれない。 |

認証画面のロゴが紹介「/」へのリンクであることは、`signin.spec.ts`の1件で押して確かめる(下表)。
未サインイン向けヘッダーの不在は、DOMのlandmarkの不在を期待値にせず、ヘッダー部品を持たないことを差分レビューと`pnpm typecheck`・未使用検査で保証する。単体・E2Eのいずれにも不在のテストを置かない。
認証レイアウトはサーバーの枠で、組み立てだけの単体テストは置かない。ヘッダー部品とその単体テスト、代替部品・テストを置かない。

## 実Auth結合と主要E2E

E2Eは`apps/web/tests/e2e/auth/signin.spec.ts`に置く。
準備は固有の利用者と実メール(Mailpit)で行い、利用者IDの比較はローカルDBで行う。

| 経路 | 利用者から見える結果 |
| --- | --- |
| 未登録メールで送付し、実メールのコードを確認する | 送付だけでは保護データを利用できず、確認後にホームへ進む。パスワードの操作を要さず、登録するかの選択や新規専用の画面がない。ローカルDBに利用者が作られる。 |
| 記録のある登録済みメールで送付し、コードを確認する | 元の利用者ID・記録のままホームを使える。重複アカウントや記録の置換がなく、別端末の既存セッションも継続する。 |
| 保護画面のパス・クエリ・設定ハッシュから、新規と既存のそれぞれが認証する | どちらも確認後に目的の画面と設定項目へ戻る。外部URL等の遷移元の組合せは単体の責務で、E2Eでは繰り返さない。 |
| 未認証で/signinを開き、メール入力段階でロゴを押す | 紹介「/」へ移り、紹介画面が表示される。リンクを持つ画面の機能のE2Eにリンクを置く規則に従い、本ファイルに1件だけ置く。ロゴは`translatorFor("shared")`の`logoAlt`で探す。 |
| 未認証・認証済みで/signupを開く(クエリ・ハッシュ付きを含む) | 専用の画面や転送がなく、任意の未定義URLと同じ結果になる。/reset-passwordの扱いと同じ形で、`navigation.spec.ts`に置く。 |

コード入力段階でも同じロゴが表示されることは、メール入力段階と同じ認証レイアウトの部品であるため、E2Eの期待値にせず手動確認で確かめる。
直接password拒否、実コードの無効条件、別端末のメール閲覧、旧セッション維持は共通テスト設計の結合・切替試験で確認する。
再設定URLと/signupは一般の未定義ルートと同じ扱いで、専用リダイレクトを期待しない。
実行条件・データ準備・完了判定は共通テスト設計に従う。
