# auth/signin テスト設計(セキュリティチェックの待ち)

## 方針

チェック待ちの規則は、分岐と状態遷移のため、単体(Vitest)で確かめる。E2Eは、利用者が「チェック完了前に押しても、サインインできる」ことの達成だけを確かめる。
待ちの上限の時間(10秒)は、E2Eで実時間を待たず、部品の単体で偽のタイマーで確かめる。
固定の文言、構造、公開側のテスト用部品(`data-hydrated`・`data-testid`を除く)は、確かめず、足さない。
同じ規則は、規則を持つ層で詳細を確かめ、他の集約は接続の確認に必要なケースだけを選ぶ。

## 既存のテストの更新

「チェック未完了でチェックのエラーを示す」を期待していたテストは、次の方針で書き換える。件数は増やさず、同じテストを新しい規則へ置き換える。

- 入力が有効でトークンが無い場合: 「チェックのエラーが載り、開始しない」を、「依頼なし、実行中かつ待ち、エラーなし」へ変える。
- 入力に不備がある場合: 「不備とチェック未完了を全て示す」を、「不備だけを示す。チェックのエラーは、状態によらず添えない」へ変える。
- オフラインの場合: 「チェック未完了を示さずオフラインを示す」は、オフラインがチェックの待ちより先に判定されること(待ちにしない)の確認として残す。
- 失敗の後の再押下: 「使用済みのトークンを再利用せず、チェックのエラーを示す」を、「エラーなしで待ちになり、手続きは1回のまま」へ変える。

## サインアップ・パスワード再設定の扱い

サインアップとパスワード再設定は、画面(`signup-form`・`reset-password-form`)が`password-setup-form`と`password-setup`集約を共有する薄い入口で、待ちは同じ経路(集約の`begin*`、`useCheckWait`)で実現される(設計どおり。設計との食い違いは無い)。

- 単体は、`password-setup-flow.test.ts`と`password-setup-form.test.tsx`で確かめ済みとし、`signup-form.test.tsx`・`reset-password-form.test.tsx`・両`page.test.tsx`には待ちのテストを足さない(同じ組合せの繰り返しになる)。ただし、トークンを渡す既存の操作(`completeCaptcha`・`onVerify`)が新しい規則でも成り立つことを、実行して確かめる。
- `otp-email-step`・`otp-code-step`が`waiting`・`onFailed`を通すこと(配線)は、`password-setup-form.test.tsx`の入口ごとの1件(到着で再開)に加え、メール欄の段階で失敗の通知で待ちが解けることを、`password-setup-form.test.tsx`で1件確かめる(失敗の通知が部品から集約まで届く唯一の経路のため)。追加チェックの表示中に待ちが続くことは、部品の単体で確かめる。
- E2E(`signup.spec.ts`)は変えない。サインインの2件が、待ちの利用者の達成を担う。

## 追加しないテスト

- `otp-email-step`・`otp-code-step`が通す配線の単独テストは足さない(上の`password-setup-form`の1件で足りる)。
- 待ちの10秒の実時間、失敗の表示、追加チェックの表示開始での上限の停止は、E2Eで確かめない(部品、フック、集約の単体で確かめる)。
- 4つの集約・フォームで同じ組合せ(再押下、オフライン、表示中の上限)を繰り返さない。詳細はサインインにだけ置く。
- チェックのエラー文言の固定値、E2Eのウィジェットの位置・寸法は期待値にしない。
- `e2eTurnstileRelease`自体のテストは書かない。E2Eの2件が使うことで足りる。

## 試験用の部品

E2Eの偽のチェック部品(`tests/e2e/helpers/turnstile.ts`)に`e2eTurnstileRelease`を足す。

- `e2eTurnstileFailFromCall`で止めた(トークンを渡さずに描かれた)ウィジェットのうち、最後に描いたものの`callback`へ、既存の`emitToken`でトークンを渡す。トークンの数も既存と同じく数える。
- 試験の側は、`page.evaluate`で呼ぶ関数(`releaseTurnstileToken(page)`)として公開し、続けて`waitForTurnstileToken`で受け取りと描画の反映を待つ。
- 追加チェックの経路は、既存の`e2eTurnstileSolve`を使う(新設しない)。
- 説明のコメントを、ファイル先頭の既存の説明へ1段落追記する。公開側には足さない。

## 手動確認

実物のCloudflareのウィジェットでしか分からないため、E2E・単体では確かめない。`pnpm preview`で次を確かめる。

1. 実際の自動チェックが終わる前(読み込み直後)に押すと、エラーなしで実行中になり、完了後に自動でサインインする。
2. 追加の操作を求められたとき、チェック欄が表示され、実行中のまま待ち、10秒を超えても失敗にならず、完了で自動で進む。
3. 追加の操作が無いまま約10秒完了しないとき(ネットワークの遮断など)、失敗が表示され、実行中が解ける。
4. 認証の失敗の後、すぐに押しても、取り直しの完了後に自動で進む。
