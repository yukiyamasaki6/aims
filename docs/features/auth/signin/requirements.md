# auth/signin

## 目的

利用者がメールアドレスを確認し、パスワードを管理せずに、新規・既存を区別せずAIMSを使い始め、または再開できるようにする。

## 要求

### サインインする

- 未登録のメールアドレスへ届いた有効な認証コードを入力すると、パスワードを入力・設定・再認証せずに登録して利用を開始できる。
- 登録済みのメールアドレスへ届いた有効な認証コードを入力すると、パスワードなしで元のアカウントと記録を利用でき、重複アカウントや記録の置換を起こさない。
- 変更済みの旧メールアドレスも、未登録であれば未登録のアドレスと同じ流れで新規登録でき、元と異なる利用者IDの別アカウントになる。元のアカウントと記録は引き継がない。
- 登録とサインインの入口を分けず、新規・既存で画面・文言・流れを分けない。登録有無を、コード送付後の画面や案内で知らせない。
- コードの要求・受信・メール閲覧・リンク操作だけでは、新しいサインインは成立しない。
- 未入力・誤り・期限切れ・使用済みコードでは新しいサインインが成立せず、認証が必要な記録を取得できない。
- 許可された遷移元がある場合は新規・既存を区別せず認証後にその画面へ戻り、ない場合や外部URL等の場合はホームへ進む。
- `/signup`は提供せず、ページ・ルート・定数・ガード対象と互換のためのリダイレクト等を設けない。
- パスワードの入力・再設定の操作や導線を表示しない。
- メール入力欄はメールの自動入力、コード欄はメールコードの自動入力に対応する。

### 認証コードの入力中

- 再送は送付から60秒待ち、残り秒数と、メールが届かない場合の確認事項が表示される。
- 待機後はセキュリティチェックを完了して新しいコードを要求でき、発行後に古いコードは使えない。
- メール入力へ戻るとメールを再利用でき、コードを入力し直せる。
- 新規・既存のいずれの利用者へのメールも、コードと15分の期限、心当たりがない場合の案内を持ち、クリックだけで認証を成立させるリンクを含まない。

### 認証済みで開く

- 認証済みで開くと、有効な遷移元があればその画面へ、なければホームへ移る。
- 切替前の有効なセッションは一律に失効させず、従来の更新条件で維持する。終了後の新規ログインはOTPを要求する。

### パスワード認証を直接要求する

- 切替時に保存済みパスワードハッシュを削除・上書きせず、以前のパスワードによる新規ログインを直接API経由も含め拒否する。
- 直接APIでパスワードの新規設定・変更・再設定を試みた後も、パスワードによる新規ログインは成立しない。

### 入力不備・重複・失敗があるとき

- メール未入力・形式不正またはコード未入力では理由を表示して対象処理を行わず、修正して再試行できる。
- 送信・再送のチェック未完了で押すと処理中として待ち、追加操作の間も待ち、完了後に自動で再開する。
- チェック欄は追加操作・失敗で表示され、完了後も取り直すまで表示を保つ。
- チェック失敗または追加操作のない待機の上限では、理由を示して解除し、再操作で改めて待てる。
- 送信・確認・再送の実行中に操作を繰り返しても同じ処理を重複開始しない。
- 誤ったコード・期限切れ・使用済み・制限・通信失敗では理由を表示し、成功と誤表示せず再試行できる。
- 送信・再送で消費したチェックは成否によらず取り直し、認証サービスの送信・確認制限を回避しない。
- オフラインでは入力不備またはネットワークの案内を表示し、処理を送信も保留もしない。

## 対象外

- メールを受信できない場合の別の復旧経路。
