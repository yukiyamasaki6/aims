# auth/signup 設計

## 概要

`/signup`でメールアドレスを受け、標準メールOTPを確認して利用を開始する。
パスワード入力・設定・パスワードでの再ログインは行わず、OTPセッションをそのまま使う。
登録済みアドレスでも同じコードを送り、元の利用者IDと記録を維持する。

## 画面と状態

| 状態 | 表示・操作 | 次の状態 |
| --- | --- | --- |
| メール入力 | メール、コード送信、チェック | 送信受理でコード入力 |
| チェック待ち | 押した入力を保持し、処理中として待つ | 到着で再開、失敗・上限で解除 |
| コード入力 | 送付先、コード、確認、戻る、再送と残り秒数、迷惑メールの案内 | 確認成功でホーム、戻るでメール入力 |
| 不備・オフライン・失敗 | 理由を示して入力を保つ | 同じ段階から再試行 |
| 確認成功 | 遷移まで処理中 | ホームへページ全体を置換 |

登録有無を画面・送付完了の文言で分岐しない。
登録済みアドレスへのメールにもコードを表示し、重複アカウントを作らない。
コードの自動入力、60秒の再送待機、戻ったときのメール保持と操作の排他はログインと共通にする。
ヘッダーからログインへ進める。認証済みで開いた場合はホームへ移る。

## 構成とデータの流れ

以下の`src/`は`apps/web/src/`からの相対である。

| ファイル | 責務 |
| --- | --- |
| `src/app/(auth)/signup/page.tsx` | Auth・Clock・Connectivity・PageReplaceを組み立て、手続きを画面へ渡す |
| `src/features/auth/application/sign-up.ts` | `createSignUp`が共通OTP処理を生成し、確認後にホームへ置換する |
| `src/features/auth/application/email-otp.ts` | コード送信・確認・再送待機の共通手続きと認証IOの約束 |
| `src/features/auth/domain/email-otp-flow.ts` | メール/コードの段階と、処理開始・入力・チェック・待機・排他の規則 |
| `src/features/auth/ui/signup-form.tsx` | 登録の文言と手続きを共通画面へ渡す |
| `src/features/auth/ui/email-otp-form.tsx` | 共通の2段階画面とOTP部品を描く |
| `src/features/auth/infrastructure/supabase-auth.ts` | `signInWithOtp`のshouldCreateUser:true、`verifyOtp`のtype:emailと結果の変換 |
| `supabase/templates/email-otp.html` | 未確認・確認済みアドレスと直接回復要求で共通のコード・15分期限・心当たりがない場合の案内 |

確認までパスワードの登録も認証済み記録へのアクセスも提供しない。
確認成功で得た同じ利用者のOTPセッションを採用し、他セッションを一括終了しない。
Auth内部でランダム値のハッシュが作られても取り出し・削除せず、発行Hookでパスワード認証への利用を禁止する。
パスワード設定用のdomain/application/uiとIOは削除し、OTP用の共通処理へ置換する。

## 設計判断

| 判断 | 理由 | 見直す条件 |
| --- | --- | --- |
| 確認後のパスワード設定とセッション置換を行わない | OTPだけで登録を完了し、パスワード認証を廃止するため | 認証方式を再検討するとき |
| 登録済みでも元のアカウントへログインする | 登録有無を画面で知らせず、元の記録を維持するため | 登録済みの案内方針を変えるとき |
