# auth/signup

## 目的

アカウントを持たない利用者がメールアドレスを確認し、パスワードを設定してAIMSを使い始められるようにする。

## 要求

### 登録する

- 未登録のメールアドレスへ届いた認証コードを確認し、要件を満たすパスワードを設定した利用者は、登録してホームへ進める。
- パスワードを入力欄で表示・非表示に切り替えて確かめられる(切り替えても入力値は保たれる)。
- 新しいパスワードの入力欄は、ブラウザやパスワード管理ツールが、強いパスワードの提案と保存ができる欄として認識される。
- 登録を完了した端末のサインインは、メールの認証コードで得たものでなく、パスワードで確かめたものになる。
  認証コードで得た古いサインインは、サーバー側でも使えなくなる(認証サービスの取得・更新に限る。期限内のアクセストークンでのデータの読み書きは通りうる。`docs/security.md`)。
  これにより、登録の直後から、パスワード変更(auth/change-password)で現在のパスワードが確認される。
- パスワード設定の段階でも、セキュリティチェックを完了する必要がある。
  完了していない利用者には理由が表示され、パスワードは設定されない。

### 認証コードの入力中

- 認証コードの入力欄は、メールで届いたコードの自動入力に対応する。
- 認証コードを送信した利用者は、再送は送付から60秒待つ必要があり、残り秒数が表示されることと、メールが届かない場合の確認事項が分かる。
- 認証コード入力からメール入力へ戻った利用者は、入力済みのメールアドレスを再利用できる。
- 再送待機時間が終わりセキュリティチェックを完了した利用者は、新しい認証コードを受け取れる。

### ほかの画面へ進む

- アカウントを持つ利用者は、サインインへ進める。

### 認証済みで開く

- 認証済みの利用者がサインアップ画面を開くと、ホームへ移動する。

### 入力の不備、重複した送信、失敗があるとき

- メールアドレス、パスワード、認証コード(未入力)、またはセキュリティチェックに不備がある場合は、理由が全て表示され、該当する認証処理は行われない。
- 送信、確認、または登録の処理中に操作を繰り返しても、同じ認証処理は重複して行われない。
- 登録済みのメールアドレスでは、認証コードの代わりに登録済みを知らせる案内のメールが届き、新しいアカウントは登録されない。
- 認証または通信に失敗した場合は、理由が表示され、同じ段階から再試行できる。
- パスワードの設定に成功した後に、パスワードでのサインインに失敗した場合も、理由が表示され、同じ段階から再試行して登録を完了できる。
- 認証コードで得た古いサインインを、サーバー側で使えなくできなかった場合も、登録は完了し、ホームへ進む。
  古いサインインは残る(`docs/security.md`の残余リスク)。
- 端末がオフラインの状態で送信(コードの送信、再送、確認、パスワード設定)した場合は、セキュリティチェックの状態によらず「ネットワークに接続されていません。接続を確認してから再度お試しください。」が表示され、認証処理は行われない(入力に不備がある場合は、その理由が表示される)。

## 対象外

- 登録済みアカウントの認証とパスワード再設定は、それぞれの機能で扱う。
- この変更より前に登録した利用者の、認証コードで得たサインイン(サーバー側に残っているもの)の掃除。
  掃除しない。
  サインアウトまたは失効までは、現在のパスワードの検査の免除が残る。
  残余リスクとして受け入れる(`docs/security.md`)。
- パスワード設定の前に離脱または再読み込みした利用者の、認証コードで得たサインインの扱い。
