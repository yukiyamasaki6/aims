# auth/signup

## 目的

利用者がメールアドレスを確認し、パスワードを管理せずにAIMSを使い始められるようにする。

## 要求

### 登録する

- 未登録のメールアドレスへ届いた有効なOTPを確認すると、パスワードを入力・設定・再認証せずに登録を完了してホームへ進める。
- 登録済みのアドレスでもコードを受け取れ、確認後は元のアカウントと記録を利用でき、重複アカウントや記録の置換を起こさない。
- 登録の有無を、コード送付後の画面や案内で知らせない。
- メール閲覧・リンク操作・コード送付だけでは新しい認証を成立させない。
- 登録とログインの入口は分け、パスワードの操作・案内・導線を表示しない。

### 認証コードの入力中

- コード入力はメールコードの自動入力に対応する。
- 再送は送付から60秒待ち、残り秒数とメール未着時の確認事項が表示され、待機後に新しいコードを要求できる。
- 新しいコードの発行後は古いコードを使えない。
- メール入力へ戻ると入力済みメールを再利用でき、コードを入力し直せる。
- 新規・既存のいずれの利用者へのメールも、コード・15分の期限・心当たりがない場合の案内を持ち、認証成立リンクやパスワード操作への誘導を含まない。

### ほかの画面へ進む

- ヘッダーからログインへ進める。本文にログインリンクは置かない。

### 認証済みで開く

- 認証済みの利用者が開くとホームへ移る。

### 入力不備・重複・失敗があるとき

- 未入力・形式不正のメールや未入力コードでは理由を表示し、対象処理を行わない。
- 送信・再送ではチェック完了前の操作を処理中として待ち、追加操作の間は待機を続け、完了すると自動再開する。
- チェック欄は追加操作・失敗で表示され、完了後も取り直すまで表示を保つ。
- チェック失敗または追加操作のない待機上限では理由を示して解除し、再操作で改めて待てる。
- 送信・確認・再送を処理中に繰り返しても重複開始しない。
- 誤り・期限切れ・再使用・送信制限・通信失敗では認証せず、理由を表示して再試行できる。
- 送信・再送のチェックは成否によらず消費後に取り直し、認証サービスの送信・確認制限を回避しない。
- オフラインでは入力不備またはネットワークの案内を示し、送信や端末への保留を行わない。

## 対象外

- メールを受信できない場合の別の復旧経路。
- パスワードの設定と、他の既存セッションの一括失効。
