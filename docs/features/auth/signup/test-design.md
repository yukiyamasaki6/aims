# auth/signup テスト設計

## 基準と担当範囲

[要件](requirements.md)・[設計](design.md)と[共通テスト設計](../test-design.md)を基準とする。
共通OTPの入力・待機・失敗・再送・離脱の組合せを重複させず、登録可否と登録完了の契約を確認する。

## 単体・コンポーネント

| 前提・操作 | 期待結果 |
| --- | --- |
| 登録入口でメールを送信する | 共通手続きを登録可で作り、AuthへshouldCreateUser:trueを渡す。 |
| コードを確認して登録が完了する | OTPセッションのままホームへページ全体を1回置換し、遷移まで処理中を保つ。パスワード設定・再ログイン・他セッション一括終了を行わない。 |
| 未登録/登録済みへの送付が受理される | どちらも共通のコード入力案内で、登録有無による画面分岐をしない。 |
| メール/コードの段階を描画し操作する | 共通OTP画面へ登録用の文言と操作を接続する。パスワード入力や設定段階はない。 |

配置は既存sign-up.test.ts、signup-form.test.tsxと共通email-otpの各テストとする。
固定の本文・DOM構造を列挙して登録画面を写すテストは追加しない。

## 実Auth結合と主要E2E

既存`apps/web/tests/e2e/auth/signup.spec.ts`を更新する。

| 経路 | 利用者から見える結果 |
| --- | --- |
| 未登録メールで送付し、実メールのコードを確認する | 送付だけでは保護データを利用できず、確認後にホームへ進む。パスワードの操作を必要としない。 |
| 記録のある登録済みメールで登録する | 同じ利用者IDと元の記録を利用し、重複アカウントや記録の置換がない。別端末の既存セッションも継続する。 |
| 認証済みで/signupを開く | ホームへ移り、入力画面へ留まらない。既存ガード試験で詳細を確認する。 |

コード誤り・期限・再使用・再送失効、共通メール、直接password signup拒否は共通テスト設計の実Auth結合で担当する。
ヘッダーのログインリンクは紹介画面の共有リンク試験に任せ、本文の旧相互リンク・パスワード設定の試験を削除する。
実行条件・データ準備・完了判定は共通テスト設計に従う。
