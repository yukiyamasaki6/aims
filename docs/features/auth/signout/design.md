# auth/signout 設計

## 概要

左パネルのサインアウトボタンから確認ダイアログを開き、確認ボタンで実行する。
手続き`createSession`の`signOut`が、認証サービスにこの端末のサインインだけを終えさせ(`signOut({ scope: "local" })`)、端末の識別情報が消えたかで完了か失敗かを判定する。
サインアウト自身は遷移しない。完了後は、`(main)`のレイアウトが始めたセッション喪失の見張りが`SIGNED_OUT`を検知して`/signin`へ遷移する（`app/navigation`）。
遷移元を付けない合図は、サインアウトを始める前に立て、失敗で解除する（集約`session-end.ts`）。失敗したらダイアログを開いたままエラーを表示し、再試行できる。
ダイアログを開くところまでは`app/navigation`の担当で、この文書は確認ダイアログ以降を扱う。

## 画面と状態

| 状態 | 表示 | 次の状態 |
| --- | --- | --- |
| 確認中 | 説明文、キャンセル、確認 | キャンセル・背景クリック・Escで閉じる、確認でサインアウト中 |
| サインアウト中 | 確認ボタンにスピナー。キャンセル・確認・背景クリック・Escは無効 | 成功で`/signin`へ遷移、失敗でサインアウト失敗 |
| サインアウト失敗 | ダイアログ内にエラー。ボタンは操作可能に戻る | 再試行、またはキャンセル |

- オフラインでも成功として扱い、`/signin`へ遷移する。オフラインの`/signin`はService Workerが`/offline`を返すため、観測できるのはオフライン画面である。`SIGNED_OUT`はオフラインでも遷移させる。

## 構成とデータの流れ

構造の方針は`docs/architecture.md`に従う。

- `src/app/(main)/layout.tsx`: 画面の入口。手続き、認証の実装、識別情報の実装、通信の可否の実装、ページ遷移の実装を生成して注入し、喪失の見張りを始め、左パネルへサインアウトの部品を渡す。接続を作る関数`createClient`は渡すだけで、描画時には呼ばない。
- `src/features/auth/ui/sign-out-button.tsx`: サインアウトのボタンと確認ダイアログ。手続きの`signOut`を呼び、失敗なら`failureMessage`の文言を返す。画面が表示中かを`isMounted`として渡す。
- `src/components/ui/confirm-dialog.tsx`: `BlockingConfirmDialog`。二重実行の防止、実行中の無効化、エラー表示、再試行を担う。`rounds/delete`と共通である。
- `src/features/auth/application/session.ts`: 手続き。`signOut`（合図を立てる、認証サービスに頼む、離脱を確かめる、識別情報を読んで判定する）と、`watch`（喪失の検知と遷移）の順序を持つ。集約の現在の値を持ち、認証サービス、識別情報の読み出し、ページ遷移の約束を宣言する。
- `src/features/auth/domain/session-end.ts`: 集約。完了の判定（識別情報が消えたか）、遷移元を付けない合図、遷移は1回、行き先を守る。
- `src/features/auth/domain/session-event.ts`: 認証状態の変化と確認結果の意味の規則。識別情報の更新と、セッション喪失の定義。
- `src/features/auth/infrastructure/supabase-session.ts`: 認証サービスの実装。この端末のサインアウト、サインインの状態の確認、認証状態の変化の購読。接続は、渡された関数で使うたびに取得する。
- `src/features/auth/infrastructure/supabase-session-state.ts`: サインインの状態の判定（`readSession`）と、確認できなかった理由の文言。他の機能（取得、同期）も使う。
- `src/features/auth/infrastructure/browser-identity-store.ts`: 端末の識別情報の読み書き。他の機能（ラウンドの参照データ、同期の開始）も読む。
- `src/features/auth/infrastructure/browser-page-load.ts`: ページ全体の読み込みと置き換え、今の場所の読み出し。
- `src/features/auth/application/local-identity.ts`、`src/app/local-identity-provider.tsx`: 端末の識別情報の記録。ルートの入口が生成して始め、認証状態の変化に追従する。
- `src/lib/connectivity/`: 通信の可否の約束と実装。見張りがオフラインの確認を保留するために使う。

契約は次のとおりである。

- 成否は、通信の成否でなく、端末の識別情報が消えたかで判断する。
- supabase-jsの`signOut`は、`scope`が`others`以外なら、サーバーがエラーでもローカルのセッションを削除する。そのためオフラインでも成功にできる。
- 識別情報の更新元は認証状態の変化だけである。
- 識別情報が残った場合は、認証サービスの失敗の文言を表示し、失敗の値が無ければ通信エラーの文言を表示する。

## 設計判断

| 判断 | 理由 | 見直す条件 |
| --- | --- | --- |
| クライアントの`signOut()`で行い、遷移はセッション喪失の検知の1経路に任せる | Server Actionのリダイレクトが遷移を横取りするレースを避けるため、Server Actionをやめた。詳細: #363。サインアウトの経路でも遷移させると検知の不具合が隠れるため1経路にする | レースを避けられる方式が出たとき |
| 遷移元を付けない合図を、集約の値にして手続きが持つ | モジュール内の変数だと、合図の設定と遷移先の決定の持ち主が分かれ、状態が見えないため。失敗で合図が解除されることを集約が守る | サインアウトの遷移を別経路にするとき |
| `scope: "local"`でこの端末のセッションだけを終了する | 既定の`global`は全端末のセッションを無効にするため。再設定の全端末のサインアウトとは、完了の意味と遷移が違うので、約束も実装も共有しない | 全端末のサインアウトを提供するとき |
| 成否を識別情報の有無で判断する | オフラインでエラーが画面に残る不具合があり、`getUser`に基づく確認と通信の成否での判断をやめた。詳細: #502 | supabase-jsの`signOut`の挙動が変わったとき |
| 識別情報の更新を認証状態の変化だけにする | オフラインでも利用者を識別するため、更新元を一本化する | 識別情報の更新元を増やす必要が出たとき |
| 二重実行の防止を手続きに入れず、確認ダイアログが持つ | 実行中の判定の持ち主を1つにするため。確認ダイアログを通らない呼び出し元は無い | 確認ダイアログ以外からサインアウトを呼ぶとき |
| 確認ダイアログを`BlockingConfirmDialog`に共通化する | 削除確認と同じ構造で、重複を除くため | 画面ごとに挙動が分かれるとき |
| 通信の可否を共有の技術にする | 取得、同期、見張りが使う技術の能力で、持ち主を1つにするため | 通信の可否に業務の言葉が入るとき |

## 制約と未対応

- 端末の識別情報が残った場合の失敗は、失敗の値が無いと通信エラーの文言で表示し、原因を区別しない。
- 保存先が使えない環境では、識別情報が常に空として読まれ、サインアウトが実際には失敗していても完了と判定される。
- 完了を待つ間に画面が離れて結果を破棄すると、遷移元を付けない合図が解除されない。失敗した後に別の理由でセッションを失うと、遷移元なしでサインインへ移る。
- 他の端末のサインインは終了しない。
- 認証サービスの失敗のうち、文言の表が無い種類は、認証サービスの言語のまま表示される。
