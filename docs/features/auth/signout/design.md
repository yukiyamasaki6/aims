# auth/signout 設計

## 概要

設定パネルの分類「アカウント」のサインアウトボタンから確認ダイアログを開き、確認ボタンで実行する。
手続き`createSession`の`signOut`は、オフラインなら何も送らず失敗(`offline`)として返す。
オンラインなら、認証サービスでこの端末のセッションの失効が受け付けられたときだけ、保存先のセッションを削除する。受け付けられなかったときは保存先に触らず、サインイン状態を保つ。
その後にサインインの状態を読み、未認証なら終えられたとする。
終えられたら、手続きが遷移元を付けずに`/signin`へ置き換える。終えられなかったら、遷移せず、ダイアログを開いたままエラーを表示し、再試行できる。
手続き全体(終了の依頼と続く読み取り)は10秒(`SIGN_OUT_TIMEOUT_MS`)で打ち切り、終えられなかった(通信エラー)として返す。
実行中の判定は集約`session-end-flow.ts`が持ち、実行中のサインアウトは始めない。実行中に見張りが喪失を検知しても遷移せず、サインアウトの判定に委ねる。
ダイアログを開くところまでは`app/settings`(置き場)と`app/navigation`(設定パネルへの導線)の担当で、この文書は確認ダイアログ以降を扱う。

## 画面と状態

| 状態 | 表示 | 次の状態 |
| --- | --- | --- |
| 確認中 | 説明文、キャンセル、確認 | キャンセル・背景クリック・Escで閉じる、確認でサインアウト中 |
| サインアウト中 | 確認ボタンにスピナー。キャンセル・確認・背景クリック・Escは無効 | 終えられたら`/signin`へ遷移、終えられなければサインアウト失敗 |
| サインアウト失敗 | ダイアログ内にエラー。ボタンは操作可能に戻る | 再試行、またはキャンセル |

- オフラインでは確認を押しても始めず、サインアウト失敗にする(文言は失敗の種類`offline`)。通信できないままサインインを終えると、`/signin`をService Workerが`/offline`へ置き換えるため再サインインできなくなる。これを避けるため、サインアウトは通信できるときだけ行う。

## 構成とデータの流れ

構造の方針は`docs/architecture.md`に従う。

- `src/app/(main)/layout.tsx`: 入口。入口が渡すセッションの手続きを`useSession`で受け取り、喪失と利用者の不一致の見張りを始める。
- `src/app/(main)/settings-panel-entry.tsx`: 入口。`useSession`で受け取った手続きの`signOut`で`SignOutButton`を作り、設定パネルの分類「アカウント」へ渡す(`app/settings`)。
- `src/features/auth/ui/sign-out-button.tsx`: サインアウトのボタンと確認ダイアログ。
  ボタンは、設定の項目一覧の行(`app/settings`の「画面の作り」)として、`variant="ghost"`と`size="row"`で描く。本文の他の3項目と同じ既存の文字14px・行高20pxを維持し、高さ44pxの操作領域と項目間の隙間0pxを保つ。確認ダイアログの文字サイズは変更しない。
  確認ダイアログは設定パネルのダイアログの中で開く入れ子のダイアログで、Escと外側の押下は確認ダイアログだけを閉じる。`BlockingConfirmDialog`に`nested`(既定は偽)を通して`DialogContent`へ渡し、`SignOutButton`は`nested`で描く。入れ子のダイアログは既定では自身の背景を描かず、外側の押下を親の背景が受けて設定パネルが閉じうるためである(`components/ui/dialog.tsx`)。
  実行中の表示とエラーを持ち、手続きの`signOut`を呼ぶ。
  結果は失敗(`failed`)とそれ以外(`ignored`。完了、実行中のため始めなかった)だけで、失敗のときだけ実行中を解いて失敗の種類の文言(UI層の文言の一覧)を示す。
  完了しても状態を変えず、遷移で画面ごと捨てられるまで実行中の表示を保つ。
- `src/components/ui/confirm-dialog.tsx`: `BlockingConfirmDialog`。`busy`と`error`と`nested`を外から受け取る表現だけの部品で、実行中は閉じず、ボタンを無効にして表示する。二重実行の拒否は呼び出し側が行う（サインアウトは集約、プリセット削除は削除側のフック）。`rounds/delete`と共通である。
- `src/features/auth/application/session.ts`: 手続き。`signOut`（実行中なら何もせず`ignored`、オフラインなら`offline`の失敗、認証サービスに頼む、サインインの状態を読む、判定する、終えられたら遷移する）と、`watch`（喪失の検知と遷移、記録の利用者と違う利用者のサインインの検知と読み込み直し）の順序を持つ。不一致のときは、新しい利用者を端末の識別情報へ書き、読み戻せたときだけ今の文書を読み込み直す。記録の利用者の照合(`RecordUser`の`isRecordUser`)と識別情報の書き込み、通信の可否(`lib/connectivity/contract`の`Connectivity`の`isOffline`)は、入口が引数で渡す。集約の現在の値を持ち、サインインの状態の読み取りを宣言する(ページ全体の置き換えの約束`PageReplace`は`page-replace.ts`)。見張りの読み込み直しは、サインインの完了が置き換えで済むようになっても残る。起動時の復元での食い違い、確認コードの検証だけで中断した後の`(main)`への移動、別のタブや再表示で届くサインインは、`(main)`の初回の通知でしか検知できないためである。
- `src/features/auth/ui/session-context.tsx`: `SessionProvider`と`useSession`。入口(`src/app/root-client-entry.tsx`)がアプリで1つ生成したセッションの手続きを、認証が要る画面の集合(`(main)`のレイアウト)と、設定パネルの入口へ渡す。
- `src/features/auth/domain/session-end-flow.ts`: 集約。実行中の判定、サインアウトの開始時のオフラインの判定(実行中の判定の後。始めず、状態も変えない)、打ち切りの上限`SIGN_OUT_TIMEOUT_MS`と世代(開始と打ち切りで進め、打ち切られた実行の遅れた続きを見分ける)、打ち切りの適用`expireSignOut`、終えられたかの判定（呼び出しの後の未認証。喪失の定義と同じ）、置き換える先を返す`leave`（実行中は置き換えない、通知の利用者が記録の利用者と同じなら置き換えない）、遷移は1回、行き先を守る。
- `src/features/auth/application/session.ts`の`holdEnd()`は、同じ実行中の排他をアカウント削除に貸す(`docs/features/auth/design.md`)。
- `src/features/auth/domain/auth-change.ts`: サインインの状態の分類と、確かめた結果の喪失の定義。
- `src/features/auth/infrastructure/supabase-auth.ts`: 利用者のセッションで認証サービスに触る唯一の実装（`docs/features/auth/design.md`）。この端末のサインアウト(`signOutHere`。失効が受け付けられたときだけ保存先を削除する)、アカウント削除の完了用の保存先の削除(`discardHere`)、サインインの状態の読み取り、認証状態の変化の購読を含む。接続は、渡された関数で使うたびに取得する。
- `src/features/auth/infrastructure/browser-page-load.ts`: ページ全体の読み込みと置き換え(`window.location.replace`)、今の文書の読み込み直し(`window.location.reload`)、今の場所(パス、クエリ、ハッシュ)の読み出し。サインアウトの完了と喪失の置き換え、利用者の不一致の読み込み直しと、サインインの入口(完了の置き換え)が同じ部品を使う。
  利用者の不一致は、今の場所への置き換えでなく読み込み直しで行う。`location.replace`は、ハッシュを含めて今と同じURLへの置き換えを文書の中の移動として扱い、読み込み直さないため。読み込み直しはハッシュを保つので、設定パネルは同じ表示で開き直る。
- `src/features/auth/application/local-identity.ts`、`src/features/auth/application/identity-reader.ts`、`src/app/root-client-entry.tsx`、`src/features/auth/infrastructure/browser-identity-store.ts`: 端末の識別情報の記録と読み出し。ルートのクライアントの入口が保存先と認証の実装を1度だけ生成し、記録を始め、認証状態の変化に追従する。読み出しは他の機能（ラウンドの参照データ、同期の開始）が入口から`IdentityReader`の型で受け取って使い、サインアウトの判定には使わない。

契約は次のとおりである。

- 終えられたかは、呼び出しの成否でなく、呼び出しの後のサインインの状態の読み取りが未認証かで決める。読み取りは保存先(cookie)を読み、サーバーの保護が読むものと同じであるため、終えられたら、この端末ではラウンドの画面もサインイン画面もサインイン済みとして扱われない。
- supabase-jsの`signOut`は、`scope`が`others`以外なら、サーバーがエラー(401・403・404以外)でもローカルのセッションを削除する。通信失敗でも削除するため、そのままでは通信できないまま終わってしまう。
  そこで`signOutHere`は、保存先のセッションを取得し、あれば`auth.admin.signOut(アクセストークン, "local")`で失効だけを頼む。成功、または401・403・404(セッションが既に無い)のときだけ、`signOut({ scope: "local" })`で保存先を削除して通知を出す。
  それ以外の失敗(届かない、5xx、429など、通信に起因しないものを含む)と、取得の失敗(期限切れの更新ができない)は、保存先に触らず失敗として返す。応答があっても失効できていないセッションを、終えたものとして扱わないためである。
- アカウント削除の完了(`holdEnd`の`complete`)は、削除済みの利用者のセッションを保存先から消す必要があるため、従来どおり失敗でも削除するSDKの`signOut({ scope: "local" })`(`discardHere`)を使う。
- 終えられなかったときの理由は、呼び出しの失敗の種類の文言(オフライン、届かなかったら通信エラー、表に無い種類は固定の文言)で、失敗が無ければ通信エラーの文言である。
- 完了を待つ間に画面が離れても、終えられたら遷移する(遷移は画面に属さない)。離れた画面の状態の更新はReactが捨てる。終了の依頼は取り消さない。
- 遷移元を付けないのは、サインアウトの手続きの遷移だけである。実行中の喪失は遷移せず、実行中が解けた後の喪失は、通常の規則どおり遷移元を付ける。
- `replace`は投げない約束のため、見張りもサインアウトも投げたときの扱いを持たない。サーバー側の保護（`proxy.ts`）は残る。
- 識別情報の更新元は、サインインの変化を受ける`application/local-identity.ts`(signed-inで記録し、signed-outで消す)が基本である。例外は`session.ts`の見張りで、記録の利用者と違う利用者のサインインを検知したとき、読み込み直しの前に新しい利用者を書き、読み戻して一致を確かめる(新しい文書の記録の利用者を一致させ、読み込み直しの繰り返しを防ぐため)。

## 設計判断

| 判断 | 理由 | 見直す条件 |
| --- | --- | --- |
| クライアントの`signOut()`で行い、Server Actionを使わない | Server Actionのリダイレクトが遷移を横取りするレースを避けるため、Server Actionをやめた。詳細: #363 | レースを避けられる方式が出たとき |
| 終えられたかを、呼び出しの後のサインインの状態の読み取りで決める | 端末の識別情報で決めると保存先が使えない環境で終えていないのに完了とし、呼び出しの成否だけで決めると別のタブの書き戻しを見落とすため | supabase-jsの`signOut`か保存先の挙動が変わったとき |
| サインアウトは通信できるときだけ行い、オフラインは送信前に拒否し、届かない・拒否も保存先を削除しない | オフラインで終えると`/signin`を開けず再サインインできなくなるため。SDKの`signOut`は通信失敗でも削除するので、失効の頼みと保存先の削除を分ける。通信に起因しない失敗(5xxなど)もサーバーで失効できていないため、削除せず理由を示して再試行させる。通信の失敗を押し込めて終えると、サーバーのセッションが残る | supabase-jsが失効だけを行う公開の手段を持ったとき |
| 終えられたときの遷移をサインアウトの手続きが行い、実行中の喪失の遷移を委ねる | 遷移の有無を、終えられたかの判定と同じ1つにするため。`SIGNED_OUT`はセッションを消した時点で起き、後で書き戻されても遷移が済んでしまう。喪失の検知(`SIGNED_OUT`の通知、更新の拒否、確認)は見張りに残し、検知の不具合を隠さない | サインアウトの遷移を見張りに戻すとき |
| 利用者の操作が待つ通信は10秒で打ち切る | 通信できないとき、SDKのセッションの更新の再試行が約25秒続き(設定で変えられない)、その間ダイアログが動かないため。打ち切った後の続きは世代で止め、状態も遷移も変えない。遅れて本当に終えられたときは見張りが遷移する | セッションの更新の再試行を設定で持てるようになったとき |
| `scope: "local"`でこの端末のセッションだけを終了する | 既定の`global`は全端末のセッションを無効にするため。サインアウトの完了はこの端末の終了として扱う。外部への呼び出しの実装は、範囲の引数で共有する（`docs/features/auth/design.md`） | 全端末のサインアウトを提供するとき |
| 識別情報の更新を認証状態の変化に追従させる(見張りの読み込み直しの前の書き込みを例外とする) | オフラインでも利用者を識別するため、更新は認証状態の変化に追従させる。見張りの書き込みは、同じ利用者の同じ値を読み込み直しの順序に依らず先に確定させるもので、`local-identity`と矛盾しない | 識別情報の更新元を増やす必要が出たとき |
| 通信の可否を共有の技術にする | 取得と同期が使う技術の能力で、持ち主を1つにするため | 通信の可否に業務の言葉が入るとき |
| 実行中の判定は集約が持ち、確認ダイアログは表現だけにする | 実行中の判定の持ち主を集約の1つにするため。ダイアログは外から実行中を受け取る。確認ダイアログ以外から呼んでも、実行中の呼び出しは`busy`で拒否される | 実行中の判定を集約の外へ移す必要が出たとき |
| 確認ダイアログを`BlockingConfirmDialog`に共通化する | 削除確認と同じ構造で、重複を除くため。実行中とエラーは呼び出し側が持つ | 画面ごとに挙動が分かれるとき |

## 制約と未対応

- 他の端末のサインインは終了しない。
- 認証サービスが失敗を返し続けると、サインアウトできない。通信できるのに拒否される状態が続く場合の回避手段は持たない。
- `auth.admin.signOut`は管理用の名前空間だが、利用者自身のアクセストークンでの失効の呼び出しとして使う(SDKの`signOut`も内部で同じ呼び出しをする)。
- 同じブラウザの別のタブが、サインアウトの後にセッションを書き戻した場合は、読み取りが認証済みになり、終えられなかったとして理由を示す。
