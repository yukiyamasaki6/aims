# auth/change-password

## 目的

サインイン済みの利用者が、現在のパスワードを確かめたうえで、メールの受信などを要さずに、自分のパスワードを新しいものへ変更できるようにする。

## 要求

### パスワードを変更する

- 現在のパスワードを正しく入力し、規則を満たす新しいパスワードを入力した利用者は、パスワードを変更でき、以後は新しいパスワードでサインインできる。
  古いパスワードではサインインできない。
- 新しいパスワードの規則と理由の文面は、サインアップ・パスワード再設定と同じである。
- 変更が完了すると、完了が伝わる。
  利用者はその画面に留まり、入力値は消える。
  完了の表示は、再読み込みや別の画面への移動の後は出なくてよい。
- パスワードの入力欄は、表示・非表示を切り替えられる(切り替えても入力値は保たれる)。
- 現在のパスワードの入力欄は現在のパスワードとして、新しいパスワードの入力欄は強いパスワードの提案と保存ができる欄として、ブラウザやパスワード管理ツールが認識できる。
- 新しいパスワードの入力欄は1つで、確認用の欄は設けない。
- 現在のパスワードの入力欄のキャプションは「現在のパスワード」、新しいパスワードの入力欄のキャプションは「新しいパスワード」だけである。
  新しいパスワードの規則は、違反したときの理由として示される。
- パスワード変更の画面の見た目は、認証の画面(サインイン、サインアップ)と同じで、中央寄せの幅の狭い枠が、画面の上下中央に表示される。
- 現在のパスワードを付けない更新は、画面を使わない直接の呼び出しでも拒否される。
  ただし、認証サービスの設定が有効であることが前提である。
- 上の拒否は、登録(auth/signup)の完了直後のサインインにも効く。
  登録の完了時に、パスワードで確かめたサインインへ置き換えるためである。
  この変更より前に登録した利用者の、認証コードで得たサインインが残る間は、現在のパスワードの検査が免除される。
  掃除はせず、残余リスクとして受け入れる(`docs/security.md`)。

### 設定画面から開く

- 設定画面の「パスワード変更」項目からの移動は、app/settingsに従う。
- パスワード変更の画面のURLを直接開く、または再読み込みしても、同じ画面が表示される(入力値は残らない)。
- ブラウザの戻る・進むで、設定画面とパスワード変更の画面の間を移動できる。
  レフトパネル/ドロワーの項目でも、設定画面へ移動できる。

### この端末と他の端末のサインイン

- パスワードを変更した後も、この端末のサインインは維持される。
- パスワードを変更すると、他の端末のサインインは終了する。
  他の端末は、アクセストークンの期限が切れた後の更新の拒否で検知され、サインイン画面へ移動する(app/navigationに従う)。
  変更前のパスワードでは再サインインできない。
  期限が切れるまでの最大約1時間は、他の端末でデータの読み書きが通りうる。
  残余リスクとして受け入れる(`docs/security.md`)。
- 完了の表示は、他の端末が終了したことを伝えない。
- 変更が行われなかったことが確実な失敗(認証サービスの拒否、送信前に止まった通信の失敗、オフライン)のときは、他の端末のサインインは終了せず、この端末のサインインも維持される。
- 応答が失われたなど、変更の結果が不明なときは、この端末の維持と他の端末の終了を保証しない。
  変更が行われていることがあり、変更前のパスワードを現在のパスワードとして再試行すると、現在のパスワードの誤りと表示される。
  新しいパスワードを現在のパスワードとして再試行し、新しいパスワードの欄も同じ値のときは、同じパスワードにはできない旨が表示される(別の値なら変更が成功する)。

### オフラインのとき

- 画面の枠が保存済みなら、オフラインでもパスワード変更の画面が開き、設定画面の項目から移動できる。
- オフラインで変更を送信しても、変更は行われず、端末にも保留されず、「ネットワークに接続されていません。接続を確認してから再度お試しください。」が表示される。
  入力に不備があるときは、その理由が表示される。
- 通信が戻ると、再び変更を送信できる。
  入力値は、その画面にいる間は保たれる(離れる、再読み込みでは消える)。

### 不備や失敗があるとき

- 現在のパスワードまたは新しいパスワードが未入力、新しいパスワードが許さない文字を含むときは、該当する理由が全て表示され、変更は行われない。
- 新しいパスワードの長さや強さの規則違反は、変更の送信後に認証サービスの拒否として規則の理由が示される。
  このとき、現在のパスワードの正誤は示されない。
- 現在のパスワードが誤っているときは、変更は行われず、現在のパスワードの誤りの理由が表示され、再入力できる。
  誤りが続いても、認証サービスの制限に達するまでは、毎回理由が表示される。
- 新しいパスワードが現在のパスワードと同じときは、変更は行われず、同じパスワードにはできない旨が表示され、別のパスワードの入力を求められる。
- 認証サービスが制限の応答を返したときは、「リクエストの間隔が短すぎます。しばらくしてから再度お試しください。」が表示され、変更は行われず、時間を置いて再試行できる。
- 認証または通信に失敗したときは、理由が表示され、入力が保たれ、再試行できる。
  応答が得られなかった失敗は、変更の結果が不明な場合を含み、区別せず「通信エラーが発生しました。しばらくしてから再度お試しください。」を表示する。
- 変更の処理中に操作を繰り返しても、同じ変更は重複して行われない。

### サインインしていないとき、サインインが切れたとき

- 未認証でパスワード変更の画面を開くと、サインイン画面へ移動し、パスワード変更の画面が遷移元として付く。
  サインインすると戻る。
- 表示中にサインインが切れたときは、サインイン画面へ移動する。
- サインアウトした後、ブラウザの戻るでパスワード変更の画面を開こうとしても、サインイン画面へ移動する。
- 画面の枠を保存した後でも、未認証または期限切れで開くと、サインイン画面へ移動する。

### 処理の途中で画面を離れたとき

- 変更の応答を待つ間に別の画面へ離れた利用者には、その応答による表示も移動も起きない。
  変更自体は、応答が成功なら行われる。

## 対象外

- パスワードの再設定(auth/password-reset)の変更と、現在のパスワードを忘れた利用者への案内。
- 認証サービスの再認証要件(`secure_password_change`)の有効化。
  無効のままにする(`docs/security.md`)。
- メールの認証コードなどによる本人確認と、Turnstile付きの事前確認。
- 認証コードで得たサインイン(この変更より前に登録した利用者のもの、盗まれたもの)の掃除と無効化。
  登録時の置き換え(auth/signup)の範囲外である。
- 現在のパスワードの総当たりの抑止の強さ。
  認証サービスの制限に委ね、アプリ側では再試行の回数を制限しない。
  盗まれたセッションの保持者による推測は、残余リスクとして受け入れる(`docs/security.md`)。
- 認証サービスの設定が本番で効いていることを、デプロイごとに自動で検証すること。
- パスワード変更と無関係に単独で行う、他の端末のサインアウト(他の端末の一覧表示や個別の終了を含む)。
- 端末へのオフライン中の変更の保留、パスワードの強度メーター、過去のパスワードの再利用の禁止。
- メール変更、アカウント削除、名前の変更、Google認証。
