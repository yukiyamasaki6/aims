# auth/change-email

## 目的

サインイン済みの利用者が、現在のメールアドレスと新しいメールアドレスの両方を確かめたうえで、自分のサインインに使うメールアドレスを新しいものへ変更できるようにする。

## 要求

### メールアドレスを変更する

- 新しいメールアドレスを入力した利用者には、現在のメールアドレスと新しいメールアドレスのそれぞれへ、別々の認証コードが送られる。
  両方の認証コードを確認した利用者は、メールアドレスを変更でき、以後は新しいメールアドレスのOTPでサインインできる。
  古いメールアドレスによる新たな認証では、変更済みの元アカウントと記録にアクセスできない。
- 2つの認証コードは、確認する順序を問わない。
- 認証コードの確認が両方済むまで、サインインに使うメールアドレスは変わらない。
  一方だけを確認した状態や、確認の前に離れた状態でも、古いメールアドレスでサインインできる。
- 変更の画面は、完了の表示の間を除いて、現在のメールアドレスを表示する。
  現在のメールアドレスを読み取れないときは、表示されない(変更の動作には影響しない)。
- 変更が完了すると、項目の名称(メールアドレス変更)と戻るの操作がヘッダーに表示され、メールアドレス・認証コードの入力欄、確認・再送の操作、セキュリティチェック、現在のメールアドレスの表示の代わりに、「メールアドレスを変更しました」が表示される。
  利用者はその画面に留まる。
  完了の表示は、再読み込みや別の画面への移動の後は出ない。
- 戻るの操作はヘッダーにあり、画面のどの段階(入力、認証コードの入力、完了)でも、押すと設定パネルの分類「アカウント」の表示へ移る。本文には分類「アカウント」へ戻る操作を置かない。
- 通信中・保存中など、変更の処理が進んでいる間は、ヘッダーの戻るの操作は押せない。
- 認証コードの入力から入力へ戻る操作は、ヘッダーの戻るの操作とは別に、本文に残る。
- 変更の完了後に、続けて別のメールアドレスへ変更したい利用者は、設定パネルの項目、ブラウザの戻る・進む、再読み込みのいずれかで画面を開きなおすと、変更の画面が新しい現在のメールアドレスとともに表示され、改めて変更できる。
- 認証コードの入力欄は、メールで届いたコードの自動入力に対応する。
- 認証コードのメールは、変更前と変更後のメールアドレスと、認証コードと、有効期限(15分間)を示す。
  現在のメールアドレス宛てと新しいメールアドレス宛てで、本文は同じである。
  心当たりがない場合は破棄してよいと示す。
- 認証コードを再要求すると、前の認証コードは使えなくなる。
  別の新しいメールアドレスで要求しなおした場合も同じで、前の新しいメールアドレスの変更は行われない。
  一方を確認済みだった場合も、確認済みの状態は引き継がれず、新しい両方の認証コードを確認しなおす。
  再要求や要求しなおしが受け付けられた後、認証コードの欄は空になる。
- 現在のメールアドレス宛てと新しいメールアドレス宛ての認証コードは、それぞれ別の欄に入力する。
  一方の認証コードの確認に成功しても、その欄の表示も、案内も変わらず、入力欄のままである。
  確認済みの欄の値を変えない限り、次の確認で、その欄は再確認されず、誤りにならない。
  確認済みの欄の値を変えたときは、新しい入力として確認される。
  その確認が誤りでも、確認済みの状態は失われず、もう一方の認証コードの確認で完了できる。

### 設定パネルから開く

- 設定パネルの「メールアドレス」の行の「変更」からの移動と、ハッシュ`#settings/account/email`での表示は、app/settingsに従う。
- ハッシュ`#settings/account/email`を付けた画面を直接開く、または再読み込みしても、設定パネルにメールアドレス変更の画面が表示される(入力値と途中の経過は残らない)。
- ブラウザの戻る・進むで、設定パネルの分類「アカウント」の表示とメールアドレス変更の画面の間を移動できる。

### 認証コードの入力中

- 認証コードを要求した利用者は、再要求は要求から60秒待つ必要があり、残り秒数が表示されることと、メールが届かない場合の確認事項が分かる。
- 再要求の待機時間が終わり、セキュリティチェックを完了した利用者は、新しい認証コードを受け取れる。
- 認証コードの入力から、新しいメールアドレスの入力へ戻り、別のメールアドレスで要求しなおせる。
  認証コードの最後の送付(要求または再要求)から60秒以内の、別のメールアドレスでの要求しなおしは、認証サービスの制限として扱われ、行われない(「不備や失敗があるとき」に従う)。
  このとき、前の要求の認証コードと新しいメールアドレスは有効なまま残る。

### この端末と他の端末のサインイン

- メールアドレスを変更した後も、この端末のサインインは維持される。
- メールアドレスを変更しても、他の端末のサインインは終了しない。
  他の端末は、変更後も引き続き使える。
- 変更が行われなかったことが確実な失敗(認証サービスの拒否、送信前に止まった通信の失敗、オフライン)のときは、サインインに使うメールアドレスも、この端末と他の端末のサインインも変わらない。
- Googleアカウントで作ったアカウントや、Googleアカウントが結び付いたアカウントも、同じ流れでメールアドレスを変更できる。
  変更後も、そのGoogleアカウントでのサインインは同じアカウントに入る。
  変更されるのは、認証コードの送付先と、認証コードでサインインするときのメールアドレスだけである。

### オフラインのとき

- 設定パネルをオフラインで開けるときは、オフラインでもメールアドレス変更の画面が開き、設定パネルの項目から移動できる。
- オフラインで認証コードの要求、再要求、確認を送信しても、処理は行われず、端末にも保留されず、「ネットワークに接続されていません。接続を確認してから再度お試しください。」が表示される。
  入力に不備があるときは、その理由が表示される。
- 通信が戻ると、再び送信できる。
  入力値は、その画面にいる間は保たれる(離れる、再読み込みでは消える)。

### 不備や失敗があるとき

- 新しいメールアドレスが未入力または形式不正、認証コードの欄が未入力(該当する欄に理由が表示される)のときは、セキュリティチェックの状態に関わらず、該当する理由が全て表示され、該当する処理は行われない。
- 再要求のセキュリティチェックが完了する前に再要求しても、エラーにならず処理中の表示になり、完了すると自動で進む。
- 再要求のセキュリティチェックに追加の操作が必要な間は、処理中のまま待ち、利用者が完了すると自動で進む。追加の操作が必要になった、またはチェックが失敗したことで表示されたチェック欄は、完了した後も、チェックが取り直されるまで表示されたままで(まだ操作を押していなくても同じ)、取り直されると畳まれる(取り直しで再び追加の操作が必要になれば、再び表示される)。操作が結果を返しても、チェックが取り直されなければ畳まれない。成功で画面が遷移するときは画面ごと消える。
- 再要求のセキュリティチェックが失敗した、または追加の操作が無いまま一定時間完了しない場合は、失敗が表示されて処理中が解け、完了するまで再要求は行われない。失敗の後に再度操作した場合も、すぐには失敗を表示せず、改めて待つ。
- 新しいメールアドレスが現在のメールアドレスと同じときは、認証コードは送られず、同じメールアドレスにはできない旨が表示される。
- 新しいメールアドレスが他の利用者のメールアドレスと重複するときは、認証コードは送られず、そのメールアドレスは使えない旨が表示され、別のメールアドレスを入力できる。
  確認の時点で重複したときも、変更は行われない。
- 認証コードが誤っているときと期限切れのときは、変更は行われず、区別せず「誤りまたは期限切れ」の理由が、誤りだった側の認証コードの欄に表示され、再入力できる。
  両方が誤りのときは、両方の欄に表示される。全体のエラーとしては表示されない。
- 確認の失敗のうち、認証コードに紐づかないもの(制限の応答、通信の失敗、その他)は、欄ではなく全体のエラーとして表示される。
  期限切れのときは、認証コードを要求しなおせる。
- 認証サービスが制限の応答を返したときは、「リクエストの間隔が短すぎます。しばらくしてから再度お試しください。」が表示され、変更は行われず、時間を置いて再試行できる。
- 認証または通信に失敗したときは、理由が表示され、入力が保たれ、同じ段階から再試行できる。
  応答が得られなかった失敗は、結果が不明な場合を含み、区別せず「通信エラーが発生しました。しばらくしてから再度お試しください。」を表示する。
- 要求、再要求、確認の処理中に操作を繰り返しても、同じ処理は重複して行われない。
- 確認の応答が得られず、結果が不明なときは、この端末のサインインは維持される。
  変更が行われていることがあり、同じ認証コードで再度確認すると、「誤りまたは期限切れ」が、その認証コードの欄に表示される。

### サインインしていないとき、サインインが切れたとき

- 未認証で、ハッシュ`#settings/account/email`を付けた画面を開くと、サインイン画面へ移動し、開こうとした画面がハッシュを含めて遷移元として付く。
  サインインすると、その画面が、設定パネルにメールアドレス変更の画面を開いた状態で表示される。
- 表示中にサインインが切れたときは、サインイン画面へ移動する。
- サインアウトした後、ブラウザの戻るでメールアドレス変更の画面を開こうとしても、サインイン画面へ移動する。
- 画面の枠を保存した後でも、未認証または期限切れで開くと、サインイン画面へ移動する。

### 処理の途中で画面を離れたとき

- 応答を待つ間に別の画面へ離れた(ブラウザの戻る・進むでハッシュが変わり、設定パネルの別の表示へ移った、または設定パネルが閉じたときを含む)利用者には、その応答による表示も移動も起きない。
  処理自体は、応答が成功なら行われる。
- 認証コードを要求した後に離れた利用者は、画面に戻っても途中の経過は残らず、最初から要求する。

## 対象外

- アカウント削除(退会)、名前の変更。
- Googleアカウント自体のメールアドレスの変更(Google側で行う)。
- 現在のメールアドレスを使えない利用者(受信できなくなった場合など)のメールアドレスの変更。
  現在のメールアドレスと新しいメールアドレスの両方の確認が要るため、できない。
- 認証サービスの二重確認(変更前後の両方のメールアドレスの確認)の無効化。
  有効のままにする(`docs/security.md`)。
- 現在のパスワードの確認。
  認証サービスは、メールアドレスの更新に現在のパスワードを要さず、画面で要求しても直接の呼び出しには効かない。
  更新の完了には、現在のメールアドレスと新しいメールアドレスの認証コードの両方が要る。
- メールアドレスの登録の有無の秘匿(auth/signinは秘匿する。ただしGoogleアカウントにだけ残るアドレスの例外がある)。
  変更では、重複するメールアドレスが使えない旨を示す。
  サインイン済みの利用者が直接の呼び出しで登録の有無を調べられることは、認証サービスの仕様として残り、残余リスクとして受け入れる(`docs/security.md`)。
- メールアドレスの変更に伴う、他の端末のサインインの終了と、認証コードで得たサインインの掃除。
- 変更前のメールアドレスの再利用の禁止、変更の履歴の記録と通知、変更の取り消し。
- 端末へのオフライン中の変更の保留。
