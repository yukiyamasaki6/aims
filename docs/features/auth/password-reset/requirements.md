# auth/password-reset

## 目的

パスワードを忘れた利用者がメールアドレスを確認し、新しいパスワードでアカウントへ戻れるようにする。

## 要求

### パスワードを変更する

- 登録済みのメールアドレスへ届いた認証コードを確認し、要件を満たす新しいパスワードへ変更した利用者は、サインアウト後にそのパスワードで再びサインインできる。
- パスワードを変更した利用者は、サインイン画面へ移動する。
- パスワードを入力欄で表示・非表示に切り替えて確かめられる(切り替えても入力値は保たれる)。
- 新しいパスワードの入力欄は、ブラウザやパスワード管理ツールが、強いパスワードの提案と保存ができる欄として認識される。

### 認証コードの入力中

- 認証コードの入力欄は、メールで届いたコードの自動入力に対応する。
- 認証コードを送信した利用者は、再送は送付から60秒待つ必要があり、残り秒数が表示されることと、メールが届かない場合の確認事項が分かる。
- 認証コード入力からメール入力へ戻った利用者は、入力済みのメールアドレスを再利用できる。
- 再送待機時間が終わりセキュリティチェックを完了した利用者は、新しい認証コードを受け取れる。

### ほかの画面へ進む

- 利用者は、ヘッダーのサインインからサインインへ戻れる。本文に「サインインに戻る」は置かない。

### 認証済みで開く

- 認証済みの利用者がパスワード再設定画面を開くと、ホームへ移動する。

### 入力の不備、重複した送信、失敗があるとき

- メールアドレス、パスワード、認証コード(未入力)に不備がある場合は、セキュリティチェックの状態に関わらず、理由が全て表示され、該当する認証処理は行われない。
- セキュリティチェックが完了する前に、コードの送信、再送、またはパスワード設定(サインアップ)を送信しても、エラーにならず処理中の表示になり、完了すると自動で処理が進む。
- セキュリティチェックに追加の操作が必要な間は、処理中のまま待ち、利用者が完了すると自動で処理が進む。追加の操作が必要になった、またはチェックが失敗したことで表示されたチェック欄は、完了した後も、チェックが取り直されるまで表示されたままで(まだ操作を押していなくても同じ)、取り直されると畳まれる(取り直しで再び追加の操作が必要になれば、再び表示される)。操作が結果を返しても、チェックが取り直されなければ畳まれない。成功で画面が遷移するときは画面ごと消える。
- セキュリティチェックが失敗した、または追加の操作が無いまま一定時間完了しない場合は、失敗が表示されて処理中が解け、完了するまで認証処理は行われない。失敗の後に再度操作した場合も、すぐには失敗を表示せず、改めて待つ。
- 送信、確認、または変更の処理中に操作を繰り返しても、同じ認証処理は重複して行われない。
- 認証または通信に失敗した場合は、理由が表示され、同じ段階から再試行できる。
- 端末がオフラインの状態で送信(コードの送信、再送、確認、パスワード設定)した場合は、セキュリティチェックの状態によらず「ネットワークに接続されていません。接続を確認してから再度お試しください。」が表示され、認証処理は行われない(入力に不備がある場合は、その理由が表示される)。

### 処理の途中で画面を離れたとき

- 変更の応答後は、この端末のサインインを終えてサインイン画面へ移動する。
- パスワードの変更を待つ間に画面を離れた利用者は、再設定の処理によって表示も移動もされない。離れた先の画面の保護による移動は、その画面の要求(`app/navigation`)に従う。

## 対象外

- パスワードを記憶している利用者の認証は、サインイン機能で扱う。
- 認証コードの確認の後にパスワードを変更せずに画面を閉じた場合に、サインインが終わらないこと(認証コードの確認でメールアドレスの所有を確かめたため)。
