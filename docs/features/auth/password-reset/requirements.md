# auth/password-reset

## 目的

パスワードを忘れた利用者がメールアドレスを確認し、新しいパスワードでアカウントへ戻れるようにする。

## 要求

### パスワードを変更する

- 登録済みのメールアドレスへ届いた認証コードを確認し、要件を満たす新しいパスワードへ変更した利用者は、サインアウト後にそのパスワードで再びサインインできる。
- パスワードを変更した利用者は、全ての端末のサインインの終了の結果によらず、サインイン画面へ移動する。

### 認証コードの入力中

- 認証コードを送信した利用者は、再送できるまでの時間とメールが届かない場合の確認事項が分かる。
- 認証コード入力からメール入力へ戻った利用者は、入力済みのメールアドレスを再利用できる。
- 再送待機時間が終わりセキュリティチェックを完了した利用者は、新しい認証コードを受け取れる。

### ほかの画面へ進む

- 利用者は、パスワード再設定からサインインへ戻れる。

### 認証済みで開く

- 認証済みの利用者がパスワード再設定画面を開くと、ラウンド一覧へ移動する。

### 入力の不備、重複した送信、失敗があるとき

- メールアドレス、認証コード、パスワード、またはセキュリティチェックに不備がある場合は、理由が表示され、該当する認証処理は行われない。
- 送信、確認、または変更の処理中に操作を繰り返しても、同じ認証処理は重複して行われない。
- 認証または通信に失敗した場合は、理由が表示され、同じ段階から再試行できる。
- 理由が表示された後に再び送信した場合は、次の結果が出るまで、表示された理由が残る。

### 処理の途中で画面を離れたとき

- パスワードの変更の要求がサーバーに届けば、画面を離れても、タブを閉じても、再読み込みしても、パスワードの変更と全ての端末のサインインの終了の両方が行われる。閉じたのが届く前でも、送信済みの要求が届けば両方が行われる。
- パスワードの変更を待つ間に画面を離れた利用者は、再設定の処理によって表示も移動もされない。離れた先の画面の保護による移動は、その画面の要求(`app/navigation`)に従う。

## 対象外

- パスワードを記憶している利用者の認証は、サインイン機能で扱う。
- 全ての端末のサインインの終了が届かない、または拒否された場合に、他の端末のサインインが残りうること。
- 認証コードの確認の後にパスワードを変更せずに画面を閉じた場合に、サインインが終わらないこと(認証コードの確認でメールアドレスの所有を確かめたため)。
