# rounds/score-entry 設計

## 概要

`/rounds/[id]`のスコアカードで、矢を1本指し、テンキーで点数を書く。
利用者が指すのは常に矢1本(記録済みの矢か、まだ記録していない新しい矢)で、エンドを選ぶ状態を持たない。
点数キーは指している矢へ書き、新しい矢なら記録、記録済みの矢なら直す。射順は扱わず、記録した矢は射順不明である。
入力は楽観的に画面へ反映し、書き込みは操作の列へ追記する。送信と再送は`rounds/sync`、集計は`rounds/detail`が扱う。

## 画面と状態

エンドを1行にし、左に番号、右に小計を置く。エンドは枠で囲まず、上下の線で区切り、左右は距離全体の枠と共通にする。間の幅いっぱいに、その距離の矢数分の場所を等間隔で用意し、記録済みの矢を左の場所から玉で入れる。残る場所(空白)には何も描かない。
矢を足しても、点数の高い順の並び直りによる入れ替わりのほかは、玉の位置は動かない。

| 状態 | 表示 | 要求 |
| :--- | :--- | :--- |
| 何も指していない | テンキーを出さない。仮の矢を出さない | score-09, 10 |
| 新しい矢を指している | そのエンドの最初の空白(記録済みの矢の後ろ)に仮の矢(主色の輪だけ。中は空で、灰色の外枠は描かない)を1つ出し、テンキーを出す | score-03, 05, 07, 19 |
| 記録済みの矢を指している | その玉の外側に主色の輪を付け、テンキーを出す | score-01, 02, 08, 18 |

| 操作 | 結果 | 要求 |
| :--- | :--- | :--- |

| 記録済みの矢に点数を書く | 点数を直し、その矢を指したまま | score-18 |

| 点数を書く・クリア | やり直しの列を捨てる | score-13, 14 |

- 入力中のラウンドを開くと、矢数に達していない最初のエンド(距離の並び順、エンドの昇順)の新しい矢を指す。全て満杯か、完了のラウンドなら何も指さない(`rounds/detail`のdetail-13、detail-20)。
- 指している記録済みの矢が他端末で消えたら、そのエンドの新しい矢を指す。指している新しい矢のエンドが他端末の追加で満杯になったら、書いた後と同じ規則で次へ進む。
- 記録済みの矢は点数の高い順(X、10、9、…、1、M)に並べ、同点の中は矢のIDの昇順にする。並びは矢の点数とIDだけで決まり、どの端末でも、再読み込みしても同じになる。
- 新しい矢のIDは、そのエンドで端末が知っている矢のIDより大きい時刻順のUUIDにする(構成とデータの流れ)。このため同じ点数の矢を足すと、既にある同点の後ろに入り、同点の玉は動かない。点数を直した矢と、戻る・進むで復活した矢はIDを変えないため、同点の中のIDの位置に入り、同点の玉が1つずれることがある(戻る・進むでは前の並びに戻る)。
- 矢を書く・直す・消す・戻る・進む、他端末の変化で並びが変わる様子を200msの動きで見せ、動きを減らす設定では動かさない。動くのは、同じエンドの中で位置が変わった玉と仮の矢である。玉の領域の幅や列の数が前の描画から変わったとき(開いた直後の幅の測定、画面の回転など)は動かさない。
- 動いている途中で次の反映が来たとき(続けて素早く点数を書いたとき)は、動いている途中の見た目の位置から、次の位置へ200msで動かし直す。前の動きを止め、途中の位置から新しい動きを始めるため、玉と仮の矢は跳ばない。前の描画から位置が変わらないものの動きは止めない。
- 仮の矢は、前の描画で同じエンドにあった輪の位置から動かす。輪が記録済みの玉に付いていたときは、その玉が消えたとき(クリア、戻る、他端末の取り消し)だけ、その玉の位置から動かす。玉が残っているとき(同じエンドの空白を押して指し替えたとき)は動かさず、玉から玉へ指し替えたときと同じにする。消えた玉は動きを付けずに消す。
- 指している記録済みの矢を消したとき(クリア、その矢を消す戻る・進む)は、消したことが画面へ反映されるまで、輪をその玉に残し、仮の矢を出さない。指す先は未反映の操作を数えて先に新しい矢へ変わるが、玉は保存が完了した操作から描くため、先に仮の矢を出すと消える前の空白(満杯のエンドでは出せない)に出て、反映の時に跳ぶためである。
- 寸法: 行の高さ40px(1段あたり)、玉の直径32px、玉の場所の幅は最小36px(玉の間隔は最小4px)、指している輪は太さ2px・内径32px(玉の外径に一致し、玉との隙間は0)・外径36px(行の高さ40pxに収まり、行の外にはみ出さない。最小の場所36pxでも場所の中に収まり、隣の場所にはみ出さない)、玉の中の文字16px。番号20px・小計32px・玉との余白は最小4px。番号・小計は距離の枠に接し、エンドの周りに余白を置かない。玉は場所の中央に置く。
- 線はエンドの上下だけにし、エンドの行の間は区切り線1本で隙間を置かない。最初のエンドの上は距離の小計の線、各エンドの左右と最後のエンドの下は距離の枠である。番号・小計と玉の領域の間に区切り線を引かず、番号・小計は薄い文字色にする。
- 玉は的のリング色から求めた薄いトーンで塗る。
- 矢数分の場所が最小の幅で1段に収まらないときは折り返す。段の数は、1段に収まる場所の数で矢数を割って切り上げた数とし、1段の場所の数は矢数を段の数で割って切り上げた数にする(例: 矢数6で1段に4つまで収まるなら3つずつ2段)。どの段も同じ幅の場所を同じ列に並べ、左上の場所から順に玉を入れる。エンドの高さは段の数×40pxで、上下の線はその外側に引く。段の数は矢数と幅から決まるため距離の中で高さが揃う。番号・小計は1段分の高さ(40px)のまま、エンドの行全体の高さの上下中央に置く(1段のときは今と同じ位置)。
- テンキーの開閉は指している矢の有無から導く。ボタンは隠さず、使えないものを無効にする。一つ戻る・一つ進むは列が空のとき無効にする。
- 縦向きは`<main>`に内蔵した下パネル、横向きは`<main>`の外の右側パネルに表示する。キーは、指している矢の距離の的に存在する点数を中心側から並べ、末尾にMを加える(score-03、score-05)。
- 玉には読み上げの名前を付けず、中の点数の文字が読まれる。エンドの最初の空白には押せる場所だと分かる読み上げの名前を付け(語は仮のもので、画面の文言の見直しで決める)、2つ目以降の空白は読み上げとTabの移動から外す。

## 構成とデータの流れ

- `rounds/[id]/scorecard-client.tsx`: エンドの行、矢数分の場所、玉、空白、仮の矢を描き、指している矢と取り消しの列をstateに持ち、操作を受ける。玉は矢のIDごとに、輪(指している玉か仮の矢)は玉の領域ごとに、前の描画の位置を覚えて動かす。動いている途中の位置は、動かすときに要素の見た目の位置(`getBoundingClientRect`)から求める。
- `rounds/[id]/scorecard-input.ts`: 指している矢の遷移(開いたとき、書いた後、クリアの後、戻る・進むの後、他端末の変化)と、取り消しの列の規則を純粋関数にまとめる。
- `rounds/[id]/scorecard-scoring.ts`: 的から点数キーと配色を求め、エンドの生きている矢の数、空きの有無、並べ方を求める。
- `rounds/[id]/shot-id.ts`: 新しい矢のID(時刻順のUUID)を作る。
- `rounds/[id]/keypad-panel.tsx`: 横向きの右側パネル。

点数の書き込みとクリアは、取り消しの列へ1件(矢のID、変えた属性の前後の値、生死の変化)を積み、操作の列へ追記する。IndexedDBへの保存が完了してから画面へ反映して送信する。
戻る・進むは、変えた属性だけを前の値・後の値で上書きする通常の記録・クリアとして積む。射手など変えていない属性は送らない。
新しい矢のIDは端末が作る時刻順のUUID(UUIDv7の形式)である。先頭48ビットの時刻の部分は、端末の時計のミリ秒と、そのエンドで端末が知っている生きている矢(まだ画面に反映されていない自分の追加を含む)のIDの先頭48ビットの最大+1の、大きい方にする。残りは版と変種のビットを除いて無作為にする。これにより新しい矢のIDは、端末の時計のずれや、移行で無作為のUUIDを付けた既存の矢があっても、そのエンドの既にある矢のIDより大きくなる。
空白・新しい矢・次のエンドへの移動の判定は、まだ画面に反映されていない自分の追加を数えに入れ、矢数を超える新しい矢を指さない。
戻る・進むで復活する矢がその時点のエンドに入らないときは、操作を積まず列を1件進める。

- 取り消しの列はstateにだけ持ち、再読み込みや画面遷移で消える。
- 距離の構成(的・エンド数・矢数)を変えた保存と、距離の削除では、その距離の矢への書き込みだけを列から捨てる。

## 設計判断

| 判断 | 理由 | 見直す条件 |
| :--- | :--- | :--- |
| 利用者が指すものを矢1本にし、エンドを選ぶ状態を持たない。新しい矢も矢として指す | 足すと直すが「指している矢へ書く」1つになり、将来の射順・位置・射手も同じ形の入力として足せるため。エンドを選んでから矢を選ぶ2段の選択は、状態と規則が増えるため採らない | 1本の矢に複数の属性を続けて入力する画面を作るとき |
| 新しい矢は指している1か所にだけ仮の矢で示し、空白には何も描かない | 空の枠や空の矢を並べると「何本目」の枠に見え、射順を表していると読まれるため | 空白を押せると気づけない利用者が多いと分かったとき |
| 矢数分の場所を行の幅いっぱいに等間隔で用意し、玉を左の場所から入れる | 矢を足しても並び直り以外で玉の位置が動かず、同じ距離のエンドの間で玉の位置が揃うため。玉の間隔を固定して左に詰める並べ方は、玉が左に寄り右に空きが偏るため採らない | 矢数が多く1段に収まらない距離が多いと分かったとき |
| 射順不明の矢を点数の高い順に並べ、並び直りを動きで見せる | 並びが入力の順や射順でないことを、文字を増やさずに伝えるため。入力した順の並びは射順と読まれるため採らない | 射順を持つ矢の並べ方を決めるとき |
| 仮の矢を玉と同じ動きの対象にし、消した玉の位置から最初の空白へ動かす。消したことが画面へ反映されるまで輪を消した玉に残す | 消すと残りの玉は詰まる動きをするのに、仮の矢は動かずに先へ現れて跳び、動き始めの玉と重なって見えたため(ユーザーの指摘)。消した矢が空になって後ろへ回る、と読めるため。玉を未反映の操作から描く案は、保存の完了前の離脱で見えた操作を失わない`rounds/sync`の規則を変えるため採らない。View Transitions APIなど別の仕組みは、既存の動きと扱いが分かれるため採らない | 消した玉を消える動きで見せたくなったとき |
| 同点の中はIDの昇順にし、新しい矢のIDをそのエンドの既にある矢より大きい時刻順のUUIDにする | 並びを矢の属性だけで決め、どの端末でも同じにしつつ、足した矢を同点の後ろに入れるため。同じ点数の玉は見た目が同じで、同点の中の順は画面に表れない。無作為のUUIDの昇順は、足した矢が同点の前と後ろのどちらに入るかが毎回変わり同点の玉が動くため採らない。前の表示での位置を保つ案は、画面の履歴によるため再読み込みや別の端末で並びが変わり採らない。サーバーの作成時刻で並べる案は、未送信の矢に時刻が無く、同じ要求で作った矢の時刻が同じで、確定の時に並びが変わるため採らない。並びの鍵の列を足す案は、DB・RPC・端末の記録の変更が大きく採らない | 点数を直した矢で同点の玉がずれることが問題になったとき。射順を持つ矢の並べ方を決めるとき |
| 記録済みの矢を直した後も、その矢を指したままにする | 直した矢を見失わず、テンキーの開閉を繰り返さないため。続けて押すと同じ矢を書き換えるが、指している矢の印と戻る1回で回復できる | 直した後に入力へ戻る手間が問題になったとき |
| 取り消しの列を画面全体の1本にし、1件は矢1本への1回の書き込みとする | エンドを選ぶ状態が無く、満杯で次のエンドへ移った直後でも、戻る1回で前のエンドの矢を戻せるため | 端末をまたぐ取り消しが必要になったとき |
| 戻る・進むは変えた属性だけを書く | 他端末が後で変えた別の属性(射手など)を古い値で戻さないため | 属性ごとの差分の操作を別に設けるとき |
| キーと配色を、的の`target_face_rings`から動的に構成する | 6点的に存在しない点数のキーが出るのを避けるため。固定12キーは採らない。Mは固定で末尾に置く | `target_face_rings`以外から的の点数を導くとき |
| 向きの判定を画面の向きで行い、横向きは右側パネル、縦向きは下パネルにする | 広い画面でテンキーが小さく表示されるのを避けるため。`md:`幅の判定は採らない | 画面の向きでなく幅でレイアウトを分けるとき |
| 縦向きの格納ボタンを、パネル上端からはみ出す、右端の点数キーと同じ大きさ(高さ48px、4列格子の1列の幅)のタブにする | スコア領域の高さに圧迫感を持たせないため。パネル内に格納用の帯を置くと、その分パネルが高くなり、スコア領域が狭くなるため帯は採らない | タブに覆われる玉の押しにくさが問題になったとき |

## 制約と未対応

- 射順を入力・表示する画面、的の位置の入力、射手の選択は扱わない。
- 記録済みの矢を直した直後に点数を押すと、同じ矢を書き換える。
- 空白には何も描かないため、押せる場所だと気づきにくいことがある。
- 記録済みの玉の押せる範囲は36×40pxで、テンキーのキー(48px)より小さい。場所が広くても、玉の押せる範囲の外は押しても何も起きない。
- 複数人が1つのエンドを射ち、各人が自分の分を入れる場面では、次のエンドへ移る判定がエンド全体の本数によるため、各人が次のエンドの空白を押して手で移る必要がある。一人あたりの上限は無く、他の人の矢も点数順に混ざって並び、誰の矢かは見えない。
- 矢数を超えて効かなかった戻る・進むは、知らせない。
- 2台の端末が互いの矢を知らずに同じエンドへ同じ点数を足すと、後から届いた矢が同点の前に入り、同点の玉が動くことがある。
- 点数を直した矢と、戻る・進むで復活した矢は、同点の中のIDの位置に入るため、同点の玉が1つずれることがある。
- 展開中、タブ(約80×48px)の下になるスコア領域の右端は押せない。指している行は覆われない位置までスクロールされる。
