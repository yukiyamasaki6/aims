# rounds/score-entry 設計

## 概要

`/rounds/[id]`のスコアカードのマスを選び、テンキーで点数を記録する。
記録済みのマスの上書き、クリア、取り消し（undo）とやり直し（redo）で修正する。
入力は楽観的に画面へ反映し、書き込みは送信キューへ積む。同期の表示と再送は`rounds/sync`が扱う。
集計は`rounds/detail`が扱う。

## 画面と状態

| 状態 | 表示 | 判定 | 要求 |
| :--- | :--- | :--- | :--- |
| テンキー格納 | マスの選択なし。テンキーは出ない | `position`が`null` | score-09, 10 |
| テンキー展開 | 選択中のマスにリングを付け、テンキーを出す | `position`がある | score-01〜03, 05, 07 |

| 操作 | 結果 | 要求 |
| :--- | :--- | :--- |
| マスをクリック | 選択して展開する。選択中のマスの再クリックは解除して格納する | score-01、score-02、score-05 |
| 点数を記録 | 次のマスへ進む。距離の最後のマスでは選択を外して格納する | score-07 |
| クリア | 点数を消して前のマスへ戻る。距離の最初のマスでは留まる | score-08 |
| 閉じる | 選択を解除して格納する | score-09、score-10 |
| 一つ戻る・進む | 履歴の遷移を適用し、そのマスを選択する。上書きとクリアの取り消しは、前の点数へ戻す | score-11、score-12 |
| 記録・クリア | やり直し履歴を無効にする | score-13、score-14 |

- 初期表示は、最初の未記録のマスを選択して展開する。全マス記録済みなら選択しない（`rounds/detail`のdetail-13）。
- テンキーの開閉は`position`の有無から導き、開閉用の別stateは持たない。
- 縦向きは`<main>`に内蔵した下パネル、横向きは`<main>`の外の右側パネルに表示する。どちらか一方だけをマウントする（score-01、score-02）。
- キーは、距離の的に存在する点数を中心側から並べ、末尾にM（ミス）を加える。複数スポットの的では、同じ点数のキーを1つにまとめる。選択するマスの距離に応じて切り替わる（score-03、score-05）。
- 記録済みのマスは、点数と、的のリング色から求めた薄い背景色を表示する（score-07）。
- 一つ戻る・進むは、履歴が空のとき無効にする。

## 構成とデータの流れ

- `rounds/[id]/scorecard-client.tsx`: `shots`、`position`、undo・redoの履歴、距離の構成をstateに持ち、操作を受ける。
- `rounds/[id]/scorecard-input.ts`: マス送りと履歴の規則を、純粋関数にまとめる。
- `rounds/[id]/scorecard-scoring.ts`: 的から点数キーと配色を求める。
- `rounds/[id]/keypad-panel.tsx`: 横向きの右側パネル。

記録・クリアは、履歴へ1件の遷移（前の状態と後の状態）を積み、`shots`を即時に更新して、送信キューへ積む。
送信キューは、IndexedDBへ保存してから送信し、再読み込み後は未送信の操作を復元する。
取り消しは前の状態へ、やり直しは後の状態へマスを戻す。上書きの取り消しは、上書き前の値へ戻す。

- 履歴はstateにだけ持ち、再読み込みや画面遷移で消える。
- 距離の構成（的・エンド数・本数）を変えた保存と、距離の削除では、その距離の履歴だけを破棄する。
- 記録とクリアは、距離の作成を待って送る。作成直後の距離への記録が先に届かないようにする。
- 選択中のマスがテンキーに隠れる場合は、縦向きに限り、テンキーの実測の高さを見込んでスクロールする。

## 設計判断

| 判断 | 理由 | 見直す条件 |
| :--- | :--- | :--- |
| スコア入力を独立画面にせず、`/rounds/[id]`に統合する | 全エンド入力後も同じ画面で内訳を確認できるようにするため | 入力専用の画面が必要になったとき |
| マス送りは距離をまたがない。距離の最後で選択を外し、最初のクリアでは留まる | 距離ごとに的と構成が異なるため、選択を距離内に留める | 距離をまたぐ入力を求められたとき |
| 履歴をstateにだけ持ち、DBへ保存しない | セッション内だけの機能とするため | 端末をまたぐ取り消しが必要になったとき |
| 構成を変えた距離の履歴だけを破棄する | 無効なマスの記録が書き戻されるのを防ぎつつ、他の距離の履歴は有効なため。距離を区別せず破棄するのは、無関係な距離の履歴まで失うため採らない。詳細: #171 | 履歴を新しい構成へ写せるようにしたとき |
| キーと配色を、的の`target_face_rings`から動的に構成する | 6点的に存在しない点数のキーが出るのを避けるため。固定12キーは採らない。Mは固定で末尾に置く | `target_face_rings`以外から的の点数を導くとき |
| マス目の背景を、的の実際のリング色から求めた薄いトーンで塗る | フィールド的など標準でない配色にも追従するため | 的の配色を固定の色表へ移すとき |
| ホバー・押下は、グレーの半透明をinset box-shadowで重ねて示す | 背景色をstyleで直接指定するため`hover:bg-muted`が効かず、brightnessは暗い背景で変化が見えないため | 背景色をクラスで指定する方式に変えるとき |
| 向きの判定を画面の向きで行い、横向きは右側パネル、縦向きは下パネルにする。側パネルのため`<main>`自身を内部スクロールにする | 広い画面でテンキーが小さく表示されるのを避け、側パネルがページと一緒にスクロールしないようにするため。`md:`幅の判定は採らない | 画面の向きでなく幅でレイアウトを分けるとき |

## 制約と未対応

- マス目以外をクリックしたときにテンキーを格納する処理はない。
- 未記録のマスをクリアしても履歴に残さず、やり直し履歴も破棄しない。
- 上書きでは、元の記録の射手を引き継ぐ。
