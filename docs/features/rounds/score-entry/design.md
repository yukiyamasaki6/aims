# rounds/score-entry 設計

## 概要

`/rounds/[id]`のスコアカードで、マスを1つ指し、テンキーで点数を書く。
エンドには射数/エンドの個数のマスを番号順に固定で並べ、マスの番号がその矢の射順である。矢はマス(距離、エンド、マスの番号)で指し、矢のIDを持たない。
点数キーは指しているマスへ書き、空のマスなら記録、記録済みのマスなら直す。点数による並べ替えはせず、マスの位置は点数や入力の順で動かない。
入力は楽観的に画面へ反映し、書き込みは操作の列へ追記する。送信と再送は`rounds/sync`、集計は`rounds/detail`が扱う。

## 画面と状態

エンドを1行にし、左に番号、右に小計を置く。エンドは枠で囲まず、上下の線で区切り、左右は距離全体の枠と共通にする。間の幅いっぱいに、射数/エンドの個数のマスを等間隔で、左上から番号順に置く。記録済みのマスは点数の玉、空のマスは灰色の細い輪(中は空。番号の文字は描かない)で描く。

| 状態 | 表示 |
| :--- | :--- |
| 何も指していない | テンキーを出さない |
| マスを指している | そのマスの外側に主色の輪を付け(空のマスは灰色の輪に替えて主色の輪にする)、テンキーを出す |

| 操作 | 結果 |
| :--- | :--- |
| マスを押す | そのマスを指し、テンキーを開く。空のマスも記録済みのマスも同じ。指しているマスを押しても何もしない |
| マス以外(番号、小計、マスの押せる範囲の外、エンドの区切り線)を押す | 何も起きない |
| 空のマスに点数を書く | 矢を記録する。同じエンドで書いたマスより後ろの最初の空のマス、無ければ同じ距離の後ろのエンドの最初の空のマスを指す。無ければ何も指さずテンキーを閉じる(次の距離へ移らない) |
| 記録済みのマスに点数を書く | 点数を直し、そのマスを指したまま |
| クリア | 記録済みのマスを指しているときだけ使える。矢を消し、そのマスを指したまま |
| 閉じる | 何も指さない |
| 一つ戻る・一つ進む | 画面全体の1本の列で、直前の自分の書き込みを1件戻す・やり直し、そのマスを指す。戻せるものが無ければ押せない |
| 点数を書く・クリア | やり直しの列を捨てる |

- 書いた後の「後ろの空のマス」は、追記の結果の画面の状態で空のマスで、他の端末の記録で埋まっているマスは飛ばす。書いたマスより前の空のマスへは戻らない。
- 入力中のラウンドを開くと、最初の空のマス(距離の並び順、エンドの昇順、マスの番号順)を指す。空のマスが無いか、完了のラウンドなら何も指さない(`rounds/detail`)。
- 指しているマスは、他端末の変化で埋まっても空になっても動かない。距離が無くなるか、構成の変更でマスが範囲外(エンド数・射数/エンドの外)になったときだけ、何も指さない。
- 玉とマスは、書く・直す・消す・戻る・進む、他端末の変化で、動きを付けずにその場で描き替える。
- 寸法: 行の高さ40px(1段あたり)、玉と空のマスの直径32px、マスの幅は最小36px(玉の間隔は最小4px)、指している輪は太さ2px・内径32px(玉の外径に一致し、玉との隙間は0)・外径36px(行の高さ40pxに収まり、最小のマス36pxでも隣のマスにはみ出さない)、空のマスの輪は太さ1px、玉の中の文字16px。番号20px・小計32px・玉との余白は最小4px。番号・小計は距離の枠に接し、エンドの周りに余白を置かない。玉と空のマスはマスの中央に置く。
- 線はエンドの上下だけにし、エンドの行の間は区切り線1本で隙間を置かない。最初のエンドの上は距離の小計の線、各エンドの左右と最後のエンドの下は距離の枠である。番号・小計と玉の領域の間に区切り線を引かず、番号・小計は薄い文字色にする。
- 玉は的のリング色から求めた薄いトーンで塗る。
- 射数/エンドの個数のマスが最小の幅で1段に収まらないときは折り返す。段の数は、1段に収まるマスの数で射数/エンドを割って切り上げた数とし、1段のマスの数は射数/エンドを段の数で割って切り上げた数にする(例: 射数/エンド6で1段に4つまで収まるなら3つずつ2段)。どの段も同じ幅のマスを同じ列に並べ、左上のマスから番号順に置く。エンドの高さは段の数×40pxで、上下の線はその外側に引く。段の数は射数/エンドと幅から決まるため距離の中で高さが揃う。番号・小計は1段分の高さ(40px)のまま、エンドの行全体の高さの上下中央に置く(1段のときは今と同じ位置)。
- テンキーの開閉は指しているマスの有無から導く。ボタンは隠さず、使えないものを無効にする。クリアは指しているマスに矢があるときだけ、一つ戻る・一つ進むは列が空でないときだけ有効にする。
- 縦向きは`<main>`に内蔵した下パネル、横向きは`<main>`の外の右側パネルに表示する。どちらも共用のヘッダー(`app/navigation`)の下の本文領域にあり、横向きのパネルの高さは本文領域の高さ(画面の高さからヘッダーを除いた分)で、キーが収まらないときはパネルの中のキーの領域がスクロールする。キーは、指しているマスの距離の的に存在する点数を中心側から並べ、末尾にMを加える。
- 全てのマスを押せるボタンにし、Tabの移動の対象にする。記録済みの玉には読み上げの名前を付けず、中の点数の文字が読まれる。空のマスには、マスの番号と空であることが分かる読み上げの名前を付ける(語は仮のもので、画面の文言の見直しで決める)。

## 構成とデータの流れ

- `features/rounds/ui/scorecard-client.tsx`: スコアカードの枠。`use-scorecard.ts`の状態と操作を、部品とテンキーへ渡す。
- `features/rounds/ui/use-shot-input.ts`: 点数の書き込み、クリア、戻る・進む、マスの押下を受ける。操作のイベントIDは手続きの入れ物(`useRoundProcedures()`の`ids.next`)から受ける。点数を書いた後に指すマスは、窓口の`append`が返す画面の状態から決める。指しているマスの保持と他端末の変化への合わせ込みは`use-reconciled-pointer.ts`が持つ。
- `features/rounds/ui/use-score-history.ts`: 取り消しの列をstateに持つ。
- `features/rounds/ui/end-row.tsx`: エンドの行と、射数/エンドの個数のマス(玉と空のマス)を描く。
- `features/rounds/ui/use-keypad.ts`: テンキーの開閉状態(指すマスの有無)、実測の高さ、指しているマスへのスクロール。スクロール(追従)は、最新の指すマスを参照から読んで行が隠れていれば動かす1つの処理`follow`で、契機は、利用者の操作で指すマスを設定したときと、配置の変化(スクロール領域の大きさ、行の段数)の2系統で、他の端末の変化では呼ばない。
- `features/rounds/ui/scroll-to-pointer.ts`: 指しているマスの行を、領域の矩形(帯・テンキーの上端まで)と、領域の中の固定表示(ラウンドの結果、距離の小計)に隠れない位置まで動かす計算と測定。行は`data-follow-row`(距離のIDとエンド番号)、スクロールの領域は`data-follow-container`、距離のカードは`data-distance-card`で探す。テスト用の`data-testid`やスタイルのクラス名には頼らない。
- `features/rounds/ui/keypad-buttons.tsx`: テンキーの中身(戻る・進む・クリアの行と、的の点数のキー)。
- `features/rounds/ui/bottom-frame.tsx`: 縦向きのテンキーと完了の帯を入れる、下端の枠。
- `features/rounds/ui/color-tone.ts`: 玉とキーの文字色と薄い色を、16進の色から求める。的の点数からリング色を引く`ringColorFor`は`features/rounds/domain/ring-color.ts`にある。
- `features/rounds/ui/keypad-panel.tsx`: 横向きの右側パネル。開閉の間は外枠の幅だけが動き、中身は開いたときの幅に固定して外枠で切り取るため、中身の文字と部品は再配置されず引き伸ばされない(作りは`rounds/history`のフィルターパネルと同じ。機能・配置・開閉の長さは変えない)。
- `features/rounds/domain/shot-cell.ts`: マス(距離のID、エンド番号、マスの番号)の型、同じマスの判定、マスの鍵(`revision`の表の鍵)、マスにある生きている矢の検索。指すマス、取り消しの列、矢の操作、同期の判定が共有する。
- `features/rounds/domain/shot-pointer.ts`、`score-history.ts`、`shot-operations.ts`: 指すマスの遷移(開いたとき、空のマスへ書いた後、他端末の変化)、取り消しの列の規則、矢の操作の組み立てを純粋関数にまとめる。
- `features/rounds/domain/scorecard-scoring.ts`: 的から点数キーと配色を求め、マスと点数が距離の構成に収まるかを判定する。

点数の書き込みとクリアは、取り消しの列へ1件(マスと、書く前後のマスの状態(点数か空))を積み、操作の列へ追記する。追記の直後に画面へ反映し、IndexedDBへの保存が完了してから送信する。保存の完了前に画面を離れると、保存が未完の末尾の数件が残らない窓がある(`rounds/sync`)。
記録は射手番号を指定する。一度も記録していないマスは操作する射つ人の番号、記録済みと取り消し済みのマスはそのマスの番号である(`rounds/shooters`)。
戻る・進むは、前か後の状態でマスを上書きする通常の記録・クリアとして積む。点数へ戻すのは記録、空へ戻すのはクリアで、点数を書くときは、取り消しの列が持つ射手番号を指定する。他の端末が後から同じマスへ書いた矢も、確定の順の後勝ちで上書きする(`rounds/sync`)。
マスの範囲は距離のエンド数と射数/エンドで決まり、範囲外のマスは描かず指さない。

- 取り消しの列はstateにだけ持ち、再読み込みや画面遷移で消える。
- 距離の構成(的・エンド数・射数/エンド)を変えた保存と、距離の削除では、その距離のマスへの書き込みだけを列から捨てる。

## 設計判断

| 判断 | 理由 | 見直す条件 |
| :--- | :--- | :--- |
| 利用者が指すものをマス1つにし、空のマスも記録済みのマスも同じ形で指す。エンドを選ぶ状態を持たない | 書く・直すが「指しているマスへ書く」1つになるため。エンドを選んでから矢を選ぶ2段の選択は、状態と規則が増えるため採らない | 1つの矢に複数の属性を続けて入力する画面を作るとき |
| エンドに射数/エンドの個数のマスを固定で並べて空のマスも描き、マスの番号を射順にする。点数で並べ替えない | 射った順に点数を残し、書いた玉を動かさないため。射順を持たずに点数の高い順に並べる方式は、射順を残せず、書いた玉が入れ替わるためやめた | 射順を持たない入力の要求が出たとき |
| マスを行の幅いっぱいに等間隔で置く | 同じ距離のエンドの間で、同じ番号のマスの位置が揃うため。玉の間隔を固定して左に詰める並べ方は、右に空きが偏るため採らない | 射数/エンドが多く1段に収まらない距離が多いと分かったとき |
| 空のマスへ書いた後は、後ろの最初の空のマスへ進み、埋まったマスを飛ばし、前の空のマスへは戻らない。直しとクリアの後は同じマスに留まる | 前から順に書くだけで射順どおりに埋まり、他の利用者が埋めたマスを続けて上書きしないため。前の空のマスへ戻ると、わざと空けたマスへ跳ぶため採らない | 前の空のマスへ戻したい要求が出たとき |
| 指しているマスを他端末の変化で動かさない | マスは記録の有無で消えないため、合わせ込みは範囲外のときだけで足りるため。他端末が埋めたマスへ書くと上書きになるが、指す輪と点数で見える | 他端末の記録で指すマスを移す要求が出たとき |
| 取り消しの列を画面全体の1本にし、1件はマス1つへの1回の書き込みとする | エンドを選ぶ状態が無く、次のエンドへ移った直後でも、戻る1回で前のエンドのマスを戻せるため | 端末をまたぐ取り消しが必要になったとき |
| 戻る・進むは点数か空と、その矢の射手を書く | 矢の記録は射手の指定が要り、書き直してもマスの射手を変えないため。他端末が後で射手を付け替えていても、後に保存した指定が残る(`rounds/shooters`) | 射手の付け替えを古い操作から守る要求が出たとき |
| キーと配色を、的の`target_face_rings`から動的に構成する | 6点的に存在しない点数のキーが出るのを避けるため。固定12キーは採らない。Mは固定で末尾に置く | `target_face_rings`以外から的の点数を導くとき |
| 向きの判定を画面の向きで行い、横向きは右側パネル、縦向きは下パネルにする | 広い画面でテンキーが小さく表示されるのを避けるため。`md:`幅の判定は採らない | 画面の向きでなく幅でレイアウトを分けるとき |
| テンキーを常時配置し、開閉は位置・幅と`visibility`のtransitionだけで行う(アンマウントしない)。左パネルのドロワーと同じ形 | 要素の追加・取り外しで動きを揃えるための2フレーム待ち・タイマー・保持の状態を要らなくするため | 閉じたテンキーの描画・測定が負荷になったとき |
| 縦向きの格納ボタンを、パネル上端からはみ出す、右端の点数キーと同じ大きさ(高さ48px、4列格子の1列の幅)のタブにする | スコア領域の高さに圧迫感を持たせないため。パネル内に格納用の帯を置くと、その分パネルが高くなり、スコア領域が狭くなるため帯は採らない | タブに覆われるマスの押しにくさが問題になったとき |
| スクロールの契機を、利用者の操作で指すマスを設定するたび(マウント時の最初の1回を含む)と、配置の変化(スクロール領域の大きさ=向き・窓・テンキーの高さ、行の段数)の2系統にし、処理は1つの`follow`にする。他の端末の変化で指すマスが直されたときは追わない。内容全体の高さは観測しない。見える範囲は領域の矩形で、領域の中の固定表示だけを`data-sticky-inset`の実測で見込む。ヘッダーと帯・テンキーは領域の外に置く | 指すマスの再計算や取得による再描画では利用者のスクロールを戻さない(同じマスの再描画で動かすと戻してしまったため、契機を絞った)。内容の高さは距離の追加・削除、エンド数の変更、他の端末の変化でも変わり、利用者が別の場所へスクロールした後に指す行へ戻してしまうため観測しない。行の段数は玉の領域の幅の測定(非同期)で決まり、最初は1段で測れてから増えるため、段数の変化は各行が知らせる。操作ごとの要求にすると同じエンド内の移動に追従できる。固定表示の高さを足し合わせる定数は、固定表示を変えたときに壊れるため採らない | 他端末の変化による指すマスの移動も追従したくなったとき |

## 制約と未対応

- 的の位置の入力、射手の選択は扱わない。射順はマスの番号で、別に入力する操作は持たない。
- 記録済みのマスを直した直後に点数を押すと、同じマスを書き換える。
- 他の端末(複数人の入力を含む)が同じマスへ書いた矢は、後に保存された方で置き換わり、置き換わったことは知らせない(`rounds/sync`)。
- 複数人が1つのエンドを射つ場面でも、射手別のマスは持たない。矢の射手は保存するが、画面では選べず、見えない。
- マスの押せる範囲は36×40pxで、テンキーのキー(48px)より小さい。マスが広くても、押せる範囲の外は押しても何も起きない。
- 展開中、タブ(約80×48px)の下になるスコア領域の右端は押せない。指している行は、テンキーと完了の帯に覆われない位置までスクロールされる。
- マスで指す形への更新の前に記録した矢は、エンドごとに点数の高い順に射順を振ったマスで表示され、射った順とは限らない(`rounds/sync`の「更新前の矢の移行」)。
