# rounds/setup 設計

## 概要

`/rounds/[id]`で、ラウンド設定（名前・実施日・種別・弓種）と各距離（距離・的・本数・エンド数・Marked/Unmarked）を、概要のクリックで開くダイアログから変える。
距離の追加・削除、的の選択も、このダイアログから行う。
検証はクライアントで保存時に行い、通れば画面へ楽観的に反映して、操作を送信キューへ積む。
再送、競合、再読み込み後の復元は`rounds/sync`が扱い、本書は積むところまでを扱う。

## 画面と状態

| 画面 | 表示 | 判定 | 要求 |
| :--- | :--- | :--- | :--- |
| ラウンド概要 | 名前・実施日・種別・弓種を「 / 」で並べ、空の部分は区切りごと省く | 常時 | setup-01 |
| 距離一覧 | 各距離の距離・的・本数×エンド数。フィールドのときだけMarked/Unmarkedを併記する。Unmarkedで距離が未入力ならUnmarkedのみ、入力済みなら距離とUnmarked（例: `45m / Unmarked`）を出す | 距離が1件以上 | setup-02 |
| ラウンド編集 | 4項目を編集し、背景クリックで変更を破棄して閉じる | 概要のクリック | setup-03, 04, 19, 24 |
| 距離編集 | 距離・的・本数・エンド数を編集し、背景クリックで変更を破棄して閉じる。フィールドだけMarked/Unmarkedの切り替えを出す | 距離概要のクリック | setup-07〜10, 20 |
| 距離の追加 | 規定値、または最後の距離のコピーで追加し、その距離編集を開く | 追加ボタン | setup-05, 06 |
| 的選択 | 種別と弓種のフィルタで絞った的を選ぶ。距離編集の上に重ね、背景クリックでこのダイアログだけ閉じる | 距離編集での的のクリック | setup-11, 13, 21 |
| 距離削除 | 削除する。得点がある距離は確認ダイアログを挟み、キャンセルや背景クリックでは削除しない | 削除ボタン | setup-14〜16, 22, 23 |
| 得点のある距離 | 的・本数・エンド数を編集不可にする。距離とMarked/Unmarkedは編集できる | 距離に記録済みの得点がある | setup-18 |

### 検証

保存ボタンのクリック時にクライアントで同期的に行い、エラーがあれば項目ごとに出して保存しない（ダイアログは開いたまま）。

| 対象 | 条件 |
| :--- | :--- |
| ラウンド名 | 51文字以上 |
| 実施日 | 未入力 |
| 種別 | フィールド以外を選び、Unmarkedの距離が残っている |
| 距離 | Markedで未入力 |
| 本数・エンド数 | 1以上の整数でない |

## 構成とデータの流れ

- `page.tsx`（Server Component）: ラウンド・距離・的を取得する。
- `scorecard-client.tsx`: ラウンド・距離・矢・取り消し/やり直しの履歴を状態に持つ。
- `round-config-panel.tsx`: ラウンド概要と編集ダイアログ。`round-config.ts`の`validateRoundConfig`で検証する。
- `distance-config-row.tsx`: 距離編集と削除確認。`distance-config.ts`の`validateDistanceDraft`で検証する。
- `TargetFacePicker`: 的選択。`filterTargetFaces`で絞り込む。
- `scorecard-distances.ts`: 追加する距離の算出と、構成が変わるかの判定。

保存の流れ: 検証、状態の楽観的更新、ダイアログを閉じる、送信キューへ積む、の順である。

| 操作 | キーと種類 | RPC |
| :--- | :--- | :--- |
| ラウンド設定の保存 | `roundConfig` / `round.updated` | `update_round` |
| 距離の追加 | `distance:<id>` / `distance.created` | `create_distance` |
| 距離の保存 | `distance:<id>` / `distance.updated` | `update_distance` |
| 距離の削除 | `distance:<id>` / `distance.disabled` | `disable_distance` |

- 距離の追加は、距離が0件なら70m・6エンド・6本・既定の的（`DEFAULT_TARGET_FACE_ID`）・Markedとする。1件以上なら並び順で最後の距離を引き継ぎ、その距離が未設定なら70mにする。並び順のキーは、最後の距離のキーに`a`を足す。
- 的選択の初期フィルタはラウンド設定の種別と弓種で、それぞれ「すべて」を持つ。種別と弓種の両方に一致する的だけを出し、的が複数の弓種を持つときはいずれかが一致すればよい。
- 的は、種別の降順、サイズの降順、名前の順に並べる。ダイアログは高さを固定し、フィルタを上に固定して一覧だけをスクロールさせる。
- フィルタの選択は、同じ距離編集の中で的選択を開き直しても保持し、距離編集を開き直すとラウンド設定の値へ戻る。
- 距離の保存で的・本数・エンド数のいずれかが変わる場合（変更前の距離が見つからない場合を含む）は、その距離の取り消し・やり直しの履歴を破棄する。距離（m）とMarked/Unmarkedだけの変更では残す。距離の削除でも、その距離の矢と履歴を破棄する。他の距離は影響しない（setup-09）。

## 設計判断

| 判断 | 理由 | 見直す条件 |
| :--- | :--- | :--- |
| 構成が変わる保存と距離の削除で、その距離の履歴を破棄する | 取り消し・やり直しが変更前の構成の矢を書き戻し、存在しない点数やマスの矢ができるため。詳細: #169 | 履歴を新しい構成へ写せるとき |
| 得点のある距離は、的・本数・エンド数を編集不可にする | `update_distance`が、得点が残る距離の構成列の変更を拒否するため。`is_marked`は点数の構成に関係しないので変更できる | RPCの拒否条件を変えたとき |
| Unmarkedはフィールドだけで使い、Unmarkedが残る間はフィールド以外へ変えられない | DBがフィールド以外のUnmarkedを持たせず、書き込みのRPCも同じ規則で拒否する。クライアントは拒否の前に知らせる。自動でMarkedへ直すことは採らない | 種別変更時の補正を許すとき |
| 距離は、Markedなら必須、Unmarkedなら未入力で保存できる | DBのCHECK（`distances_marked_requires_distance`）と同じ規則で、Unmarkedは距離を非公開にするため | Unmarkedでも距離を保存・公開できるよう、DBのCHECKを変えたとき |
| ラウンド名は50文字以内とし、DBのCHECKと同じ上限をクライアントにも置く | 一覧と要約行が折り返しと省略に対応せず、表示崩れを防ぐため | 表示が折り返しに対応したとき |
| 検証をクライアントで保存前に行い、送信キューには検証後の操作だけを積む | 未入力などをRPCで拒否される前に知らせるため | 検証をサーバーへ寄せるとき |
| 書き込みは楽観的に反映し、送信キュー（IndexedDB）からRPCで送る | 未同期の操作を永続化して自動で同期するため。書き込みはRPCへ統一している | 送信キューを使わず、RPCの完了を待つ書き込みへ変えるとき |
| 的選択は種別と弓種のフィルタを分け、ラウンド設定を初期値にして「すべて」を持たせる | 全種別の混在で選びにくく、弓種で得点方式が異なるインドアの的を取り違えるため。種別だけの絞り込みは採らない | フィルタなしで選べる数まで的が減ったとき |
