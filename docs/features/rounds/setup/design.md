# rounds/setup 設計

## 概要

`/rounds/[id]`で、ラウンド名はヘッダーの名前をその場で編集し、実施日・種別・弓種と各距離（Marked/Unmarked・距離・射数/エンド・エンド数・的）は、概要のクリックで開くダイアログから変える。
距離の追加・削除、的の選択も、このダイアログから行う。
検証はクライアントで保存時に行い、通れば画面へ楽観的に反映して、操作を操作の列へ追記する。
再送、競合、再読み込み後の復元は`rounds/sync`が扱い、本書は積むところまでを扱う。

## 画面と状態

| 画面 | 表示 | 判定 |
| :--- | :--- | :--- |
| ラウンド名 | 共用のヘッダー枠のタイトルの位置(戻るの隣)に、名前を押せる表示で出す。長い名前は末尾を省略し、空のときは薄い文字のプレースホルダー(「ラウンド名」。`roundNamePlaceholder`)を出して、同じく押せる。表示のボタンの名前は、空のときも名前のあるときも「ラウンド名を編集」で始まる(`roundNameEdit`。名前のあるときは「ラウンド名を編集: <名前>」、`roundNameEditNamed`)。どちらも見える文字(名前またはプレースホルダー)を名前に含む。押すと、その場で入力欄に変わり、フォーカスが入って、入力欄の文字が全て選択された状態になる(空のときは選択する文字がない)。入力欄は見えるラベルを持たないため、名前「ラウンド名」(`roundConfigName`)を`aria-label`で付け、プレースホルダーも同じ文言にする。表示のボタンと入力欄は同時に存在せず、入力欄の名前「ラウンド名」と表示のボタンの名前(「ラウンド名を編集」で始まる)は区別できる。文字の大きさ・太さ・字体は、表示と入力欄で同じにし、編集に入っても文字の大きさと位置が動かない。大きさは常に14px(`text-sm`。「戻る」と同じ)とする。iOSでは、入力欄の文字が16px未満のため、フォーカス時に画面が拡大する場合がある。viewportで拡大を禁止していないため、利用者が拡大を戻せるので、この挙動は受け入れる。入力欄の枠(幅)は、入力されている文字に応じて増減し、空のときはプレースホルダーの幅とする。幅は、表示のボタンと入力欄で同じ式(文字の幅に、同じ内側の余白と枠線を足す)で決まり、編集に入っても、見た目の幅が変わらない。最大幅はヘッダーの残りの幅(戻る・プリセット保存・メニューを除く)で、表示は末尾を省略し、入力欄は他の入力欄と同じく内部でスクロールする。Enter(変換中を除く)か入力欄の外の操作で確定し、Escで取り消して表示に戻る。入力欄は50文字までで、51文字目以降は入力できない(貼り付けの超過分は切る)。変えた内容がなければ操作を積まない。編集中は、外の値の変化で入力を書き換えず、保存は編集を始めたときの名前との差だけを送る | ラウンドが表示されているとき(完了済みを含む)。取得中・見つからないときはタイトルを出さない |
| ラウンド概要 | 実施日・種別・弓種を「 / 」で並べ、空の部分は区切りごと省く | 常時 |
| 距離一覧 | 各距離を1行にし、左に区分と距離、射数×エンド数を縦に、左側のすぐ右に的の情報(行をまたいで左端をそろえる。左に全体の図、右上にサイズ表記、右下に中心の拡大図)を置き、行の右端に展開記号を置く。的は、一覧に的IDが無ければ「的データを取得できません」を出す。フィールドのときだけ、区分を距離より先に置き、距離を括弧で添える（例: `Marked (90m)`、`Unmarked (45m)`）。Unmarkedで距離が未入力なら区分のみを出す | 距離が1件以上 |
| ラウンド編集 | 実施日、種別・弓種(横に2つ並べる)の順に編集し、背景クリックで変更を破棄して閉じる。種別・弓種は選択肢から1つ選ぶ欄(共通の`Select`。必須のため「指定なし」はない)。開いている間は、外の値の変化で入力を書き換えず、保存は開いたときの値との差だけを送る | 概要のクリック |
| 距離編集 | 上から、フィールドは1行目に「Marked/Unmarked」と距離、フィールド以外は1行目に距離(幅いっぱい)、2行目に射数/エンドとエンド数(横に2つ)、3行目に的の順に編集し、背景クリックで変更を破棄して閉じる。Marked/Unmarkedは選択肢から1つ選ぶ欄(共通の`Select`)で、種別がフィールドのときだけ出す。開いている間は、外の値の変化で入力を書き換えず、保存は開いたときの値との差だけを送る | 距離概要のクリック |
| 距離の追加 | 規定値、または最後の距離のコピーで追加し、その距離編集を開く。続けて追加したときは、最後に追加した距離の編集だけを開く | 追加ボタン |
| 的選択 | トリガーは的の2状態（ある・見つからない）を表示し、どちらの状態でも開ける。ラベルは、ある: 的の名前、見つからない: 「的データを取得できません（タップで変更）」で、得点があるときだけ開かず理由を出す。種別と弓種のフィルタで絞った的を選ぶ。距離編集の上に重ね、背景クリックでこのダイアログだけ閉じる | 距離編集での的のクリック |
| 距離削除 | 削除する。得点がある距離は確認ダイアログを挟み、キャンセルや背景クリックでは削除しない | 削除ボタン |
| 得点のある距離 | 的だけ編集不可にする(読み取り専用。disabledにしない)。クリックすると、的の直下に「スコアが記録済みのため変更できません」を`role="alert"`で表示し、選択ダイアログは開かない。総エンド数・射数/エンド・距離・Marked/Unmarkedは編集できる | 距離に記録済みの得点がある |

### 検証

保存ボタンのクリック時にクライアントで同期的に行い、エラーがあれば項目ごとに出して保存しない（ダイアログは開いたまま）。エラーと理由は、その項目を含む行の下に、幅いっぱいで出す(半幅の列の下では折り返しが多くなるため)。種別のエラーは種別・弓種の行の下、射数/エンド・エンド数のエラーと矢に収まらない理由は射数/エンド・エンド数の行の下、的の理由は的の欄の下に出す。

| 対象 | 条件 |
| :--- | :--- |
| 実施日 | 未入力 |
| 種別 | フィールド以外を選び、Unmarkedの距離が残っている |
| 距離 | Markedで未入力。値を入れたときは、1以上の整数で上限(100)以下でない(Unmarkedも同じ) |
| 射数/エンド・エンド数 | 1以上の整数で、それぞれの上限(射数/エンド12、エンド数60)以下でない。範囲外は、1以上の整数でないとき「1以上の整数を入力してください。」、上限を超えるとき項目ごとの上限値を示す文言 |
| 総エンド数・射数/エンドが記録済みの矢に収まらない | 総エンド数か射数/エンドが開いたときから変わり、距離の生きている矢のどれかが新しい構成(開いたときの的)に収まらない(エンドが総エンド数を超える、マスの番号が射数/エンドを超える、的に無い点数。サーバーの`shot_fits`と同じ判定、`shotsFitDistance`)。射数/エンド・エンド数の行の下に「記録済みのスコアが失われるため、変更できません。先にスコアを削除してください。」を`role="alert"`で表示し、射数/エンドとエンド数の両方から`aria-describedby`で参照する。総エンド数・射数/エンドが変わらない保存では判定しない |

## 構成とデータの流れ

- `page.tsx`: 静的な枠。ラウンド・距離・的の取得は`rounds/detail`が扱う。
- `features/rounds/ui/use-scorecard.ts`: ラウンド・距離・矢は、操作の列から導いた状態を使う。
- `features/rounds/ui/use-score-history.ts`: 取り消し/やり直しの履歴を状態に持つ。
- `features/rounds/ui/use-distance-editing.ts`: 距離の編集の開閉(編集を開く距離は1つだけで、同じ距離なら閉じ、違う距離なら替える。距離を追加すると、追加した距離の編集を開く)と、距離の追加、保存。構成が変わる保存で、その距離の履歴を捨てる。削除での履歴の破棄は`scorecard-client.tsx`が`discardDistance`を直接呼ぶ。削除は追記の直後に状態から距離が無くなり、距離のカードの消滅が編集のダイアログを同じ描画で閉じる。削除した距離のマスを指していたときは、指すマスの合わせ直しが外す。距離のIDとイベントIDは手続きの入れ物の`ids.next`から受ける。
- `features/rounds/ui/round-config-panel.tsx`: ラウンド概要(実施日・種別・弓種)と編集ダイアログ。`features/rounds/domain/round-config.ts`の`validateRoundConfig`で実施日・種別を検証し、イベントIDは手続きの入れ物の`ids.next`から受ける。種別・弓種は、ボタンの組でなく共通の`Select`(`components/ui/select.tsx`)で選ぶ。
- `features/rounds/ui/round-name-editor.tsx`: ヘッダーのラウンド名(表示と、その場の編集)。名前の表示用のボタン、編集用の入力欄(共通の`Input`。`maxLength`に`NAME_MAX_LENGTH`を渡す)を持つ。2つは同じ箱(高さ、内側の余白、枠線(表示は透明)、字体)を共有し、幅は、同じ文字(入力値、空のときはプレースホルダー)を測る見えない要素の幅から決める(`field-sizing`に頼らず、ブラウザによらず同じ幅にする)。編集を始めたときの名前を起点に持ち、`buildRoundUpdatedOperation`で起点との差から操作を作って追記する。変えていなければ操作を積まない。イベントIDは手続きの入れ物の`ids.next`から受ける。`scorecard-client.tsx`が`RoundDetailFrame`のタイトルとして渡す。
- `features/rounds/ui/distance-edit-fields.tsx`(ダイアログと操作)、`distance-fields.tsx`(欄の描画。Marked/Unmarkedは共通の`Select`で、真偽値との写しはここの1か所に置く)、`use-distance-draft.ts`(下書き、検証、保存、削除): 距離編集と削除確認。`features/rounds/domain/distance-config.ts`の`validateDistanceDraft`で検証し、操作は`distance-operations.ts`で組み立て、イベントIDは手続きの入れ物の`ids.next`から受ける。
- `features/rounds/domain/round-constants.ts`: 距離(m)・総エンド数・射数/エンドの上限(`DISTANCE_LIMITS`: 100・60・12)。検証(`distance-config.ts`)と文言(`distance-fields.tsx`)が項目別に参照する。数値の入力欄はこの編集だけで、ラウンドの開始画面(プリセットの選択)とプリセット保存(表示中の構成の送信)は入力欄を持たず、検証済みまたはDBの制約を通った値だけを送る。
- DBの上限: `distances`・`preset_distances`の3列にCHECK制約(`*_distance_max`・`*_total_ends_max`・`*_arrows_per_end_max`)を持つ。`create_round`・`create_distance`・`update_distance`・`save_round_as_preset`は、書く前に`distance_config_over_limit`で上限を判定し、超過をPT422で拒否する(何も保存しない)。PT422は送信側が再試行せず破棄する(`rounds/sync`)ため、同期は詰まらない。CHECK制約はRPCを通らない書き込みと判定漏れの最後の砦で、RPCより先には効かない。
- `features/rounds/ui/target-face-picker.tsx`: 的選択。`features/rounds/domain/target-face-filter.ts`の`filterTargetFaces`で絞り込む。種別と弓種の絞り込み欄(`TargetFaceFilters`)は、共通の`components/ui/select.tsx`(`Select`)を使い、点数一覧の距離行(`rounds/history`)の的の選択も同じ欄を使う。
- `features/rounds/domain/distance-operations.ts`: 追加する距離の算出と、構成が変わるかの判定、距離の更新と無効化の操作。

保存の流れ: 検証、操作の列へ追記する(追記の直後に画面の状態が変わる)、ダイアログを閉じる(ヘッダーの名前は編集を終えて表示に戻る)、の順である。設定・距離の保存の反映は、保存の完了を待たない。
保存は、保存した設定との差分(変えた項目だけ)を1つの操作として積み、何も変わらない保存は操作を積まない。サーバーが項目ごとに判定する。構成(的・エンド数・射数/エンド)は1組で、どれかが変われば3項目をまとめて積む。

| 操作 | 種類 | RPC |
| :--- | :--- | :--- |
| ラウンド設定の保存 | `round.updated` | `update_round` |
| 距離の追加 | `distance.created` | `create_distance` |
| 距離の保存 | `distance.updated` | `update_distance` |
| 距離の削除 | `distance.disabled` | `disable_distance` |

- 距離の追加は、距離が0件なら70m・6エンド・射数/エンド6・既定の的（`DEFAULT_TARGET_FACE_ID`）・Markedとする。1件以上なら並び順で最後の距離を引き継ぎ、その距離が未設定なら70mにする。並び順のキーは、最後の距離のキーより大きく、最後の文字を1つ進め、`z`以上なら`a`を足す。同じキーの距離は(位置キー、ID)の順で並ぶ。別の端末が同じ位置へ同時に追加しても、両方が保存され、並びはキーとIDで全端末で同じになる。
- 的選択の初期フィルタはラウンド設定の種別と弓種で、それぞれ絞り込みなしを持ち、表示は「指定なし」である。種別と弓種の両方に一致する的だけを出し、的が複数の弓種を持つときはいずれかが一致すればよい。
- 的は、種別の降順、サイズの降順、名前の順に並べる。ダイアログは高さを固定し、フィルタを上に固定して一覧だけをスクロールさせる。
- フィルタの選択は、同じ距離編集の中で的選択を開き直しても保持し、距離編集を開き直すとラウンド設定の値へ戻る。
- form外の入力欄は、共通の`Input`が、変換中でないEnterでフォーカスを外す（保存や閉鎖はしない）。
- 距離の保存で的・射数/エンド・エンド数のいずれかが変わる場合は、その距離の取り消し・やり直しの履歴を破棄する。距離（m）とMarked/Unmarkedだけの変更では残す。距離の削除でも、その距離の矢と履歴を破棄する。他の距離は影響しない。

## 設計判断

| 判断 | 理由 | 見直す条件 |
| :--- | :--- | :--- |
| 構成が変わる保存と距離の削除で、その距離の矢への書き込みを取り消しの列から捨てる | 取り消し・やり直しが変更前の構成の矢を書き戻し、存在しない点数やエンドの矢、射数/エンドを超える矢ができるため。詳細: #169 | 取り消しの列を新しい構成へ写せるとき |
| 得点のある距離は、的を編集不可にする | 的を替えると、記録済みの点数が新しい的に無くなりうるため。射数/エンド・エンド数は、記録済みの矢が収まる変更だけを保存前に許す(判定はサーバーの`shot_fits`と同じ)。`is_marked`は点数の構成に関係しないので変更できる | 矢を新しい的へ移せるようになったとき |
| 編集不可をdisabledにせず、読み取り専用+押下でインライン表示する | disabledは押下を受けず理由を出せない。サインインでも同じ理由でdisabledをやめた(#317)ため戻さない。トーストは消えると再確認できず採らない | 編集不可を解く、または理由表示の共通部品ができたとき |
| Unmarkedはフィールドだけで使い、Unmarkedが残る間はフィールド以外へ変えられない | DBがフィールド以外のUnmarkedを持たせず、書き込みのRPCも同じ規則で、不変条件を破る後の項目を効かせない(拒否も補正もしない)。クライアントは保存前に知らせる。自動でMarkedへ直すことは採らない | 種別変更時の補正を許すとき |
| 距離は、Markedなら必須、Unmarkedなら未入力で保存できる | DBのCHECK（`distances_marked_requires_distance`）と同じ規則で、サーバーは破る後の項目を効かせない(補正しない)。クライアントは保存前に知らせる。Unmarkedは距離を非公開にするため | Unmarkedでも距離を保存・公開できるよう、DBのCHECKを変えたとき |
| 距離(m)は100、総エンド数は60、射数/エンドは12を上限とし、DBのCHECK制約・RPC・クライアントの3か所が同じ値を持つ。総エンド数の上限×射数/エンドの上限(720)は、PostgRESTの`max_rows`(`supabase/config.toml`、1000)以下に保つ | 実用上の限界を超える値は、スコアカードの表示と同期の費用を増やすだけで使われない。ラウンド詳細・一覧の矢の入れ子取得は`max_rows`が距離ごとに効き、1距離の矢が1000本を超えると表示と合計点が欠けるため、総エンド数を100(1200本)でなく60(720本)にした。上限がbigint全域だと、画面が崩れる値も保存できた。RPCを変えずCHECKだけを足すと、超過操作が23514で再試行され続けて同期が詰まるため、RPCがPT422で先に拒否する | 上限を変えるとき(DBとクライアントを同じPRで更新する) |
| ラウンド名は50文字以内とし、DBのCHECKと同じ上限を、ヘッダーの入力欄の最大文字数(`NAME_MAX_LENGTH`)として置く。名前の検証関数は持たない | 一覧の行が折り返しに対応せず、表示崩れを防ぐため。入力で50文字を超えられないため、確定でのエラーと検証は要らない。名前を編集するのはヘッダーの入力欄だけで、ラウンド編集ダイアログの`validateRoundConfig`は名前を検証しない(`tooLong`の誤りと文言は持たない)。入力欄の文字数は(UTF-16の単位で)DBの文字数以下になる | 表示が折り返しに対応したとき |
| 検証をクライアントで保存前に行い、操作の列には検証後の操作だけを追記する | 未入力などをRPCで拒否される前に知らせるため | 検証をサーバーへ寄せるとき |
| 書き込みは楽観的に反映し、操作の列（IndexedDB）からRPCで送る | 未同期の操作を永続化して自動で同期するため。書き込みはRPCへ統一している | 操作の列を使わず、RPCの完了を待つ書き込みへ変えるとき |
| 編集ダイアログの下書きは、開いたときに作り、閉じるまで外の値で書き換えない。保存は開いたときの値との差だけを送る | 取得や他の端末の変更で入力が消えず、変えていない項目の古い値で、届いた他の端末の変更を戻さないため。内容の変化で下書きを戻す案や、再マウントする案は、他の端末の変更が届くと入力が消えるため採らない | 他の端末の変更を編集中に見せる要求が出たとき |
| 的選択は種別と弓種のフィルタを分け、ラウンド設定を初期値にして絞り込みなし(「指定なし」)を持たせる。1項目につき1つの選択欄(共通の`Select`)から選ぶ | 全種別の混在で選びにくく、弓種で得点方式が異なるインドアの的を取り違えるため。種別だけの絞り込みは採らない | フィルタなしで選べる数まで的が減ったとき |
| 絞り込み欄は、base-uiのSelectを包んだ共通部品(`components/ui/select.tsx`)にし、選択肢・項目名・未選択の表示は使う側が渡す。選択肢の一覧はアプリの見た目で描く。外側押しなどの専用の仕組みは持たず、base-uiの既定のまま使う。`Dialog`と使う側は変えない | 標準selectは展開後の一覧が端末標準の見た目でアプリと揃わないため。base-uiのSelectは、キーボードで操作でき、項目名と現在値が支援技術へ伝わる。ネストしたダイアログ内の一覧の重なり、外側の操作の反映(展開中でも展開していないときと同じ)、選択・Escでダイアログが閉じないことは、base-uiの既定で得られる(Chromium・WebKit、幅375pxで確認)。この既定へ依存するため、base-uiを更新するときは手動で確かめる。ダイアログ側での対処は、動作の保証が部品の外へ漏れるため採らない。横並びボタンは選択肢が常時並び幅を使うため採らない | 外側押しの扱いがbase-uiの更新で変わったとき |
| 的の情報は、全体の図(48px)の右に、サイズ表記(14px)と中心の拡大図(外側75×28px、枠線の内側73×26px、左の余白5%)を縦に並べ、距離の行は左に距離と射数×エンド数、左側のすぐ右に的の情報を置いて左詰めにし、左側の最小幅(7.5rem)で左端をそろえる | 幅375pxで距離の行(ラウンド詳細、プリセット選択、保存確認)が横にあふれないよう、的の情報の幅を約127pxに収めるため。拡大図は外側75×28pxにし、得点の文字は倍率から決まり約10.7px、覗き5.0px以上を保つ。十字は実寸0.2cmのままで、小さい的では左端に接する。的選択ダイアログの一覧は、項目の最小幅(9rem)から列の数を自動で決める格子(幅375pxで2列)で、各項目の中央に的の情報を置く。幅の検出や切替は採らない。左側の最小幅を種別ごとに分けることは、種別で見た目の規則が分かれるため採らない | 375px未満を対象にするとき、得点の文字をさらに大きくする要件が出たとき、または十字の欠けが問題になったとき |
| 位置キーの重複を許す | DBに一意制約はなく、並びは(position_key, id)で決まる。サーバーが削除済みを含めて同じ位置を拒否すると、端末は削除済みのキーを知れず、同時追加も衝突して、追加した距離と得点が失われる。生成側でIDを足す案は、キーが追加ごとに32文字伸びるため採らなかった。プリセットの保存では、IDが変わるため、並びを確定してからキーを連番で振り直し、プリセットのキーは重複しない | 位置キーで1件の距離を一意に指す必要が生じたとき |
| ラウンド名を、ラウンド編集ダイアログでなくヘッダーの名前でその場で編集する | 名前は他の項目と独立で、ダイアログを開かずに変えられるため(ユーザーの判断)。確定が1項目の操作を積む | 名前に他の項目との整合の検証が要るとき |
| ヘッダーの名前の確定は、Enter(変換中を除く)と入力欄のblurで行い、Escでは確定せず取り消す | 入力欄の外の操作でも確定するという要件のため。Escで取り消した後のblurで確定しないよう、取り消しを区別する。共通の`Input`は`form`なしのEnterでblurするため、Enterはkeydownで確定する | 確定の操作が分かりにくいと分かったとき |
| ヘッダーのラウンド名は、表示と入力欄で同じ箱・同じ文字の大きさ(常に14px。「戻る」と同じ)にし、幅を入力文字に応じて増減させる | 編集に入っても見た目が動かないというユーザーの判断のため。文字の大きさを画面の幅で変えると、表示と入力欄の大きさが画面の幅で分かれるため採らない。iOSは16px未満の入力欄のフォーカス時に拡大する場合があるが、利用者が戻せるため受け入れる。幅を文字から決める見えない要素は、`field-sizing: content`が使えない環境でも同じ幅にするため | 名前の入力欄の拡大が問題になったとき |
| 種別・弓種とMarked/Unmarkedを、共通の`Select`のドロップダウンにする。必須のため「指定なし」を持たない(履歴の`NullableSelect`は使わない) | 選択肢から1つ選ぶ操作を、ほかの選択欄(的のフィルタ、履歴のフィルター)と同じ部品にそろえ、横に2つ並べる行に収めるため(ユーザーの判断)。`Select`の項目名は見えるラベルで、トリガーへ関連付く。必須の印は、使う側が項目名として渡す | 選択肢が増えて、ボタンの組のほうが選びやすくなったとき |

## 制約と未対応

- 最大構成(1距離で総エンド数60×射数/エンド12=720本)でも、スコアカードの表示・記録・同期が使える状態を保つ。
- 連続して保存した操作は列に残り、順序どおりに送られる。設定の保存と、同じ距離の矢の記録の順序は`rounds/sync`の衝突の規則が保つ。
