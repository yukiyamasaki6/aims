# rounds/preset 設計

## 概要

`/rounds/[id]`の「プリセット保存」で、画面に表示中の構成（種別・弓種・距離構成）を個人プリセットとして保存する。
個人プリセットは`/rounds/new`の個人プリセット欄に並び、各カードのメニューから削除できる。
プリセットは元のラウンドと紐付かない独立したデータである。
保存は表示中の構成をそのまま`save_round_as_preset` RPCへ送る。
公式プリセットは保存も削除もできない。

## 画面と状態

保存ダイアログ（`/rounds/[id]`）

| 状態 | 表示 | 判定 | 要求 |
| :--- | :--- | :--- | :--- |
| 閉じている | 「プリセット保存」ボタンのみ | `open`が`false` | preset-01, 04, 09 |
| 入力中 | 名前欄にラウンド名を事前入力し、空なら距離構成から自動生成した名前をプレースホルダーに出す | `open`が`true` | preset-03, 05〜07 |
| 保存中 | 保存ボタンを無効にし、背景クリックやEscでは閉じない | `submitting`が`true` | preset-08 |
| 保存失敗 | 開いたままエラーを出し、再び押せる | 名前が51文字以上、または保存が失敗 | preset-19, 20 |

削除（`/rounds/new`）

| 状態 | 表示 | 判定 | 要求 |
| :--- | :--- | :--- | :--- |
| メニュー表示 | 個人プリセットの行に「削除」を出し、外側のクリックで閉じる | メニューを開いている | preset-10 |
| 確認中 | `BlockingConfirmDialog`に「「<プリセット名>」を削除しますか？」 | `presetToDelete`が設定されている | preset-12〜15 |
| 削除中 | キャンセルと確認を無効にし、背景クリックでも閉じない | 完了していない | preset-16 |
| 削除成功 | 一覧から除く。削除対象が選択中なら選択も解除する | 結果が成功 | preset-17 |
| 削除失敗 | 開いたままエラーを出し、確認ボタンを再び押せる | 結果が`failed` | - |

## 構成とデータの流れ

- `save-preset-dialog.tsx`: 保存ダイアログの状態を持ち、`save_round_as_preset`を呼ぶ。
- `scorecard-preset.ts`: 開閉時の事前入力と破棄、名前の決定と長さ検証、RPC引数の生成、結果の反映を純関数で行う。
- `delete-preset.ts`: セッションを確認し、`preset_rounds`を`id`で直接DELETEする。

- 名前が空白のみなら、距離を位置順に`-`でつないだ名前（未入力の距離は`??`）で保存する。
- 名前は50文字以内とし、クライアントの検証とDBのCHECK制約の両方で守る。
- `save_round_as_preset`は、渡された名前・種別・弓種・距離配列を`preset_rounds`と`preset_distances`へ1トランザクションで書く。`rounds`・`distances`は読まない。SECURITY INVOKERで、呼び出し元のRLSに従う。
- 削除は直接のDELETEで、`preset_rounds`のDELETEポリシーが認可を担う。`preset_distances`は外部キーのCASCADEで消える。
- アプリが書き込む経路は、保存のRPCと削除だけである。`preset_rounds`のUPDATEと`preset_distances`のUPDATE・DELETEのポリシーとGRANTは持たない。
- 削除は送信キューを使わず、`BlockingConfirmDialog`が完了を待つ。

## 設計判断

| 判断 | 理由 | 見直す条件 |
| :--- | :--- | :--- |
| 保存は画面に表示中の構成を送り、保存済みの`rounds`・`distances`を読み直さない | 読み直す方式は、送信キューの完了待ちが解決しない間、ダイアログが閉じられず固まるため、やめた。詳細: #471 | キューの完了を待たずに保存の整合を取れるとき |
| 保存を`/rounds/[id]`にだけ置く | 構成の入力と編集を`/rounds/[id]`へ一本化し、保存は現在の構成を対象にするため | `/rounds/new`で構成を編集できるようにするとき |
| プリセットの作成と距離の複製を1つのRPCで行う | アプリ側の順次挿入と補償削除は、途中のクラッシュで距離のない空のプリセットが残るため、やめた | 距離を持たないプリセットを許すとき |
| 自動生成名は距離構成だけにする | 弓種は個人でほぼ固定で、種別は距離から判別できるため。種別・弓種を含む名前は採らない | 弓種を複数使う利用が増えたとき |
| 名前の上限を50文字にする | 一覧と要約行が折り返しと省略に対応していないため | 一覧が折り返しに対応したとき |
| 削除の確認に完了を待つ`BlockingConfirmDialog`を使う | 破壊的な操作で、完了前に閉じると結果を確認できないため | 削除を取り消せるようにしたとき |
| 削除メニューは、名前ボタンとメニューボタンだけを囲む`relative`ラッパー内で中央寄せする | カード全体を基準にすると、距離構成の展開時にメニューボタンが名前の行からずれるため | カードの構造を変えたとき |

## 制約と未対応

- 同名のプリセットを保存できる（一意制約を持たない）。
- プリセットの名前変更・内容編集はできない。
