# rounds/detail 設計

## 概要

`/rounds/[id]`でラウンドのスコアカードを表示する。
エンドごとの記録と小計、距離ごとの合計、ラウンド全体の合計と最高点数・X数を、1画面で確認する。
集計はクライアントの純粋関数で行い、的のリング構成から、Xの有無と最高点数・次の点数を導く。
画面の枠は静的で、ラウンドはクライアントが取得するため、オフラインでも枠は開き、取得の失敗を枠内で区別して表示する。
点数の入力は`rounds/score-entry`、設定の編集は`rounds/setup`、同期の表示は`rounds/sync`が扱う。

## 画面と状態

| 領域 | 内容 | 固定表示 | 要求 |
| :--- | :--- | :--- | :--- |
| 同期・一覧へ戻る行 | 同期状態と「一覧へ戻る」リンク | 常に画面上端 | detail-12 |
| ラウンドの結果 | 合計。条件を満たすときだけ最高点数・X数、または最高点数・次点数を併記 | 同期・一覧へ戻る行の下 | detail-02、detail-10 |
| 距離の結果 | 距離ごとの合計と、最高点数・X数、または最高点数・次点数 | 距離の範囲内で、ラウンドの結果の下 | detail-06、detail-07、detail-11 |
| エンド | 各矢の点数、エンドの小計 | なし | detail-01 |

枠の状態は、取得の結果で決まる。

| 状態 | 表示 | 判定 | 要求 |
| :--- | :--- | :--- | :--- |
| 取得中 | 「一覧へ戻る」の行と読み込み中の表示 | 取得が完了していない | - |
| 見つからない | 「ラウンドが見つかりません。」と「一覧へ戻る」リンク。存在しない・権限なし・論理削除済み・UUIDでないIDを区別しない | ラウンドが得られない | detail-15 |
| オフライン | 「ネットワークに接続されていません」と再試行 | 通信できない | detail-16 |
| 取得エラー | エラーメッセージと再試行 | 取得がエラー | detail-17 |

- 点数の記録で、合計・小計・最高点数・X数は即時に更新する（detail-08）。
- 距離がないラウンドでは、ラウンド編集ダイアログを開いた状態で表示する（detail-14）。
- 最初の未記録のマスを選択して、テンキーを展開する。全マス記録済みなら選択しない（detail-13）。
- Xのある的は「最高点数/X数」、ない的は「最高点数/次点数」を表示する。X数は`score_str`、その他は`score_int`から数える。
- ラウンド全体の最高点数・X数は、全距離でXの有無、最高点数、次の点数が一致するときだけ表示する。一致しなければ合計だけを表示する。

## 構成とデータの流れ

- `rounds/[id]/page.tsx`: 静的な枠。`generateStaticParams`で`/rounds/_`だけをプリレンダーし（`dynamicParams = false`）、取得も`cookies()`も使わない。`/rounds/<ID>`はnext.configのrewriteで`/rounds/_`の枠へ向ける。
- `rounds/[id]/round-detail-client.tsx`: `usePathname()`のIDで取得し、状態に応じて枠の内表示かスコアカードを出す。ラウンドの削除が未送信なら`/rounds`へ遷移する。
- `rounds/[id]/round-detail-id.ts`: pathnameからUUIDを取り出す。UUIDでなければ`null`で、問い合わせずに見つからないとする。
- `rounds/[id]/fetch-round-detail.ts`: ラウンド・距離・矢を1回のネスト取得、的を1回の取得で得て、`FetchResult`に分類する。的は自分の分と公式に絞る。
- `rounds/[id]/load-round-detail.ts`: 取得の結果へ、未送信の操作を重ねる。
- `rounds/[id]/round-detail-frame.tsx`、`back-to-list-link.tsx`: 枠と「一覧へ戻る」リンク。
- `rounds/[id]/scorecard-client.tsx`（Client Component）: `shots`と距離の構成を保持し、表示を組み立てる。
- `rounds/[id]/scorecard-scoring.ts`: 距離とラウンドの集計、エンドの小計を求める純粋関数。
- `rounds/[id]/round-summary.tsx`、`distance-summary.tsx`: ラウンドの結果、距離の結果。

集計は、点数を入力するたびにクライアントで再計算し、サーバーへ問い合わせない。
取得の結果は`ScorecardClient`へ渡し、以降の更新は楽観的UIと送信キューで行って、再取得を待たない。
未送信の操作は、取得の前後にoutboxを読んだ和集合を、操作の古い順に重ねる。読み取り中に送信に成功して消えた操作と、読み取り後に積まれた操作の、どちらも落とさないためである。重ね合わせは冪等で、二重の適用は結果を変えない。
`data-hydrated`はスコアカードの根にだけ付け、E2Eはこれを待つ。
静的化は、`next build`の出力が`● /rounds/[id]`・`└ /rounds/_`になり、`.next/server/app/rounds/_.html`にユーザー・ラウンドのデータが含まれないことで確かめる。

## 設計判断

| 判断 | 理由 | 見直す条件 |
| :--- | :--- | :--- |
| 入力と表示を`/rounds/[id]`の1画面にまとめ、独立した集計画面を設けない | 入力後も同じ画面で内訳を確認できるようにするため | 集計だけを見る用途が増えたとき |
| ラウンドの結果と距離の結果を、スクロール中も固定する。上端の行（`h-14`）の下に`top-14`、さらに下に`top-[88px]`で重ねずに並べる | 長いスコアカードでも合計を見られるようにするため | 固定要素の高さを変えるとき |
| 最高点数・X数を、的のリング構成から動的に求め、Xのない的は最高点数と次の点数を表示する | 6点的やコンパウンドの40cm的など、標準の10点的以外にも対応するため。Xの有無を固定とした集計は採らない。詳細: #418 | 的の種類を増やすとき |
| 表示の順を「最高点数/X数」にし、X数は`score_str`で数える | Xのない的でも最高点数が先頭にあるほうが読みやすいため、「X数/最高点数」の順をやめた。`score_int`だけではXと10を区別できない | 最高点数とX数の並びを利用者が選べるようにするとき |
| ラウンド全体の最高点数・X数は、全距離で一致するときだけ表示する | 的が異なる距離を足した最高点数・X数は意味を持たないため | 的が異なる距離の集計を定義するとき |
| 印の無い距離（フィールド）は、的に存在しない点数を数えない | フィールド的に10点・Xなどがないため | フィールド的に10点・Xなどの点数を設けるとき |
| ページを静的な枠にし、ラウンドをクライアントで取得する。更新は楽観的UIと送信キューで行う | オフラインでも枠を出し、取得の失敗を枠内で区別するため。書き込みの完了を待たずに反映するため。詳細は`rounds/sync`、#648 | 取得をサーバーで行う必要が出たとき |
| `generateStaticParams`で`[{ id: "_" }]`だけを返し、`dynamicParams = false`にする | `/rounds/<ID>`はnext.configのrewriteで`/rounds/_`へ向くため未知のIDは動的ルートに届かず、IDごとのHTMLが永続化され続けるのを防ぐ。オンラインの未知のIDも枠が返り、見つからないは枠内に出す | rewriteをやめるとき |
| `data-hydrated`を枠の状態に付けず、取得後のスコアカードにだけ付ける | 枠に付けると、E2Eの待ちが取得の完了より先に解け、状態を前提にする操作が競合するため | E2Eの待ちの方式を変えるとき |
| 未送信の操作の重ね合わせを取得の中で行い、`ScorecardClient`のマウント後には行わない | サーバーの値が一瞬見えるちらつきを避け、最初の未記録のマス（detail-13）が未送信の矢を含む状態で決まるようにするため | 取得と重ね合わせを分ける必要が出たとき |

## 制約と未対応

- ラウンドの結果の最高点数・X数は、的が異なる距離を含むラウンドでは表示しない。
- オフラインのときは取得できず、未送信の操作の楽観値も表示されない。復旧は再取得（#647）と枠の返却（#648）の範囲である。
