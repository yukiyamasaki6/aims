# 点数一覧のフィルターパネルと点数カードのテスト設計

## 基準と範囲

基準は[履歴の要件](requirements.md)と[設計](design.md)だけである。
本書は実装やテストコードの内容から期待値を導かない。
外側は非モーダルのパネルとし、外側タップでは保持、Escはフォーカスと最前面の操作に従う契約を採用する。

優先順位は、意図しない適用・編集消失の防止、一覧と入力の操作到達性、指定された配置と開閉の動きの順とする。
対象は外側フィルターの置換と、先頭の行の閉じるボタン、表示単位の切り替え、下部のリセット・検索、展開中の漏斗の見た目と、それに接続する編集・取得・保存・フォーカス・一覧スクロールの回帰である。
検索の意味、RPC、同期、点数キーボードの仕様は変更対象外であり、既存の下層テストを再利用する。保存値は、単位ごとの得点の範囲を足した形であり、「表示単位と単位ごとの条件」で確かめる。
新しいDBテストや全条件のE2E総当たりは追加しない。

## 編集・確定・破棄のケース

次の表はテスト名の案と条件・操作・期待結果であり、要求との対応表ではない。
異なる操作は別テストにし、各ケースは正常系から異常系の順に実装する。

| テスト名の案 | 前提と操作 | 期待結果 |
| --- | --- | --- |
| フィルターを開くと適用済みの全条件から編集を始める | 既定と非既定の適用済み条件をそれぞれ用意して開く。 | 日付順・得点順、期間、単位ごとの得点範囲、種別・弓種、構成、単位、保持中の距離指定が復元される。開くだけでは一覧・取得条件・記憶は変わらない。 |
| 条件を編集しても適用前の一覧と印を保つ | 適用済みの一覧で各条件を編集する。 | 下書きの表示だけが変わり、一覧、適用中の印、取得条件、保存済み条件は変わらない。 |
| 有効な変更を検索すると新しい条件の先頭を表示する | 複数ページ表示済みの一覧で有効な取得条件の変更を検索する。 | 条件が確定・記憶され、縦長ではパネルが閉じ、横長では開いたまま入力値が残り、旧表示はスケルトンになり、新条件の先頭ページが表示される。旧ページは連結されない。 |
| 条件を変えずに検索すると一覧を維持する | 適用済みと同じ値で検索する。 | 縦長ではパネルが閉じ、横長では開いたままで、表示済みのページを維持し、新たな履歴取得を起こさない。 |
| ラウンド単位で非表示の距離だけを変更して検索すると取得しない | 距離単位で距離を選び、ラウンド単位へ戻して検索する。導出条件が元と同じになるよう準備する。 | 距離指定は入力値として保持され、取得と印には影響しない。再度距離単位を編集すると指定が現れる。 |
| リセットは下書きとエラーだけを既定に戻す | 非既定の全条件と範囲エラーがある編集状態でリセットする。 | 全条件が既定となり、両単位の得点範囲、構成、距離指定とエラーが消える。適用済み条件・一覧・印・記憶は変わらず、取得しない。 |
| リセットした条件を検索すると既定条件を確定する | 非既定の取得条件からリセット済みの下書きを検索する。 | 既定条件が確定し（縦長は閉じ、横長は開いたまま）、先頭から取得し、印が消える。 |
| 検索せず閉じて開き直すと下書きとエラーを持ち越さない | 編集・エラーのある状態で閉じて再表示する。 | 適用済み条件から編集を始め、未適用の文字とエラーが残らず、取得・記憶は変わらない。 |
| 取得状態が変わっても編集中の文字とエラーを保つ | 編集中に保留した取得を成功・失敗へ進める。 | 入力中の文字・選択・エラーと開いた状態を保ち、応答が編集を確定・破棄しない。 |
| 不正な範囲を検索すると該当欄にエラーを示して編集を続ける | 開始日が終了日より後、最低点が最高点より大きい、負数、小数、文字や途中の`-`・`e`を個別に入力し検索する。 | 原因に応じた欄の近くにエラーがあり、入力文字を保ち、パネルは閉じず、一覧・印・適用済み条件・記憶が変わらず、取得しない。 |
| エラーを表示した入力を修正しても次の検索までエラーを保つ | エラー済みの値を修正してblurする。Enterの場合は別ケースにする。 | 次の検索までエラーが更新されず、適用・保存・取得・閉鎖が起きない。 |
| 修正した条件を検索するとエラーを解消して確定する | 範囲エラーがあり、有効な値への修正済み状態で検索する。 | 正しい値だけが確定し、縦長はパネルが閉じ、横長は開いたまま、条件の差分に従って一覧を取得する。 |
| 入力中のEnterで暗黙に検索しない | 有効な変更のあるテキスト入力でEnterを押す。 | 一覧・記憶・印が変わらず、パネルが閉じず、エラー検証も起こらない。 |

範囲の詳細な妥当性は既存の純粋関数テストで保証し、UIでは各原因から該当欄への接続を確認する。
期間は未指定・片側・同日・順序逆転、点数は空・0・正の整数・上下同値・逆転・負数・小数・不正文字を下層で確認する。
設計で定義された不正な日付の経路は純粋関数で確認し、ブラウザが受理しない日付文字列をUIから無理に入力しない。
フォーム化の回帰として、リセットによる意図しないブラウザ標準の巻き戻し、検索によるページ遷移・再読み込みがないこともブラウザで確認する。

## 閉じるボタンと展開中の漏斗

閉じるボタンの有無・名前・押した結果は、振る舞いとして確認する。
位置(先頭の行の右端の閉じるボタン、下部のリセット・検索の並び)は配置のためE2Eの期待値にせず、コンポーネントテストでは下部の行の要素の並び順(リセット、検索の順)で確かめ、見た目の位置と、リセット・検索が幅を半分ずつ占めること(等分)は配置のため、E2Eで幅を測らず、手動確認に割り当てる。
展開中の漏斗の背景は固定のクラスや色の値を期待値にせず、コンポーネントテストでは開閉の状態(`open`)に応じて漏斗の見た目の出力が変わることと、閉じた状態と同じに戻ることを、同じ部品の閉じた描画との比較で確かめる。
実際の色合いと適用中の印との見分けやすさは手動確認で行う。
ホバーの濃さは、格納中のホバー、展開中の背景、展開中のホバーの順に濃くなる。
展開中のホバーが展開中の背景と異なる濃さになることは、`hover:`が実ポインターのホバーに依存し固定のスタイル値になるため、コンポーネント・E2Eでは検証せず、手動確認で行う。
格納中ホバーと展開中の背景が同じ濃さであること、閉じた後にポインターを乗せたままホバーの色が残ることは受け入れる事項で、抑える仕組みを持たないため検証しない。
`aria-expanded`の真偽と経路ごとの戻りはコンポーネントテストで確かめ、背景の変化はコンポーネントテストの出力の比較と手動確認で確かめる。

| テスト名の案 | 前提と操作 | 期待結果 | 層 |
| --- | --- | --- | --- |
| 開くと先頭の行に名前「閉じる」のボタンがあり、下部の行にリセット・検索がある | 縦長・横長の各向きでフィルターを開く。 | 名前「閉じる」のボタンが先頭の行に1つだけあり、type=buttonの通常のボタンで、下部の行の並びはリセット、検索の順である(幅の等分は期待値にしない)。検索・リセットは閉じるボタンを押してもsubmit・resetされない。 | コンポーネント |
| 閉じるボタンを押すと未適用の変更とエラーを破棄して閉じ、漏斗へフォーカスが戻る | 適用済み条件と別の未適用の変更と範囲エラーを作り、閉じるボタンを押す(縦長・横長を別ケースにする)。 | パネルが閉じ、フォーカスがヘッダーの漏斗に戻る。一覧・適用中の印・取得条件・記憶は変わらず、取得しない。開き直すと適用済み条件から始まり、未適用の値とエラーは残らない。 | コンポーネント |

| 閉じている間は閉じるボタンが見えず、Tabで届かない | 初期の閉じた状態、開いて閉じた後(格納の完了後)を観測する。 | 閉じるボタンは`inert`・`aria-hidden`を持つ。開くと持たない。 | コンポーネント |

## 一覧・取得・保存とE2E

取得境界には固定の条件・カーソルと制御可能な応答を用い、内部の呼び出し順序や購読回数を固定しない。
取得しない契約に限って境界の要求記録を操作前後で比較する。
条件Aの先頭または続きの取得を保留し、条件Bを適用後にAを解決しても、Bの一覧へAが混入しないことを単体テストで確認する。
条件変更は同期を起こさず、ホーム表示・入力の開始・再開に影響しない既存の境界契約を維持する。
失敗済みの取得からの再試行は成功ケースと分け、再試行が下書きを確定・破棄せず、適用済み条件を使うことを確認する。

末尾に近づくと続きが取得され、重複表示がなく、終端なら止まることは、既存のE2E(`history.spec.ts`のページ送り)で確かめる。
パネル開閉だけでスクロールが先頭へ初期化されないことは、先頭以外の識別可能なカードが見えている状態から確認する。
領域変更で末尾が近づいたことによる正当な追加取得と、条件変更による先頭の再取得を区別する。
詳細から戻る経路では離れる前の一覧・スクロールが復元され、パネルだけが閉じて始まることを確認する。取得の回数と、ブラウザの戻る・進むの往復はE2Eでは数えず、取得しない契約は取得境界の要求記録を使う単体で確かめる。
適用済み条件は再読み込み・詳細往復・他画面への移動で保持し、未適用の文字・エラー・開いた状態は保持しない。
タブ別・利用者別の保存分離と保存不能時の扱いは既存の記憶境界テストを実行し、今回のパネルで同じ組合せを重ねない。

主要E2Eは次の2経路に絞る。

- サーバー反映済みの完了ラウンドと入力中ラウンドを用意し、点数一覧でパネルを開き、期間・種別等の条件を検索して目的の完了ラウンドを見つけ、カードを押して詳細のURLへ遷移し、一覧へ戻る。
  各段階で画面と状態を確認し、入力中の混入がなく、戻ると条件と一覧を保持してパネルが閉じていることを確認する。
- 構成の異なる完了ラウンドに共通の距離を用意し、距離単位と距離指定・小計条件を検索して、構成をまたいだ目的の距離を見つけ、該当ラウンドの詳細のURLへ遷移する。
  総合計による誤判定を検出できる点数とし、適用した距離・小計の表示を確認する。

既存の同等E2Eは新パネル操作へ更新して再利用し、全入力境界・回転・取得状態の総当たりは上位層で繰り返さない。
リンクはhrefの検査だけにせず、カードを押してURLと遷移先画面の両方を確認する。

## 手動での表示確認

ビルドを含む`pnpm preview`（port 3000）で確認し、既存プロセスは停止しない。
縦長の例は360×800・375×667、横長の例は800×360・1024×768とし、小さい高さとナビゲーションを開いた状態も含める。
縦横比の境界は実際のmedia queryと照合し、同じ幅でも高さによって上側・右側が変わることを確認する。
以下の寸法は設計との比較対象であり、合意にない許容差や新しい数値目標は設けない。

| 条件 | 確認内容 |
| --- | --- |
| 縦長での開閉 | ヘッダー直下から上側に展開し、上へ格納する。ヘッダーは覆われず、下部の行でリセット・検索が幅を半分ずつ占め、先頭の行の右端に✖の閉じるボタンがあり、押すと閉じる。ヘッダーのフィルターアイコンの再クリックでも閉じる。一覧はパネルの高さの分だけ押し下げられ、覆われない。パネルの下端は角丸なしで、枠線と下向きの影が点数キーボードの縦長と同様に付く。ヘッダーのアイコンは図柄が漏斗のままで、開いている間は背景がやや灰色になり、閉じると戻る。初期は閉じている。 |
| 横長での開閉 | 本文右側に展開し右へ格納する。ヘッダーと漏斗・印を覆わず、右パネルの先頭の行の右端に✖の閉じるボタンがあり、下部の行でリセット・検索が幅を半分ずつ占める。枠線だけで、角丸・影はない。ヘッダーのアイコンは漏斗のまま、開いている間は背景がやや灰色で、横長で検索して開いたままのときも続く。 |
| 領域確保と動き | 展開・格納の領域確保とスライドの量・所要時間を、設計書（design.md）の値と比較する。両者が連動し、一覧領域が残り、点数キーボードに沿う操作感である。 |
| 長い条件と短い画面 | 入力と一覧が独立してスクロールし、先頭の行と下部のリセット・検索は残り、入力欄がスクロールしても常に見えて押せ、全入力に到達できる。横あふれや文字の欠けがなく、必要なら並べ替え選択が折り返す。800×360でレフトパネルを開いた状態でも、リセット・検索の文言が欠けず、各行があふれない。 |

## データ・実行・完了条件

単体はGiven・When・Thenを分け、1つの前提と操作による結果を検証する。
UIはIntlTestProviderで描画し、探索と期待値には翻訳ヘルパーを使う。
「リセット」など指定文言そのものを直接検証するケースだけは文字列を使い、テスト名で目的を明示する。
内部部品は原則実物にし、外部状態・時刻・通信・画面制御には既存の共有偽物を利用する。
任意秒数のsleepや実タイムアウトに頼らず、制御したPromise、画面状態、アニメーション完了の観測で同期する。
格納競合の検証では時間やイベントを制御し、古い終了通知が再表示後に届く順序を明示する。
テスト失敗時は操作、向き、一覧状態、期待した入力・取得条件・フォーカス先と実測値が分かるようにする。

データは固定した日付・名前・点数とし、屋外は各距離12エンド×3射か6エンド×6射、屋内は10エンド×3射か5エンド×6射で揃える。
データ量を理由に成立しない短縮ラウンドを作らず、入力境界そのものを検証する不正値だけを例外とする。
E2Eは独立したローカル環境だけを用い、本番秘密情報・共有DB・他worktreeへの操作・DBリセットを行わない。
環境が用意できない場合は、実行した単体と、未実行のE2E・手動項目を分けて報告する。

後続担当は本書の対象テスト、関連する既存の条件・記憶・ページ送り・戻り・キーボードの回帰テスト、主要E2E、表示確認、lint・typecheckを実施する。
要件正本の書式移行に伴う対象テストの範囲はdocs/features/README.mdに従い、履歴以外の責務へ広げない。
合否はカバレッジ率の数値で決めず、適用・破棄・保持、フォーカス内外・子、回転の両方向、取得の非発火、格納中の再表示が未検証でないかを確認する。
未実行・環境制約・既存失敗を成功に含めず記録し、本書の作成自体ではテスト実装・実行・ビルド・画面操作は行わない。

## 点数カードの表示項目

基準は[要件](requirements.md)の「点数カードの表示項目」と[設計](design.md)の「点数カード」「カードの項目の取得」である。

行の高さ・幅・文字の大きさ・位置・列数は、`agents/testing.md`の規則によりE2Eの期待値にせず、単体・コンポーネントでも固定の見た目の値を期待値にしない。これらは目視で確認する。

### 要素の出し分け(`selectCardColumns`)のケース

幅と文字の幅は引数で与える純粋な関数である。正常系から異常系の順にする。

| テスト名の案 | 前提と操作 | 期待結果 |
| --- | --- | --- |
| 十分な幅では全ての要素を出す | 全ての要素が入る幅で、ラウンド単位と距離単位を個別に呼ぶ。 | 合計点(小計)、日付、距離一覧(距離)、ラウンド名、種別、弓種が全て出る。距離一覧のセル数はラウンド単位が4、距離単位が1である。 |
| 幅が足りないときは優先順位の低い要素から出なくなる | 優先順位の各境界で、1つ上の要素までが入り、次の要素が入らない幅で呼ぶ。 | ラウンド単位は合計点、日付、距離一覧、ラウンド名、種別、弓種の順に、距離単位は小計、日付、距離、ラウンド名、種別、弓種の順に、高い要素が先に出る。 |
| 入らない要素だけを出さず、より低い入る要素を出す | 距離一覧が入らず、種別だけが入る幅で呼ぶ。 | 距離一覧は出ず、種別が出る。 |
| ラウンド名は日付が出ているときだけ、最小幅に入るときに出す | 日付が入らない幅と、日付だけが入る幅で呼ぶ。 | 日付が入らなければラウンド名も出ない。ラウンド名の最小幅(全角4文字分)に足りなければ出ない。 |
| 弓種は種別が出ているときだけ出す | 種別が入らず、弓種だけが入る幅で呼ぶ。 | 弓種は出ない。 |
| 距離一覧のセル数は入る最大の数にする | ラウンド単位で、4・3・2セルが入る幅と、2セルも入らない幅を個別に呼ぶ。 | セル数は4、3、2になり、2セルも入らなければ0(出さない)。 |
| 距離一覧のセル数は、4セルが入る幅を大きく超える幅でも4のままである | ラウンド単位で、`selectCardColumns`の引数`available`(使える幅。画面の幅ではない)に、4セルが必要とする幅の2倍の値を渡す。他の引数は4セルが入る幅のときと同じにする。 | セル数は4で、5以上にならない。上限(`CELL_COUNTS`の先頭)が外れる変更を検出する。 |
| セル数は、ラウンド名・種別・弓種の内容に左右されない | 内容(タグの文字の幅、ラウンド名の有無)だけを変えて、同じ幅で呼ぶ。 | セル数は同じである。 |
| ラウンド名が空・距離が0件のときは、その要素を出さない | 内容の有無を変えて呼ぶ。 | ラウンド名の要素、距離一覧は出ず、他の要素の選択は変わらない。 |
| どの要素も入らない幅では何も出さない | 合計点も入らない幅で呼ぶ。 | 何も出ない。 |

### コンポーネントのケース

測定値は、テスト側で`clientWidth`などの寸法をスタブして与える(`use-card-fit.test.tsx`と同じ方式)。本番コードに測定値を差し込む口は置かない。表示された内容と有無だけを確かめる。1テストは1つの前提と操作の結果に限る。

| テスト名の案 | 前提と操作 | 期待結果 |
| --- | --- | --- |
| 距離が列の数以下なら全て表示する | 列の数が4になる寸法のスタブで、4距離のラウンドを描く。 | 4つの距離と小計が表示され、「+N」がない。 |
| 距離が列の数を超えるときは(列の数-1)個と「+N」を表示する | 列の数が4・3・2になる寸法のスタブで、距離が超えるラウンドを個別に描く。 | 先頭から(列の数-1)個の距離と小計が表示され、残りは「+(総数-表示した数)」になる。 |
| フィールドの行はMarked/Unmarkedを距離に添える | 種別がフィールドで、Marked・Unmarked(距離あり)・Unmarked(距離なし)の距離を描く。 | 「Marked」「Unmarked」が省略されずに表示され、距離なしの無印は距離を表示しない。 |

| 距離単位の行は日付・ラウンド名・種別・弓種・距離・小計を表示し、n/Nを表示しない | 距離単位の項目を描く。 | 各項目が表示され、距離のまとまりに番号と総数の表示がない。 |
| 距離単位の行はメニューを持たず、ラウンド単位の行はメニューを持つ | 両方を描く。 | 距離単位に削除のメニューがなく、ラウンド単位にはある。 |

既存の`rounds-home.test.tsx`・`rounds-history.test.tsx`の「合計点」「実施日」「履歴の距離」「小計」の期待値は、新しい表示へ更新して再利用し、重複して追加しない。
合計点の数字を`getByText`で探すテストは、1距離のラウンドで合計点と小計が同じ数字になり複数に一致するため、要素を絞って探す。

### DBのケース

既存の`rounds_list.sql`・`distances_list.sql`の「返す項目」のケースを新しい項目に合わせて更新する。追加の行列テストは変えない。

- `rounds_list`の返す項目に`format`・`bow_type`・`distances`が加わり、`distances_list`の返す項目に`format`・`bow_type`が加わる。画面に出さない項目(作成時刻、各射の点、距離の番号)は返らない。
- ラウンドごとに、`distances`の`total`の和が`total`と一致する。
- `distances`は射つ順((position_key, id))に並ぶ。
- 無効な距離と無効な矢は、`distances`にも小計にも含まれない。
- 矢が無い距離の小計は0である。
- 距離が0件のラウンドの`distances`は空配列である。
- 変更の前後で`total`・並び・件数・続きの有無が変わらない(既存のケースを維持する)。
- データは屋外の形(各距離12エンド×3射か6エンド×6射)を基本とし、屋内の1ケースを含める。

### E2Eのケース

既存の主要経路の期待値の更新に限る。

- ホームのE2E(`home.spec.ts`): 実行する画面の幅で距離ごとの小計が出ることを前提に、入力中のラウンドの行に、記録した点から求めた合計点と距離ごとの小計、種別・弓種が表示され、行を押すと詳細のURLへ遷移する。
- 点数一覧のE2E(`history.spec.ts`): 完了したラウンドの行に、サーバーから返る種別・弓種・距離ごとの小計・合計点が表示され、距離単位に切り替えると距離・小計が表示される。行を押すと詳細のURLへ遷移する。
- 合計点と小計は、複数距離で値が異なるデータにし、総合計との取り違えを検出できるようにする。
- E2Eは、ホームと点数一覧でできること(行の表示内容の確認、距離単位への切り替え、行を押して詳細へ遷移すること)だけを確かめる。遷移先の詳細の中身は確かめない。
- 幅によって要素の有無が変わるため、E2Eの確認は実行する画面の幅で表示される要素だけに限り、特定の幅での列の有無は期待値にしない。
