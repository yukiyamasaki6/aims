# 点数一覧のフィルターパネルのテスト設計

## 基準と範囲

基準は[履歴の要件](requirements.md)と[設計](design.md)だけである。
本書は実装やテストコードの内容から期待値を導かない。
外側は非モーダルのパネルとし、外側タップでは保持、Escはフォーカスと最前面の操作に従う契約を採用する。

優先順位は、意図しない適用・編集消失の防止、一覧と入力の操作到達性、指定された配置と開閉の動きの順とする。
対象は外側フィルターの置換と、操作行右端の閉じるボタン、展開中の漏斗の見た目と、それに接続する編集・取得・保存・フォーカス・一覧スクロールの回帰である。
検索の意味、RPC、同期、保存形式、点数キーボードの仕様は変更対象外であり、既存の下層テストを再利用する。
新しいDBテストや全条件のE2E総当たりは追加しない。

## テスト層と観測

| 層 | 保証する内容 | 観測方法 |
| --- | --- | --- |
| 単体・コンポーネント（Vitest） | 下書き・エラー・確定と破棄、操作名と開閉状態、条件に応じた表示 | 公開UIの入力、role、名前、状態と確定結果を確認する。 |
| 結合（Vitest） | 実物のパネル・フォーム・一覧と、条件導出・取得・記憶の接続 | 所有する部品を実物でつなぎ、取得・記憶など境界の外側を制御する。 |
| ブラウザ結合（Playwright） | Portal、実際のTab・Esc・フォーカス、向き変更、格納中の操作、一覧スクロール | 実ブラウザの操作結果を観測する。認証・取得を制御した場合はE2Eと区別する。 |
| E2E（Playwright） | 条件を検索して完了ラウンド・距離を探し、詳細から戻る主要経路 | 実ブラウザ・認証・独立したローカルDBを通す。 |
| 手動表示確認 | 上側・右側の配置、寸法、並び、折り返し、展開と格納の見え方 | ビルド済みpreviewで設計と変更前の画像を比較する。 |

配置候補は`apps/web/src/features/rounds/ui/rounds-history.test.tsx`と`apps/web/tests/e2e/rounds/history.spec.ts`である。
部品単独で保証できるケースは点数一覧専用部品のテストへ置いてよく、ファイル名や内部ツリーを契約にしない。
既存の`history-filter-draft.test.ts`、`history-view-state.test.ts`、`use-history-view.test.ts`、`use-history-pages.test.tsx`、`history-navigation.test.tsx`、`browser-history-view-memory.test.ts`などは担当する契約の安全網として再利用する。
テスト内容の確認と不足分の選別は後続担当が行い、同等ケースがあれば更新して重複追加しない。
private処理、描画回数、Effect回数、固定のCSSクラス、SVGのpath、DOM全体のスナップショットは期待値にしない。

## 編集・確定・破棄のケース

次の表はテスト名の案と条件・操作・期待結果であり、要求との対応表ではない。
異なる操作は別テストにし、各ケースは正常系から異常系の順に実装する。

| テスト名の案 | 前提と操作 | 期待結果 |
| --- | --- | --- |
| フィルターを開くと適用済みの全条件から編集を始める | 既定と非既定の適用済み条件をそれぞれ用意して開く。 | 日付順・得点順、期間、得点範囲、種別・弓種、構成、単位、保持中の距離指定が復元される。開くだけでは一覧・取得条件・記憶は変わらない。 |
| 条件を編集しても適用前の一覧と印を保つ | 適用済みの一覧で各条件を編集する。 | 下書きの表示だけが変わり、一覧、適用中の印、取得条件、保存済み条件は変わらない。 |
| 有効な変更を検索すると新しい条件の先頭を表示する | 複数ページ表示済みの一覧で有効な取得条件の変更を検索する。 | 条件が確定・記憶され、縦長ではパネルが閉じ、横長では開いたまま入力値が残り、旧表示はスケルトンになり、新条件の先頭ページが表示される。旧ページは連結されない。 |
| 条件を変えずに検索すると一覧を維持する | 適用済みと同じ値で検索する。 | 縦長ではパネルが閉じ、横長では開いたままで、表示済みのページを維持し、新たな履歴取得を起こさない。 |
| ラウンド単位で非表示の距離だけを変更して検索すると取得しない | 距離単位で距離を選び、ラウンド単位へ戻して検索する。導出条件が元と同じになるよう準備する。 | 距離指定は入力値として保持され、取得と印には影響しない。再度距離単位を編集すると指定が現れる。 |
| リセットは下書きとエラーだけを既定に戻す | 非既定の全条件と範囲エラーがある編集状態でリセットする。 | 全条件が既定となり、構成と距離指定とエラーが消える。適用済み条件・一覧・印・記憶は変わらず、取得しない。 |
| リセットした条件を検索すると既定条件を確定する | 非既定の取得条件からリセット済みの下書きを検索する。 | 既定条件が確定し（縦長は閉じ、横長は開いたまま）、先頭から取得し、印が消える。 |
| 検索せず閉じて開き直すと下書きとエラーを持ち越さない | 編集・エラーのある状態で閉じて再表示する。 | 適用済み条件から編集を始め、未適用の文字とエラーが残らず、取得・記憶は変わらない。 |
| 取得状態が変わっても編集中の文字とエラーを保つ | 編集中に保留した取得を成功・失敗へ進める。 | 入力中の文字・選択・エラーと開いた状態を保ち、応答が編集を確定・破棄しない。 |
| 不正な範囲を検索すると該当欄にエラーを示して編集を続ける | 開始日が終了日より後、最低点が最高点より大きい、負数、小数、文字や途中の`-`・`e`を個別に入力し検索する。 | 原因に応じた欄の近くにエラーがあり、入力文字を保ち、パネルは閉じず、一覧・印・適用済み条件・記憶が変わらず、取得しない。 |
| エラーを表示した入力を修正しても次の検索までエラーを保つ | エラー済みの値を修正してblurする。Enterの場合は別ケースにする。 | 次の検索までエラーが更新されず、適用・保存・取得・閉鎖が起きない。 |
| 修正した条件を検索するとエラーを解消して確定する | 範囲エラーがあり、有効な値への修正済み状態で検索する。 | 正しい値だけが確定し、縦長はパネルが閉じ、横長は開いたまま、条件の差分に従って一覧を取得する。 |
| 入力中のEnterで暗黙に検索しない | 有効な変更のあるテキスト入力でEnterを押す。 | 一覧・記憶・印が変わらず、パネルが閉じず、エラー検証も起こらない。 |

範囲の詳細な妥当性は既存の純粋関数テストで保証し、UIでは各原因から該当欄への接続を確認する。
期間は未指定・片側・同日・順序逆転、点数は空・0・正の整数・上下同値・逆転・負数・小数・不正文字を下層で確認する。
設計で定義された不正な日付の経路は純粋関数で確認し、ブラウザが受理しない日付文字列をUIから無理に入力しない。
フォーム化の回帰として、リセットによる意図しないブラウザ標準の巻き戻し、検索によるページ遷移・再読み込みがないこともブラウザで確認する。

## 子ダイアログと継承する条件操作

| テスト名の案 | 前提と操作 | 期待結果 |
| --- | --- | --- |
| 距離の確定は外側の下書きだけを変更する | 構成の追加・編集・削除、距離単位の決定・編集・削除を個別に行う。 | 要約または選択ボタンが下書きに対応し、外側が閉じず、一覧・取得・記憶は変わらない。子のボタンが外側をsubmitしない。 |
| 距離の編集を中止しても外側の編集を保つ | 他条件を変更後、子に未確定の入力を作りEscまたは子の外側タップで閉じる。 | 子の入力だけが破棄され、確定済み要約と他の下書きは変わらない。外側タップで閉じるのは子だけである。 |
| 的を選ぶと距離の編集中の値だけに反映する | 距離の子から的の孫を開き、的または「指定なし」を選ぶ。 | 的が距離の入力に反映され、距離の確定前は要約に、外側の適用前は一覧に反映されない。 |
| 距離の不正は子の確定時にだけ示す | 距離が空・0・101・小数、矢数が0・13・小数を入力して子の確定を押す。 | 子が閉じず、該当欄にエラーが出て、要約と一覧は変わらない。修正中は次の確定までエラーを保つ。 |
| 各条件を組み合わせて検索しても意味が変わらない | 日付順・得点順、期間、得点、種別・弓種、構成を組み合わせて検索する。 | 適用した入力値と導出条件が既存契約に一致する。単位を距離にすると得点は小計、日付等は親ラウンドを対象にする。 |

距離1・100とその外側0・101、矢数1・12とその外側0・13、矢数空の許容は下層の境界テストにまとめる。
構成の順序・重複・行数、任意項目、両端を含む範囲、同点時の並び、無効行の扱いなど既存の検索規則は既存テストを維持し、パネルで全組合せを重ねない。
距離単位をオフにしても距離指定を保持し、オンに戻したとき再表示できること、構成を空に戻せることはフォームの接続として確認する。

## 閉じるボタンと展開中の漏斗

閉じるボタンの有無・名前・押した結果は、振る舞いとして確認する。
位置(操作行の右端、左端のリセット・検索との並び)は配置のためE2Eの期待値にせず、コンポーネントテストでは操作行内の要素の並び順(リセット、検索、閉じるの順)で確かめ、見た目の位置と、リセット・検索が閉じるボタンを除いた幅を半分ずつ占めること(等分)は配置のため、E2Eやブラウザ結合で幅を測らず、手動確認に割り当てる。
展開中の漏斗の背景は固定のクラスや色の値を期待値にせず、コンポーネントテストでは開閉の状態(`open`)に応じて漏斗の見た目の出力が変わることと、閉じた状態と同じに戻ることを、同じ部品の閉じた描画との比較で確かめる。
実際の色合いと適用中の印との見分けやすさは手動確認で行う。
ホバーの濃さは、格納中のホバー、展開中の背景、展開中のホバーの順に濃くなる。
展開中のホバーが展開中の背景と異なる濃さになることは、`hover:`が実ポインターのホバーに依存し固定のスタイル値になるため、コンポーネント・ブラウザ結合・E2Eでは検証せず、手動確認で行う。
格納中ホバーと展開中の背景が同じ濃さであること、閉じた後にポインターを乗せたままホバーの色が残ることは受け入れる事項で、抑える仕組みを持たないため検証しない。
ブラウザ結合の期待値は`aria-expanded`の真偽と経路ごとの戻りに限り、背景の変化はコンポーネントテストの出力の比較と手動確認で確かめる。

| テスト名の案 | 前提と操作 | 期待結果 | 層 |
| --- | --- | --- | --- |
| 開くと操作行に名前「閉じる」のボタンがあり、リセット・検索の後ろに並ぶ | 縦長・横長の各向きでフィルターを開く。 | 名前「閉じる」のボタンが操作行に1つだけあり、フォーム外の通常のボタンで、操作行の並びはリセット、検索、閉じるの順である(幅の等分は期待値にしない)。検索・リセットは閉じるボタンを押してもsubmit・resetされない。 | コンポーネント、ブラウザ結合 |

| 条件が多くスクロールが必要でも閉じるボタンに到達できる | 縦長・横長の小さい高さで、入力欄をスクロールした状態にする。 | 入力欄をスクロールしても閉じるボタンが隠れず、中心点の最前面の要素が閉じるボタン自身で、押すと閉じる。位置・寸法の値は期待値にしない。 | ブラウザ結合 |
| 閉じている間は閉じるボタンが見えず、Tabで届かない | 初期の閉じた状態、開いて閉じた後(格納の完了後)で、Tab・Shift+Tabで移動する。 | 閉じるボタンは操作・探索の対象外(`inert`・`aria-hidden`)で、フォーカスが入らず、クリックもできない。開くと対象になる。 | ブラウザ結合 |
| 閉じるボタンは目的を支援技術に伝える | 開いた状態で名前付きregion「フィルター」の中を探す。 | 名前「閉じる」のボタンがregion内にあり、図柄(✖)は名前を持たない。 | コンポーネント |

| 開くと漏斗の見た目が開いている状態に変わり、閉じると元に戻る | 縦長・横長の各向きで、閉じた状態の漏斗の見た目を記録し、開く。続けて、漏斗の再押下、閉じるボタン、Esc、縦長の検索を別々の前提から実行して閉じる。 | コンポーネント: 開いている間は漏斗の見た目の出力が閉じた状態と異なり、閉じると閉じた状態と同じに戻る。ブラウザ結合: `aria-expanded`が開いている間は真で、どの経路で閉じても偽に戻る(背景は期待値にしない)。図柄(漏斗)と名前「フィルター」は開閉で変わらない。 | コンポーネント(見た目の出力の比較)、ブラウザ結合(`aria-expanded`の経路ごとの戻り) |
| 横長で検索して開いたままのときは展開中の見た目が続く | 横長で有効な変更を検索する。 | パネルが開いたままで、漏斗の見た目は開いている状態のままで、`aria-expanded`も真のままである。 | ブラウザ結合 |

縦長・横長の見た目の位置、漏斗の灰色の濃さ、印との見分けやすさは次節の手動確認で行う。

## ブラウザでの操作・フォーカス・回転

以下は両向きに共通する契約を代表向きで確認し、操作行は1つで向き別に複製しないため、検索・リセット・閉じるボタンのTab・Enterでの到達と、閉じる操作の各経路(ヘッダーのフィルター、閉じるボタン、Esc、縦長の検索)は両向きで確認する。
回転は実viewportを変更し、縦長→横長と横長→縦長をそれぞれ検証する。
向きは幅の固定ブレークポイントではなく`(orientation: landscape)`で決まり、縦横が同じ場合と、その両側のviewportでも配置切替後の操作と状態保持を確認する。

| テスト名の案 | 前提と操作 | 期待結果 |
| --- | --- | --- |
| 開いたフィルターと一覧へキーボードで移動できる | フィルターを開き、Tab・Shift+Tabで操作する。 | 最初の条件入力にフォーカスが移り、一覧へも移動でき、外側のフォーカストラップや背後の不活性化がない。 |
| パネルの開閉と操作目的を支援技術に伝える | 初期、開く、閉じるを観測する。 | 初期は閉じ、開くと名前付きregion「フィルター」があり、ヘッダーボタンのexpandedとcontrolsが対応する。検索・リセット・閉じるボタンは1組だけが探索・操作可能である。 |
| 明示的な終了でヘッダーのフィルターへ戻る | ヘッダーのフィルター（縦長・横長）、閉じるボタン（縦長・横長）、縦長の検索を別々に実行する。 | パネルが閉じてヘッダーのボタンにフォーカスが戻る。閉じる操作では未適用の変更・エラーが破棄される。 |
| 横長では検索しても閉じず、編集を続けられる | 横長で有効な変更を検索し、続けて別の値へ編集して再度検索する。不正な値でも検索する。 | パネルが開いたままで入力値が残り、適用済み条件と一覧・印が更新される。再編集と再検索ができる。不正な値は従来どおりエラーを示し、検索せず開いたままである。検索後にEscを押すと、その後の未適用の変更を破棄して閉じ、再表示は直近に適用した条件で始まる。 |
| 横長で検索した後もフォーカスが「検索」に残る | 横長で有効な変更を検索し、続けてTabとEnterで再度検索する。縦長でも検索する。 | 横長ではフォーカスが押した「検索」に残り、漏斗へ戻らず、Tab・Enterで再検索できる。縦長は検索で閉じ、フォーカスが漏斗へ戻る。 |
| 向きを変えてから検索すると変えた後の向きの挙動になる | パネルを開き、縦長から横長へ、横長から縦長へ、それぞれ向きを変えてから検索する。 | 向きは検索を押した時点で読まれる。縦長から横長へ変えた後の検索は閉じず、フォーカスは「検索」に残る。横長から縦長へ変えた後の検索は閉じ、フォーカスが漏斗へ戻る。向きを変えただけではフォーカスも開閉も変わらない。 |
| パネル内のEscで未適用の変更を破棄する | 子がない状態で入力欄にフォーカスしてEscを押す。別に、ヘッダーの操作群にフォーカスしてEscを押す。 | 入力欄の場合は外側が閉じ、ヘッダーのフィルターの操作へ戻り、再表示は適用済み条件で始まる。ヘッダーの操作群の場合は閉じず、編集中の条件とエラーを保つ。 |
| 一覧とメニューのEscはフィルターを閉じない | 下書きとエラーを持つ状態で一覧の操作へフォーカスを移しEscを押す。メニュー操作は別ケースにする。 | 外側と下書き・エラーを保ち、メニューがある場合はその既存のEsc動作が優先される。 |
| 子のEscは最前面だけを閉じる | 距離のみ、距離と的、Selectが開いている各状態でEscを押す。 | 的→距離→外側の順に一段だけ閉じる。Selectなら選択肢だけが閉じ、外側の下書き・エラーは残る。PortalのEscが外側まで閉じない。 |
| 子からフォーカスを戻して編集を続けられる | 子を確定・中止して閉じる操作を個別に実行する。 | 起点の要約・追加・選択へ戻る。削除で要約が消えた場合は残る追加・選択操作に戻り、bodyや非表示要素に残らない。 |
| 外側タップと一覧スクロールで編集を失わない | 編集・エラーがある状態で一覧の余白をタップし、一覧をスクロールする。スクロール後に、ヘッダーのフィルター操作（漏斗）の中心点を`elementFromPoint`で調べ、漏斗を押して閉じ、もう一度押して開く。 | 外側、下書き、エラーを維持し、一覧だけをスクロールできる。スクロール後も漏斗が見えて、押せる（中心点の要素が漏斗自身）。押すと閉じ、もう一度押すと開く。位置・寸法の値は期待値にしない。 |
| パネルを開いたまま一覧項目から詳細へ移動できる | 未適用の変更・エラーを作り、表示中のカードを押す。 | 対象の詳細URLと画面が表示され、画面遷移時は旧ヘッダーへフォーカスを戻さない。戻ると外側は閉じ、未適用の値・エラーは残らない。 |
| 再読み込みで未適用の変更を破棄する | 適用済みの条件と別に、未適用の変更・エラーを作り、再読み込みする。 | 適用済みの条件は保たれ、パネルは閉じ、開くと未適用の値・エラーは残らない。 |
| 他の画面への移動で未適用の変更を破棄する | 未適用の変更・エラーを作り、レフトパネルなどから他の画面へ移動、またはブラウザの戻るで離れ、点数一覧へ戻る。 | 適用済みの条件は保たれ、パネルは閉じ、開くと未適用の値・エラーは残らない。 |
| 取得の各状態でも条件を操作できる | 保存済み条件の読み込み後に、先頭取得保留・失敗・空・オフライン・成功を各々成立させて開く。 | 条件の編集、検索・リセットへ到達でき、一覧は状態に対応する表示を保つ。保存条件の読み込み前・Suspense待機中は操作を出さない。 |
| 回転しても開いた状態と全条件の下書き・エラーを保つ | 全種類の条件を編集し、範囲エラーと入力途中の文字を持つ状態で回転する。 | 配置だけが切り替わり、値・エラー・開閉状態を保つ。適用・保存・取得は起きない。 |
| 子ダイアログの入力とエラーは回転で消えない | 距離入力中・距離エラー表示中・的の選択中を別々に用意して回転する。 | 最前面の子と未確定の距離・矢数・的の入力を保ち、元の編集を続けられる。 |
| 回転でフォーカスを失わない | 入力欄、子、操作行の各操作にフォーカスして回転する。 | 操作行は1つで複製がないため、入力欄・子・操作行のいずれでも回転してもフォーカスは動かない。 |
| Selectを開いたまま別の条件を操作できる | 種別のSelectを開いて弓種を押す。スイッチ・入力欄の場合は別ケースにする。 | 押下が吸収されず、対象の選択・切替・入力を続けられ、外側の下書きは失われない。 |
| 格納開始時から入力を操作できない | 閉じる直後、アニメーション中にTab移動・クリック・入力を試す。 | 閉じた入力と操作行(閉じるボタンを含む)は操作・Tab・アクセシビリティツリーの対象外で、再適用や古い下書きの変更が起きない。 |
| 格納途中に再表示しても古い編集を復活させない | 編集後に閉じ、格納終了前に開き直して新しい値を編集し、その後古い終了通知を完了させる。 | 適用済み値から新しく編集でき、古い入力や通知によって新しい編集が閉鎖・消去・適用されない。 |
| 動きを減らす設定でも閉じて次の編集を始められる | reduced motionで閉じ、開き直す。 | 即時に操作対象外となり、古い編集が片付き、新しい編集と検索を妨げない。transition終了イベントが来ない場合も同じ結果になる。 |

preventDefault済みのEscが外側を閉じない分岐は、必要に応じてコンポーネントテストで対象領域へ処理済みイベントを送り確認する。
Portal・inert・実フォーカス・CSSによる非表示はjsdomの結果だけで保証せず、ブラウザで確認する。
条件のスクロール後にも各操作が見えて押せることを確認し、重なりの有無は対象中心の`elementFromPoint`で確かめる。
位置・寸法・スタイル値をブラウザ結合やE2Eの期待値にせず、次節の表示確認に割り当てる。

## 一覧・取得・保存との結合とE2E

取得境界には固定の条件・カーソルと制御可能な応答を用い、内部の呼び出し順序や購読回数を固定しない。
取得しない契約に限って境界の要求記録を操作前後で比較する。
条件Aの先頭または続きの取得を保留し、条件Bを適用後にAを解決しても、Bの一覧へAが混入しないことを結合テストで確認する。
条件変更は同期を起こさず、ホーム表示・入力の開始・再開に影響しない既存の境界契約を維持する。
失敗済みの取得からの再試行は成功ケースと分け、再試行が下書きを確定・破棄せず、適用済み条件を使うことを確認する。

一覧の開閉・回転後も末尾に近づくと続きが取得され、重複表示がなく、終端なら止まることをブラウザ結合で確認する。
パネル開閉だけでスクロールが先頭へ初期化されないことは、先頭以外の識別可能なカードが見えている状態から確認する。
領域変更で末尾が近づいたことによる正当な追加取得と、条件変更による先頭の再取得を区別する。
詳細から戻る経路では離れる前の一覧・スクロールが復元され、先頭を取得し直さず、パネルだけが閉じて始まることを確認する。
適用済み条件は再読み込み・詳細往復・他画面への移動で保持し、未適用の文字・エラー・開いた状態は保持しない。
タブ別・利用者別の保存分離と保存不能時の扱いは既存の記憶境界テストを実行し、今回のパネルで同じ組合せを重ねない。

主要E2Eは次の2経路に絞る。

- サーバー反映済みの完了ラウンドと入力中ラウンドを用意し、点数一覧でパネルを開き、期間・種別等の条件を検索して目的の完了ラウンドを見つけ、カードから詳細を開いて戻る。
  各段階で画面と状態を確認し、入力中の混入がなく、戻ると条件と一覧を保持してパネルが閉じていることを確認する。
- 構成の異なる完了ラウンドに共通の距離を用意し、距離単位と距離指定・小計条件を検索して、構成をまたいだ目的の距離を見つけ、該当ラウンドの詳細を開く。
  総合計による誤判定を検出できる点数とし、適用した距離・小計の表示を確認する。

既存の同等E2Eは新パネル操作へ更新して再利用し、全入力境界・回転・取得状態の総当たりは上位層で繰り返さない。
リンクはhrefの検査だけにせず、カードを押してURLと遷移先画面の両方を確認する。

## 手動での表示確認

ビルドを含む`pnpm preview`（port 3000）で確認し、既存プロセスは停止しない。
縦長の例は360×800・375×667、横長の例は800×360・1024×768とし、小さい高さとナビゲーションを開いた状態も含める。
縦横比の境界は実際のmedia queryと照合し、同じ幅でも高さによって上側・右側が変わることを確認する。
以下の寸法は設計との比較対象であり、合意にない許容差や新しい数値目標は設けない。

| 条件 | 確認内容 |
| --- | --- |
| 縦長での開閉 | ヘッダー直下から上側に展開し、上へ格納する。ヘッダーは覆われず、リセット・検索が✖を除いた幅を半分ずつ占め、右端に✖の閉じるボタンがあり、押すと閉じる。ヘッダーのフィルターアイコンの再クリックでも閉じる。一覧はパネルの高さの分だけ押し下げられ、覆われない。パネルの下端は角丸なしで、枠線と下向きの影が点数キーボードの縦長と同様に付く。ヘッダーのアイコンは図柄が漏斗のままで、開いている間は背景がやや灰色になり、閉じると戻る。初期は閉じている。 |
| 横長での開閉 | 本文右側に展開し右へ格納する。ヘッダーと漏斗・印を覆わず、右パネル上部で、リセット・検索が✖を除いた幅を半分ずつ占め、右端に✖の閉じるボタンが並ぶ。枠線だけで、角丸・影はない。ヘッダーのアイコンは漏斗のまま、開いている間は背景がやや灰色で、横長で検索して開いたままのときも続く。 |
| 領域確保と動き | 展開・格納の領域確保とスライドの量・所要時間を、設計書（design.md）の値と比較する。両者が連動し、一覧領域が残り、点数キーボードに沿う操作感である。 |
| 長い条件と短い画面 | 入力と一覧が独立してスクロールし、操作行は残り、全入力に到達できる。横あふれや文字の欠けがなく、必要なら並べ替え選択が折り返す。800×360でレフトパネルを開いた状態でも、リセット・検索の文言が欠けず、操作行があふれない。 |
| ヘッダーと操作行 | タイトルが収まり、ヘッダーの高さ・フィルター位置・フォーカス輪を維持する。閉じるボタンがヘッダーの高さ・位置に影響しない。800×360でレフトパネルを開いた状態でも、操作行のリセット・検索・✖が欠けず収まる。 |
| 展開中の漏斗と適用中の印 | 既定でない条件で開き、漏斗の背景が灰色で、右上の印(濃い点と縁取り)が背景から切り離して見え、両方を判別できる。閉じた漏斗にホバーして押すと、押した前後で背景が変わらない。開いたままホバーを乗せると展開中の背景より濃くなり、離すと戻る。閉じると背景だけが戻る(閉じた後にポインターを乗せたままホバーの色が残ることは受け入れ、確認しない)。縦長・横長で同じである。 |
| 文言・印・要約 | 表示は「リセット」「閉じる」、外側の名前「フィルター」は読み上げ用で、条件順・距離要約・適用中の印は設計どおりである。 |
| 子と回転 | 距離・的のダイアログとSelectが適切な前後関係で表示され、回転後も入力と操作が画面に収まる。 |
| 他画面 | ホーム、点数入力の縦横キーボード、詳細の表示と基本操作を変更前と比較し、共通枠の回帰がない。 |

変更前の同じ画面条件の画像を可能なら残し、比較したviewport・状態・結果を後続報告に記載する。
画像がない場合は比較不能の範囲を明記し、確認済みとしない。

## データ・実行・完了条件

単体はGiven・When・Thenを分け、1つの前提と操作による結果を検証する。
UIはIntlTestProviderで描画し、探索と期待値には翻訳ヘルパーを使う。
「リセット」など指定文言そのものを直接検証するケースだけは文字列を使い、テスト名で目的を明示する。
内部部品は原則実物にし、外部状態・時刻・通信・画面制御には既存の共有偽物を利用する。
任意秒数のsleepや実タイムアウトに頼らず、制御したPromise、画面状態、アニメーション完了の観測で同期する。
格納競合の検証では時間やイベントを制御し、古い終了通知が再表示後に届く順序を明示する。
テスト失敗時は操作、向き、一覧状態、期待した入力・取得条件・フォーカス先と実測値が分かるようにする。

データは固定した日付・名前・点数とし、屋外は各距離12エンド×3射か6エンド×6射、屋内は10エンド×3射か5エンド×6射で揃える。
データ量を理由に成立しない短縮ラウンドを作らず、入力境界そのものを検証する不正値だけを例外とする。
E2Eは独立したローカル環境だけを用い、本番秘密情報・共有DB・他worktreeへの操作・DBリセットを行わない。
環境が用意できない場合は、実行した単体・結合と、未実行のE2E・手動項目を分けて報告する。

後続担当は本書の対象テスト、関連する既存の条件・記憶・ページ送り・戻り・キーボードの回帰テスト、主要E2E、表示確認、lint・typecheckを実施する。
要件正本の書式移行に伴う対象テストの範囲はdocs/features/README.mdに従い、履歴以外の責務へ広げない。
合否はカバレッジ率の数値で決めず、適用・破棄・保持、フォーカス内外・子、回転の両方向、取得の非発火、格納中の再表示が未検証でないかを確認する。
未実行・環境制約・既存失敗を成功に含めず記録し、本書の作成自体ではテスト実装・実行・ビルド・画面操作は行わない。
