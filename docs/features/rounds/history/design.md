# rounds/history 設計

## 概要

`/rounds`で、ユーザーが属するラウンドを実施日の新しい順に一覧する。
各カードに名前・実施日・合計点を出し、カードから`/rounds/[id]`へ、右下の新規作成ボタンから`/rounds/new`へ遷移する。
一覧は読み取り中心の画面で、書き込みはカードのメニューからの削除だけである。
削除は`rounds/delete`が扱う。
取得はクライアントで行い、枠（見出し、新規作成ボタン）は静的である。取得中・未接続・エラーは枠内に表示する。

## 画面と状態

| 状態 | 表示 | 判定 | 要求 |
| :--- | :--- | :--- | :--- |
| 一覧あり | ラウンドカードを`round_date`降順に並べる | 取得結果が1件以上 | history-01, 03, 05 |
| 一覧なし | 「まだラウンドがありません。」 | 取得が成功し、結果が0件 | - |
| 取得中 | スケルトン | 取得が完了するまで。静的な枠のHTMLもこの状態 | - |
| 未接続 | 「未接続」と再試行ボタン | 通信できない | history-06 |
| エラー | エラーメッセージと再試行ボタン | 取得がエラー。未認証は「サインインが必要です。」 | history-07 |

- 新規作成ボタンは、全状態で常に表示する（history-02）。
- 未認証のアクセスは`proxy.ts`が`/signin`へ送る。この挙動は一覧の要求に含めない。

## 構成とデータの流れ

- `rounds/page.tsx`（Server Component）: 枠（見出し）を描画する。取得せず、`cookies()`も読まない。
- `rounds/fetch-rounds-list.ts`: ラウンド・距離・矢を1回で取得し、合計点を求めて`RoundListItem[]`にする。
- `rounds/rounds-list-client.tsx`（Client Component）: 取得結果に応じて、カード・削除メニュー、または取得中・未接続・エラーの表示を描画する。新規作成ボタンは全状態で描画する。削除成功時にカードをstateから除く。

取得は`fetchContent`（`features/fetch-result`）経由で、`.retry(false)`を付ける。`rounds`から`distances(disabled_at, shots(score_int, disabled_at))`までのネストで1回行う。
- 対象は`rounds.disabled_at is null`で、並びは`round_date`の降順である。同じ実施日の並びは定めない。
- 合計点は、無効でない距離の、無効でない矢の`score_int`の総和を、クライアントで計算する。
- 取得できる行は、RLSの`select_if_member`により、ユーザーが`round_users`で属するラウンドに限る。
- 一覧はRPCを介さず、直接SELECTする。
- 一覧はIndexedDBの未同期イベントを読まない。合計点は、サーバーに同期済みの射影だけを反映する。

## 設計判断

| 判断 | 理由 | 見直す条件 |
| :--- | :--- | :--- |
| 合計点を、ネスト取得の結果からクライアントで計算する | 一覧の取得を1回に収めるため。合計点の列や集計ビューは持たない | ラウンド数が増え、取得量が問題になるとき |
| 論理削除された行を、ラウンド・距離・矢の3段階で一覧と合計点から除く | 削除を`disabled_at`で射影しており、無効化後の後続イベントも通常表示へ戻さないため | 削除の方式を変えるとき |
| 一覧の取得は、RPCでなくRLSの直接SELECTのまま残す | 書き込みをRPCへ統一する際も、SELECTポリシーは維持する方針のため | 読み取りも認可RPCへ統一するとき |
| 枠は静的にし、取得はクライアントから行う（枠をSWが返す前提。詳細は#648） | 静的な枠を即座に返し、取得の失敗を枠内で区別して示すため | 一覧をサーバーで取得する必要が生じたとき |
| 新規作成ボタンを右下に固定し、常時表示する | 一覧から作成画面へ辿る導線を常に示すため | 作成の導線を別へ移すとき |
| 新規作成ボタンに`data-hydrated`を付ける | ハードナビゲーション直後の操作が、ハイドレーション前に空振りするのをE2Eが待てるようにするため | ハイドレーション完了の通知を共通化するとき |

## 制約と未対応

- 全件を1回で取得し、ページングや上限はない。
- 再試行ボタンのみで、オンライン復帰時の自動再取得は#647で扱う。
- 未同期のローカルイベントを反映しないため、記録直後の合計点がサーバーの同期前は古い。
