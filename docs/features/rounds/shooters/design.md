# rounds/shooters 設計

## 概要

各ラウンドの射手を、参加者の表`round_users`の行として持ち、ラウンド内の番号(`shooter_number`)で区別する。
矢と矢の変更履歴は、射手を番号で指す。
番号は記録する人が選び、DBは採番しない。
射手を選ぶ画面は持たず、画面が射手を決めて指定する。

## 構成とデータの流れ

パスは`apps/web/src/features/rounds/`からの相対である。

| ファイル | 責務 |
| :--- | :--- |
| `domain/sync-events.ts` | 矢の記録の操作は射手番号を必ず持つ。射手の追加の操作`shooter.added`は番号を持つ |
| `domain/score-history.ts` | 取り消しの列が、前後の矢の状態とともに射手番号を持つ |
| `domain/shot-operations.ts` | 画面が指定する射手の決定と、矢の記録・射手の追加の操作の組み立て |
| `domain/round-tables.ts`、`scorecard-types.ts` | 射手の一覧と、各マス(取り消し済みを含む)の射手番号を持つ |
| `domain/round-op-apply.ts` | 指定された射手を書く。射手の追加は、同じ番号が無いときだけ一覧へ足し、既にある行は変えない |
| `domain/round-op-conflicts.ts`、`op-plan.ts` | 同じ番号の射手の追加が確定するまで、その番号の矢の記録を送らない |
| `domain/round-base.ts`、`round-retention.ts` | 射手の追加の反映の判定と、ベースの新旧の判定(`rounds/sync`) |
| `domain/round-view.ts`、`ui/use-shot-input.ts` | 取り消し済みを含むマスの射手を入力へ渡し、記録・戻る・進むの操作に射手を指定する |
| `infrastructure/round-op-transport.ts` | 射手番号を`record_shots`へ、射手の追加を`add_round_shooter`へ送る |
| `infrastructure/round-queries.ts` | 射手の一覧と矢の射手番号を数値で取得する |
| `supabase/migrations/`の追加migration | 射手の表の定義、制約、RPC、匿名化の内部関数 |

### データ

`round_users`の1行は、参加の権限(`role`。`rounds/roles`)と射手(`shooter_number`)を持つ。
有効な行は次の3種類で、CHECK制約が保つ。

| 行 | `user_id` | `role` | `shooter_number` |
| :--- | :--- | :--- | :--- |
| 射つ人 | あり | `owner` | あり |
| 代理の人 | あり | `editor` | なし |
| 利用者に紐づかない射手 | なし | なし | あり |

同じラウンドで、利用者も番号も1行だけである。
利用者に紐づかない射手は、アカウントの無い人として加えた行と、匿名化した行を区別しない。
`shots`と`shot_events`は`round_id`と`shooter_number`を持ち、`(round_id, shooter_number)`の外部キーで同じラウンドの射手を指す。
番号は1〜2147483647で、DB、RPC、端末の保存のいずれでも数値として扱う。
列と制約の一覧は`docs/erd.md`に置く。
一度付いた番号の変更とNULL化、射手の行のラウンドの変更は、更新のトリガーが拒否する。
`user_id`の変更は拒否しない。

### 画面が指定する射手

- 一度も記録していないマスは、操作する射つ人の射手番号を指定する。
- 記録済みと取り消し済みのマス(直す、消してから記録する、戻る・進む)は、そのマスの射手番号を指定する。

### DBの契約

関数は`SECURITY DEFINER`で所有者は`postgres`、`search_path`を固定する。

- `record_shots`: 各要素の`shooter_number`は必須で、省略を補わない。対象ラウンドは距離から決める。ラウンドに無い番号と、利用者が射つ人でない行の番号は`PT403`で拒否する。射手の自動の追加、紐づけ、採番はしない。指定された番号を、距離の`round_id`とともに`shots`と`shot_events`へ保存する。
- `record_shots`の判定の順: 入力の形(`PT422`)、距離があるときの認可(`PT403`)、距離の有無(`MISSING`)、同じ`event_id`の再送(記録した結果を返し、射手を変えない)、ラウンドと距離の削除(`DISABLED`)、射手、構成と点数(`UNFIT`)。効いた記録の`applied_fields`は`score`と`shooter_number`である。
- `clear_shots`: 射手番号を変えず、取り消しの履歴にも同じ番号を保存する。行の無いマスに射手を作らない。
- `add_round_shooter(p_round_id uuid, p_shooter_number jsonb DEFAULT NULL)`: 射つ人と代理の人が実行できる。番号が無ければ利用者と役割がNULLの行を足し、あれば何も変えない。どちらも`{revision: null, applied: true, reason: null}`を返す。
- `add_round_shooter`の判定の順: 入力の形(`PT422`)、操作者とラウンドのロック、ラウンドの有無(`applied: false`、`MISSING`)、認可(`PT403`)、削除済み(`applied: false`、`DISABLED`)、番号の有無、追加。
- 射手番号の検査: 値が無い、JSONの数値でない、1未満、2147483647超、整数でないものは`PT422`である。数値は`numeric`で検査してから`integer`へ変換する(`2.0`と`2e0`は受理する)。
- `anonymize_round_shooter(round_id, user_id)`: 1つのラウンドで、番号を持つその利用者の行の`user_id`と`role`をNULLにする内部関数で、番号と行のIDを変えない。アカウントの削除は対象の各ラウンドにこの関数を使う(`auth/delete-account`)。
- 実行権限: `add_round_shooter`は`PUBLIC`・`anon`から剥奪して`authenticated`へ付与する。`anonymize_round_shooter`と番号の検査のトリガー関数は、`PUBLIC`・`anon`・`authenticated`から剥奪する。

### 同期

矢の記録は点数と射手を1つの操作で保存し、同じマスは射手を含めて後に保存された内容になる(`rounds/sync`)。
番号は端末で操作を作る時点で決まり、サーバーで変わらないため、未送信の操作と取り消しの列の射手を付け替える処理は無い。

## 設計判断

| 判断 | 理由 | 見直す条件 |
| :--- | :--- | :--- |
| 射手を参加者の表の行にし、射手だけの表を持たない | 参加と射手を1行で表し、2つの表の整合の検査が要らないため。矢と履歴から一覧を導く案は、矢の無い射手を持てないため採らない | 1人の利用者が1つのラウンドで複数の射手を持つとき |
| 矢は射手を番号で指す | 外部キーだけで同じラウンドの射手の存在を検査でき、端末が選んだ番号がそのまま使えるため。行のIDで指す案は、番号とIDの対応付けが要るため採らない | 番号を後から振り直す要求が出たとき |
| 矢の記録で射手を必須にし、DBが補わない | 誰の記録でも指定した射手の矢にするため | 射手を指定しない入力の要求が出たとき |
| 古い端末の射手の指定を補正も拒否もしない | 同じマスは後に保存した内容にする同期の規則に合わせるため | 射手の付け替えを古い操作から守る要求が出たとき |
| アカウント削除の匿名化を、ラウンド単位で射手を匿名化する1つの内部関数にする(利用者が指定した制約) | ラウンドから外れる操作などでも同じ匿名化を使えるようにするため | 匿名化の結果を操作ごとに変えるとき |
| 番号の引数と要素を`jsonb`の値で検査する | 型の変換の失敗より先に`PT422`で拒否し、送信器が破棄して再送し続けないようにするため | RPCの入力の検査の方式を変えるとき |

## 制約と未対応

- 射手・番号・名前を選ぶ画面と表示は無い。射手の追加は、操作の組み立て・保存・送信の口だけを持つ。
- 作った人以外を番号へ結び付ける操作と、番号に結び付く利用者を変える操作は無い。データは利用者の変更を表せ、変更後は過去の矢も変更後の利用者の矢になる。変える操作を作るときは、射つ人が番号を失わないように前の利用者の扱いを決める。
- 代理の人が画面で一度も記録していないマスへ書く場合の射手の指定は持たない(代理の人を加える操作と代理記録の画面は無い)。
- 射手を一覧から削除する操作は無い。射手の行はラウンドの物理削除でだけ消える。
