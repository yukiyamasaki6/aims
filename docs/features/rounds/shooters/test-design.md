# rounds/shooters テスト設計

## 基準と範囲

基準は[shootersの要件](requirements.md)・[設計](design.md)と[ERD](../../../erd.md)である。
実装やマイグレーションの内容から期待値を導かない。
役割・認可・閲覧・ロックは[rolesのテスト設計](../roles/test-design.md)、射手の追加の送信と反映は[syncのテスト設計](../sync/test-design.md)、匿名化と復元は[delete-accountのテスト設計](../../auth/delete-account/test-design.md)で扱う。
射手・番号を選ぶ画面と、番号に結び付く利用者を変える操作は無いため、画面の操作としては確かめない。
代理の人が一度も記録していないマスへ画面で書く場合の射手は定まっていないため、期待値を置かない。

優先順位は、矢が別の射手のものになることの防止、射手と矢の整合、不正な指定の拒否の順とする。

## テスト層と観測

| 層 | 保証する内容 | 観測方法 |
| --- | --- | --- |
| 単体(Vitest、domain) | 画面が指定する射手、操作の組み立て、取り消しの列、楽観適用、端末の状態の導出 | 公開の関数の入力と戻り値。 |
| コンポーネント(Vitest、ui) | 認証中の利用者と各マスの射手が、画面の操作で積む操作に届くこと | 公開の操作と、操作の列へ追記された内容。 |
| DB(pgTAP) | 制約、`record_shots`・`clear_shots`・`add_round_shooter`の契約、履歴、利用者の変更 | 実DBの行と応答。 |
| PostgREST結合(Playwright) | JSONの番号が関数に届き、受理と`PT422`の拒否がHTTPの応答になること | 公開APIの呼び出し。 |
| E2E(Playwright) | 画面の記録が射手を保って実DBへ保存され、再読み込み後も続くこと | 実ブラウザ・実DB。射手番号はDBから読んで確かめる。 |

## 検証データ

- 参加の行は、射つ人(利用者、`owner`、番号)、代理の人(利用者、`editor`、番号なし)、利用者に紐づかない射手(番号だけ)の3種類だけで作り、どのラウンドにも射つ人を1人以上置く。
- 射つ人の複数人、代理の人、番号に結び付く利用者の変更は、作る操作が無いためDBへ直接用意する。
- 利用者の変更は、変更先の利用者がそのラウンドに行を持たない状態から、射手の行の`user_id`を変える(射つ人と番号は保つ)。
- 操作する射つ人の番号を確かめるテストでは、番号が1でない射つ人を使い、1の固定と区別する。
- 距離は屋外の形にする。

## 単体(domain)

ケースは正常系から異常系の順に書く。
ここでは射手だけを確かめる。
点数と指すマスは[score-entryのテスト設計](../score-entry/test-design.md)、行の上書きと生き返りは[syncのテスト設計](../sync/test-design.md)に置く。
前提と操作がscore-entryのケースと同じ場合は、1つのテストに射手の期待を足し、別のテストを重ねない。

| テスト名の案 | 前提と操作 | 期待結果 |
| --- | --- | --- |
| 一度も記録していないマスは、操作する射つ人の射手番号を指定する | 射手1(別の射つ人)、射手2(紐づかない)、射手3(操作する射つ人)の表で空のマスの射手を求める。 | 3になる。 |
| 記録済みのマスは、そのマスの射手を指定する | 紐づかない射手のマスと、別の射つ人のマス。 | 各マスの番号になる。 |
| 取り消し済みのマスは、そのマスの射手を指定する | 端末で取り消した矢と、取得した取り消し済みの矢。 | 取り消し前の番号になる。 |
| 矢の記録の操作は射手番号を持ち、クリアの操作は持たない | 記録とクリアの操作を組み立てる。 | 記録は指定した番号を持つ。 |
| 一つ戻ると、直しとクリアの前の射手を指定する | 紐づかない射手のマスの直しとクリアを積んで戻す。 | 戻す記録の射手が書く前の射手である。 |
| 一つ進むと、やり直す書き込みの射手を指定する | 戻した直しを進める。 | 進む記録の射手がやり直す書き込みの射手である。 |
| 空のマスへの記録を戻して進むと、同じ射手を指定する | 記録を戻して進める。 | 進む記録の射手が元の射手である。 |
| マスの射手が後で変わっても、戻る・進むは取り消しの列の射手を指定する | 列を積んだ後、表のマスの射手を別の番号にして戻す。 | 列の射手の記録になる。 |
| 射手の追加の操作は、ラウンドと選んだ番号を持つ | 番号を指定して組み立てる。 | `shooter.added`がラウンド、番号、操作のIDを持つ。 |
| 確定済みの記録は、点数と射手を重ねる | 効いた項目が点数と射手の確定済みの操作を重ねる。 | 両方が反映される。 |
| クリアの重ね合わせは射手を変えない | 紐づかない射手の矢をクリアする。 | 行は取り消し済みで射手は同じである。 |
| 射手の追加は、同じ番号が無いときだけ一覧へ足す | 無い番号を重ね、同じ操作をもう一度重ねる。 | 利用者と役割の無い射手が1つだけ増える。欠けた番号は補わない。 |
| 既にある番号の追加は、行を変えない | 利用者に紐づく射手の番号と、紐づかない射手の番号を追加する。 | 利用者と役割を含めて変わらない。 |
| 射手の追加に続くその番号の記録は、一覧と矢に反映される | 追加と記録を順に重ねる。 | 射手が一覧にあり、矢がその番号になる。 |
| 取得から作る端末の記録は、番号を持つ行を射手の一覧にする | 射つ人、代理の人、矢の無い紐づかない射手を含む取得結果。 | 射つ人と紐づかない射手が数値の番号で一覧に入り、代理の人は射手にならない。 |
| 取得した取り消し済みの矢は、射手を保ち、画面には空のマスとして扱う | 取り消し済みの矢を含む取得結果から画面の状態を導く。 | マスは空で、小計と合計に含まれない。マスの射手は入力へ渡る。 |
| 取得した取り消し済みの矢は、生きた矢の判定に含まれない | 同じ表で、最初の空のマス、満杯、構成の変更の可否、ホームの一覧の合計を求める。 | 取り消し済みのマスは空として扱われ、構成の変更を妨げない。 |
| 未送信の作成のラウンドは、認証中の利用者を射手1の射つ人として持つ | 開始の操作だけの記録から状態を導き、空のマスの射手を求める。 | 射手の一覧が射手1の射つ人だけで、空のマスは1になる。 |

## DB(pgTAP)

新しい`supabase/tests/shooters.sql`に置く。
同じマスの上書き・生き返り(射手の置き換えと効いた属性を含む)・構成の範囲は[syncのテスト設計](../sync/test-design.md)の`shot_identity.sql`に置き、重ねない。
拒否のケースは、期待するエラーに加え、行と履歴が増減しないことを確かめる。
射つ人の遅延の制約は[rolesのテスト設計](../roles/test-design.md)に従う。

### 参加と射手の行、矢の参照

| テスト名の案 | 前提と操作 | 期待結果 |
| --- | --- | --- |
| 参加の行は3種類の組合せだけを保存できる | 役割(`owner`、`editor`、`viewer`、NULL)、利用者(あり、NULL)、番号(あり、NULL)の全ての組合せをINSERTする期待値表。 | 射つ人・代理の人・紐づかない射手の3組だけが成功し、他は`23514`。 |
| 番号は1以上で、削除済みの利用者は結び付けられない | 番号0・-1と、利用者に「削除済みの利用者」を指定する。 | `23514`。 |
| 有効な行を無効な形へ更新できない | 射つ人の番号のNULL化・利用者のNULL化、代理の人への番号の追加。 | 拒否される。 |
| 同じラウンドの利用者と番号は1行だけで、別のラウンドでは同じ番号を使える | 同じ利用者、同じ番号の2行目と、別のラウンドの同じ番号。 | 前の2つは`23505`、後は成功する。 |
| 一度付いた番号と射手の行のラウンドは変えられない | `shooter_number`と`round_id`をUPDATEする。 | 拒否され、行は変わらない。 |
| 矢と矢の履歴は、同じラウンドの射手と距離だけを参照できる | `shots`と`shot_events`へ、無い番号、他ラウンドだけの番号、`round_id`と距離のラウンドの不一致を直接INSERTする。 | `23503`。 |
| 矢と矢の履歴は、ラウンドと射手番号の無い行を持てない | `round_id`と`shooter_number`をNULLにする。 | `23502`。 |
| 矢が参照する射手の行は削除できない | 矢または履歴のある紐づかない射手の行を削除する。 | `23503`。 |
| 利用者の削除は参加の行を連鎖で消さない | 参加の行が残る利用者を直接削除する。 | `23503`で拒否され、行が残る。 |
| ラウンドの物理削除は、履歴を先に消すと距離・矢・射手が残らない | 履歴を消した後にラウンドを削除する。 | 対象の行だけが消える。 |

`migrations_final_state.sql`は、`shooter_id`の列が無いこと、`shots`と`shot_events`の距離の外部キーが`(round_id, distance_id)`の1本だけであること、射手の外部キーと索引、`round_users.user_id`の外部キーが連鎖しないことを確かめる。

### `record_shots`・`clear_shots`の射手

| テスト名の案 | 前提と操作 | 期待結果 |
| --- | --- | --- |
| 射つ人の記録は、指定した射手の矢と履歴を保存する | 自分、別の射つ人、紐づかない射手の番号で記録する。 | 矢と履歴が指定した番号と距離のラウンドを持つ。 |
| 代理の人の記録は、指定した射手の矢になる | 代理の人が射つ人の番号で記録する。 | 射手は指定した番号、操作者は代理の人である。 |
| 付け替えた射手を元へ戻しても、履歴は各記録の射手を保つ | 同じマスへ番号を1、2、1の順に記録する。 | 現在の矢は1で、履歴は順に1、2、1を持つ。 |
| 同じ番号は、ラウンドごとの射手を指す | 番号2を持つ2つのラウンドへ記録する。 | 各矢が自分のラウンドを参照する。 |
| 記録は射手の行を増やさず変えない | 記録の前後で参加の行を比べる。 | 同じである。 |
| クリアは射手を変えず、取り消しの履歴に同じ番号を残す | 紐づかない射手の矢をクリアする。 | 矢と`CLEARED`の履歴が同じ番号である。 |
| 記録の無いマスのクリアは射手を作らない | 空のマスをクリアする。 | `MISSING`で、参加の行も履歴も増えない。 |
| 同じ`event_id`の再送は、番号が違っても射手を変えない | 記録後、同じ`event_id`で別の番号を送る。 | 記録した結果が返り、矢と履歴は変わらない。 |
| 削除済みのラウンド・距離への記録は、射手の検査より先に`DISABLED`になる | 削除済みの対象へ、無い番号で記録する。 | `DISABLED`。 |
| ラウンドに無い番号は`PT403`で拒否する | 無い番号と、他ラウンドだけにある番号。構成の範囲外のマスも組み合わせる。 | `UNFIT`より先に`PT403`となり、射手も矢も増えない。 |
| 拒否する要素を含む要求は、全体を保存しない | 有効な要素と、無い番号の要素を1要求にする。 | `PT403`で、有効な要素も保存されない。 |

利用者が射つ人でない番号の行は制約が作らせないため、記録の拒否のケースは置かない。

### 射手の番号の検査

`record_shots`の要素と`add_round_shooter`の引数に、同じ値の期待値表を適用する。

| テスト名の案 | 前提と操作 | 期待結果 |
| --- | --- | --- |
| 整数として1〜2147483647のJSON数値を受理する | 1、2、2147483647、`2.0`、`2e0`。記録は対象の番号の射手を用意する。 | 成功し、整数の番号で保存する。 |
| それ以外の値は`PT422`で拒否する | キー・引数の省略、SQL NULL(引数)、JSON null、`"2"`、`"abc"`、真偽値、配列、object、0、-1、1.5、2147483648、`bigint`を超える数。 | 全て`PT422`(型の変換の`22003`などにならない)で、行は増えない。 |
| 番号の形の拒否は、認可と存在の確認より先である | 非参加者、無い距離・ラウンドへ不正な番号を送る。 | `PT422`。 |
| 不正な番号を含む要求は、全体を保存しない | 有効な要素と不正な要素を1要求にする。 | `PT422`で何も保存しない。 |

### `add_round_shooter`

役割ごとの可否は`rpc_matrix.sql`に置く。

| テスト名の案 | 前提と操作 | 期待結果 |
| --- | --- | --- |
| 無い番号を追加すると、利用者と役割の無い射手が1行増える | 欠番のある番号(射手1だけのラウンドへ7)を追加する。 | `{revision:null,applied:true,reason:null}`。7だけが増え、2〜6は増えない。 |
| 既にある番号の追加は、何も変えず成功する | 射つ人の番号と、紐づかない射手の番号を追加する。 | 同じ応答で、行(利用者、役割、ID、更新時刻)が変わらない。 |
| 再送しても射手は1行である | 同じ呼び出しを2回行う。 | 両方成功し、1行。 |
| 別のラウンドの同じ番号は、別の射手である | 2つのラウンドへ同じ番号を追加する。 | 各ラウンドに1行。 |
| 追加した射手は矢の記録で指定でき、矢が無くても残る | 追加して記録・クリア・距離の削除を行う。 | 射手の行が残る。 |
| 無いラウンドは`MISSING`、削除済みのラウンドは`DISABLED`で適用しない | 各状態で呼ぶ。削除済みでは既にある番号も使う。 | `applied:false`と理由で、行は変わらない。 |
| 認可は存在の確認の後、削除の判定より先である | 非参加者が、無いラウンドと削除済みのラウンドへ呼ぶ。 | 順に`MISSING`、`PT403`。 |

### 番号に結び付く利用者の変更

| テスト名の案 | 前提と操作 | 期待結果 |
| --- | --- | --- |
| 射手1の利用者を変えると、過去の矢も変更後の利用者の矢になる | Aの矢と履歴を作り、射手1の`user_id`をBへ変える。 | 矢と履歴の番号と`author_id`は変わらず、番号1からたどる利用者はBである。 |
| 利用者を変えた番号の追加は、作った人へ戻さない | 変更後に番号1を追加する。 | 結び付きはBのままである。 |

## PostgREST結合

既定のPlaywright構成の`tests/e2e/rounds/sync.spec.ts`に置き、公開APIを呼ぶ。
JSONからSQLの引数への変換は実APIでしか確かめられないため、番号の値はpgTAPと重ねる。

| テスト名の案 | 前提と操作 | 期待結果 |
| --- | --- | --- |
| 射手の追加は、有効な番号を受理し、不正な番号をHTTP 422の`PT422`で拒否する | 上の値の表を`p_shooter_number`で送る。引数の省略を含み、`2.0`と`2e0`は生のJSONの本文で送る。 | 受理した番号の射手だけが増える。省略も関数が見つからない失敗にならず`PT422`。 |
| 矢の記録は、有効な射手番号を受理し、不正な番号をHTTP 422の`PT422`で拒否する | 上の値の表を`shooter_number`で送る。`2.0`と`2e0`は生のJSONの本文で送る。 | 受理した記録だけが保存される。 |

## E2E

射手を選ぶ画面は無いため、紐づかない射手とその矢は公開APIで用意する。

| テスト名の案 | 前提と操作 | 期待結果 |
| --- | --- | --- |
| 紐づかない射手のマスを直し、消して書き直し、戻して進めても、再読み込み後まで同じ射手の矢である(`score-entry.spec.ts`) | 射手2の矢があるラウンドを開いて操作する。空のマスにも1本書く。再読み込みしてから、消したマスへ書き直す。 | 点数は画面の操作どおりで、射手2のマスはDBで2のまま、空だったマスは1である。 |
| オフラインで開始したラウンドに記録すると、オンラインに戻った後、射手1の矢として保存される(`sync.spec.ts`の既存の経路へ確認を足す) | オフラインで開始して書き、復帰する。 | ラウンドと矢が保存され、射手は1で、再読み込み後も表示される。 |
