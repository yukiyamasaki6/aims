# 矢のマス目形式(同期・DB)のテスト設計

## 基準と範囲

基準は[syncの要件](requirements.md)・[設計](design.md)と[ERD](../../../erd.md)の「矢の記録」だけである。
実装やマイグレーションの内容から期待値を導かない。
画面と指すマスの規則は[score-entryのテスト設計](../score-entry/test-design.md)で扱う。
既存の同期の規則(ラウンド・距離の項目ごとの後勝ち、失敗の再送、サインイン、削除)は変更対象外であり、既存テストを維持する。
以前の版で端末に保存した内容と記録は、確認の対象にしない([app/offline-pwaの要件](../../app/offline-pwa/requirements.md))。

優先順位は、同じマスの後勝ちと別のマスが残ること、射数/エンドの上限、契約に合わない要素の安全な破棄の順とする。

## テスト層と観測

| 層 | 保証する内容 | 観測方法 |
| --- | --- | --- |
| 単体(Vitest、domain) | 操作の衝突、重ね合わせ`applyOperations`、送信の計画 | 純粋関数の入力と戻り値。 |
| 単体(Vitest、application・infrastructure) | RPCの要求の形、契約の不一致の拒否の扱い、端末の保存、取り直しに`overlay`が無いこと | 公開の窓口と送信部。外部は偽物で隔離する。 |
| DB(pgTAP) | RPCの契約、主キーと制約、履歴 | 実DBの行と応答。期待値表と実測を全件比較する行列テストを維持する。 |
| E2E(Playwright) | オフラインで同じマスを書き直す、他の端末と同じマス・別のマスへ書く経路 | 実ブラウザ・実DB。他端末は`helpers/other-device.ts`。 |

## 単体(domain)

| テスト名の案 | 前提と操作 | 期待結果 |
| --- | --- | --- |
| 矢の操作どうしは、同じマスなら衝突し、同じエンドの別のマス・別の距離の同じ番号は衝突しない | 記録とクリアの組を、マスの3つの一致・不一致で組み合わせる。 | 同じマスだけ衝突する。矢の操作と距離の削除・構成の変更の衝突は既存どおり。 |
| 衝突しない矢の操作は止まった先行を待たずに並行で送る計画になり、同じマスの操作は先行の確定まで送らない | 同じエンドの別のマスと同じマスの操作の列から計画を作る。 | 別のマスは同時に送り、同じマスは順番に送る。1要求は同じ距離の矢だけ、100件まで。 |
| 空のマスへの記録は、同じマスの行として足す。別のマスの記録は互いに残る | 同じエンドの別のマスを重ねる。 | 両方の行が残る。 |
| 同じマスへの記録は点数を置き換え、行の射手を保つ | 記録済みのマスへ重ねる。 | 位置は同じで点数だけが変わる。 |
| 取り消したマスへの記録は、行を生き返らせ、射手を引き継ぐ | 取り消し済みの行へ重ねる。射手を省いた記録。 | 行が生き、点数は新しく、射手は行の射手である。 |
| 行の無いマスへの記録で射手が無ければ、実行者を射手にする | 行の無いマスへ重ねる。 | 射手は実行者。 |
| クリアは同じマスの行を取り消し済みにし、別のマスは消さない。行が無い・取り消し済みのマスのクリアは何もしない | クリアを重ねる。 | 期待どおり。 |
| 未確定の操作は、構成に収まらない矢(範囲外のマスの番号・エンド、的に無い点数)を重ねない | 範囲の境界値と的に無い点数。 | 境界の内側は重なり、外側は重ならない。 |
| 確定済みの操作は、構成を判定せずに重ねる。重ねられずに取り直す印を返さない | 確定済みの記録を重ねる。構成が狭まった表も用意する。 | 確定済みは常に重なる。戻り値に`overlay`・取り直しの印が無い。 |
| 上限は範囲と同じマスの置き換えで守られ、生きている矢の数で判定しない | 範囲内のマスを全て埋めた表へ、別の記録を重ねる。 | 範囲内なら上書きされ、数を理由に重ならないことがない。範囲外は重ならない。 |
| 構成の変更は、表示中の矢が全て範囲内のマスにあり有効なときだけ効き、矢を値もマスも変えず引き継ぐ。取り消し済みの矢は判定に含めない | 範囲内外の矢と取り消し済みの矢。 | 範囲外の生きている矢があれば3項目とも効かず、同じ保存の他の項目は効く。 |
| 同じ操作の列を重ねても結果は変わらない。衝突しない操作の入れ替えで結果は変わらない | 冪等性と交換の既存の検証を、マス目形式で維持する。 | 結果が同じ。 |
| 同じマスの操作は適用順で最後が残る | 同じマスへ別の点数を2回、記録とクリアの順を入れ替えて重ねる。 | 後の操作の結果になる。 |

## 単体(application・infrastructure)

| テスト名の案 | 前提と操作 | 期待結果 |
| --- | --- | --- |
| 記録の要求は、マスの`end_number`・`shot_number`を送り、`shot_id`を送らない。クリアも同じ | 送信部へ矢の操作を渡し、偽のRPCの引数を見る。 | 要素にマスの3つがあり、`shot_id`が無い。同じ距離だけを1要求にまとめ、100件で分ける。 |
| 契約の不一致(`PT422`)で拒否された操作は、その操作だけ消え、後続と他の記録は送られる | `PT422`を返す偽のRPC。 | その操作だけ破棄され、利用者へ知らせる状態は出ず、他は送られる。 |
| 矢の取得の選択列に矢のIDを含めない | 取得の問い合わせを見る。 | 選択列が`id`を持たず、マスと点数・射手などで足りる。 |
| 端末の保存のversionを上げると、全てのstoreを内容を移行せずに作り直し、前の内容を返さない | 前のversionのDBを作って開く。 | 前の内容が無く、新しいstoreで読み書きできる。 |
| 版の更新が他の接続に塞がれている間は開く処理が終わらず、その接続を閉じると再開する | 閉じない接続を残したまま追記する。 | 閉じる前は終わらず、閉じた後に追記と読み出しができる。 |
| 追記は、サーバーに無い(`null`)ベースを受けると、操作だけを保存し、ベースの行を書かない | 保存済みのベースが無い列へ、`null`のベースを添えて追記する。 | 追記は成功し、操作は読み出せて、ベースは無い。 |
| 一覧・詳細の取得は、取り直しの契機に`overlay`・取り直しの印を使わない | 取り直しの制御と窓口の既存テストを維持する。 | 確定済みの記録を重ねる経路で取り直しが起きない。 |

## DB(pgTAP)

既存の`supabase/tests`の体系に置く。新しい形に合わせて書き換えるファイルは、末尾の一覧に示す。
ケースは正常系から異常系の順に書く。

### `record_shots`・`clear_shots`(`shot_identity.sql`を作り直す)

| テスト名の案 | 前提と操作 | 期待結果 |
| --- | --- | --- |
| 空のマスへの記録は、マスに行を作り、射手を省くと実行者を射手にし、効いた属性をscoreとshooter_idにする | 新しいマスへ記録する。 | 行が1つ、`applied_fields`と履歴の`set_fields`が`{score,shooter_id}`、履歴のマスと`revision`が1、`rejected_fields`は空。 |
| 記録済みのマスへの記録は行を置き換え、射手を省けば射手を変えず、指定すれば変える | 射手あり・なしで重ねる。 | 点数が最新になり、射手は期待どおり。履歴の`revision`がマスごとに進む。 |
| 取り消したマスへの記録は行を生き返らせ、射手を省くと行の射手を引き継ぐ | クリア後に記録する。 | 行が生き、射手は元の射手で、`disabled_at`がnullになる。 |
| 別の端末が先に確定したマスへ後から記録すると、後の記録が残り、2本の矢にならない | 同じマスへ別の`event_id`で2回記録する。 | 行は1つで点数は後の記録。履歴は2件。 |
| 同じエンドの別のマスは全て残り、生きている矢の数が射数/エンドを超えない | 射数/エンド分の全マスを埋め、さらに同じマスへ記録する。 | 行は射数/エンドの個数で、数を超えない。 |
| 範囲外のマスへの記録は効かない(`UNFIT`) | エンドが1・エンド数・エンド数+1、番号が1・射数/エンド・射数/エンド+1、的に無い点数の各境界。 | 内側は効き、外側と的に無い点数は`UNFIT`で何も記録しない。 |
| `shot_number`が無い・0・負・整数でない・`end_number`が無いときは契約の不一致(`PT422`) | 各入力。 | `PT422`で拒否し、行も履歴も増えない。 |
| `shot_id`で矢を指し`shot_number`が無い要素は`PT422`で拒否する | `shot_id`だけで指す要素。 | `PT422`。 |
| 同じ`event_id`の再送は冪等で、2回目は履歴も`revision`も増えない。確定済みの再送は効いた項目を返す | 同じ要素を2回送る。 | 応答は同じで増えない。 |
| 記録のメンバー・viewer・非メンバーの権限、削除済みの距離・ラウンドへの記録は既存の行列どおり | 行列の期待値表(`rpc_matrix.sql`)。 | マスの形で期待値表が更新される。 |
| クリアは記録済みのマスを取り消し済みにして履歴を足し、他のマスは変えない | クリアする。 | `disabled_at`が入り、他のマスは変わらない。 |
| 行が無いマスのクリアは`MISSING`、取り消し済みのマスのクリアは`DISABLED`で、記録しない | 各状態でクリアする。 | 履歴も`revision`も増えない。 |
| 別の利用者を射手にした矢を、射手を含まない記録が書き換えても射手は保たれる | 射手の異なる矢へ、射手を省いて記録する。 | 点数だけが変わり射手は残る。 |

### 距離の構成とスキーマ

| テスト名の案 | 前提と操作 | 期待結果 |
| --- | --- | --- |
| 構成の変更は、生きている矢が新しい範囲(エンド数・射数/エンド・的)に収まるなら3項目とも効き、矢はマスも値も変わらない | 収まる構成へ変更する。 | 効き、全ての矢が残る。 |
| 生きている矢が範囲外になるなら3項目とも効かず(`UNFIT`)、同じ保存の距離(m)などは効く | 範囲外になる構成へ変更する。 | 構成は元のまま、距離(m)は変わる。 |
| 取り消し済みの矢だけが範囲外なら、構成は効く | 取り消し済みの範囲外の矢。 | 効く。 |
| 矢の数の超過でなくマスの範囲で判定する | 射数/エンドを減らして、全マスが埋まった距離。 | 範囲外のマスの生きている矢があれば効かない。 |
| `shots`は主キーを`(distance_id, end_number, shot_number)`とし、`end_number`・`shot_number`はNOT NULL | カタログを見る。 | 主キーと列が設計どおり。 |
| `shot_events`はマスの3列がNOT NULLで、`(distance_id, end_number, shot_number, revision)`が一意 | カタログを見る。 | 設計どおり。同じマスで同じ`revision`は入れられない。 |
| RLSはメンバーだけが矢と履歴を読め、書き込み権限は付かない(`rls_matrix.sql`) | 行列の期待値表。 | 既存どおり。列が変わった表で全件比較する。 |
| ラウンド・距離のアカウント削除は、矢と履歴を`distance_id`で消す | `delete_account.sql`の矢の準備をマス形式で。 | 残る編集者がいないラウンドの矢と履歴が消え、他は残る。 |
| ラウンド一覧・距離一覧・履歴の小計と合計は、生きている矢だけの和である | `rounds_list.sql`・`distances_list.sql`ほか。 | 値が変わらない。 |

`migrations_final_state.sql`は、`shots`の主キー、マスの列のNOT NULL、`shot_events`の一意制約を確かめる。

## E2E

| テスト名の案 | 前提と操作 | 期待結果 |
| --- | --- | --- |
| オフラインで点数を記録してその矢を消し、同じマスへ別の点数を記録してラウンドの名前を保存すると、オンラインに戻った後、最後の点数だけが保存され、再読み込みしても最後の点数が表示される(既存の置き換え) | 既存の経路をマスの用語で維持する。 | 同じマスに最後の点数だけが残る。 |
| 他の端末が同じマスへ後から記録すると、後に保存された点数だけがそのマスに残り、どちらの端末でも2本の矢は表示されない | `other-device`で同じマスへ記録し、この端末でも記録する。 | 後の点数だけが残り、再読み込み後も同じ。 |
| 他の端末が同じエンドの別のマスへ記録した矢は、全て残り、どちらの端末でも表示される | 別のマスへ記録する。 | 両方が残る。 |
| 一つ戻るは、他の端末が同じエンドの別のマスへ記録した矢を消さない | 自分の記録を戻す。 | 他のマスは残る。 |
| 他の端末が消したマスを知らずに直すと、直した点数で再び表示され、直したマスを他の端末が後で消すと空になる | 他端末の操作を挟む。 | 期待どおり。 |

上記は既存のE2Eの規模を超えない。同じマスの順序や構成の判定の組合せは単体とpgTAPで確かめ、E2Eには足さない。
