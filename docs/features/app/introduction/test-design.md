# 紹介画面のテスト設計

## 基準と範囲

基準は、[introductionの要件](requirements.md)と[設計](design.md)である。
認証画面のロゴを押して紹介画面へ移ることは[auth/signin](../../auth/signin/test-design.md)の責務、認証済みの画面のロゴからの遷移は[app/navigation](../navigation/test-design.md)の責務で、本書では扱わない。
オフラインで`/`を開いたときのオフラインのページは`app/offline-pwa`の責務で、本書では扱わない。
認証済みの転送の規則(`proxy.ts`)は`app/navigation`の責務で、本書では紹介画面の「記録を始める」から着くことだけを確かめる。
本書は実装結果から期待値を導かない。
配置候補は既存ファイルを使うための案で、部品の内部構造やprivateな関数を契約にしない。

紹介の項目、文言、図の絵柄、配色、カードの列数、ロゴの大きさと位置は、配置とデザインである。文言と図(カード01〜05)は、ユーザーが確定した。
これらはテストの期待値にせず、手動で確認する。
文言は、将来の差し替えがありうるため、テストは文言を`translatorFor("introduction")`で得て、文字列を直書きしない。
文言の差し替えと項目の増減でテストを直さずに済むことを、この設計の条件とする。

壊れた場合の影響が大きい順に、次を防ぐ。

1. 「記録を始める」を押しても統合認証入口`/signin`へ移れない(入口の喪失)。
2. 認証済みの利用者が、「記録を始める」で移動先の画面から出られない。
3. 紹介の各項目の番号と見出し・本文の対応が崩れる。

今使えない機能や利用の条件(料金・登録・ゲスト)を紹介に載せないこと、見出し構造、図が装飾であること、最初の表示範囲や末尾での操作の隠れは、機械では検出せず、手動確認とレビューで確かめる(`agents/testing.md`の方針。配置・見た目・文言は途中の実装でありE2E・単体の期待値にしない)。

## 層と観測方法

| 層 | 保証する内容 | 観測方法 |
| --- | --- | --- |
| 単体・コンポーネント(Vitest) | 各項目の番号の整形(01〜)と順序、番号・見出し・本文の対応 | 公開のUIを描画し、文言は翻訳ヘルパーで得る。 |
| E2E(Playwright) | 未認証で、先頭と末尾の「記録を始める」を押した遷移先(`/signin`)、認証済みで押した行き先 | 実ブラウザ・認証・DBを通す。認証済みはローカルの認証状態を使い、転送の規則(`proxy.ts`)を通す。1リンク1件。 |
| 手動確認 | 文言、図の絵柄と配色、カードの並び(幅に応じた自動の並べ替え)と並び、最上部のロゴの大きさ・余白・キャッチとの並び、文と図が伝える内容の一致、今ない機能・利用の条件に触れていないこと | ビルドを含む`pnpm preview`(port 3000)で確認する。 |

リンクの押下と遷移先は、Playwrightで確かめる。リンクの`href`だけの単体の確認は置かない。
位置・寸法・クラス・配色・列数・最前面は、E2Eでも単体でも期待値にしない。
単体・コンポーネントは、固定の見た目(固定のクラス、固定のスタイル値)、固定の構造、本番の定義の写しを期待値にしない。

文言を描くテストは`IntlTestProvider`で包む。
次のファイル・ケースは、組み立て・固定の構造・固定の語の確認で、部品自身の分岐ではないため置かない(削除)。
`app/page.test.tsx`(入口の描画)、`start-button.test.tsx`、`intro-screen.test.tsx`のキャッチ見出し・「記録を始める」が2つ・図の`aria-hidden`・利用の条件の語・今ない機能の語の各ケース、`target-definitions.test.ts`(図の定数とSQLの一致)。
`IntroCard`と図の各部品も、個別のテストは設けない。

### 紹介画面(`intro-screen.test.tsx`)

| テスト名の案 | 前提・操作 | 期待結果 |
| --- | --- | --- |

| テスト名の案 | 前提・操作 | 期待結果 |

ロゴの48pxという高さ、キャッチより前という位置は、固定の見た目と配置であり期待値にしない。手動で確認する。

## E2Eのケース(Playwright)

配置は、`apps/web/tests/e2e/app/introduction.spec.ts`である。
利用者がこの画面でできること(読んで、「記録を始める」から統合認証入口へ進む)だけを確かめる。
表示の配置・最前面・スクロールの手段・Tabの順・視口による違いは、直接の検証対象にしない。
文言は`translatorFor("introduction")`で得る。

### 同名のリンクの探し方

「記録を始める」は2つあるため、名前だけでは1つに絞れない(strict modeの違反になる)。
- 紹介画面は未サインイン向けヘッダーとそのリンクを持たない。
- 先頭の「記録を始める」は、`page.getByRole("main")`の中の同名のリンクの`first()`、末尾は`last()`とする。
「2つある」ことそのものは確かめない。

### 1リンク1件の遷移

未認証(保存された認証状態を空にする)で、`/`を開いて押す。

| テスト名の案 | 操作 | 結果 |
| --- | --- | --- |
| 未認証で`/`を開き、先頭の「記録を始める」を押すと、統合認証入口へ移動する | `/`を開き、キャッチの見出し(level 1)が表示されることを確かめる。先頭の「記録を始める」を押す。 | URLが`/signin`で、メール入力の画面が表示される。`/signup`ではない。 |
| 未認証で、末尾の「記録を始める」を押すと、統合認証入口へ移動する | 末尾の「記録を始める」を押す(`click()`が必要なスクロールを行う)。 | URLが`/signin`で、メール入力の画面が表示される。 |

先頭の「記録を始める」は、視口を1つに統合し、縦長・横長の2件にしない。
末尾の件は、読み進めた後に隠れないこと(`elementFromPoint`・`scrollIntoViewIfNeeded()`による最前面の確認)を確かめず、押して遷移することだけを確かめる。
ヘッダーを持たないため、ヘッダーのリンクの件と、ヘッダーを経るキーボード操作（Tab・Enter）の件は置かない。

### 認証済み

保存された認証状態を使う(`SHARED_AUTH_STATE_PATH`)。

| テスト名の案 | 操作 | 結果 |
| --- | --- | --- |
| 認証済みで`/`を開くと、紹介画面のまま表示され、先頭の「記録を始める」を押すと、`/signin`の転送を経て、ホームへ移動する | `/`を開く。移動せずにURLが`/`で、キャッチの見出しが表示されることを確かめる。先頭の「記録を始める」を押す。 | URLが`/rounds`で、ホームの見出しが表示される。 |

末尾の「記録を始める」は、先頭と同じ部品で同じ行き先のため、認証済みでは繰り返さない。
転送の規則の詳細(遷移元の保持など)は、`proxy.test.ts`の責務で、ここでは繰り返さない。
`proxy.test.ts`には、認証済みで遷移元なしの`/signin`を開くと`/rounds`へ移るケースが無い(対象パスの一致と、遷移元付きの`/signin`だけがある)。
ボタンの行き先がこの転送に依るため、`app/navigation`のテストとして次の1件を`proxy.test.ts`に加える。`/signup`はこのケースに含めない(未定義URLと同じ扱いは[auth/signin](../../auth/signin/test-design.md)の単体で確認する)。

| テスト名の案 | 前提・操作 | 期待結果 |
| --- | --- | --- |
| 認証済みで、遷移元のない`/signin`を開くと、ホーム(`/rounds`)へリダイレクトする | 認証済みの状態で、遷移元なしの`/signin`を開く。 | リダイレクト先が`/rounds`である。 |

## E2Eの主要経路

保存された認証状態を空にした利用者が、`/`を開き、統合認証入口`/signin`へ進む経路を持つ。
上の「未認証で、末尾の「記録を始める」を押すと…」と「先頭の…」が、この主要な経路を兼ねる。
E2Eを別に増やさない。
認証を完了してホームへ着く経路(新規・既存)は`auth/signin.spec.ts`の責務で、ここでは繰り返さない。

## 更新の要否を確かめる観点との関係

紹介の文言と機能の一致は、テストで検出しない。
`agents/review.md`の次の2つの観点で、人が確かめる。

- 利用者から見える機能の振る舞いを変える・削除する変更では、紹介画面が今の振る舞いと食い違わないかを確かめる。
- 機能を加える変更では、紹介画面に載せるかを判断し、判断と理由をPRの説明に書く。

未実装の機能と利用の条件の語を載せないことは、機械では検出せず、上の人の確認とレビューに任せる(禁止語の単体は置かない)。
画面の配置や見た目が変わっても図が誤りにならないことは、図が画面に依存しない概念図であるという設計の性質で保たれ、テストで確かめない。

## 手動での表示確認

`pnpm preview`をport 3000で起動し、ビルド済みの表示で確認する。
文言と図(カード01〜05)は、ユーザーが確定した。次の確認は、確定した状態が保たれていることの確認である。
確認した文言の最終版は、`introduction-messages.ts`と設計の「紹介する項目」の見出しをそろえる。

| 条件 | 確認内容 |
| --- | --- |
| 幅375px、800px、1024px、1440px | カードが幅に応じて自動で並べ替わり、1枚だけが極端に余る、極端に細くなる、はみ出すことがなく、カードの高さが行ごとにそろう。 |
| 同上、320px・通常のPC幅・縦に短い画面を含む | 最上部のロゴが高さ48pxで縦横比を保ち、キャッチより前に表示される。余白・キャッチ・開始操作との並びが自然で、旧ヘッダーの空きや下線が残らない。ロゴはリンクでなく、本文とともにスクロールする。 |
| 認証画面(`/signin`のメール入力とコード入力の段階) | ヘッダー・下線・認証リンクがなく、フォームの前に高さ24pxのロゴが通常配置され、見出しがない。ロゴが紹介「/」へのリンクである。幅320pxでロゴとフォームが重ならず、縦に小さい画面でもスクロールでフォームの全体へ届く。左上に固定のロゴが重複せず、ログイン・登録の相互遷移の文もない。 |
| 認証済み画面・オフライン画面・削除/メール変更 | ロゴの既定の高さ、ScreenFrame・目的ヘッダー・戻る、固定のロゴが変更前と同じ(波及がない)。 |
| 紹介の5項目 | 文言が機能の今の振る舞いと食い違わず、上限値・件数・的の全件を書いていない。今ない機能(分析・グラフ・共有・チーム・累計統計)と、料金・登録の要否・ゲスト利用に触れない。 |
| 図 | 絵柄が項目の内容と合い、的が実際の的の配色で、輪の境の線により白地に溶けない(標準の的(カード01・03・05)は、5色の同心円で色の境に線がなく、白の外周の細い線により溶けない)。グラフ・推移の線を描いていない。図が伝える内容が本文の文でも伝わる。 |
| キャッチ | 「アーチェリーのスコア記録・分析・共有アプリ」の旧文言が残らず、「あなたの点数記録を、もっと自由に」が表示される。 |
| 「記録を始める」 | キャッチの下と末尾の2か所にあり、塗りの主ボタンとして目立つ。 |

## データと実行上の条件

単体・コンポーネントのテストは、フェーズコメント(Given・When・Then)を`agents/testing.md`の規則に従って置き、正常系から異常系の順に書く。
紹介画面は状態・データ・通信を持たないため、時刻・通信・視口の偽物は使わない。
E2Eは有効なローカル認証・DB接続設定を使い、本番の秘密情報・共有DB・DBリセットは使わない。
設定が不足する場合は、実行できた検証と未確認のケースを分けて報告する。
紹介画面のリンクは水和の前でも動くため、`waitForHydration`で待たない。
ただし、サインイン画面の水和を要する操作は、既存のspecに従う。

## 認証画面のロゴとヘッダーの不在

未サインイン向けヘッダーは持たない。紹介画面は本文最上部のロゴ、認証画面はフォーム前のロゴを置く。
認証画面のロゴから紹介「/」への遷移は、`auth/signin.spec.ts`の1件で確かめる([auth/signin](../../auth/signin/test-design.md))。紹介のロゴはリンクでなく、遷移の試験を置かない。
ヘッダーの不在は、DOMのlandmarkの不在を期待値にせず(固定の構造を確かめることになるため)、ヘッダー部品を持たないことを差分レビューと型・未使用検査で保証する。ヘッダーのための単体テストと新しいE2Eは置かない。
ロゴの大きさ・位置と、狭い画面・スクロールは、上の手動での表示確認で確かめる。この確認は、機能テストの実装・実行より前に、ビルドを含む`pnpm preview`(port 3000)でユーザーが行う。

## 検証の完了判定

後続担当は、上の単体・E2Eのケースと、既存の関連するテストを実行する。
既存の関連するテストは、`app-logo.test.tsx`、`screen-frame.test.tsx`、`proxy.test.ts`である。
併せて`pnpm lint`と`pnpm typecheck`を実施する。
手動確認は、実施した条件と、未確認の項目を分けて報告する。
未実行、環境の制約による未確認、既存の失敗を、成功に含めない。
行カバレッジの数値を合否にしない。
