# introduction 設計

## 概要

`/`は認証状態によらず同じ静的な紹介画面を出し、認証の確認を持たない。
紹介画面は未サインイン向けの共通ヘッダーを使わず、本文の最上部、キャッチより前に既存資産のロゴを高さ48pxで表示し、リンクにしない。
ヘッダーの高さ・下線・認証リンクを持たず、ロゴも本文と一緒にスクロールする。
本文は、キャッチ(主見出し。1行)・「記録を始める」、紹介のカードの並び、末尾の「記録を始める」の順に並ぶ。紹介は1項目1枚のカードで、各カードに番号(01〜05)を付け、画面の幅に応じて列数が自動で変わる。
紹介の図は、画面に依存しない静止の概念図で、的は実際の的の配色で描く。図が伝える内容は全て文でも伝える。

## 画面と状態

| 画面・状態 | 内容 |
| :--- | :--- |
| `/` | 未認証・認証済みとも同じ内容。最上部の高さ48pxのロゴ、キャッチ(`h1`)、「記録を始める」、紹介の5項目のカード(各`h2`)、末尾の「記録を始める」を表示する。 |
| 最上部のロゴ | 既存のlogo.svgを高さ48px、縦横比を維持してキャッチより前に表示し、リンクにしない。認証リンクやヘッダー枠は置かない。 |
| 紹介のカードの並び | 幅に応じて自動で並べ替わり、列数を幅ごとに決めない。カードの幅は最小18remで、幅が足りなければ1列になる。カードの高さは行ごとにそろう。各カードは上に図、下に番号(01〜05)・見出し・2段落の本文を持つ。 |
| 「記録を始める」 | `/signin`へのリンク。最初の表示範囲(キャッチの下)と本文の末尾の2か所に置く。 |
| 認証済みで押す | 本文の先頭・末尾の「記録を始める」は、`proxy.ts`の認証済みの転送で`/rounds`(ホーム)へ着く(`app/navigation`)。 |

## 紹介する項目

項目は`docs/features/README.md`の機能一覧の行に対応させる。今実現できることだけを書き、数値の上限や件数など変わりやすい値は書かない。

| 見出し | 対応する機能一覧の行 |
| :--- | :--- |
| 自分のスタイルに合わせて、点数を記録 | rounds/setup |
| いつものラウンドを、すぐに開始 | rounds/preset、rounds/start |
| スマホで記録して、PCで振り返る | rounds/sync、rounds/history |
| オフラインでも、記録を止めない | rounds/sync、app/offline-pwa |
| 記録を振り返り、次の練習のヒントに | rounds/history、rounds/detail |

一射ずつの記録(rounds/score-entry)は、キャッチと各項目の本文で伝える。
文言は`introduction-messages.ts`が、図は項目ごとの図の部品が正本で、本表は項目と機能の対応だけを持つ。文言と図は1項目ずつ差し替えられる。

## 設計判断

| 判断 | 理由 | 見直す条件 |
| :--- | :--- | :--- |
| 「記録を始める」は、認証状態によらず固定の行き先へのリンクにする | 紹介画面を静的に保ち、認証の確認を持たないため。認証済みなら`proxy.ts`の転送で`/rounds`へ着く(転送が1回増える)。確認を持つと、手続き・規則・インフラの3段で経路を受け渡す必要がある。 | 行き先を認証状態で変えたいとき。 |
| 紹介のロゴを本文の最上部に置き、共通ヘッダーを持たない | ロゴを大きく示す指示を満たし、操作を持たないヘッダー枠を不要にするため | 入口の構成を変えるとき |

| 末尾にも「記録を始める」を置く | 読み終えた位置から先頭へ戻らずに統合入口へ進めるため。同じ部品を2回描くだけで、状態を持たない。 | 末尾の操作が使われないと分かったとき。 |
| 紹介のロゴに既存の固定配置のAppLogoを使わない | AppLogoはオフライン画面で左上の固定リンクを担い、本文最上部の高さ48pxのロゴとは配置の責務が異なるため | 紹介のロゴも固定する要求があるとき |
| 図は画面に依存しない静止の概念図にし、スクリーンショット・実UI部品・画面を再現した動きは使わない | 画面の配置や見た目を変えても図が誤りにならず、紹介の更新を機能の振る舞いの変更だけに限れるため。 | 概念図では伝わらないと分かったとき(AI生成のイラストを検討する)。 |
| 図の的を実際の的の配色にする | 的と一目で分かるため(ユーザーの指示)。アプリは既に点数の玉とテンキーを的の輪の色で塗っており、白黒基調の画面と同じ色の組み合わせで共存している。輪の境に暗い線(`#231F20`)を引き、白地・薄い地に白・金の輪が溶けない(線と各色の比は4.8〜16.3)。標準の的(カード01・03・05)は、一番外側の白の外周にだけ最小限の太さの線を引き、色の境に線は引かない。色だけで意味を伝えず、装飾なので、画面の配色(テーマ)に依存させない。 | ダークモードを入れるとき(的の外側の線と地の比を確かめる)。 |
| 紹介を1項目1枚のカードにし、幅に応じて自動で並べ替える(`auto-fit`と`minmax`) | 項目を独立に読み比べられ、広い画面で縦に間延びしないため。列数を幅ごとに決めると項目数や幅の変更のたびに直すことになるため、カードの最小幅だけを決める(ユーザーの指示)。最終行にカードが余ることは許容する。 | 項目の数が変わったとき。 |
| 図を装飾(`aria-hidden`)にし、内容を全て文で書く | 図の代替テキストを文と二重に保たずに済むため。 | 図だけが伝える情報を持たせるとき。 |
| 紹介の文に、上限値・件数・的の一覧の全件を書かない | 値やデータの追加で記述が古くならないため。的は種類の例と「など」で書く。 | なし。 |
| 機能の振る舞いを変えるPRで、紹介の更新要否をレビューで確かめる(`agents/review.md`) | 項目が5つで、人の判断で足りるため。テストで文言と機能の一致を機械的に検出しない。 | 項目が増え、更新漏れが起きたとき。 |

## 制約と未対応

- オフラインで`/`を開くと、オフラインのページが出る(`app/offline-pwa`)。
- オフラインのページはヘッダー枠を持たず、左上に固定のロゴだけを持つ。
- アプリはダークモードを持たない(`globals.css`に暗い配色の定義が無い)。図の的の色は固定値、線は`currentColor`である。
- 図の動き、閲覧の計測、料金・登録の要否・ゲスト利用の記述は扱わない(要件の対象外)。

実装時は機能テストに進む前に、ビルドを含む`pnpm preview`（port 3000）で最上部のロゴ・キャッチ・先頭と末尾の開始操作を表示し、ユーザーが見た目を確認する。
