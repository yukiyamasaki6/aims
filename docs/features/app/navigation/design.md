# navigation 設計

## 概要

未認証には紹介画面を見せ、認証済みには個人のラウンド一覧へ直行させる。
認証状態に合わない画面へのアクセスは、`proxy.ts` が入口の画面へ移す。
サインイン後の画面では、レフトパネルから `/rounds` へ戻れる。
レフトパネルは画面幅でモバイル（ドロワー）とデスクトップ（折りたたみ）の2つの挙動を持つ。

## 画面と状態

| 画面・状態 | 内容 | 要求 |
| :--- | :--- | :--- |
| `/`（未認証） | アプリ名、説明文、開始ボタンを持つ。開始ボタンは `/signup` へのリンクである。 | navigation-01, 02 |
| `/`、`/reset-password`（認証済み） | `/rounds` へリダイレクトする。 | navigation-13 |
| `/rounds` 配下（未認証） | `/signin` へリダイレクトする。`/rounds/new`、`/rounds/[id]` も対象である。 | navigation-14 |
| レフトパネルのリンク | AIMSリンクと個人リンクは `/rounds` へ遷移する。サインアウトボタンは確認ダイアログを開く。 | navigation-03, 05 |
| レフトパネル（モバイル） | 初期は格納。ハンバーガーボタンで展開し、閉じるボタンまたはオーバーレイで格納する。 | navigation-06, 07, 09 |
| レフトパネル（デスクトップ） | 初期は展開。格納ボタンと開くボタンで切り替える。 | navigation-10, 11, 12 |

- モバイルとデスクトップの開閉状態は別々に持つ。
- モバイルの格納は画面外へ押し出すだけで、DOMからは消えない。

## 構成とデータの流れ

- `src/proxy.ts` は `/`、`/signin`、`/signup`、`/reset-password`、`/rounds/:path*` を対象に `updateSession` を呼ぶ。
- `src/lib/supabase/session.ts` の `updateSession` が、認証状態で分岐する。
  - 未認証で `/rounds` 配下なら `/signin` へリダイレクトする。
  - 認証済みで `/`、`/signin`、`/signup`、`/reset-password` なら `/rounds` へリダイレクトする。
  - Server Action呼び出しはどちらも対象外とする。
- `src/app/page.tsx` が静的な紹介画面である。
- `src/app/(main)/left-panel.tsx` が開閉、リンク、サインアウト確認ダイアログを持つ。認証状態は持たず、常に全内容を表示する。未認証のガードは `proxy.ts` が担う。

## 設計判断

| 判断 | 理由 | 見直す条件 |
| :--- | :--- | :--- |
| 認証状態によるリダイレクトを `proxy.ts` に集約する | 各ページの認証確認とリダイレクトの重複を除くため。画面ごとの回帰テストは、画面ごとに独立して壊れうるため残す。 | ページごとの分岐が必要になったとき。 |
| 未認証の `/` はリダイレクトせず紹介画面を表示する | サインアップへの導線を最小限の画面で示すため。 | 紹介の内容を拡充するとき。 |
| AIMSリンクの遷移先を `/rounds` にする | レフトパネルは認証済みの画面にしか置かれず、`/` は認証済みなら `/rounds` へ移るだけなので、往復を省くため。 | 認証済みにも見せる画面を `/` に置くとき。 |
| Server Action呼び出しをリダイレクトの対象外にする | リダイレクトするとNext.jsが期待する応答形式と合わず、分かりにくいエラーになるため。未サインイン時は各Server Actionのガードが扱う。 | Server Actionの認証を共通化するとき。 |
| レフトパネルのサインアウトを確認ダイアログ経由にする | 誤操作を防ぐため。ダイアログはブロッキング方式に統一する。 | ダイアログをブロッキング方式以外にするとき。詳細: `auth/signout`。 |

## 制約と未対応

- 開閉状態は画面遷移やリロードで初期状態へ戻る。
