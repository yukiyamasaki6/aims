# navigation 設計

## 概要

セッションを失ったら`/signin`へ移す（入口は`proxy.ts`、表示中は`(main)`のレイアウトが始める見張り）。
AIMSロゴ（レフトパネル、紹介画面・認証画面のヘッダー、`/offline`の左上）は`/`(紹介画面。`app/introduction`)へ戻る。
レフトパネルは画面の幅で、ドロワー（幅768px未満。モーダル）と縦の列（幅768px以上。本文と横に並ぶ）を別の枠として切り替える。
ログイン後(`(main)`配下)の各画面は、本文側の上端に共用のヘッダー枠(`ScreenFrame`)を持ち、中身を画面ごとに差し替える。ヘッダーの左端のメニューボタンが、ドロワーと、閉じている縦の列の開き口である。閉じるボタンはパネルの最上段の左端で、メニューボタンと同じ位置に来る。最上段の行はヘッダーと同じ高さである。
階層は、レフトパネル > ヘッダー > 点数キーボードである。配置は幅だけで決め、向きは使わない。
ラウンドの開始画面(`/rounds/new`)への入口は、レフトパネルの最上部のラウンドの開始ボタンと、ホームの右下のラウンドの開始ボタン(`rounds/history`)の2つで、画面の幅では出し分けない。

## 画面と状態

| 画面・状態 | 内容 |
| :--- | :--- |
| `/rounds` 配下（未認証） | 遷移元のパス付きで `/signin` へリダイレクトする。`/rounds/history`、`/rounds/new`、`/rounds/[id]` も対象である。要求にハッシュは含まれないため、ブラウザが元のハッシュを`/signin`へ引き継ぎ、サインインが遷移元に足す(`auth/signin`)。 |
| ロゴ | レフトパネルのAIMSロゴ、紹介画面・認証画面のヘッダーのロゴ、`/offline` の左上のロゴは `/` へ遷移する。 |
| セッション喪失 | `SIGNED_OUT`（通知は発生元を区別せず届く）と、マウント時の `unauthenticated` で、遷移元(パス、クエリ、ハッシュ)付きで `/signin` へ遷移する。明示のサインアウトの実行中の喪失は、サインアウトの判定に委ねる(終えられたら遷移元を付けずに移る。`auth/signout`)。`unknown` では留まる。保存先が空の未認証は、オフラインでもマウント時に `/signin` へ移り、`/offline` が出る。 |
| レフトパネルのラウンドの開始ボタン | 最上部(閉じるボタンとロゴの行の下、移動項目の上)に、全画面・全幅で出す。`/rounds/new`へのリンクで、文言と名前は「ラウンドを開始」。移動項目と違い、`Plus`のアイコンと太めの文字(`font-medium`)を持ち、移動項目より上の最上部に、移動項目の並びとの間に広い空白を空けて置く。塗りと枠線は持たない。`aria-current`は付けない。`/rounds/new`を表示中に押すと、遷移せず(既定の動作を止める)、ドロワーを閉じるだけで、開始画面の選択は保たれる。 |
| レフトパネルの項目 | 「ホーム」項目は `/rounds` へ、「点数一覧」項目は `/rounds/history` へ遷移する。下端の「設定」項目は、画面を移らずに設定パネルを開く(`app/settings`)。`aria-current="page"`は、表示中のビューの「ホーム」か「点数一覧」の項目に、設定パネルの開閉によらず付く。「設定」項目は設定パネルを開くだけの項目で、`aria-current`も現在の見た目も付かない。 |
| レフトパネル（幅768px未満） | 開き口は、各画面のヘッダーの左端のメニューボタン(アイコンだけ。名前は「メニューを開く」)である。向きによらず同じで、独立した帯は持たない。始まりは格納。メニューボタンで展開し、閉じるボタン・背景で格納する。展開中はパネル内または背景の左スワイプに追従し、十分に引いて離すと格納し、それ以外では元の位置に戻る。背景の濃さはドロワーの移動に合わせて変わり、通常の開閉でも同じ時間でフェードする。本文に重なる。展開中はフォーカスをドロワー内に閉じ込め、本文を`inert`にし、Escで格納する。背景はフォーカスの対象にしない。 |
| レフトパネル（幅768px以上） | 開いている間は画面の全高の縦の列(幅224px)で、本文を押しのけて横に並ぶ。始まりは開。閉じるボタン(名前は「メニューを閉じる」)で閉じ、幅0になって本文が全幅を使う。閉じている間だけ、ヘッダーの左端にメニューボタンを出し、押すと開く。開いたら閉じるボタンへ、閉じたらメニューボタンへフォーカスを移す。モーダルではなく、閉じ込めとEscは持たない。 |
| ヘッダー（`(main)`配下） | 本文領域の上端に、全画面で同じ位置・高さ(下端の線を含めて45px)で出す。左から、メニューボタン(幅768px未満では常に、幅768px以上では縦の列が閉じている間だけ)、戻る(ある画面だけ)、現在地の名称(`h1`)、右端に画面固有の操作を置く。中身は下表。 |

| 画面 | 戻る | 現在地 | 右端 |
| :--- | :--- | :--- | :--- |
| ホーム(`/rounds`) | なし | ホーム | なし(ラウンドの開始ボタンは本文の右下に置く。`rounds/history`) |
| 点数一覧(`/rounds/history`) | なし | 点数一覧 | フィルターのアイコン(`rounds/history`) |
| ラウンドの開始画面(`/rounds/new`) | ホームへ(どこから開いても) | ラウンドを開始 | なし |
| 詳細(`/rounds/[id]`) | 遷移元へ(`rounds/detail`) | なし | プリセット保存、ラウンドのメニュー(取得の後だけ) |

- 開閉状態は2つの真偽値をメモリ上(`useState`)だけで持つ。ドロワーは `drawerOpen`（始まりは閉）、列は `railOpen`（始まりは開）。向きは値・枠・開き口のどれにも使わない。幅をまたいで往復しても、それぞれの値が保たれる。再読み込みで初期値に戻る。
- 開閉の幅と位置は、開閉の操作で200msのtransitionで動く。列は外枠の幅(224px↔0)だけを動かし、中身は224pxのまま外枠で切り取る(閉じる途中で中身が折り返さない)。幅768pxをまたぐ切り替え（回転、窓の変形）は、ドロワーと縦の列が別の枠で切り替わるので動かない。初回表示は最初から切り替え後の状態で表示する。
- ドロワーの格納と列の閉は、`visibility: hidden` で、フォーカスと読み上げの対象から外す。DOMからは消えない。開くときはvisibilityを即時に変え(開いた直後の`focus()`が効くように)、閉じるときだけ動きの終わりまで見せる。
- ドロワーの閉じ込めは、ドロワーが表示されている間(`drawerOpen`かつ幅768px未満)だけ働く。幅768px以上は`matchMedia("(min-width: 768px)")`で知る(水和までは幅768px未満とみなす。`drawerOpen`の始まりは閉なので、水和の前に閉じ込めは働かない)。働く間は、本文領域に`inert`を付け、`document`の`keydown`でTab・Shift+Tabを端で回し(フォーカスがドロワーの外にあれば先頭・末尾へ入れる)、Escで`drawerOpen`を閉にする。幅768px以上へ変わると、`drawerOpen`が開のままでも閉じ込めは外れる。
- 開閉時のフォーカス移動はドロワーと列で同じ規則にする。開いたらパネル内の最初のボタン(閉じるボタン)へ移し、閉じたら、フォーカスが`body`かパネル内にあるときだけ、その枠のメニューボタンへ移す。初回表示では移さない。
- ラウンドの開始ボタンと「ホーム」「点数一覧」「設定」項目の押下は、ドロワーの値(`drawerOpen`)だけを閉にし、列の値(`railOpen`)を変えない。配置の判定はしない。「設定」項目の押下でドロワーを閉じるときは、フォーカスをメニューボタンへ移さず(上の閉じたときの規則の例外)、開いた設定パネルが受け取る。
- 設定パネルが閉じたときは、入口から受けた戻し先の種類に従ってフォーカスを移す。開き口へ戻すときは、幅768px以上で縦の列が開いていれば(`railOpen`)列の「設定」項目へ、幅768px以上で縦の列が閉じていれば列用のメニューボタンへ、幅768px未満ではドロワー用のメニューボタンへ移し、ドロワーと列の開閉は変えない。背景の画面の先頭へ移すときは、本文領域(`tabIndex=-1`)へ移す。設定パネルが開いている間は、設定パネルのダイアログが外側(レフトパネルを含む)に`aria-hidden`を付けてフォーカスを閉じ込め、外側の押下はダイアログの背景が受ける(`inert`は付かない。`app/settings`)。

レフトパネルとドロワーの中身は、共通の`PanelBody`が描く。上から、ラウンドの開始ボタン、移動項目(「ホーム」「点数一覧」)、下端の「設定」項目の順である。
ラウンドの開始ボタンは、移動項目と同じ左右の余白(`px-2`)の中で幅いっぱい(`w-full`)に置き、`Plus`のアイコン(20px四方、`aria-hidden="true"`)と文字を左寄せで並べる。リンクのクラスは`flex w-full items-center gap-2 rounded-lg px-3 py-3 text-sm font-medium transition-colors hover:bg-foreground/5`で、塗りと枠線は持たない。ボタンの高さは44px(`py-3`と20pxの行)で、押しやすさの一般的な下限に合わせる。左右と上下の余白・角丸・文字の大きさ・マウスを重ねたときの塗りは移動項目(`navItemClassName`)と同じにし、最上部の位置、`Plus`のアイコン、下の空白、太めの文字で、移動項目と区別する。
開始ボタンを包む要素は`px-2 pt-1 pb-5`で、下に20pxの空白を持つ。移動項目の並び(`nav`)は上の余白を持たず、開始ボタンのアイコンと「ホーム」のアイコンの縁どうしは44px(ボタン1つ分)で、ボタンの間の空きは20px(上下の内側余白12px×2を足して44px)になる。移動項目どうしの間は0である。空白は、移動項目の並びの間隔でなく、開始ボタンの側の下の余白で持つ。開始ボタンを除いても移動項目の並びが変わらず、空白の持ち主が開始ボタンの1つに決まるためである。ドロワーと縦の列は同じ`PanelBody`を描くため、どちらでも同じ見え方になる。
マウスを重ねたときは、移動項目と同じ`hover:bg-foreground/5`で塗る。パネルの中の押せるものが同じ手がかりで応え、開始ボタンだけが重ねても変わらない(押せるかどうか分かりにくい)ことを避けるためである。開始ボタンは現在のビューにならないため、現在のビューの強調(`bg-foreground/10`)とは混ざらない。
`buttonVariants`には該当する見た目が無く、移動項目もクラスで描くため、variantを足さずにクラスで指定する。
移動項目は、アイコンと文字を並べる。
アイコンは既存の`lucide-react`の`House`（ホーム）・`ListOrdered`（点数一覧）・`Settings`（設定）を使い、文字の左に20px四方、文字との間隔8pxを基準に置き、縮まないようにする。
アイコンは文字色を継承し、現在地の背景・文字の強調はリンク全体に適用する。
移動項目(「設定」項目を含む)のクラスは、`navItemClassName`が決める。「設定」項目は常に現在のビューでない側のクラスで描く。基本は`flex items-center gap-2 rounded-lg px-3 py-3 text-sm transition-colors`で、現在のビューでないときは`hover:bg-foreground/5`、現在のビューのときは`bg-foreground/10 font-medium`を足す。
濃さの順は、通常(塗りなし、明るさ1.0) < マウスを重ねたとき(5%、約0.96) < 現在のビュー(10%、約0.91)である。現在のビューの項目は、マウスを重ねても濃さを変えない(重ねたときのクラスを付けない)。重ねたときに濃くすると、現在地の強調と押せることの表示が混ざるためである。開始ボタンを重ねたときも、移動項目と同じ5%である。`--muted`(0.97)は重ねたとき(約0.96)との差が小さく現在地が目立たないため、現在のビューには使わない。文字(`--foreground`、0.145)との明暗の差は大きく、読みやすさは保たれる。
Tailwind v4の`hover:`は、マウスを重ねられる環境(`@media (hover: hover)`)だけで働くため、タッチ端末で押した後に塗りが残らない。キーボードのフォーカスの表示は、全体の規則(`outline-ring/50`のアウトライン)のままで、塗りとは別の線で示すため混ざらない。現在のビューは、見た目と別に`aria-current="page"`で支援技術へ伝える。`--foreground`に基づくため、色の反転でも背景に対して同じ向きの濃さになる。
アイコンは装飾として`aria-hidden="true"`にし、フォーカス対象や独立した操作を持たせず、リンクの名前は文字の項目名から得る。
設定の区画は下端の配置を保ち、余白は8px(`p-2`)にし、区切り線だけを取り除く。
`/rounds/history`の画面見出しも「点数一覧」とし、入口と遷移先の名称を統一する。見出しの文言はrounds側が所有する。

## 構成とデータの流れ

- `src/proxy.ts`(入口): `/signin`、`/signup`、`/reset-password`、`/rounds/:path*` を対象に、`updateSession` が返すサインインしているかから、認証の機能の経路の規則(`features/auth/domain/auth-routes.ts` の `redirectFor`)を呼び、行き先があればリダイレクトし、無ければ `updateSession` の応答を返す。`config.matcher` は Next.js がビルド時に静的に読み、定数を参照できないため、経路を文字列で再掲し、`proxy.test.ts` が経路表の `ROUNDS_PATH` との一致を確かめる。`/` は対象外である。設定はハッシュで表すため、対象に含めない(`app/settings`)。
- `src/lib/supabase/infrastructure/session.ts`(共有の技術の実装): `updateSession` が要求ごとにセッションを更新し、`getClaims`(端末内でトークンの署名と期限を検証する)でサインインしているかと、更新したcookieを書いた応答を返す。経路の規則は持たない。規則は認証の機能の `redirectFor` が持ち、`proxy.ts` が呼ぶ。
  - 未認証で保護の範囲(`/rounds`の配下)なら、`signInHref` で遷移元を付けた `/signin` へリダイレクトする。
  - 認証済みで `/signin`、`/signup`、`/reset-password` なら `/rounds`(ホーム)へリダイレクトする。`/signin` は有効な遷移元があればそこへ送る（`auth/signin`）。
- `src/features/auth/application/session.ts` の手続き`createSession`の`watch`が、セッション喪失の検知（`SIGNED_OUT`と、マウント時の`unauthenticated`）と、`/signin`への遷移（`replace`。今の場所(パス、クエリ、ハッシュ)を遷移元に付ける）、記録の利用者と違う利用者のサインインの検知と今の場所の読み込み直しを持つ。確かめた結果の喪失の定義(`lostByStatus`)は`domain/auth-change.ts`、遷移の規則（遷移元、サインアウトの実行中は移らない）は`domain/session-end-flow.ts`。手続きと実装はルートの入口(`app/root-client-entry.tsx`)がアプリで1つ生成し、`SessionProvider`で渡す。`(main)`のレイアウトは`useSession`で受け取り、見張りを始める。
- `src/features/navigation/ui/navigation-messages.ts`(UI層): 左パネルの文言の一覧(名前空間`navigation`)。部品は`useTranslations("navigation")`で文言を得る。紹介画面の文言は`app/introduction`が持つ。
- 遷移の約束(アプリ全体): ナビゲーションの機能は遷移の約束を持たない。ルーターで進む遷移は共有の技術の `PageNavigation`(`src/lib/page-navigation/contract/page-navigation.ts`。認証のパスワード再設定とラウンドの開始、完了、削除して離れるが使う)、ページ全体の読み込みの遷移は認証の `PageReplace`(`src/features/auth/application/page-replace.ts`。実装は `infrastructure/browser-page-load.ts`。サインイン、サインアップの完了、サインアウト、セッションの喪失、利用者の不一致が使う)、遷移元の読み出しは入口の `readReturnTo` である。
- `src/app/(main)/layout.tsx`(入口): 認証が要る画面の集合の枠。入口が渡すセッションの手続きを`useSession`で受け取って見張りを始める。根の枠(幅によらず横並び)の中に`LeftPanel`を描き、画面を`LeftPanel`の子(本文領域)として渡す。設定の経路の操作(`useSettingsRoute`)を呼び、設定パネルが開いているか・開く操作・閉じたときの戻し先の種類を`LeftPanel`へ渡し、設定パネルの入口を`LeftPanel`の外(兄弟)に描く(`app/settings`)。
- `src/components/screen-frame.tsx`(共有の画面部品): ヘッダー枠。`ScreenFrame`は、ヘッダー(`<header>`。高さは下端の線を含めて45px(`h-[45px]`、`box-sizing: border-box`で線の1pxを含む)で、操作の置き場は44px。行は幅を制限せず本文領域の幅いっぱいである。ヘッダーは左右に6px(`px-1.5`)の余白を持ち、行の要素の間隔は2px(`gap-0.5`。右端の`trailing`の中も同じ)とする。アイコンのボタンは内側に余白4pxを持つため、端から最初のアイコンまでの見た目は約10px(6+4)、アイコン同士の見た目も約10px(4+2+4)で同じになる。中身は高さ44px(45pxから下線1pxを除いた分)の行の上下中央に置く。アイコンの枠32pxでは、上下の余白も左右と同じ6px((44px−32px)/2)になる。アイコンのボタン(メニューボタン、点数一覧のフィルター、ラウンドのメニュー)は、押せる範囲の枠(32px四方。アイコン24pxと周囲4pxの内側の余白(`p-1`))も含めて1つのアイコンとする。アイコンを大きくした分は内側の余白を小さくして吸収し、枠の寸法は変えない。文字の要素も周囲に6pxの余白を取る: 現在地は`p-1.5 text-base leading-5`(文字16px、行の高さ20pxで32px。上下6px)、戻るは`py-1 pl-0 pr-1.5 gap-0.5`(高さ32px。幅は従来の60pxから、〈の左の余白(従来`pl-2`の8px)をなくした分、8px狭い。端から〈の見た目まで約11px。図柄の「〈」は24px(高さ`h-6`)で描き、図柄の左右の空白だけを切り落とした幅16px(`w-4`、`preserveAspectRatio="xMidYMid slice"`。図柄は中央の幅6pxで、はみ出ない)の枠に入れる。24pxの正方形の枠のままだと、図柄の右に約9pxの空白が残り、文字から離れて見えるため。「〈」の位置と大きさは24pxの枠のときと同じで、「〈」と文字の見た目の距離は約7px(従来は約10px))、プリセット保存は従来の28pxの背景のあるボタン(`size="sm"`)の左右の外側に`mx-1`(4px。上下の外側の余白は持たず、行の上下中央に置く)。背景の端から隣のアイコンまでの見た目が、約10px(4+2+4)になる。どれも44pxの内側に収まる。見た目の距離の定義は、アイコンのボタンの内側の余白(4px)を含めて測る。下端に区切りの線(`border-b`)を引く)と、その下の本文領域の枠(`min-h-0 flex-1 overflow-hidden`)を縦に並べ、`h-full`で親に従う。本文領域の枠は高さ(画面の高さからヘッダーを除いた分)を子に与えるだけで、スクロールしない。スクロールの有無と入れ物は各画面が決め、子は`h-full`で枠の高さを受ける。行には、文脈から受けたメニューの部品、`leading`(戻る)、`title`(現在地の名称、または詳細のラウンド名の部品。`ReactNode`を受け、`h1`の中に置く。太字にしない。`min-w-0 flex-1`で余りの幅を受け、長い文字は`truncate`で省略する。`trailing`は`ml-auto`のため、現在地だけの画面で位置は変わらない)、右端(本文領域の右端)に`trailing`(画面固有の操作)を置く。ヘッダーのアイコンだけのボタン(メニューボタン、点数一覧のフィルター、詳細のラウンドのメニュー)は、大きさだけをそろえる(アイコン24px表示を含む32px四方の枠)。色と見た目の種類は各ボタンの従来のままで、そろえない。部品は各機能が持ち、共通の部品にはしない。`ScreenMenuProvider`がメニューの部品(`ReactNode`)を文脈で渡し、文脈が無いとき(画面の単体のテスト)はメニューを出さない。業務の言葉を持たず、ドロワーを知らない。z-indexを持たない。
- 各画面の部品(`rounds-home.tsx`、`rounds-history.tsx`、`round-preset-select.tsx`、`round-detail-frame.tsx`。詳細は現在地でなくラウンド名を`title`に渡す)が、自分の状態から中身を決めて`ScreenFrame`を描き、本文のスクロールの入れ物を自分で持つ(ホーム・点数一覧は本文全体、ラウンドの開始画面は一覧だけ、詳細は`<main>`だけ)。`LeftPanel`の本文領域もスクロールしない。ヘッダーの下線と本文の間の余白も各画面の本文が持ち、ホーム・点数一覧・詳細は32px(`p-8`・`py-8`)である。設定パネルの項目の画面(`change-email-form.tsx`、`change-password-form.tsx`、`delete-account-form.tsx`)も`ScreenFrame`を描くが、設定パネルの入口はReactの木で`LeftPanel`の外にあり、`ScreenMenuProvider`の文脈を受けないため、メニューボタンは出ない(文脈はポータルを越えて伝わるため、ポータルかどうかでは決まらない。`app/settings`)。取得中の枠とSuspenseの代替表示も同じ枠を描き、ヘッダーを動かさない。現在地の名称の文言は各画面の機能の文言の一覧が持つ。
- `src/components/app-logo.tsx`(共有の画面部品)が、`/offline` の左上のロゴである。紹介画面・認証画面のロゴはヘッダー(`guest-header.tsx`)の中にあり、`app-logo.tsx`を使わない(`app/introduction`)。ロゴの行き先は、経路表(`src/routes.ts`)の `HOME_PATH`(`/`)で、`left-panel.tsx` のロゴも同じである。
- `src/components/logo-image.tsx`(共有の画面部品)が、文字付きロゴの画像（`public/logo.svg`）を表示する。代替テキスト「AIMS」がロゴのリンクの名前になる。`app-logo.tsx`、`left-panel.tsx`、`guest-header.tsx`が使う。
- `public/logo.svg` は、`scripts/generate-icon.mjs` が、マークと同じ値と、`geist` のGeist SansのBoldの字形から生成する。文字は図形にし、フォントを参照しない。READMEの冒頭も同じファイルを表示する。
- `src/features/navigation/ui/left-panel.tsx`(UI層)が開閉（ドロワーと列の2つの値）と、ラウンドの開始ボタン、「ホーム」「点数一覧」「設定」の項目を持つ。ラウンドの開始ボタンは経路表の `NEW_ROUND_PATH` へのリンクで、見た目は`left-panel.tsx`の中のクラスで指定する(上記)。押下はドロワーを閉じ、`usePathname`が`NEW_ROUND_PATH`と等しいときだけ既定の動作を止める。文言は文言の一覧の`leftPanelStartRound`(「ラウンドを開始」)が持つ。「ホーム」「点数一覧」項目の向き先は経路表(`src/routes.ts`)の `ROUNDS_HOME_PATH`、`ROUNDS_HISTORY_PATH` である。「設定」項目は、経路表の `SETTINGS_ACCOUNT_HASH` を`href`に持つリンクで、押下は既定の動作を止め、ドロワーを閉じて、入口から受けた開く操作を呼ぶ。現在のビューは、`usePathname` が向き先と等しい「ホーム」か「点数一覧」の項目に、設定パネルの開閉によらず、`aria-current="page"` と現在の見た目を付けて示す(詳細・ラウンドの開始画面ではどちらにも付かない)。「設定」項目には付けない。設定パネルが開いているかは、閉じたときのフォーカスの戻し先にだけ使い、現在のビューの判定には使わない。設定パネルが閉じたときのフォーカスの移動(上記)も持つ。下端に「設定」項目を置き、その区画の上端には区切り線を引かない。認証状態は持たず、常に全内容を表示する。ドロワーの枠と縦の列の枠を別の要素にして、幅(`md:`)で出し分ける（中身=最上段の行(左端に閉じるボタン、その右にロゴ)・ラウンドの開始ボタン・「ホーム」「点数一覧」「設定」項目は共有の部品を2つの枠に置く）。最上段の行はヘッダーと同じ高さ(45px)・左右の余白6pxで、下端の線は引かない。中身は上端から44px(ヘッダーの線を除いた行と同じ範囲)の上下中央に置く。閉じるボタンのアイコンは✕(ドロワーと列で同じ)である。閉じるボタンは内側の余白6pxとアイコン20pxで、ヘッダーのメニューボタンとアイコンの中心が同じ位置(枠の左上から22px)に来る(メニューは24px、閉じるボタンは対象外で20px)。「ホーム」「点数一覧」の項目の並びは上の余白を持たない(間は開始ボタンの下の20px)。最上段の行に線が無く、ロゴの直下に背景が詰まって見えるのは、開始ボタンの上の余白4px(`pt-1`)が防ぐ。`LeftPanel`は子(本文領域)を受け、縦の列の右に本文領域を置き、本文領域を`ScreenMenuProvider`で包んでメニューの部品を渡す。部品は2つのメニューボタン(名前はどちらも「メニューを開く」)で、ドロワー用(`md:hidden`。押すと`drawerOpen`を開)と、列用(`railOpen`が閉の間だけ描き、`max-md:hidden`。押すと`railOpen`を開)である。押した時点の幅を調べずに済み、幅をまたいで値を引き継がないため、ボタンを分ける。開き口の帯は持たず、向き(`landscape`)を参照しない。ドロワーの閉じ込め(本文領域の`inert`、Tabの回送、Esc)と、幅768px以上かどうかの購読も持つ。ドロワーと背景は`fixed`(`z-50`、`z-40`)で、ヘッダーと点数キーボード(`z-30`)の上に重なる。入口のガードは `proxy.ts`、表示中の喪失は`(main)`のレイアウトが始める見張りが担う。
- `src/lib/supabase/infrastructure/client.ts`(共有の技術の実装): ブラウザの接続。入口が、接続を作る関数として認証の実装へ渡す。
- `src/lib/utils.ts`(共有の画面部品): クラス名の結合。

## 設計判断

| 判断 | 理由 | 見直す条件 |
| :--- | :--- | :--- |
| 入口のガードを `proxy.ts`、表示中の喪失の検知を `(main)` のレイアウトが始める見張りに分ける | `proxy.ts` はリクエスト時しか働かず、サインアウト・更新拒否・SWの枠を検知できないため。 | ガードを1か所にできる方式が出たとき。 |
| 喪失を `SIGNED_OUT` と、マウント時の `readSession` の未認証（保存先が空、またはサーバーの拒否が確定）に限る | `INITIAL_SESSION` のnullと `AuthRetryableFetchError` は通信失敗でも起き、入力中の画面を誤って遷移させるため使わない。 | supabase-jsのイベントの意味が変わったとき。 |
| 喪失の見張りを`(main)`のレイアウトが始める | 認証が要る画面の集合をルートグループで表し、除外リストを持たないため。`/offline` はSWが元のURLのまま返すため、パスでの除外は画面と食い違う。 | `(main)` の外に認証が要る画面を置くとき。 |
| `window.location.replace` で遷移する | 前の利用者の画面の状態とRouter Cacheを捨てるため。`router.push` は捨てられないため採らない。サインアウトの完了、セッションの喪失に加え、記録の利用者と違う利用者のサインイン(利用者の切り替え)の読み込み直しも、同じ部品(`createBrowserPageLoad`)で行う。サインインとサインアップの完了も、一覧が開いた後の読み込み直しを避け、読み込みを1回にするため、この部品で置き換える。 | Router Cacheを明示的に消せるようになったとき。 |
| 文字付きロゴは、文字を図形にしたSVGの画像で表示し、HTMLの文字で組まない | 表示する環境のフォントによらず同じ形にし、READMEと同じ画像にするため。マークだけを別の生成で作ると、マークを変えたときにロゴのマークが古い形で残るため、アイコンと同じスクリプトと値で作る。 | ダークモードを入れるとき。マークを別の方法で作るとき。 |
| 文字付きロゴに白い丸角の地を付け、明るい表示用の1種類にする | GitHubの暗い表示で黒い絵柄が見えなくならないため。アプリは白地なので地は見えない。暗い表示用の画像を分けると、画面とREADMEで同じ画像でなくなるため採らない。 | ダークモードを入れるとき。 |
| AIMSロゴ・リンクの遷移先を全画面で `/` にする | 認証画面を含め、どの画面からもアプリの入口へ戻れるようにするため。`/rounds` へは「ホーム」項目と紹介画面の「記録を始める」で移る。 | ロゴに別の役割を持たせるとき。 |
| proxy は `getClaims` で端末内に認証を判定する | 要求ごとに認証サービスへ問い合わせず、署名と期限を端末内で検証する(署名鍵は非対称鍵(JWKS)。ローカルと本番で確認)。サーバー側で無効にされたセッション(パスワード変更、停止、削除)は、アクセストークンの期限(3600秒)までページの枠が開き、期限後の更新の拒否で見張りが検知する。無効化後も期限内のトークンでは、データの読み書きは通る(ローカル実測)。署名の検証に失敗したときと `getClaims` が投げたときは未認証とする | 失効の即時の検知を要求に加えるとき。 |
| 明示のサインアウトの実行中は、見張りの遷移を行わず、サインアウトの判定に委ねる | 終えられたかと遷移の有無を1つの判定にするため。終えられたら、サインアウトの手続きが遷移元を付けずに移る | サインアウトの遷移を見張りに戻すとき |
| 配置を幅だけで決め、向きを使わない | 回転・ソフトキーボードで配置が変わらず、横向きで本文を押し広げないため。開き口をヘッダーのメニューボタンにし、横向きの左端の縦の帯は本文の幅を削るためやめた。 | 向きで配置を変えたい要求が出たとき。 |
| ヘッダー枠を共有の部品(`ScreenFrame`)にして各画面が描き、メニューボタンだけをレフトパネルが文脈で渡す | 中身(戻るの押せなさ、フィルターの条件、ラウンドの値)は画面の状態から決まり、画面が直接渡せるため。静的な枠のHTML(オフライン用の枠を含む)に中身まで含まれる。`(main)/layout.tsx`に枠を置きポータルで中身を差し込む案は、水和の後まで中身が出ず、画面の単体のテストに差し込み先が要るため採らない。 | 全画面で中身が同じになったとき。枠を描き忘れた画面が出たとき。 |
| ヘッダーの行は`max-w-xl`の列にそろえず、本文領域の幅いっぱいに置く | メニュー・戻る・操作を、画面の幅によらず本文領域の左右の端に置くため(ユーザーの指示)。広い画面では、ヘッダーの左右の端と本文の列の端はそろわない。 | ヘッダーと本文の列をそろえたい要求が出たとき。 |
| `ScreenFrame`の本文領域の枠はスクロールせず、スクロールの入れ物は各画面が持つ | 一部だけをスクロールする画面(詳細の`<main>`と下端の枠・右のパネル、ラウンドの開始画面の一覧と開始の帯)と、全体をスクロールする画面があり、入れ物の位置は画面の構成で決まるため。枠がスクロールすると、詳細・ラウンドの開始画面で入れ物が二重になる。 | 全画面で本文全体をスクロールするようになったとき。 |
| 点数キーボード(横向きの右のパネルを含む)を、ヘッダーの下の本文領域に置く | 階層(レフトパネル > ヘッダー > 点数キーボード)を構造で満たすため。ヘッダーの高さは一定なので、キーボードの領域は遷移・取得の状態で変わらない。 | 階層の要求が変わったとき。 |
| 開閉状態を、ドロワーと列の2つの真偽値で持つ | 表示ごとに必要な状態が違い（ドロワーは閉じ始め、列は開き始め）、項目の押下でドロワーだけを閉じられるため。初期値は固定で、幅で分岐しない（水和の不一致を避ける）。 | 幅をまたいで操作を引き継ぎたいとき。 |
| ドロワーと縦の列を別の枠にし、中身を共有の部品にする | スマートフォンの回転は幅768pxをまたぎ、1つの枠だと回転のたびに枠が動くため。 | 枠の切り替えの動きが不要になったとき（1つの枠に戻せる）。 |
| ドロワーの閉じ込めを自前(`inert`と`keydown`)で持ち、`@base-ui/react`のDialog・Drawerに置き換えない | 既存のスワイプの追従、背景のフェード、常にDOMにある枠、閉じたときにフォーカスを奪わない規則をそのまま保てるため。置き換えると、幅768px以上で`drawerOpen`が開のまま残る間もモーダルとして働かないよう、結局は幅の判定が要る。 | ドロワーにダイアログ類と同じ部品の振る舞い(入れ子、ポータル)が要るとき。 |
| 縦の列は格納(狭い幅)を持たず、閉じると幅0にし、開き口をヘッダーのメニューボタンにする | 閉じるボタンとメニューボタンが同じ位置に来て、開閉で押す位置が動かないため。メニューボタンの出し分けは`LeftPanel`が渡す部品の中で決め、`ScreenFrame`はドロワーと列を知らないままにする。 | 列に狭い幅の状態を戻すとき。 |
| 開閉のtransitionを常に付ける | 状態とタイマーを持たず、`transition` のclassだけで済ませるため。枠を別の要素にしたので、回転・窓の変形の切り替えでは動かない。 | 切り替えの動きが利用者に不都合になったとき。 |
| ラウンドの開始画面の入口を、レフトパネルの最上部とホームの右下の2つにし、画面の幅では出し分けない | 押しやすい位置が端末で逆になるため(スマートフォンは親指の届く右下、PCは他の操作に近いレフトパネル)。幅で出し分けて幅768px以上をレフトパネルだけにすると、レフトパネルを閉じたホームに入口が無くなる。幅768px未満をホームの右下だけにすると、ホーム以外の画面から入れなくなる。2つは同じ`/rounds/new`へのリンクで状態を持たないため、二重にしても食い違わない。幅768px以上でレフトパネルが開いたホームでは、同じ名前のリンクが2つ並ぶ | 入口の位置の要求が変わったとき。どちらかの入口が使われないと分かったとき。 |
| レフトパネルのラウンドの開始ボタンは、開始画面を表示中なら遷移しない | 同じURLへのリンクでもNext.jsは遷移の処理を行うため、開始画面の選択が保たれることを遷移の扱いに頼らず、既定の動作を止めて遷移そのものを起こさない。ドロワーは他の押下と同じく閉じる | 開始画面で押したときの要求が変わったとき。 |
| サインアウトをレフトパネルでなく設定パネルに置く | アカウントの操作を設定パネルの一か所にまとめ、レフトパネルを移動の項目だけにするため。レフトパネルは下端に「設定」項目を置く。詳細: `app/settings`。 | サインアウトをレフトパネルへ戻すとき。 |
| ヘッダーのアイコン(メニュー・戻る・ラウンドのメニュー・点数一覧のフィルター)は24pxで表示し、増えた分は内側の余白(6pxから4px。戻るは図柄の空白の切り落としも併用)を小さくして吸収し、押せる範囲(32px四方、戻るは高さ32pxと従来の幅)とヘッダー高さ45pxを変えない | 視認性を上げつつ、操作面とヘッダーの寸法・遷移時の不動を保つため。余白で寸法を決めるので、図柄が枠からはみ出さない。 | ヘッダーの高さや操作面を見直すとき。 |

## 表示領域の高さの補償

スタンドアロン(`display-mode: standalone`)かつ`navigator.virtualKeyboard`のある環境(Android Chrome系)では、起動時などに`100dvh`が可視の高さからずれ、画面の下端がはみ出すことがあった。
そのため`src/hooks/use-app-height.ts`の`useAppHeight`(入口`root-client-entry.tsx`が呼ぶ)が、可視の高さ(`visualViewport.height * scale`、無ければ`innerHeight`)を`--app-height`へpxで書く。`app/layout.tsx`のbodyの高さ(`h-(--app-height)`)と各画面の`h-full`が、これに従う。
書き直す契機は、マウント時、`window`の`resize`、`visualViewport`の`resize`だけで、直前の値との差が0.5px未満なら書かない。アンマウントで購読を全て解除する。
ブラウザのタブやiOS Safariでは何もせず、`--app-height`は既定の`100dvh`のままである。iOS Safariはキーボードでの縮み方が変わる恐れがあるため対象にしない。

削った契機: マウントから0.5秒・2秒後の再確認、`pageshow`・`orientationchange`・`visibilitychange`の購読。
- 理由: 実機でAndroid Chrome系は上記の契機がなくても補償の効果が確認でき、タイマーと購読が増えるだけの複雑さを避けるため。
- リスク: 通知(`resize`)なしに可視の高さが変わる環境で、値を取りこぼして下端がはみ出す恐れがある。はみ出しが起動直後、復帰直後、向きの変更後に再現したら、削った契機を`use-app-height.ts`へ戻す。

## 制約と未対応

- 開閉状態は画面遷移やリロードで初期状態へ戻る。
- オフラインではrefresh tokenの失効を検知できず、オンラインに戻った後の認証サービスの更新で検知する。
- 遷移の瞬間に未完了のIndexedDBの書き込みは中断されうる。
- 縦の列を閉じるとAIMSロゴは見えない（「ホーム」「点数一覧」「設定」項目と同じ）。
- ドロワーの閉じ込めは本文領域だけを`inert`にする。`body`直下のポータル(ダイアログ類)は対象外で、ドロワーの展開中にそれらが開くことは想定しない。
- 幅768px以上で縦の列を開閉すると本文領域の幅が変わり、ヘッダーの左端と、本文の大きさに従う表示(スコア入力の指す矢へのスクロールの追従など)が200msの間動く。
- 横向きの点数キーボードのパネルの高さは、画面の高さからヘッダー(45px)を除いた分である。キーが収まらない低い画面では、パネルの中のキーの領域がスクロールする。
- 認証画面とオフラインのページはヘッダー枠を持たない。紹介画面は共用のヘッダー枠を使わず、専用のヘッダーを持つ(`app/introduction`)。
