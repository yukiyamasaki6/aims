# navigation 設計

## 概要

`/`は認証状態によらず紹介画面を出し、開始ボタンの行き先だけを認証状態で分ける。
セッションを失ったら`/signin`へ移す（入口は`proxy.ts`、表示中は`(main)`のレイアウトが始める見張り）。
AIMSロゴ（レフトパネルと、認証画面・`/`・`/offline`の左上）は`/`へ戻る。
レフトパネルは画面の幅で、ドロワー（幅768px未満）と縦の列（幅768px以上）を別の枠として切り替える。ドロワーの開き口は、縦向きでは上端の横のバー、横向きでは左端の縦の帯である。

## 画面と状態

| 画面・状態 | 内容 |
| :--- | :--- |
| `/` | 未認証・認証済みとも、アプリ名、説明文、開始ボタンを持つ紹介画面を表示する。開始ボタンは常に`/signup`へのリンクで、認証済みなら`/signup`の認証済みの転送で`/rounds`へ着く。 |
| `/rounds` 配下（未認証） | 遷移元のパス付きで `/signin` へリダイレクトする。`/rounds/new`、`/rounds/[id]` も対象である。 |
| ロゴ | レフトパネルのAIMSロゴと、認証画面・`/`・`/offline` の左上のロゴは `/` へ遷移する。 |
| セッション喪失 | `SIGNED_OUT`（通知は発生元を区別せず届く）と、マウント時の `unauthenticated` で、遷移元のパス付きで `/signin` へ遷移する。明示のサインアウトの実行中の喪失は、サインアウトの判定に委ねる(終えられたら遷移元を付けずに移る。`auth/signout`)。`unknown` では留まる。保存先が空の未認証は、オフラインでもマウント時に `/signin` へ移り、`/offline` が出る。 |
| レフトパネルのリンク | 個人リンクは `/rounds` へ遷移する。サインアウトボタンは確認ダイアログを開く。 |
| レフトパネル（幅768px未満） | 開き口（縦向きは上端の帯、横向きは左端の縦の帯）を出す。始まりは格納。ハンバーガーボタンで展開し、閉じるボタン・背景で格納する。本文に重なる。 |
| レフトパネル（幅768px以上） | 縦の列に出す。始まりは展開。`toggle-wide` で格納・展開を切り替える。 |

- 開閉状態は2つの真偽値で持つ。ドロワーは `drawerOpen`（始まりは閉）、列は `railOpen`（始まりは開）。向きは開き口の形にだけ使い、値・枠には使わない。幅をまたいで往復しても、それぞれの値が保たれる。
- 開閉の幅と位置は、開閉の操作で200msのtransitionで動く。幅768pxをまたぐ切り替え（回転、窓の変形）は、ドロワーと縦の列が別の枠で切り替わるので動かない。初回表示は最初から切り替え後の状態で表示する。
- ドロワーの格納は画面外へ押し出し、`visibility: hidden` で、フォーカスと読み上げの対象から外す。DOMからは消えない。
- 個人リンクの押下は、ドロワーの値(`drawerOpen`)だけを閉にし、列の値(`railOpen`)を変えない。配置の判定はしない。

## 構成とデータの流れ

- `src/proxy.ts`(要求の入口): `/signin`、`/signup`、`/reset-password`、`/rounds/:path*` を対象に、`updateSession` が返すサインインしているかから、認証の機能の経路の規則(`features/auth/domain/auth-routes.ts` の `redirectFor`)を呼び、行き先があればリダイレクトし、無ければ `updateSession` の応答を返す。`config.matcher` は Next.js がビルド時に静的に読み、定数を参照できないため、経路を文字列で再掲し、`proxy.test.ts` が経路表の `ROUNDS_PATH` との一致を確かめる。`/` は対象外である。
- `src/lib/supabase/infrastructure/session.ts`(共有の技術の実装): `updateSession` が要求ごとにセッションを更新し、`getClaims`(端末内でトークンの署名と期限を検証する)でサインインしているかと、更新したcookieを書いた応答を返す。経路の規則は持たない。規則は認証の機能の `redirectFor` が持ち、`proxy.ts` が呼ぶ。
  - 未認証で `/rounds` 配下なら、`signInHref` で遷移元を付けた `/signin` へリダイレクトする。
  - 認証済みで `/signin`、`/signup`、`/reset-password` なら `/rounds` へリダイレクトする。`/signin` は有効な遷移元があればそこへ送る（`auth/signin`）。
- `src/features/auth/application/session.ts` の手続き`createSession`の`watch`が、セッション喪失の検知（`SIGNED_OUT`と、マウント時の`unauthenticated`）と、`/signin`への遷移（`replace`。今の場所を遷移元に付ける）、記録の利用者と違う利用者のサインインの検知と今の場所の読み込み直しを持つ。確かめた結果の喪失の定義(`lostByStatus`)は`domain/auth-change.ts`、遷移の規則（遷移元、サインアウトの実行中は移らない）は`domain/session-end-flow.ts`。手続きと実装はルートの入口(`app/root-client-entry.tsx`)がアプリで1つ生成し、`SessionProvider`で渡す。`(main)`のレイアウトは`useSession`で受け取り、見張りを始める。
- `src/app/page.tsx`(画面の入口): 静的な紹介画面の入口。紹介画面を描くだけで、開始の行き先は渡さない。
- `src/features/navigation/ui/intro-screen.tsx`(UI層): 紹介画面。アプリ名、説明文、左上のロゴ、開始ボタンを表示する。
- `src/features/navigation/ui/start-button.tsx`(UI層): 開始ボタン。経路表(`src/routes.ts`)の `SIGN_UP_PATH` へのリンクで、状態を持たない。
- `src/features/navigation/ui/navigation-messages.ts`(UI層): 紹介画面と左パネルの文言の一覧(名前空間`navigation`)。部品は`useTranslations("navigation")`で文言を得る。
- 遷移の約束(アプリ全体): ナビゲーションの機能は遷移の約束を持たない。開始の行き先は、経路表の `SIGN_UP_PATH` へ、`start-button.tsx` のリンクで遷移する。ルーターで進む遷移は共有の技術の `PageNavigation`(`src/lib/page-navigation/contract/page-navigation.ts`。認証のパスワード再設定とラウンドの開始、完了、削除して離れるが使う)、ページ全体の読み込みの遷移は認証の `PageReplace`(`src/features/auth/application/page-replace.ts`。実装は `infrastructure/browser-page-load.ts`。サインイン、サインアップの完了、サインアウト、セッションの喪失、利用者の不一致が使う)、遷移元の読み出しは画面の入口の `readReturnTo` である。
- `src/app/(main)/layout.tsx`(画面の入口): 認証が要る画面の集合の枠。入口が渡すセッションの手続きを`useSession`で受け取って見張りを始め、レフトパネルと、サインアウトの部品(`features/auth/ui/sign-out-button.tsx`)を描く。
- `src/components/app-logo.tsx`(共有の画面部品)が、認証画面・`/`・`/offline` の左上のロゴである。ロゴの行き先は、経路表(`src/routes.ts`)の `HOME_PATH`(`/`)で、`left-panel.tsx` のロゴも同じである。
- `src/components/logo-image.tsx`(共有の画面部品)が、文字付きロゴの画像（`public/logo.svg`）を表示する。代替テキスト「AIMS」がロゴのリンクの名前になる。`app-logo.tsx` と `left-panel.tsx` が使う。
- `public/logo.svg` は、`scripts/generate-icon.mjs` が、マークと同じ値と、`geist` のGeist SansのBoldの字形から生成する。文字は図形にし、フォントを参照しない。READMEの冒頭も同じファイルを表示する。
- `src/features/navigation/ui/left-panel.tsx`(UI層)が開閉（ドロワーと列の2つの値）とリンクを持つ。個人リンクは経路表(`src/routes.ts`)の `ROUNDS_PATH` を向き、下端に、入口が渡すサインアウトの部品（`features/auth/ui/sign-out-button.tsx`）を描く。認証状態は持たず、常に全内容を表示する。ドロワーの枠と縦の列の枠を別の要素にして、幅(`md:`)で出し分ける（中身=ロゴ・個人リンク・サインアウトは共有の部品を2つの枠に置く）。開き口の形だけ向き(`max-md:landscape:`)で決める。入口のガードは `proxy.ts`、表示中の喪失は`(main)`のレイアウトが始める見張りが担う。
- `src/lib/supabase/infrastructure/client.ts`(共有の技術の実装): ブラウザの接続。入口が、接続を作る関数として認証の実装へ渡す。
- `src/lib/utils.ts`(共有の画面部品): クラス名の結合。
- 各ファイルの用語は方針(`docs/architecture.md`)の既定の置き場に従う。画面のパッケージは `react`、`next-intl`、`next/link`、`next/image`、`lucide-react`、`clsx`、`tailwind-merge`、`class-variance-authority`、`@base-ui/react`、その他のパッケージは `@supabase/ssr`、`@supabase/supabase-js`、`next/server` である。

## 設計判断

| 判断 | 理由 | 見直す条件 |
| :--- | :--- | :--- |
| 入口のガードを `proxy.ts`、表示中の喪失の検知を `(main)` のレイアウトが始める見張りに分ける | `proxy.ts` はリクエスト時しか働かず、サインアウト・更新拒否・SWの枠を検知できないため。 | ガードを1か所にできる方式が出たとき。 |
| 喪失を `SIGNED_OUT` と、マウント時の `readSession` の未認証（保存先が空、またはサーバーの拒否が確定）に限る | `INITIAL_SESSION` のnullと `AuthRetryableFetchError` は通信失敗でも起き、入力中の画面を誤って遷移させるため使わない。 | supabase-jsのイベントの意味が変わったとき。 |
| 喪失の見張りを`(main)`のレイアウトが始める | 認証が要る画面の集合をルートグループで表し、除外リストを持たないため。`/offline` はSWが元のURLのまま返すため、パスでの除外は画面と食い違う。 | `(main)` の外に認証が要る画面を置くとき。 |
| `window.location.replace` で遷移する | 前の利用者の画面の状態とRouter Cacheを捨てるため。`router.push` は捨てられないため採らない。サインアウトの完了、セッションの喪失に加え、記録の利用者と違う利用者のサインイン(利用者の切り替え)の読み込み直しも、同じ部品(`createBrowserPageLoad`)で行う。サインインとサインアップの完了も、一覧が開いた後の読み込み直しを避け、読み込みを1回にするため、この部品で置き換える。 | Router Cacheを明示的に消せるようになったとき。 |
| 文字付きロゴは、文字を図形にしたSVGの画像で表示し、HTMLの文字で組まない | 表示する環境のフォントによらず同じ形にし、READMEと同じ画像にするため。マークだけを別の生成で作ると、マークを変えたときにロゴのマークが古い形で残るため、アイコンと同じスクリプトと値で作る。 | ダークモードを入れるとき。マークを別の方法で作るとき。 |
| 文字付きロゴに白い丸角の地を付け、明るい表示用の1種類にする | GitHubの暗い表示で黒い絵柄が見えなくならないため。アプリは白地なので地は見えない。暗い表示用の画像を分けると、画面とREADMEで同じ画像でなくなるため採らない。 | ダークモードを入れるとき。 |
| AIMSロゴ・リンクの遷移先を全画面で `/` にする | 認証画面を含め、どの画面からもアプリの入口へ戻れるようにするため。`/rounds` へは個人リンクと開始ボタンで移る。 | ロゴに別の役割を持たせるとき。 |
| 開始ボタンは常に `/signup` へのリンクにする | 紹介画面を静的に保ち、認証の確認を持たないため。認証済みなら `/signup` の認証済みの転送で `/rounds` へ着く(転送が1回増える)。確認を持つと、手続き・規則・インフラの3段で経路を受け渡す必要があった | 開始の行き先を認証状態で変えたいとき。 |
| proxy は `getClaims` で端末内に認証を判定する | 要求ごとに認証サービスへ問い合わせず、署名と期限を端末内で検証する(署名鍵は非対称鍵(JWKS)。ローカルと本番で確認)。サーバー側で無効にされたセッション(パスワード変更、停止、削除)は、アクセストークンの期限(3600秒)までページの枠が開き、期限後の更新の拒否で見張りが検知する。無効化後も期限内のトークンでは、データの読み書きは通る(ローカル実測)。署名の検証に失敗したときと `getClaims` が投げたときは未認証とする | 失効の即時の検知を要求に加えるとき。 |
| 明示のサインアウトの実行中は、見張りの遷移を行わず、サインアウトの判定に委ねる | 終えられたかと遷移の有無を1つの判定にするため。終えられたら、サインアウトの手続きが遷移元を付けずに移る | サインアウトの遷移を見張りに戻すとき |
| 配置を幅だけで決め、向きは開き口の形だけに使う | 回転・ソフトキーボードで配置が変わらず、横向きで本文を押し広げないため。 | 向きで配置を変えたい要求が出たとき。 |
| 開閉状態を、ドロワーと列の2つの真偽値で持つ | 表示ごとに必要な状態が違い（ドロワーは閉じ始め、列は開き始め）、個人リンクの押下でドロワーだけを閉じられるため。初期値は固定で、幅で分岐しない（水和の不一致を避ける）。 | 幅をまたいで操作を引き継ぎたいとき。 |
| ドロワーと縦の列を別の枠にし、中身を共有の部品にする | スマートフォンの回転は幅768pxをまたぎ、1つの枠だと回転のたびに枠が動くため。サインアウトの状態（確認の開閉・実行中・失敗）が2つの枠で別々になることは許容した。 | 枠の切り替えの動きが不要になったとき（1つの枠に戻せる）。 |
| 開閉のtransitionを常に付ける | 状態とタイマーを持たず、`transition` のclassだけで済ませるため。枠を別の要素にしたので、回転・窓の変形の切り替えでは動かない。 | 切り替えの動きが利用者に不都合になったとき。 |
| レフトパネルのサインアウトを確認ダイアログ経由にする | 誤操作を防ぐため。ダイアログはブロッキング方式に統一する。 | ダイアログをブロッキング方式以外にするとき。詳細: `auth/signout`。 |

## 制約と未対応

- 開閉状態は画面遷移やリロードで初期状態へ戻る。
- オフラインではrefresh tokenの失効を検知できず、オンラインに戻った後の認証サービスの更新で検知する。
- 遷移の瞬間に未完了のIndexedDBの書き込みは中断されうる。
- 縦の列でレフトパネルを格納するとAIMSロゴは隠れる（個人リンク・サインアウトと同じ）。
- サインアウトの状態は、ドロワーと縦の列の2つの枠で別々である。確認ダイアログを開いたまま枠が切り替わっても、ダイアログは開いたままである。
