# app/navigation

## 目的

利用者が、紹介画面、ラウンドのホームと点数一覧の画面、設定パネル、サインイン画面の間を迷わず移動できるようにする。

## 要求

### 紹介画面から始める

- 紹介画面(`/`)を開くと、サインインの有無によらず、アプリ名と説明文が表示される。
- 開始ボタンを押すと、サインインの有無によらずサインアップ画面へ移動する。認証済みの利用者は、サインアップ画面から、サインインの後の既定の行き先(ホーム)へ移動する。

### ロゴとレフトパネルから移動する

- 認証画面と紹介画面のAIMSロゴを押すと、紹介画面へ移動する。
- レフトパネルのAIMSロゴを押すと、紹介画面へ移動する。
- レフトパネル/ドロワーの上部の「ホーム」項目を押すとホームへ、「点数一覧」項目を押すと点数一覧へ移動する。ただし、幅768px以上で設定パネルが開いている間は、押しても設定パネルが閉じるだけで移動しない(app/settingsで扱う)。項目は、ホーム・点数一覧・詳細・作成のどの画面でも表示される。
- レフトパネル/ドロワーのホーム・点数一覧・設定の各移動項目は、文字の項目名とともに用途に対応するアイコンを表示し、キーボードと支援技術で識別・操作できる。
- ホームか点数一覧を表示しているときは、設定パネルが開いている間を除き、その項目が現在のビューとして識別でき、支援技術に現在のビューとして伝わる。詳細・作成画面では、どちらも現在のビューにならない。
- 項目はキーボードで操作できる。ドロワーを開く操作と項目の表示は、履歴の取得を起動しない。
- レフトパネル/ドロワーの下部の「設定」項目を押すと、今の画面の上に設定パネルが開く(app/settingsで扱う)。レフトパネル/ドロワーにサインアウトボタンは表示されない。

### レフトパネルを開閉する

- 幅768px未満の画面では、向きによらず、レフトパネルが格納された状態で始まる。
- 幅768px以上の画面では、レフトパネルが展開された状態で始まる。
- 幅768px未満の画面では、メニューボタンを押すとレフトパネルが展開され、本文に重なって中身が見える。
- 幅768px未満の画面では、閉じるボタンまたは背景を押すとレフトパネルが格納され、中身が見えなくなる。
- 幅768px以上の画面では、レフトパネルの閉じるボタンを押すとレフトパネルが閉じ、メニューボタンを押すと開く。レフトパネルは幅を狭めた状態(格納)を持たず、閉じている間は中身が見えず、本文が画面の全幅を使う。開閉の格納・展開のボタンは存在しない。
- 幅768px以上でレフトパネルが開くと、本文を押しのけて横に並ぶ。開閉は、幅の変化として今と同じ時間で動く。
- 幅768px以上で、レフトパネルを開くとキーボードのフォーカスがレフトパネルの閉じるボタンへ移り、閉じるとメニューボタンへ移る。
- 幅768px未満でレフトパネルが格納されているときと、幅768px以上でレフトパネルが閉じているときは、中身にキーボードのフォーカスが届かず、支援技術にも伝わらない。
- 幅768px未満でレフトパネル(ドロワー)が展開されている間は、キーボードのフォーカスがドロワーの中に留まり(末尾のTabで先頭へ、先頭のShift+Tabで末尾へ回る)、ドロワーの外の内容はキーボード・支援技術の操作・読み上げの対象にならない。ドロワーの背景はフォーカスの対象にならない。Escキーを押すとドロワーが格納される。閉じたあとは外の内容が元どおり操作できる。
- 幅768px未満で、ドロワーを開くとフォーカスがドロワー内へ移り、閉じるとメニューボタンへ戻る(別の要素に既にフォーカスがあれば奪わない)。「設定」項目を押してドロワーが格納されたときは、フォーカスは開いた設定パネルへ移る(app/settingsで扱う)。
- 幅768px以上のレフトパネルは本文と並ぶため、フォーカスをパネル内に閉じ込めず、Escキーでも閉じない。
- 幅768px未満でレフトパネルが展開されているときに「ホーム」「点数一覧」「設定」項目を押すと、レフトパネルが格納される。幅768px以上では、項目を押しても開閉は変わらない。

### ヘッダーから現在地と操作を得る

- `/rounds/history`の画面見出しは、レフトパネル/ドロワーの項目名と同じ「点数一覧」と表示される。

- ログイン後(`/rounds`配下)の全画面で、ヘッダーが同じ位置・同じ高さに表示される。画面の遷移や取得中から表示への切り替えでは動かない。幅768px以上では、レフトパネルの開閉によってヘッダーの左端が変わる。
- ホーム、点数一覧、作成では、ヘッダーに現在地の名称が表示され、支援技術に見出しとして伝わる(幅によらない)。設定パネルを開いても、背景の画面のヘッダーの現在地は変わらない。
- 作成のヘッダーには戻る(ホームへ)がある。この戻るは本文には置かない。
- 点数一覧のフィルター入口はヘッダーの右にある。ホームの新規ラウンドの追加ボタンは右下に残る。
- ラウンド詳細(スコア入力を含む)のヘッダーには、戻る、プリセット保存、ラウンドメニューがある(従来と同じ)。
- 幅768px未満では、ヘッダーの左端にメニューボタン(名称「メニューを開く」)があり、戻るがある画面ではその右に戻るがある。向きによらず同じで、縦向きの上端の帯と横向きの左端の縦の帯は表示されない。
- 幅768px以上では、レフトパネルが閉じている間だけ、ヘッダーの左端にメニューボタンが表示される。レフトパネルが開いている間は表示されない。メニューボタンが表示されるときは、戻るがある画面ではその右に戻るがある。
- ドロワー(幅768px未満)とレフトパネル(幅768px以上)の閉じるボタンは、パネル内の最上段の行の左端にあり、その右にAIMSロゴが並ぶ。閉じるボタンの位置は、メニューボタンの位置とおよそ同じである。
- 階層は、レフトパネル、ヘッダー、点数キーボードの順である。幅768px以上ではレフトパネルが開いている間、全高の列で、ヘッダーはその右の本文側の上端にあり、閉じている間はヘッダーが画面の左端から始まり、点数キーボードはヘッダーの下にある(横向きでも同じ)。幅768px未満では、展開したドロワーがヘッダーとキーボードの上に重なる。向きで変わるのはキーボードの大きさだけである。

### 画面の向きや幅が変わったとき

- 開閉を操作していないときは、画面の向きや幅が変わると、レフトパネルは変わった後の画面の始まりの状態で表示される。
- 幅768px以上でレフトパネルを開閉した後は、幅が変わって戻っても、同じ状態で表示される。開閉の状態はメモリ上だけで持ち、再読み込みすると開いた状態に戻る。幅768px未満でレフトパネルを展開した後は、向きを変えても、幅768px未満の間は展開されたままで、幅が変わって戻っても保たれる。幅768px以上と幅768px未満の間で、開閉の状態は引き継がれない。

### サインインしていないとき、サインインが切れたとき

- 未認証でラウンドの画面(`/rounds`、`/rounds/history`とその下の画面)を開くと、サインイン画面へ移動する。保存先が空の未認証の端末は、オフラインで開いても移動し、オフライン画面が表示される。
- 再読み込みや画面の遷移で未認証と確定すると、サインイン画面へ移動する。別のタブのサインアウトの通知による移動は、保証も禁止もしない。
- サーバー側で無効にされたセッションが、アクセストークンの期限を過ぎて更新を拒否されると、サインイン画面へ移動する。
- 未認証で開いたとき、またはサインインが切れたときにサインイン画面へ移動する場合、`/rounds`とその下の画面(`/rounds/history`、`/rounds/new`など)からは、開いていた画面が遷移元として付く。設定パネルのハッシュを遷移元に含めることは、app/settingsで扱う。
- セッションの更新が通信の失敗で終わったときは、サインイン画面へ移動せず、画面に留まる。
- オンラインに戻ったときのセッションの更新が別の書き手の更新と重なっても、サインイン画面へ移動せず、画面に留まる。

## 対象外

- サインアウトの確認、実行、失敗の表示と、その操作の置き場は、auth/signoutとapp/settingsで扱う。
- サインイン後に遷移元へ戻ることと、認証済みで認証画面を開いたときの移動は、auth/signin、auth/signup、auth/password-resetで扱う。
- オフラインで開いたときの画面と、その画面からの復帰は、app/offline-pwaで扱う。
- レフトパネルの開閉の状態は、画面の移動や再読み込みの後には保たれない。
- オフラインの間は、サインインの失効を検知せず、オンラインに戻った後の認証サービスの更新で検知する。
