# app/navigation

## 目的

利用者が、紹介画面、ラウンドの画面、サインイン画面の間を迷わず移動できるようにする。

## 要求

### 紹介画面から始める

- 紹介画面(`/`)を開くと、サインインの有無によらず、アプリ名と説明文が表示される。
- 開始ボタンを押すと、サインインの有無によらずサインアップ画面へ移動する。認証済みの利用者は、サインアップ画面から、サインインの後の既定の行き先(ラウンド一覧)へ移動する。

### ロゴとレフトパネルから移動する

- 認証画面と紹介画面のAIMSロゴを押すと、紹介画面へ移動する。
- レフトパネルのAIMSロゴを押すと、紹介画面へ移動する。
- レフトパネルの個人リンクを押すと、ラウンド一覧へ移動する。
- レフトパネルのサインアウトボタンを押すと、サインアウトの確認ダイアログが表示される。

### レフトパネルを開閉する

- 幅768px未満の画面では、向きによらず、レフトパネルが格納された状態で始まる。
- 幅768px以上の画面では、レフトパネルが展開された状態で始まる。
- 幅768px未満の画面では、ハンバーガーボタンを押すとレフトパネルが展開され、本文に重なって中身が見える(縦向きでは上端の帯、横向きでは左端の縦の帯がハンバーガーボタンを持つ)。
- 幅768px未満の画面では、閉じるボタンまたは背景を押すとレフトパネルが格納され、中身が見えなくなる。
- 幅768px以上の画面では、格納ボタンと開くボタンで、レフトパネルを格納・展開できる。
- 幅768px未満でレフトパネルが格納されているときは、中身にキーボードのフォーカスが届かない。
- 幅768px未満でレフトパネルが展開されているときに個人リンクを押すと、レフトパネルが格納される。幅768px以上では、個人リンクを押しても開閉は変わらない。

### 画面の向きや幅が変わったとき

- 開閉を操作していないときは、画面の向きや幅が変わると、レフトパネルは変わった後の画面の始まりの状態で表示される。
- 幅768px以上でレフトパネルを格納・展開した後は、幅が変わって戻っても、同じ状態で表示される。幅768px未満でレフトパネルを展開した後は、向きを変えても、幅768px未満の間は展開されたままで、幅が変わって戻っても保たれる。幅768px以上と幅768px未満の間で、開閉の状態は引き継がれない。

### サインインしていないとき、サインインが切れたとき

- 未認証でラウンドの画面(`/rounds`とその下の画面)を開くと、サインイン画面へ移動する。保存先が空の未認証の端末は、オフラインで開いても移動し、オフライン画面が表示される。
- 再読み込みや画面の遷移で未認証と確定すると、サインイン画面へ移動する。別のタブのサインアウトの通知による移動は、保証も禁止もしない。
- サーバー側で無効にされたセッションが、アクセストークンの期限を過ぎて更新を拒否されると、サインイン画面へ移動する。
- 未認証で開いたとき、またはサインインが切れたときにサインイン画面へ移動する場合、`/rounds`とその下の画面(`/rounds/new`など)からは、開いていた画面が遷移元として付く。
- セッションの更新が通信の失敗で終わったときは、サインイン画面へ移動せず、画面に留まる。
- オンラインに戻ったときのセッションの更新が別の書き手の更新と重なっても、サインイン画面へ移動せず、画面に留まる。

## 対象外

- サインアウトの確認、実行、失敗の表示は、auth/signoutで扱う。
- サインイン後に遷移元へ戻ることと、認証済みで認証画面を開いたときの移動は、auth/signin、auth/signup、auth/password-resetで扱う。
- オフラインで開いたときの画面と、その画面からの復帰は、app/offline-pwaで扱う。
- レフトパネルの開閉の状態は、画面の移動や再読み込みの後には保たれない。
- オフラインの間は、サインインの失効を検知せず、オンラインに戻った後の認証サービスの更新で検知する。
