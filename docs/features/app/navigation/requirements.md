# app/navigation

## 目的

利用者が、紹介画面、ラウンドの画面、サインイン画面の間を迷わず移動できるようにする。

## 要求

### 紹介画面から始める

- 紹介画面(`/`)を開くと、サインインの有無によらず、アプリ名と説明文が表示される。
- 未認証で開始ボタンを押すと、サインアップ画面へ移動する。
- 認証済みで開始ボタンを押すと、ラウンド一覧へ移動する。
- サインインの状態の確認が通信の失敗などで「不明」になったとき(オフラインを含む)に開始ボタンを押すと、ラウンド一覧へ移動する。

### ロゴとレフトパネルから移動する

- 認証画面と紹介画面のAIMSロゴを押すと、紹介画面へ移動する。
- レフトパネルのAIMSロゴを押すと、紹介画面へ移動する。
- レフトパネルの個人リンクを押すと、ラウンド一覧へ移動する。
- レフトパネルのサインアウトボタンを押すと、サインアウトの確認ダイアログが表示される。

### レフトパネルを開閉する

- 狭い画面では、向きによらず、レフトパネルが格納された状態で始まる。
- 広い画面では、レフトパネルが展開された状態で始まる。
- 縦向きで狭い画面では、ハンバーガーボタンを押すとレフトパネルが展開され、中身が見える。
- 縦向きで狭い画面では、閉じるボタンを押すとレフトパネルが格納され、中身が見えなくなる。
- 縦向きで狭い画面でレフトパネルが展開されているときは、背景を押すとレフトパネルが格納され、中身が見えなくなる。
- 広い画面と、横向きで狭い画面では、開くボタンを押すとレフトパネルが展開され、中身が見える。
- 広い画面と、横向きで狭い画面では、格納ボタンを押すとレフトパネルが格納され、中身が見えなくなる。

### 画面の向きや幅が変わったとき

- 開閉を操作していないときは、画面の向きや幅が変わると、レフトパネルは変わった後の画面の始まりの状態で表示される。
- 開閉を操作した後は、画面の向きや幅が変わっても、レフトパネルは最後の操作の結果(展開か格納)のまま表示される。

### サインインしていないとき、サインインが切れたとき

- 未認証でラウンドの画面(`/rounds`とその下の画面)を開くと、サインイン画面へ移動する。
- 別のタブでサインアウトすると、開いているラウンドの画面もサインイン画面へ移動する。
- サーバー側で無効にされたセッションが、アクセストークンの期限を過ぎて更新を拒否されると、サインイン画面へ移動する。
- 未認証で開いたとき、またはサインインが切れたときにサインイン画面へ移動する場合、`/rounds`より下の画面(`/rounds/new`など)からは、開いていた画面が遷移元として付く。
- 未認証で開いたとき、またはサインインが切れたときにサインイン画面へ移動する場合、`/rounds`からは、遷移元が付かない。
- セッションの更新が通信の失敗で終わったときは、サインイン画面へ移動せず、画面に留まる。
- オンラインに戻ったときのセッションの更新が別の書き手の更新と重なっても、サインイン画面へ移動せず、画面に留まる。

## 対象外

- サインアウトの確認、実行、失敗の表示は、auth/signoutで扱う。
- サインイン後に遷移元へ戻ることと、認証済みで認証画面を開いたときの移動は、auth/signin、auth/signup、auth/password-resetで扱う。
- オフラインで開いたときの画面と、その画面からの復帰は、app/offline-pwaで扱う。
- レフトパネルの開閉の状態は、画面の移動や再読み込みの後には保たれない。
- オフラインの間は、サインインの失効を検知せず、オンラインに戻った後の更新で検知する。
