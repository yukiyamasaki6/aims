# app/navigation

## 目的

利用者が、紹介画面、ラウンドのホームと履歴の画面、設定画面、サインイン画面の間を迷わず移動できるようにする。

## 要求

### 紹介画面から始める

- 紹介画面(`/`)を開くと、サインインの有無によらず、アプリ名と説明文が表示される。
- 開始ボタンを押すと、サインインの有無によらずサインアップ画面へ移動する。認証済みの利用者は、サインアップ画面から、サインインの後の既定の行き先(ホーム)へ移動する。

### ロゴとレフトパネルから移動する

- 認証画面と紹介画面のAIMSロゴを押すと、紹介画面へ移動する。
- レフトパネルのAIMSロゴを押すと、紹介画面へ移動する。
- レフトパネル/ドロワーの上部の「ホーム」項目を押すとホームへ、「履歴」項目を押すと履歴へ移動する。項目は、ホーム・履歴・詳細・作成のどの画面でも表示される。
- ホームか履歴を表示しているときは、その項目が現在のビューとして識別でき、支援技術に現在のビューとして伝わる。詳細・作成画面では、どちらも現在のビューにならない。
- 項目はキーボードで操作できる。ドロワーを開く操作と項目の表示は、履歴の取得を起動しない。
- レフトパネル/ドロワーの下部の「設定」項目を押すと設定画面へ移動する(app/settingsで扱う)。レフトパネル/ドロワーにサインアウトボタンは表示されない。

### レフトパネルを開閉する

- 幅768px未満の画面では、向きによらず、レフトパネルが格納された状態で始まる。
- 幅768px以上の画面では、レフトパネルが展開された状態で始まる。
- 幅768px未満の画面では、メニューボタンを押すとレフトパネルが展開され、本文に重なって中身が見える。
- 幅768px未満の画面では、閉じるボタンまたは背景を押すとレフトパネルが格納され、中身が見えなくなる。
- 幅768px以上の画面では、格納ボタンと開くボタンで、レフトパネルを格納・展開できる。
- 幅768px未満でレフトパネルが格納されているときは、中身にキーボードのフォーカスが届かない。
- 幅768px未満でレフトパネルが展開されているときに「ホーム」「履歴」「設定」項目を押すと、レフトパネルが格納される。幅768px以上では、項目を押しても開閉は変わらない。

### ヘッダーから現在地と操作を得る

- ログイン後(`/rounds`、`/settings`配下)の全画面で、ヘッダーが同じ位置・同じ高さに表示される。画面の遷移や取得中から表示への切り替えで動かない。
- ホーム、履歴、作成、設定、メール変更、パスワード変更、アカウント削除では、ヘッダーに現在地の名称が表示され、支援技術に見出しとして伝わる(幅によらない)。
- 作成のヘッダーには戻る(ホームへ)がある。メール変更・パスワード変更・アカウント削除のヘッダーには、段階によらず戻る(設定へ)がある。アカウント削除の戻るは、削除の処理中は押せない。これらの戻るは本文には置かない。
- 履歴のフィルター入口はヘッダーの右にある。ホームの新規ラウンドの追加ボタンは右下に残る。
- ラウンド詳細(スコア入力を含む)のヘッダーには、戻る、プリセット保存、ラウンドメニューがある(従来と同じ)。
- 幅768px未満では、ヘッダーの左端にメニューボタン(名称「メニューを開く」)があり、戻るがある画面ではその右に戻るがある。向きによらず同じで、縦向きの上端の帯と横向きの左端の縦の帯は表示されない。
- 幅768px以上では、メニューボタンは表示されない。
- 階層は、レフトパネル、ヘッダー、点数キーボードの順である。幅768px以上ではレフトパネルが全高の列で、ヘッダーはその右の本文側の上端にあり、点数キーボードはヘッダーの下にある(横向きでも同じ)。幅768px未満では、展開したドロワーがヘッダーとキーボードの上に重なる。向きで変わるのはキーボードの大きさだけである。

### 画面の向きや幅が変わったとき

- 開閉を操作していないときは、画面の向きや幅が変わると、レフトパネルは変わった後の画面の始まりの状態で表示される。
- 幅768px以上でレフトパネルを格納・展開した後は、幅が変わって戻っても、同じ状態で表示される。幅768px未満でレフトパネルを展開した後は、向きを変えても、幅768px未満の間は展開されたままで、幅が変わって戻っても保たれる。幅768px以上と幅768px未満の間で、開閉の状態は引き継がれない。

### サインインしていないとき、サインインが切れたとき

- 未認証でラウンドの画面(`/rounds`、`/rounds/history`とその下の画面)または設定画面(`/settings`とその下の画面)を開くと、サインイン画面へ移動する。保存先が空の未認証の端末は、オフラインで開いても移動し、オフライン画面が表示される。
- 再読み込みや画面の遷移で未認証と確定すると、サインイン画面へ移動する。別のタブのサインアウトの通知による移動は、保証も禁止もしない。
- サーバー側で無効にされたセッションが、アクセストークンの期限を過ぎて更新を拒否されると、サインイン画面へ移動する。
- 未認証で開いたとき、またはサインインが切れたときにサインイン画面へ移動する場合、`/rounds`とその下の画面(`/rounds/history`、`/rounds/new`など)と`/settings`とその下の画面からは、開いていた画面が遷移元として付く。
- セッションの更新が通信の失敗で終わったときは、サインイン画面へ移動せず、画面に留まる。
- オンラインに戻ったときのセッションの更新が別の書き手の更新と重なっても、サインイン画面へ移動せず、画面に留まる。

## 対象外

- サインアウトの確認、実行、失敗の表示と、その操作の置き場は、auth/signoutとapp/settingsで扱う。
- サインイン後に遷移元へ戻ることと、認証済みで認証画面を開いたときの移動は、auth/signin、auth/signup、auth/password-resetで扱う。
- オフラインで開いたときの画面と、その画面からの復帰は、app/offline-pwaで扱う。
- レフトパネルの開閉の状態は、画面の移動や再読み込みの後には保たれない。
- オフラインの間は、サインインの失効を検知せず、オンラインに戻った後の認証サービスの更新で検知する。
