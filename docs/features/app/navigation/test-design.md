# レフトパネルの移動項目と点数一覧見出しのテスト設計

## 基準と範囲

基準は、[navigationの要件](requirements.md)・[設計](design.md)と、[rounds/historyの要件](../../rounds/history/requirements.md)・[設計](../../rounds/history/design.md)である。
今回の変更である「点数一覧」への項目名・見出しの統一、ホーム・点数一覧・設定の装飾アイコン、設定上部の区切り線削除と、それらが触れる既存の操作を検証する。
本書は本体コードやテストコードの実装結果から期待値を導かない。
テストの配置候補は既存ファイルを利用するための案であり、部品の内部構造やprivateな関数を契約にしない。

最初に移動先の誤り、現在地の誤表示、キーボード操作不能を防ぎ、次に名称・見出しの不一致と不要な取得を防ぐ。
アイコンの図柄と区切り線も必須の受入対象とし、表示確認を省略しない。
認証、DB/RPC、並べ替え・絞り込みの計算や保存形式は変更対象外であり、新しい網羅テストやDBテストは設けない。

## 層と観測方法

| 層 | 保証する内容 | 観測方法 |
| --- | --- | --- |
| 単体・コンポーネント（Vitest） | 指定文言、アクセシブルな名前、装飾アイコンの扱い、完全一致の現在地、一覧の各状態の見出し | 公開されるUIを描画し、role・名前・aria-current・アイコンのaria-hiddenを確認する。 |
| 結合（Vitest） | メニュー開閉と一覧の取得境界の分離、一覧状態とメニューの接続 | パネル・画面・一覧の手続きを実物で接続し、取得境界の外側だけを制御する。 |
| 結合（Playwright） | リンクの押下、URL・遷移先画面、フォーカスとブラウザの操作可否 | 実ブラウザでリンクを操作する。認証など主対象外の境界を制御する場合は結合とする。 |
| E2E（Playwright） | 点数一覧から完了ラウンドを見つけて開く主要経路 | 実ブラウザ・認証・ローカルDBを通す。 |
| 手動確認 | 図柄、アイコンと文字の配置、設定の区切り線と下端配置、現在地の強調 | ビルドを含むpreviewで両画面幅の表示を比較する。 |

リンク先は単体のhrefだけでは保証せず、ブラウザで押してURLと表示先を確かめる。
固定のCSSクラス、SVGのpath、アイコンライブラリの内部構造、DOM全体のスナップショットは期待値にしない。
設計にある図柄House・ListOrdered・Settingsと寸法・配置は手動で確認し、装飾であることは単体でも確認する。

## 単体・コンポーネントのケース

配置候補は`apps/web/src/features/navigation/ui/left-panel.test.tsx`と`apps/web/src/features/rounds/ui/rounds-history.test.tsx`である。
以下はケース名の案であり、異なる操作は別テストにする。

| テスト名の案 | 前提・操作 | 期待結果 |
| --- | --- | --- |
| 開いたメニューには文字で識別できる3つの移動項目がある | パネルを開いて描画する。 | ホーム・点数一覧・設定のリンクがあり、名前の重複がない。サインアウトボタンはない。 |
| 点数一覧の項目名は指定された日本語で表示される | 開いたメニューを描画する。 | 表示文字列とリンク名が文字列「点数一覧」に一致する。「履歴」「一覧」の名前のリンクはない。 |
| 移動項目のアイコンはリンク名と操作対象を増やさない | 各項目を描画する。 | 各項目に装飾アイコンがあり、aria-hiddenがtrueで、独立したボタン・リンク・フォーカス対象を追加しない。リンクの名前は文字ラベルだけである。 |
| 現在の画面と完全一致する項目だけが現在地になる | ホーム、点数一覧、設定のパスをそれぞれ与えて描画する。 | 対応する1項目だけがaria-current="page"になる。 |
| 詳細と作成ではホームと点数一覧を現在地にしない | 実在可能な詳細のパスと`/rounds/new`をそれぞれ与えて描画する。 | ホームと点数一覧のどちらにもaria-current="page"が付かない。 |
| 点数一覧の見出しは取得状態にかかわらず表示される | 先頭取得中、成功0件、成功1件以上、通信失敗、オフラインを個別に用意して画面を描画する。 | heading level 1の文字列が「点数一覧」である。本文の状態表示やカードも各前提に対応する。 |
| 点数一覧の見出しはSuspenseの待機中も表示される | 未解決の待機を制御し、代替表示を表示する。 | heading level 1の文字列が「点数一覧」である。通常表示に移っても同じ名称を保つ。 |

メニューの項目表示はホーム・点数一覧・詳細・作成で確認する。
現在地の詳細なパス組合せは単体に集め、同じ表をE2Eで繰り返さない。
通常の探索と期待値には翻訳ヘルパーを使い、名称そのものを保証する上記のケースだけは「点数一覧」を直接期待する。
文言のテスト名に、指定された日本語を確認する目的を明示する。

## 一覧とメニューの結合ケース

配置候補は、実物の画面とパネルを組み立てられるnavigationまたはroundsのUI結合テストとする。
片方の部品を偽物にして、この接続を保証した扱いにはしない。
一覧の状態は先頭取得中・空・成功・通信失敗・オフラインを用意し、見出しとメニューの整合を検証する。

| テスト名の案 | 前提・操作 | 期待結果 |
| --- | --- | --- |
| 一覧の状態によらずメニューを開くと同じ項目を利用できる | 各一覧状態を成立させ、狭い画面でメニューを開く。広い画面では開いた状態を描画する。 | 3項目の文字・装飾アイコン・名前が保たれ、見出しは「点数一覧」のままである。 |
| メニューの表示と開閉だけでは履歴を取得しない | ホームを表示し、メニューを開く、または閉じて開く。 | 履歴取得境界に要求が出ず、ホームの表示が維持される。 |
| 点数一覧のメニューを開閉しても取得を追加しない | 先頭取得を保留した場合と取得済みの場合を別に用意し、メニューを開閉する。 | 準備時点から新たな履歴取得要求が増えず、保留中の取得を解除した結果も通常どおり表示される。 |
| 通信失敗後に再試行すると結果と見出しが表示される | 通信失敗の状態を用意し、次の取得を成功させて再試行を押す。 | 一覧が成功表示になり、見出しとメニューの項目名は「点数一覧」のままである。 |

不要な取得の検証に限り、取得境界の観測記録を操作前後で比較する。
内部Effectの回数、購読回数、描画回数、内部の呼び出し順は固定しない。
既存の同等の検証があれば更新・再利用し、重複するテストは追加しない。
再試行の失敗表示と成功は別の振る舞いとして分け、成功テストでは失敗済みの状態を準備に置く。

## ブラウザでの遷移とフォーカス

配置候補は`apps/web/tests/e2e/app/navigation.spec.ts`で、点数一覧側の経路は`apps/web/tests/e2e/rounds/history.spec.ts`も利用する。
ブラウザテストの種別は配置先ではなく、実物で通す境界で決める。
リンクは1リンク1件とし、ホーム・点数一覧・設定をそれぞれ押して、遷移先のpathnameと対応する見出しを確認する。
狭い画面と広い画面の両方で、この3項目の操作を確認する。
点数一覧は表示開始後に`return=1`が付くため、クエリなしURLへの完全一致を期待しない。
リンクの選択時は、狭い画面ではドロワーが閉じ、広い画面では開いたパネルが維持されることも観測する。
キーボードでTab移動してEnterで点数一覧を選ぶケースを含め、アイコンが余分なTab停止点を作らないことを確認する。

既存の開閉・フォーカスの安全網は次の範囲を実行し、不足がある場合だけ補う。

- 狭い画面では初期に閉じており、開くと閉じるボタンへフォーカスが移り、TabとShift+Tabがドロワー内で回る。
- Esc、閉じるボタン、背景による閉鎖を別ケースで確認し、外の操作を再開できる。
- 閉じたパネルにはキーボードと支援技術から届かず、開いた狭いドロワーの外も操作・読み上げの対象外になる。
- 広い画面では初期に開いており、閉じるとメニューボタン、開くと閉じるボタンへフォーカスが移る。
- 広い画面ではTabが本文へ進み、Escでは閉じない。
- 閉じる時点で別の要素にフォーカスが移っている場合は奪わない。
- 幅767・768・769pxで768pxを境に枠と初期状態が変わり、幅の往復でドロワーと列の操作済み状態を相互に引き継がず、それぞれ保つ。
- 再読み込みで初期状態へ戻る。

境界値767・768・769pxは同じテスト内で比較し、それ以外の状態保持ケースとは分ける。
表示・非表示の結果は実ブラウザで確認し、重なりによる操作阻害を調べる場合はelementFromPointで最前面を確かめる。
位置・寸法・スタイルをE2Eの期待値にしない。

## E2Eの主要経路

認証済みのローカル利用者に、サーバー反映済みの完了ラウンドと端末の入力中ラウンドを用意する。
ホームで入力中ラウンドが表示されたことを確認し、メニューの「点数一覧」を選び、見出しと完了ラウンドの名前・実施日・合計点が表示されたことを確認して、そのカードから該当ラウンドの詳細を開けることを確認する。
点数一覧には入力中ラウンドが混ざらないことを確認する。
この経路は既存の同等ケースを再利用し、画面幅と一覧状態の全組合せをE2Eへ追加しない。

## 手動での表示確認

`pnpm preview`をport 3000で起動し、ビルド済みの表示で確認する。
比較対象は設計で定めた外観と、利用できる場合は変更前の同じ画面幅の画像とする。
変更前画像がない場合は、その制約を報告し、比較したと記録しない。

| 条件 | 確認内容 |
| --- | --- |
| 幅375pxのドロワーと幅1024pxのレフトパネル | ホームは家（House）、点数一覧は番号付きリスト（ListOrdered）、設定は歯車（Settings）で、全項目に文字が残る。 |
| 同上 | アイコンが文字の左で上下中央に並び、20px四方・間隔8pxを基準として縮まず、文字色を継承する。 |
| 同上 | 設定上部の区切り線がなく、設定は従来の下端の位置と余白を保つ。項目順、ロゴ、閉じるボタンの配置が維持される。 |
| 各項目の現在地表示 | 背景と文字の強調が維持され、アイコンも文字と整合する。 |
| 狭い画面で縦向き・横向き、開閉途中 | アイコンと文字が収まり、開閉の動きやクリック可能範囲を損なわない。 |
| 点数一覧の取得中・空・成功・失敗・オフライン | メニューと見出しの名称が一致し、他画面の名称・操作の見た目に意図しない変更がない。 |

## データと実行上の条件

文言を描く単体・コンポーネントテストはIntlTestProviderを使い、未登録キーは失敗させる。
内部依存は実物とし、取得の成功・保留・失敗は所有するI/O境界の外側で制御する。
時刻・通信状態・画面幅の制御には共有のClock・Connectivity・Viewportの偽物を使い、実ブラウザでは実際のviewportを変更する。
待機は画面状態や制御したPromiseの解決を使い、任意秒数のsleepや実ネットワークのタイムアウトに依存しない。
完了ラウンドのデータは実際の屋外構成（各距離12エンド×3射または6エンド×6射）を満たし、点数も固定する。
データ量を理由に成立しない短縮ラウンドを作らない。
E2Eは有効なローカル認証・DB接続設定を使い、本番の秘密情報・共有DB・DBリセットは利用しない。
設定が不足する場合は実行できた検証と未確認のケースを分けて報告する。

単体はGiven・When・Thenを分けて正常系から異常系の順に実装し、各テストは1つの前提と操作による結果を確かめる。
ブラウザは利用者の操作順に書き、複数段階では遷移先・状態を確認してから次へ進む。
失敗時は対象項目・パス・画面幅・一覧状態と実際の値が分かるようにする。

## 検証の完了判定

後続担当は対象の単体・結合テスト、既存の関連する遷移・現在地・開閉・フォーカスのテスト、主要E2E、手動確認を実施する。
併せて`pnpm lint`と`pnpm typecheck`を実施する。
未実行、環境制約による未確認、既存の失敗を成功に含めず報告する。
行カバレッジの数値を合否にせず、名称の直接検証、各一覧状態、現在地の一致・不一致、768px境界、取得の非発火が未検証でないかを確認する。
本書の作成ではテスト実装・実行、ビルド、ブラウザ操作は行わない。
