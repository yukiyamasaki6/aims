# app/open-focus 設計

## 概要

開いた直後のフォーカスを、入力欄ではなく「開いたもの自体」へ置く。スマホでは、入力欄へのフォーカスがOSのキーボードを出し、利用者が入力しないと自分で閉じるため、画面が動くため。
方針は共通部品の既定で持ち、個別の画面は例外のときだけ上書きする。

## 方針

- 原則: 開いた直後に、入力欄(`input`・`textarea`・contenteditable)へフォーカスしない。フォーカスは、パネルの領域またはダイアログのポップアップへ置く(`tabIndex=-1`で、フォーカスは受けるがTab順には入らない)。そこからTabで中の最初の操作へ進める。
- 共通のダイアログ部品: `components/ui/dialog.tsx`の`DialogContent`が、ポップアップのrefコールバック(マウント時、同期)で、`focusTarget`(`RefObject`。例外の指定口)の要素があればそこへ、なければポップアップ自身へ`focus({ preventScroll: true })`する。呼び出し側が`initialFocus`を渡さないときだけ、Base UIへ`initialFocus={false}`を渡して二重の移動を防ぐ。呼び出し側の`ref`は尊重する。Base UIの`initialFocus`は開いた直後の非同期で動き、直後の入力を奪うため、同期のrefコールバックで移す。ライブラリの既定は、タッチ判定が開くボタン(Trigger)経由でしか設定されず、Triggerを持たない制御ダイアログではタッチでも最初のtabbableへ移るため、頼らない。個別の画面は`initialFocus`も`focusTarget`も渡さない。
- フィルターパネル: パネルの領域(`HistoryFilterPanel`のregion)が`tabIndex=-1`を持ち、開いたときにその領域へ`focus({ preventScroll: true })`する。フォームは開いたときの`focus`を持たない。
- 確認ダイアログ(`ConfirmDialog`・`BlockingConfirmDialog`)もポップアップ自身とする。先頭のTabで「キャンセル」(DOMの先頭)へ進むため、破壊的な操作へ最初に移らない。
- 例外: 入力欄でない先頭の操作へ移すことは、その操作が閉じるボタンなど、キーボードを出さず、開いた目的に合うときだけ認める。例外は、使う側が`DialogContent`の`focusTarget`で明示し、理由をコードのコメントに1行で書き、`test-design.md`の例外の表に載せる。設定パネルは閉じるボタンへ移す(`app/settings`)。
- フォーカスの輪: ポップアップと領域は、フォーカスを受けても輪を出さない(`outline-none`)。操作できる要素ではなく、開いたことは名前付きの領域・ダイアログで伝わるため。中の操作の輪は残す。
- 閉じた後の戻り先は、各画面の既存の規則に従い、この方針は変えない。

## 構成とデータの流れ

| ファイル | 責務 |
| --- | --- |
| `components/ui/dialog.tsx` | `DialogContent`が、ポップアップのrefコールバックでマウント時に同期でポップアップへフォーカスする(呼び出し側の`ref`と合成)。`focusTarget`の要素があればそこへ、なければポップアップ自身へ移す。`initialFocus`の指定がないときだけBase UIへ`initialFocus={false}`を渡し、指定があるときはその指定に従う |
| `features/rounds/ui/history-filter-panel.tsx` | 領域に`tabIndex=-1`とrefを持ち、`open`が真になったときに領域へフォーカスする |
| `features/rounds/ui/history-filter-form.tsx` | 開いたときの最初の入力欄への`focus`を削除する |
| `features/settings/ui/settings-panel.tsx` | 例外。閉じるボタンのrefを`focusTarget`に渡し、現在の振る舞いを既定の偶然でなく明示にする |

構造(置き場所と依存の向き)は変えないため、構造図は作らない。

## 設計判断

| 判断 | 理由 | 見直す条件 |
| --- | --- | --- |
| 既定をライブラリの`initialFocus`の既定でなく、ポップアップ自身へ自前で同期的に移す | Triggerの有無や開く手段で挙動が変わるため。ライブラリの`initialFocus`は開いた直後の非同期で動き直後の入力を奪うため、使わず`false`で止める。移さずに`false`だけにすると、フォーカスが開く前の要素に残り、Tabの起点とキーボード利用者への通知が不定になる | Base UIが、Triggerによらず入力欄へ移さない既定を提供したとき |
| 方針を共通部品の既定で持つ | 新しいダイアログが、指定なしで自動的に従うため | 共通部品を使わないダイアログが現れたとき |
| 入力欄でない先頭の操作は例外で、明示と一覧への記載を必須とする | 例外が静かに増えると、方針の網羅が崩れるため | 例外が増えて表の管理が重くなったとき |

## 制約と未対応

- 認証系と設定内の画面は、再現しなかったため変更しない。
