# app/open-focus テスト設計

## 方針

開いたときのフォーカスの行き先は、利用者が画面でできることの達成の途中の実装であるため、E2Eの直接の検証対象にせず、Vitest(jsdom)で`document.activeElement`を観測して確かめる(`agents/testing.md`)。
Triggerなしの制御ダイアログでも、行き先を共通部品が明示して移すため、jsdomの観測が、タッチ判定によらず同じ結果を保証する。

## 対象

| 対象 | 開き方 | 種類 |
| --- | --- | --- |
| フィルターパネル(`HistoryFilterPanel`) | 漏斗のボタン | 領域 |
| ラウンド設定(`round-config-panel`) | 制御(Triggerなし) | ポップアップ |
| 距離設定(`history-distance-dialog`) | Triggerあり・制御 | ポップアップ |
| 保存プリセット名(`save-preset-dialog`) | Triggerあり | ポップアップ |
| 距離編集(`distance-edit-fields`) | 制御 | ポップアップ |
| 的の選択(`history-target-selection`、`target-face-picker`) | Triggerあり | ポップアップ |
| 確認ダイアログ(`ConfirmDialog`、`BlockingConfirmDialog`) | 制御 | ポップアップ |

例外(入力欄でない先頭の操作へ移すもの)

| 対象 | 行き先 |
| --- | --- |
| 設定パネル(`settings-panel`) | 閉じるボタン |

## 確認

| テスト名の案 | 層 | 前提と操作 | 期待結果 |
| --- | --- | --- | --- |
| 共通ダイアログは先頭が入力欄でもポップアップへフォーカスする | 単体(`dialog.test.tsx`) | Triggerなしで、先頭に入力欄を持つ`DialogContent`を開く。別に、呼び出し側が`focusTarget`を指定した場合と、`ref`を渡した場合も開く | 既定ではポップアップがフォーカスを持ち(`tabIndex=-1`でフォーカスを受けられる)、入力欄は持たない。指定した場合は指定先が持つ。`ref`を渡しても既定が外れない。既定を外す(ライブラリの既定に戻す)と失敗する |
| 開いたとき、領域へフォーカスし、初期表示ではしない(フィルターパネル) | 単体(`rounds-history.test.tsx`) | 初期表示と、フィルターを開いた状態を観測する | 初期(閉)ではフォーカスが動かない。開くと領域が持ち、入力欄は持たない。入力欄をクリックするとその入力欄が持つ |
| 確認ダイアログはポップアップへフォーカスし、Tabでキャンセルへ進む | 単体 | 両方の確認ダイアログを開く | ポップアップがフォーカスを持ち、Tabの先頭はキャンセル |
| フィルターを開いても入力欄にフォーカスしない | 単体(`rounds-history.test.tsx`) | フィルターを開き、Tab・Escを操作する | 領域が持ち、入力欄・表示単位の項目は持たない。Tabで表示単位の選択中の項目へ進み、Escで閉じて漏斗へ戻る。入力欄をクリックするとフォーカスされる |
| 各ダイアログを開いても入力欄にフォーカスしない | 単体(各ダイアログのテスト) | 「対象」の各ダイアログ(ラウンド設定、距離設定、保存プリセット名、距離編集、的の選択)を、Triggerの有無によらず開く | `activeElement`が入力欄でなくポップアップ。Tabで中の最初の操作へ進み、Escで閉じて起点へ戻る。先頭が入力欄のダイアログは、入力欄をクリックするとフォーカスされる |
| 既存のフォーカス契約が変わらない | 既存の単体・結合(`rounds-history.test.tsx`、`settings.spec.ts`ほか) | 閉じた後の起点への復帰、横長の検索後は「検索」に残る、向き変更で動かない、画面遷移で戻さないを、既存のテストで観測する | 既存のテストを変更せず通る(実装前後の差分で、期待値を緩めない) |
| 設定パネルは閉じるボタンへ移る(例外) | 既存の単体・結合 | 設定パネルを開く | 閉じるボタンがフォーカスを持つ(既存のテストを維持) |

E2Eは、この方針の検証のために追加しない。

## 網羅の確認

- 共通部品の使用の一覧: 単体テストが、`src`の中で`components/ui/dialog`から`Dialog`か`DialogContent`をimportするファイルと、`@base-ui/react/dialog`をimportするファイルを調べる。後者は`components/ui/dialog.tsx`だけでなければならない。前者は、上の「対象」と「例外」の表に載せたファイル名の一覧に、すべて含まれなければならない。ファイルが増えて一覧に足されなければ失敗する。
- 例外の指定の一覧: 同じテストが、`DialogContent`に`focusTarget`を渡すファイルを調べ、「例外」の表のファイルだけであることを確かめる。
- 一覧の各ファイルは、単体の確認で`activeElement`を観測するケースを1つ以上持つ。
- import元の表記: 走査は、`@/components/ui/dialog`の別名と相対パスの両方、および`export ... from`による再公開を数える。
- 共通部品を使わない入力欄への自動フォーカスの一覧: 同じ走査テストが、`src`(テストを除く)の`autoFocus`の属性と、`.focus(`・`focus({`の呼び出しを持つファイルを調べ、許可の一覧(閉じた後の戻り先、利用者の操作への応答、フィルターパネルの領域への移動、共通のダイアログ部品`components/ui/dialog.tsx`のポップアップへの移動、設定パネルの例外)のファイルだけであることを確かめる。許可の一覧の各行は、理由を1行で持つ。増えて一覧に足されなければ失敗する。共通部品を使わない新しいパネルが、入力欄へ自動でフォーカスする追加を検出するためである。
- 走査は、変更前の状態で、対象外の既存ファイルを許可の一覧に載せて通るようにしてから、方針に反する追加(入力欄の`autoFocus`)を加えると失敗することを確かめる。
