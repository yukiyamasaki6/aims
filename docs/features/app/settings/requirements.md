# app/settings

## 目的

サインイン済みの利用者が、アカウント設定などを一か所で確認・変更するための画面へ、どの画面からでも着けるようにする。

## 要求

### 設定画面を開く

- レフトパネル/ドロワーの「設定」項目を押すと、設定画面(`/settings`)へ移動する。項目は、ホーム・履歴・詳細・作成・設定のどの画面でも表示される。
- 設定画面を表示しているときは、「設定」項目が現在のビューとして識別でき、支援技術に現在のビューとして伝わる。ホーム・履歴の項目は現在のビューにならない。
- 幅768px未満でドロワーが展開されているときに「設定」項目を押すと、ドロワーが格納される。幅768px以上では開閉は変わらない。
- 「設定」項目はキーボードで操作できる。
- 設定画面のURLを直接開く、または再読み込みしても、同じ設定画面が表示される。ブラウザの戻る・進むで、設定画面とその前の画面の間を移動できる。
- 設定画面から、レフトパネル/ドロワーでホーム・履歴へ移動できる。

### 設定画面の内容を使う

- 設定画面には、画面の見出しと、分類「アカウント」「診断」が表示される。
- 分類「アカウント」の中に、サインアウトがある。サインアウトの確認、実行、失敗の表示、完了後の遷移は、auth/signoutに従う。
- レフトパネル/ドロワーにサインアウトボタンは表示されない。
- 設定画面のサインアウトは、キーボードで操作できる。
- 分類「診断」の中に、「表示領域の診断」の切り替えがある。切り替えはapp/viewport-diagnosticsに従う。

### サインインしていないとき、サインインが切れたとき

- 未認証で設定画面を開くと、サインイン画面へ移動し、設定画面が遷移元として付く。サインインすると設定画面へ戻る。
- 設定画面の表示中にサインインが切れたときも、サインイン画面へ移動する。
- サインアウトした後、ブラウザの戻るで設定画面を開こうとしても、サインイン画面へ移動する。

### オフラインのとき

- 画面の枠を保存した後は、オフラインで設定画面を開くと、サインイン画面やオフラインのページではなく、設定画面が表示される。サインインしていない状態で枠を保存した後にサインインした場合も同じである。
- オフラインの設定画面で、サインアウトを操作できる。

## 対象外

- 個別の設定項目(メール変更、アカウント削除、パスワード変更、テーマ、デフォルト入力設定、ログ収集など)の実装は扱わない。設定値の保存は扱わない(「表示領域の診断」の切り替えを除く)。
- 設定項目が通信を要するときの、オフラインでの操作不可の表示と、オンライン復帰時の扱いは、項目を加えるときの要求で定める。
- 分類ごとのURLは持たない。
- サインアウトの確認、実行、失敗の表示は、auth/signoutで扱う。
- 画面の枠をオフラインで保存する仕組みは、app/offline-pwaで扱う。
