# settings 設計

## 概要

設定は、ログイン後の画面(ホーム・点数一覧・ラウンドの開始画面・詳細。`(main)`配下)の上に重ねるパネルで、パスを持たず、URLのハッシュ(`#settings/<分類>[/<項目>]`)で表示を表す。
パネルの開閉と表示はハッシュだけから決める。開く操作とパネルの中の移動は`history.pushState`で履歴を1つずつ積み、閉じる操作は開いた起点まで履歴を戻す。
パネルは`@base-ui/react`のモーダルのダイアログで、フォーカスの閉じ込め、外側の`aria-hidden`、Esc、外側の押下、入れ子のダイアログ(サインアウトの確認)の扱いを任せる。
ハッシュはサーバーへ送られないため、保護(`proxy.ts`)と枠の保存(`app/offline-pwa`)は背景の画面のものがそのまま効き、設定のための経路・枠・保護の範囲を持たない。
項目の画面(メールアドレス変更、アカウント削除)とサインアウトは認証の部品で、入口が組み立ててパネルへ渡す。

## 画面と状態

| ハッシュ | 表示 |
| :--- | :--- |
| `#settings/account` | 分類「アカウント」。メールアドレス変更、アカウント削除の項目と、サインアウトを、囲み枠なしで項目間だけを区切る一覧に並べる。本文に分類の見出しは置かない。 |
| `#settings/account/email` | メールアドレス変更の画面(`auth/change-email`) |
| `#settings/account/delete-account` | アカウント削除の画面(`auth/delete-account`) |
| `#settings`、`#settings/`で始まる上記以外 | 分類「アカウント」として開き、`history.replaceState`でハッシュを`#settings/account`に書き換える(履歴を増やさない)。 |
| 上記以外(ハッシュなし、`#settingsfoo`など) | 閉じている。ハッシュは変えない。 |

- パネルは、見出し「設定」(`Dialog.Title`。対話の領域の名前になる)、閉じるボタン、分類の一覧(「アカウント」だけ)を常に出す。分類の一覧は、幅768px以上では表示の領域の左の縦の列、幅768px未満では表示の領域の上の横並びのタブである。項目の画面を表示している間も、分類「アカウント」が選ばれている(`aria-current="page"`)。
- 分類の一覧の各分類(`settings-panel.tsx`の`CategoryLink`。縦の一覧とタブで同じ部品)は、基本を`flex h-11 items-center gap-0 md:gap-2 shrink-0 whitespace-nowrap rounded-lg px-3 py-3 text-sm transition-colors`とし、選んでいる分類には`bg-foreground/10 font-medium`を、選んでいない分類で操作を受け付けるとき(処理中でないとき)には`hover:bg-foreground/5`を足す。処理中は`opacity-50`で、重ねたときの塗りを付けない。選んでいる分類は、重ねても塗りを変えない。値は、レフトパネルの移動項目の現在のビューと重ねたときの塗り(`app/navigation`の`navItemClassName`)と同じにする。
- 分類「アカウント」は、幅768px以上の縦列でだけ、文字の左にlucide-reactの`UserRound`を`hidden size-5 shrink-0 md:block`で置く。幅768px未満の横並びではアイコンとそのための空き領域を表示しない。縦列のアイコンと文字の間隔は8px(`md:gap-2`)で、大きさと間隔をレフトパネルの移動項目に揃える。アイコンは文字と同じ色を継承し、`aria-hidden="true"`で装飾として扱い、名前・独立したフォーカス対象を追加しない。分類は縦列・横並びで同じ部品を使い、リンクと`aria-current="page"`・`aria-disabled`を保つ。
- 幅768px以上は、背景の上に置いた枠で、外側に背景の画面が見える。幅768px未満は画面全体を覆う。パネルと背景はドロワー(`z-50`)より上に重なる。
- 項目の画面は、共用のヘッダー枠(`ScreenFrame`)に項目の名称と戻る(`SettingsBackLink`)を置く。設定パネルの入口は、`(main)/layout.tsx`が`LeftPanel`の外(兄弟)に描く。メニューの文脈(`ScreenMenuProvider`。Reactの文脈で、ポータルを越えて伝わる)は`LeftPanel`の子の中にだけあるため、項目の画面のヘッダー枠はメニューボタンを出さない。
- 開いている間は、ダイアログが外側(レフトパネルを含む)に`aria-hidden`を付けてフォーカスをパネルの中に閉じ込め、外側の押下はダイアログの背景(`Dialog.Backdrop`)が受けて閉じる。外側に`inert`は付かないが、押下は背景が受け、フォーカスは閉じ込められるため、背景の画面の操作とフォーカスは届かない。レフトパネルの項目とボタン(「ホーム」「点数一覧」「ラウンドを開始」など)への押下も背景が受けるため、閉じるだけで移らない。
- 開いた直後のフォーカスは、入力欄でなく閉じるボタンへ置く。共通のダイアログ部品の既定(ポップアップ自身。`app/open-focus`)の例外として、`DialogContent`の`focusTarget`で閉じるボタンを明示する。
- 背景の画面は、開いても遷移も再取得もしない。`pushState`はNext.jsのルーターへ同じ経路の復元として伝わり、ページを描き直さない。
- 処理中(項目の画面が処理中を知らせている間)は、閉じる操作・Esc・外側の押下(`onOpenChange(false)`)、分類の選択、項目の画面の戻るを受け付けない。ブラウザの戻る・進むは止めない。ハッシュが変われば項目の画面は外れ、画面の`isMounted`が偽になるため、応答による表示は起きない(`docs/features/auth/design.md`の離脱の原則)。
- サインアウトの確認ダイアログは、パネルのダイアログの中で開く入れ子のダイアログで、Escと外側の押下は確認ダイアログだけを閉じる。入れ子のダイアログは既定では自身の背景を描かず外側の押下を拾えないため、`BlockingConfirmDialog`に`nested`を通して背景を描かせる(`auth/signout`)。

### 履歴の積み方と閉じ方

- パネルが積む履歴の項目は、状態(`history.state`)に、起点からの段数(1以上)と、積んだ文書の識別子(文書の読み込みごとに作る乱数)を持つ。`pushState`・`replaceState`には自分の値だけを持つ新しいオブジェクトを渡す(今の`history.state`を渡すと、Next.jsは内部の印`__NA`を見て取り込まない。`rounds/history`と同じ)。この文書が積んでいない項目(読み込み時の項目、アドレス欄でハッシュを書き換えた項目、前の文書が積んだ項目)は段数0とする。
- 開く操作(「設定」項目)とパネルの中の移動(分類の選択、項目の押下、項目の画面の戻る)は、今の段数に1を足した項目を`pushState`で積む。今と同じハッシュへの移動は積まない。
- 閉じる操作は、今の段数kだけ`history.go(-k)`で起点へ戻り、起点のハッシュが設定のハッシュなら`replaceState`でハッシュを外す。kが0のときは戻らずにハッシュを外す。
  - 読み込みより後に開いたパネル(進むで開いたものを含む)は、起点がハッシュのない開く前の項目なので、戻るだけで閉じる。開いた分の履歴を戻るため、閉じた後の戻るはパネルを開かない。
  - 読み込み時に開いたパネル(直接開いた、再読み込み、サインイン後の復帰)は、起点が読み込み時の項目で、ハッシュを外して閉じる。その後の戻るは、読み込みより前の履歴へ移る。
- 閉じた後のフォーカスは、起点でハッシュを外した閉じ方では背景の画面の先頭(本文領域)へ、それ以外(起点へ戻るだけの閉じ方、ブラウザの戻るで閉じたとき)では開き口(幅768px以上で縦の列が開いていれば「設定」項目、幅768px以上で縦の列が閉じているときと幅768px未満はヘッダーのメニューボタン)へ移す。レフトパネルの開閉は変えない。パネルは`finalFocus={false}`でダイアログの既定の戻し(開く前にフォーカスのあった要素へ戻す)を止め、戻し先の種類を入口経由でレフトパネルへ渡し、レフトパネルが移す(`app/navigation`)。

## 画面の作り

- 分類の一覧の各分類は、経路表のハッシュを`href`に持つリンクで、押下は既定の動作を止めて、受け取った移る操作を呼ぶ。
- 幅768px未満の横並びのタブは、並びを`flex`に`overflow-x-auto`を付けた1行(折り返さない)にし、各タブは`shrink-0`で、幅を伸ばす指定(`flex-1`、`w-full`)を持たない。各タブの幅は名称の文字と左右各12pxの内側余白の幅になり、分類が1つでも横いっぱいに広がらない。並びがパネルの幅を超えると並びだけが横にスクロールし、キーボードでフォーカスしたタブはブラウザが見える位置までスクロールする。
- 分類リンクと本文の全操作行は高さ44px(`h-11`)とし、レフトパネルの移動項目の通常の高さ44pxに揃える。分類リンクの上下の内側余白は各12px(`py-3`)、左右は各12px(`px-3`)とする。分類の親の`gap-1`を削除し、縦列・横並びの両方で項目間を0px(`gap-0`)にする。本文も項目間の隙間は0pxで、1pxの区切り線は44pxの行の内側に含める。アイコンと文字の間隔8pxと、分類同士の間隔0pxは区別する。
- 分類「アカウント」の一覧は、外周の境界線・角丸・`overflow-hidden`を持たず、隣接する行の間だけに1pxの区切り線を置く。
  一覧側が区切り線を持ち、4項目なら3本、サインアウトが渡されない3項目なら2本とする。
  先頭の上線、末尾の下線、左右の線は描かず、各行の先頭・末尾を丸める指定も持たない。
  配置は`flex flex-col`を保ち、一覧に`[&>*:not(:last-child)]:border-b [&>*:not(:last-child)]:border-foreground/40`を指定し、末尾以外の直下の行に下線を付ける。
  このセレクターは親のユーティリティクラスと`:not(:last-child)`によって詳細度が`0,2,0`となり、同じutilitiesレイヤーの行の`border-0`とButton基本クラスの`border-transparent`(いずれも`0,1,0`)に勝つ。
  このため、行の境界線幅を0にしても下だけ1pxとなり、透明色も`foreground`の40%に上書きされる。
- 行は、項目のリンクもサインアウトのボタンも、`variant="ghost"`と大きさの種類`size="row"`で描く。
  `row`は`Button`(`src/components/ui/button.tsx`)の大きさの種類で、高さ44px、幅いっぱい、左寄せ、角丸なし、左右の内側余白12px、境界線なし、フォーカス中は前面(`relative h-11 w-full justify-start rounded-none border-0 px-3 focus-visible:z-10`相当)とする。
  本文4項目と分類タブは、いずれも既存の文字14px・行高20px(`text-sm`)を維持する。本文はButton基本クラス、分類は`CategoryLink`の指定を使い、rowに文字サイズや行高の上書きを加えない。
  区切り線の位置と色は一覧側が担い、`row`自身は境界線を追加しない。
  リンクは`cn(buttonVariants({ variant: "ghost", size: "row" }))`を使い、`Button`と同じ`cn`(`twMerge`)で角丸と境界線のクラスを解決する。
- メールアドレス変更、アカウント削除、サインアウトの全3項目は、文字ラベルだけで示し、アイコンを置かない。
- 境界線の色は`border-foreground/40`である。既存の`--border`は、白の背景に対するコントラストが約1.3:1で、目視でほぼ見えなかった。`--ring`や`--muted-foreground`は意味(フォーカス、補助の文字)が違うため使わない。
- フォーカスリングは`Button`の規約のまま外側に描く。一覧を囲む`overflow-hidden`を持たないため切れず、フォーカス中の行は`z-10`で隣の行の背景に覆われない。
- 色と大きさは、既存のトークン(`globals.css`)とButtonの規約だけを使う。配置と見た目はE2Eで確かめない(`agents/testing.md`)。

### 区切り線の検証

- 実装前に、ロックファイルに従って導入済みのTailwindを使い、一時的な入力で上記2つの任意バリアント、行の`border-0`、Button基本クラスの`border-transparent`をコンパイルする。
  `apps/web`から`require("tailwindcss").compile`に`@theme { --color-foreground: #171717; } @tailwind utilities;`を渡し、返されたコンパイラーの`build`にこれら4クラスを渡せば、アプリを変更せずに生成CSSを確認できる。
  生成セレクターが親クラスに続く`> :not(:last-child)`で、末尾以外へ`border-bottom-width: 1px`と`foreground`の40%の`border-color`を出すこと、詳細度`0,2,0`で行側の幅0と透明色に勝つことを確認する。
  さらに生成CSSを読み込む一時的な4行のHTML(3リンクと1ボタン)に、実際のButton基本クラスと新rowの合成結果、一覧の2クラスを付けてブラウザで開き、先頭3行の下線が1px・solid・透明でないこと、末尾の下と全行の上・左右の境界線幅が0であることを開発者ツールで確認する。
  合成は実装と同じ`cn(buttonVariants(...))`を基準にし、確認後は一時ファイルを削除する。
- 実装後は、ビルドを含む`pnpm preview`(port 3000)で設定のアカウント一覧を開き、画面幅375px・767px・768px・1280pxで3本の区切り線が見えることを確認する。
  375pxから1280pxの間でも幅を変え、縦列・横並びの切替を含めて線が消えず、先頭・末尾・左右に外周線が出ないことを確認する。
  幅767pxでは分類アイコンと空き領域がなく、幅768pxではアイコンが表示されること、全確認幅で分類と本文が44px・項目間0pxであることを開発者ツールと実表示で確認する。
  分類が1つでも親のgapが縦列・横並びとも0であることを確認し、分類の文字とフォーカス対象は幅切替で変わらないことも確認する。
  全確認幅で本文4項目と分類の文字14px・行高20pxをComputedと目視で確認し、文字が欠けず、44pxの領域全体で操作できることを確認する（px値は通常のルート文字サイズ16px時）。
  各行のホバー、Tabによるフォーカス、サインアウト確認の開閉後も、線と操作対象を識別でき、フォーカスリングが見えることを確認する。
- この確認は生成CSSと実表示の確認として行い、固定クラスを期待値にする新規テストや外観専用のE2Eは増やさない。

## 構成とデータの流れ

- `src/routes.ts`(経路表): 設定のハッシュ`SETTINGS_HASH`(`#settings`)、`SETTINGS_ACCOUNT_HASH`(`#settings/account`)、`CHANGE_EMAIL_HASH`(`#settings/account/email`)、`DELETE_ACCOUNT_HASH`(`#settings/account/delete-account`)を持つ。設定のパスと枠は持たない。
- `src/features/settings/domain/settings-location.ts`(ドメイン): ハッシュから表示(`account`、`email`、`delete-account`、または閉)と正規化の要否を返す規則、表示からハッシュを返す規則、履歴の状態と文書の識別子から段数を読む規則と、積む状態を作る規則。純関数で、経路表のハッシュを読む。
- `src/features/settings/ui/use-settings-route.ts`(UI): ハッシュと履歴の読み書き。`popstate`、`hashchange`と自分の書き込みを`useSyncExternalStore`で購読し、事前描画と水和では閉とする(枠は静的なため、開くのは水和の後)。正規化、開く、移る、閉じる、閉じたときのフォーカスの戻し先の種類を返す。閉じるの`history.go`の後の`replaceState`は、起点に着いた`popstate`で行う。
- `src/features/settings/ui/settings-panel.tsx`(UI): パネル。`components/ui/dialog.tsx`の`Dialog`の上に、見出し、閉じる、分類の一覧、表示の領域を描く。処理中の値を持ち、表示が変わると解く。項目の画面は、入口が渡す描画の関数に、戻る操作と処理中の知らせを渡して描き、表示が変わると外す(入力と途中の経過は残らない)。
- `src/features/settings/ui/settings-account.tsx`(UI): 分類「アカウント」の本文。項目の行(経路表のハッシュを`href`に持つリンク。押下は既定の動作を止めて、受け取った移る操作を呼ぶ)と、入口が渡すサインアウトの行を並べる。
- `src/features/settings/ui/settings-messages.ts`(UI): 文言(名前空間`settings`。見出し、閉じる、分類、項目)。
- `src/app/(main)/layout.tsx`(入口): `useSettingsRoute`を呼び、開いているか・開く操作・戻し先の種類をレフトパネルへ、経路の操作を設定パネルの入口へ渡す。設定パネルの入口は`LeftPanel`の外(兄弟)に描く(メニューの文脈を受けないため)。
- `src/app/(main)/settings-panel-entry.tsx`(入口): `SettingsPanel`に、サインアウトの行(`useSession`の`signOut`で作る`SignOutButton`)と、項目の画面の描画の関数を渡す。項目の画面は、手続きを生成して`ChangeEmailForm`、`DeleteAccountForm`(手続きは`useDeleteAccount`)を描き、戻る操作と処理中の知らせを渡す。
- レフトパネルの「設定」項目(設定パネルを開くだけで、現在のビューにならない)、閉じた後のフォーカスは`app/navigation`、未認証の遷移元のハッシュは`auth/signin`、オフラインは`app/offline-pwa`に従う。
- 各ファイルの層は`docs/architecture.md`の「1. 構造」に従う。

## 設計判断

| 判断 | 理由 | 見直す条件 |
| :--- | :--- | :--- |
| 設定をパスでなくハッシュで表し、背景の画面の上に重ねる | 背景の画面(入力途中のラウンドなど)を離れずに開閉するため。パスにすると画面が移り、背景の状態を失う。Next.jsのインターセプトするルートは、直接開いたときに背景の画面を持たず、背景の4画面ごとに経路が要るため採らない。 | 設定を単独の画面として開く要求が出たとき。 |
| 設定のための枠、保護の範囲、`proxy.ts`の対象を持たない | ハッシュはサーバーへ送られず、背景の画面の枠と保護がそのまま効くため。未認証の遷移元に付くハッシュは、サインインが引き継ぐ(`auth/signin`)。 | 設定をサーバーで描く必要が出たとき。 |
| 開閉と表示をハッシュだけから決め、中の移動も`pushState`で積む | 戻る・進む・再読み込み・直接開くを1つの規則で扱うため。開閉をReactの状態に別に持つと、履歴と食い違う。 | 設定の表示を履歴に積まない要求が出たとき。 |
| 閉じる操作は`history.go(-段数)`で起点まで戻り、起点がハッシュ付きなら`replaceState`で外す。段数と文書の識別子を履歴の状態に持つ | 開いた分の履歴を戻し、閉じた後の戻るでパネルを開かせないため。段数を履歴の状態に持つと、戻る・進むの後も各項目の段数が分かる。識別子が無いと、再読み込みの後に前の文書の段数で読み込みより前の画面まで戻ってしまう。 | 閉じた後の戻る・進むの要求が変わったとき。 |
| `history.pushState`を直接使い、`router.push`のハッシュの遷移と`location.hash`の代入を使わない | Next.jsは外部の`pushState`・`replaceState`を取り込み、内部の状態を写して戻る・進むを扱う(Next.js 16.2の`app-router`)。`router.push`のハッシュの遷移は要素へのスクロールを伴い、状態を積めない。`location.hash`の代入は状態のない項目を作り、段数を失う。 | Next.jsが外部の`pushState`を取り込まなくなったとき。 |
| パネルを`@base-ui/react`のモーダルのダイアログにし、外側の押下はダイアログの背景が受ける | フォーカスの閉じ込め、外側の`aria-hidden`、Esc、入れ子のダイアログのEscと外側の押下を既存の部品に任せるため。外側のレフトパネルの項目とボタンへの押下も背景が受け、閉じるだけになる。 | 背景を操作できる非モーダルの要求が出たとき。 |
| E2Eで外側の押下を確かめるときは、設定パネルの領域とビューポートから求めた、パネルの外側の点(背景が受ける点)を座標で押す。背景の要素が押下で動かないことは、要求の対象のレフトパネルの項目のうち、押すと今の画面から移る項目(ホームを背景にするなら縦の列の「点数一覧」)を座標で押して確かめる | 外側かどうかはパネルの領域だけで決まり、他の機能の要素(ホームのラウンドの開始ボタンなど)の位置と形に依ると、その機能の変更で設定のテストが壊れるため。背景が受ける点は、パネルの外側ならどこでも同じ結果になる。外側の点は、パネルの左右の余白(幅768px以上)の中央に取る | パネルが画面全体を覆う幅で、外側の押下を確かめる要求が出たとき。 |
| 閉じた後のフォーカスはパネルが戻さず、戻し先の種類をレフトパネルへ渡して移させる | 戻し先(「設定」項目、メニューボタン、本文領域)はレフトパネルの要素で、設定の機能から参照できないため(R3)。ダイアログの既定(開く前にフォーカスのあった要素へ戻す)では、幅768px未満で格納されたドロワーの中の項目へ戻してしまう。 | 戻し先の規則が変わったとき。 |
| 分類の一覧の強調と重ねたときの塗りを、レフトパネルの移動項目と同じクラス値で、`settings-panel.tsx`に書く | 要件が、選んでいる分類の強調をレフトパネルの現在のビューと同じ見え方にすると定めるため。設定の機能はナビゲーションの機能のUIをimportできず(R3)、2つのクラス値を共有の部品へ出すほどの量でもないため、同じ値をそれぞれに書く。値を変えるときは、`app/navigation`の`navItemClassName`と同時に変える | 現在のビューの見た目を使う部品が3つ以上になったとき(共有の画面部品へ出す)。 |
| サインアウトと項目の画面は、入口が認証の部品を組み立てて渡す | 設定の機能が認証の機能のUIを直接importできないため(R3)。 | 設定の機能が認証の入口(`index.ts`)を介して部品を受け取れるようになったとき。 |
| 行の大きさを`Button`の大きさの種類`row`に置き、区切り線は一覧側で管理する | 入口が渡すサインアウトのボタンと項目のリンクの大きさを揃え、区切り線を隣接行の間だけに置くため。一覧の任意バリアントで行の境界線幅0と透明色より詳細度を高くし、線の幅と色を適用する。 | 行に説明文や右端の表示が要るとき。 |

## 制約と未対応

- 分類は「アカウント」の1つで、項目の並びは、メールアドレス変更、アカウント削除(リンク)、サインアウト(入口が渡す)の順である。
- パネルを描くのは`(main)`のレイアウトだけで、サインイン・紹介・`/offline`・見つからない旨の画面では、ハッシュを読まない。
- 読み込み時に開いたパネルを閉じた後も、進むの履歴にはパネルの中で移った項目が残り、進むで開く。
- アドレス欄でハッシュを手入力で書き換えた履歴の項目は、状態が`null`で、Next.jsの印`__NA`を持たない(水和の前に「設定」項目を押した項目も同じ)。そこから積んだ項目と、そこでの正規化・閉じるの`replaceState`の項目も`__NA`を持たない(Next.jsは今の状態から`__NA`を写すため)。これらの項目へブラウザの戻る・進むで移ると、Next.jsの`popstate`の処理がページ全体を読み込み直し、背景の画面の状態(入力途中の内容など)は失われる。読み込み直した画面では、ハッシュが指す表示の設定パネルが、読み込み時に開いたパネルとして開く。この場合は受け入れ、対処しない。
- 旧版の`/settings`配下のURLは、他の存在しないURLと同じに扱う(オンラインは見つからない旨の画面、オフラインは`/offline`。`app/offline-pwa`)。

未知項目は既存の一般規則で正規化する。廃止したパスワード項目の定数・専用判定・互換遷移は持たない。
