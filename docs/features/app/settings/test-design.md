# 設定画面UI変更のテスト設計

## 基準と範囲

基準は[設定の要件](requirements.md)と[確定設計](design.md)である。
分類アイコンは768px以上の縦列だけに表示し、768px未満の横並びには表示しない。
分類と本文の全操作行を高さ44px・項目間0pxとし、本文は囲み枠をなくして隣接行間だけを1pxの線で区切る。
本文3項目にはアイコンを置かず、文言・並び順・リンクとボタンの意味・認証処理・ハッシュと履歴・パネルの開閉・処理中の制限を維持する。
分類が1つの現行構成を対象とし、将来の分類や入力フォームの組合せを増やさない。
本書はテスト設計であり、テスト実装・実行や表示確認の結果を示さない。

## 優先順位と層

最優先は、誤った移動、確認前のサインアウト、処理中の誤操作、キーボード操作不能を防ぐことである。
次に、外周の除去・区切り線・分類アイコンの表示範囲・44pxと0px・フォーカスリングの視認性を確認する。
外観も必須の受入対象とし、自動テストの成功だけでは完了にしない。

| 層 | 保証する内容 | 方針 |
| --- | --- | --- |
| 単体・コンポーネント（Vitest） | 並び順、名前、装飾の扱い、操作と通知、現在の分類、処理中の抑止と解除 | 既存テストを再利用し、変更箇所の不足だけを補う。 |
| E2E（Playwright） | リンク押下とハッシュ・画面 | 既存のsettings.spec.tsを再利用し、1リンク1件で確認する。 |
| E2E（Playwright） | 実認証を通すサインアウト完了と失敗後の回復 | 既存のauth/signout.spec.tsを再利用する。 |
| 生成CSS・手動確認 | 線の適用、図柄と表示幅、寸法、収まり、ホバーとフォーカスの見え方 | 確定設計の一時HTMLとビルドを含むpreviewで確認する。 |

テスト種別は実物で通す境界で判断し、Playwrightのファイル内にあることだけでE2Eとはしない。
固定クラス・寸法・色・SVGのpath・DOM全体のスナップショットを期待値とする新規テストや、外観専用のE2Eは追加しない。
認証SDK・DB・RPC・永続化の契約変更はないため、新しいDBテストや認証障害の組合せは追加しない。

パスは特記のない限り`apps/web/src/`からの相対である。
表の各行は検証する振る舞いの案であり、異なる前提や操作は別のテストとする。

配置先は`features/settings/ui/settings-panel.test.tsx`とする。

幅によるアイコンの表示切替はCSSの責務であり、jsdomの幅変更やクラス検証で保証した扱いにしない。
名前の確認は読み上げ実機の代替ではないため、previewでもアクセシビリティツリーを確認する。

### 共通Button・入口・サインアウト

- `components/ui/button.test.tsx`のロール・disabled・クリック・propsの接続を維持し、他のsize・variantを変更しないことを確認する。
- 既存のrowの固定クラス検証には旧高さ`h-10`が含まれるため、そのままでは設計変更に追随できない。
  固定外観の列挙を新値へ置換し続ける方針は採らず、その検証は手動の寸法確認へ移し、Buttonの意味・操作の既存テストを残す。
- `app/(main)/settings-panel-entry.test.tsx`は、表示の分岐(`switch`の2項目、サイトキーが無いとき空)だけを残し、入口から認証UIを通した動作は`sign-out-button.test.tsx`・`settings-panel.test.tsx`が担う。
- `features/auth/ui/sign-out-button.test.tsx`の確認を開くだけでは実行しないこと、失敗後のエラー表示・再確認、確認を閉じるとエラーを消すことを再利用する。
- 入れ子の確認のEsc・背景押下で親パネルを閉じないことは既存のパネル・サインアウトの各責務のテストを再利用する。
- 失敗と再確認は別の振る舞いに分け、再確認のテストは失敗済み状態をGivenへ置く。

## ブラウザ境界と主要経路

`apps/web/tests/e2e/app/settings.spec.ts`は、利用者がこの画面でできること(設定を開いて閉じる、項目の画面へ移る、分類へ戻る)を確かめる主要経路に絞る。
外観のための新規ケースは追加しない。

- ホームで「設定」項目を押すと設定パネルが開き、分類「アカウント」が選ばれて、閉じると開く前の画面へ戻る。
- 分類「アカウント」の項目(メールアドレス変更・アカウント削除・サインアウト)が表示される。
- メールアドレス変更・アカウント削除を各1件で押し、それぞれ期待するハッシュと項目画面が表示される。
- 項目の画面から分類へ戻る。
- 未認証では、設定のハッシュを付けてもパネルが開かない。

ハッシュの直接指定・ブラウザの戻る進む・閉じ方の変種・閉じた後のフォーカス・フォーカスの閉じ込め・処理中の抑止は、途中の実装であり、E2Eの対象にしない。
これらは、`use-settings-route.test.tsx`、`settings-location.test.ts`、`settings-panel.test.tsx`など、部品自身の判定を検証する単体テストが担う。

サインアウト完了は`apps/web/tests/e2e/auth/signout.spec.ts`の既存経路を使い、確認後にセッションが終了して遷移元のないサインインへ移ることを確認する。
失敗・再確認の経路も既存の回帰として実行する。
幅変更中の確認維持、入れ子の確認だけを閉じる経路(Esc・背景押下)は、E2Eの対象にしない。

## 生成CSSと実表示の確認

### 実装前の確認

1. 現行の`pnpm preview`（port 3000）で分類・本文・ホバー・フォーカスを記録し、変更後と同条件で比較できるようにする。
2. 確定設計の「区切り線の検証」に従い、導入済みTailwindで一覧の2つの任意バリアントと行の`border-0`、Button基本クラスの`border-transparent`をコンパイルする。
3. 末尾以外の直下の行へ下線1pxとforegroundの40%の色を適用するCSSが生成され、詳細度0,2,0が行の0,1,0より高いことを確認する。
4. 生成CSSと実装同様の`cn(buttonVariants(...))`による基本クラス・新rowの合成結果を使う一時HTMLに2リンクと1ボタンを置き、実ブラウザで計算済みスタイルを確認する。
5. 先頭2行の下線は1px・solid・非透明、末尾の下と全行の上・左右は0であることを確認する。
6. 同じ一時HTMLでサインアウトの行を除き、2行では下線1本・末尾の下線なしになることを確認し、一時ファイルを削除する。

生成CSSの静的な確認だけでは、ブラウザのカスケードや実際のポータルとの組合せを保証しない。

### 実装後のpreview確認

ビルドを含む`pnpm preview`をport 3000で起動し、認証済みの設定一覧を開く。
画面高はまず667pxに揃え、幅375px・767px・768px・1280pxを確認し、375pxから1280pxの間も連続的に変える。
768pxの前後である767px・768px・769pxも同じ操作で確認する。

| 条件・操作 | 期待する観測結果 |
| --- | --- |
| 各確認幅で一覧を開く | 3項目の間にだけ2本の線が見え、先頭上・末尾下・左右の外周と囲み枠の角丸がない。パネル外周と分類・本文の境界は設計どおり残る。 |
| 各確認幅で寸法を計測する | 分類リンクと本文全3行が44px、本文行間が0pxで、区切り線は44pxの内側に収まる。リンクとサインアウトの文字と操作領域が揃う。 |
| 分類の親を確認する | 分類が1つでも計算済みgapが横並び・縦列とも0pxである。分類を増やすための本体変更は行わない。 |
| 幅767px以下で分類を確認する | アイコンと空き領域がなく、分類は文字と左右12pxの余白の内容幅で、全幅に伸びず折り返さない。 |
| 幅768px以上で分類を確認する | 文字の左にUserRoundが20px・間隔8pxで表示され、文字色を継承する。縦列の幅192pxと選択表示を保つ。 |
| 各確認幅と幅変更の途中で本文を確認する | 3項目にアイコンや矢印がなく、文字やアイコンの欠け、不要な本文全体の横スクロールがない。幅変更でも線が消えない。 |
| 各行をホバーする | 行の操作領域と区切り線を識別でき、リンク2行とボタンで見た目が揃う。 |
| Tab・Shift+Tabで分類と本文3項目へ移る | 操作名を識別でき、余計な停止先がなく、フォーカスリングが欠けたり隣接行の背景に隠れたりしない。Enterで各操作を実行できる。 |
| サインアウト確認を開き、キャンセル・Esc・背景押下で個別に閉じる | 確認だけが閉じて一覧が残り、確認ポータルの開閉によって末尾の下線や余計な区切り線が増えない。 |
| 分類の通常・選択・処理中と解除後を確認する | 名前と現在の分類を保ち、アイコンも文字とともに処理中の薄表示になる。処理中は移動せず、解除後は操作できる。 |
| アクセシビリティツリーを確認して幅を切り替える | 分類の名前は文字だけで、アイコンの独立した名前やフォーカス対象が増えない。 |

分類列だけの横スクロールは設計上許容するが、現在は1分類のため溢れた複数分類の実動作は追加検証の対象にしない。
線の太さや色を数値で確認したうえで、目視でも背景と区別できることを確認する。

## データ・ダブル・テストの書き方

- `IntlTestProvider`と翻訳ヘルパーを使い、文言は要素を探す手掛かりとして翻訳関数から得る。
- 分類テストの処理中通知には既存の`ItemProbe`を使い、Button・SettingsAccount・ダイアログ・アイコンは実物を使う。
- `onMove`・`onClose`は所有する公開境界として観測し、内部関数の呼出順や細かな回数を新たに固定しない。
- サインアウトの成功・失敗・保留は既存の手続き境界のダブルで制御し、認証の契約は既存の実サービスを通すE2Eで接続する。
- 時間に依存するケースは既存の制御された時計や保留Promiseを使い、任意のsleepを追加しない。
- サインアウトの実行確認には使い捨て利用者を使い、共有の認証状態でサインアウトしない。
- VitestはGiven・When・Thenを分け、描画を検証する場合は描画をWhen、操作を検証する場合は描画をGivenへ置く。
- 正常系を先に置き、処理中・解除・失敗・再確認を続ける。
- 失敗時に操作対象・現在の名前や属性・表示が分かるアサーションを使う。

## 実行順序と完了条件

1. 生成CSS・一時HTMLの確認を行い、実装前後のpreviewで比較する。
2. 既存4ファイル（settings-account・settings-panel・sign-out-button・button）と入口の関連Vitestを実行する。
3. ハッシュと履歴の既存`settings-location.test.ts`・`use-settings-route.test.tsx`を回帰実行する。
4. `pnpm lint`・`pnpm typecheck`を実行する。
5. port 3000のpreviewで上記の幅・状態・キーボード・線を確認し、結果を記録する。
6. 既定のPlaywright構成で`app/settings.spec.ts`と`auth/signout.spec.ts`を実行する。

Vitestの対象を絞る場合は`pnpm --filter web exec vitest run <対象パス> --coverage.enabled=false`を使い、対象外ファイルの網羅閾値による失敗と分ける。
最終の全体回帰は既定の`pnpm test`でカバレッジと既存閾値を維持する。
Playwrightは`pnpm --filter web exec playwright test tests/e2e/app/settings.spec.ts tests/e2e/auth/signout.spec.ts`を使い、既定構成がpreviewをport 3100で起動する。
手動previewのport 3000と区別し、同じ作業ディレクトリのビルド出力の競合を避けるため、手動previewを終了してからPlaywrightを実行する。
秘密情報を表示せず、既存のローカル認証・DB環境を使用する。

行カバレッジだけでなく、サインアウトあり・なし、分類の通常・処理中・解除、確認の開閉、表示切替と遅い応答の分岐に未検証がないかを確認する。
CSSの表示切替と線の適用はカバレッジ値に表れないため、生成CSS・一時HTML・previewの記録で補う。
実行結果には対象、実行コマンド、成否、確認幅、確認状態、未確認事項と理由を残し、寸法を測った結果と目視の判断を区別する。
自動テストと必須の外観確認を完了し、未確認があれば明示してからレビューへ渡す。

定義されない任意の設定項目で、既存の一般的な正規化を確認する。旧password項目の定数や専用互換テストは残さない。


## メールOTP一本化に伴う接続の回帰

設定の本文はメールアドレス変更・アカウント削除・サインアウトの3項目を対象とする。
パスワード変更の項目・画面・分岐の専用テストを削除し、一般の未知ハッシュ規則は任意の未定義名で検証する。
一覧のリンクは2つであり、signOutがなければ2項目とする。
削除の意思確認・コード要求・コード入力のヘッダーの戻るは全て分類「アカウント」へ移り、削除RPCを呼ばないことを公開UIで確認する。
コード送信・確認・削除の処理中通知で閉じる・分類切替・戻るが抑止され、失敗後に解除されることを既存パネルの試験へ接続する。
ハッシュの直接指定・再読み込み・ブラウザ履歴と認証後の復帰は既存settings/navigationの試験を維持する。
Auth・DBの変更は[認証共通](../../auth/test-design.md)と[削除](../../auth/delete-account/test-design.md)が担当し、本書の外観変更に関するDB試験不要の記述を認証変更へ適用しない。
