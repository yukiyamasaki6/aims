# オフライン要件定義メモ（検討中・一時ファイル）

rd.md/roadmap.mdへの正式な記述はまだ行っていない。決定事項の一時的な記録。

## 1. オフライン表示
- 仕組み: Service Workerによるキャッシュ（ベストエフォート、キャッシュ対象に優先順位を持たせる）
- キャッシュ無し → アプリ全体のオフライン画面を表示
- キャッシュ有り → 枠組み（シェル）と直前のキャッシュデータを表示し、データ領域にのみ「未接続」を表示。枠組みとデータは別々にキャッシュ・表示する
- プリセット・的データはマスターデータとして、他のページデータより優先してプリフェッチ・キャッシュする
- 関連issue: #477（Service Worker・Manifest導入）, #479（/rounds系ページのキャッシュ戦略）, #474（/rounds/[id]のServer ComponentがnotFound()を呼ばずnullを渡し、クライアント側でローカル状態から描画）, #264（的・プリセットをIndexedDBへ保存）

## 2. 閲覧不可時の表示
- 仕組み: リダイレクトはせず、同一URL上でサーバーの応答状態（存在しない／権限なし）に応じて表示コンポーネントを出し分ける
- 関連issue: なし

## 3. ラウンド作成・削除
- 作成：クライアント側でIDを発行し、`create_round`の完了を待たずに`/rounds/[id]`へ即座に遷移。実際の作成はバックグラウンドの送信キューで非同期実行
  - 関連issue: #301（親: #476）
- 削除：確認ボタン押下と同時に一覧からその場で除去し、削除操作を送信キューに追加。キューでの削除が後から失敗した場合、次回一覧取得時にそのラウンドが再表示されることを許容する（復活時の専用通知UIは作らない）
  - 関連issue: なし

## 4. 同期キュー
- `online`イベントを検知してキューの再送を能動的にトリガーする処理を追加（現状はページ再マウント時のみ再開）
  - 関連issue: なし
- 既存の指数バックオフ自動リトライ（最大4回、3s/6s/12s/24s）は維持する。`online`イベントでは検知できない「オンラインだが不安定な接続」に対応するためで、オンライン復帰トリガーとは別の役割を持つ
- リトライ4回失敗後の「同期失敗」状態からの手動再送ボタンは追加しない
- ヘッダー等への常設接続状態インジケーターは追加しない（データ領域ごとの未接続表示で足りると判断）

## 5. 認証切れ
- 同期操作が認証エラー（`permanent: true`）で失敗しても、キュー側は割り込み処理をせず既存の「同期失敗」表示のみに留め、サインイン誘導は行わない
  - 関連issue: #303（`use-sync-queue`内の個別実装を共通の検知・リダイレクト機構に置き換える）
- 認証ガード（未認証アクセス時のリダイレクト、および#303のセッション切れ検知）に遷移元パスを`?redirect=`等で付与し、サインイン成功後にそのパスへ戻す機能を追加。値は同一オリジンの相対パスであることを検証する（オープンリダイレクト対策）
  - 関連issue: #303に明記なし（追記または新規issue化）
