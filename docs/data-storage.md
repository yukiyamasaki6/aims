# データと保存の設計

## 責務と境界

DBの現在の定義は`supabase/migrations/`、端末の操作の保存は`apps/web/src/lib/local-op-log/`、同期と画面への導出は`apps/web/src/features/rounds/`が担う。
認証設定は`supabase/config.toml`と`supabase/templates/`、バックアップと復元は[バックアップと復元](backup.md)に従う。
端末の保存と認証済み利用者の分離は[同期の設計](features/rounds/sync/design.md)、更新の切替は[オフラインと更新](features/app/offline-pwa/design.md)に従う。

## DBの定義

基礎となるmigrationは、現在のスキーマ、関数、権限、RLS、トリガー、拡張と公式データを直接作る。
ユーザーと認証、的、ラウンド、プリセット、履歴、アカウント削除の責務で分割し、参照先から順に適用する。
過去の列や関数の一時的な作成、過去のデータの変換、不要になった定義の削除は基礎となるmigrationに含めない。
関数の所有者、実行権限、`SECURITY DEFINER`または`SECURITY INVOKER`、`search_path`、既定権限は機能の一部として扱う。
公式の的とプリセット、認証とプロフィールの匿名化先はmigrationが作り、テスト利用者と削除記録の無効化はローカルとプレビューのseedだけに置く。
本番へseedを適用しない。
後続の通常の変更は、新しいmigrationで差分を適用する。

## 端末の保存

同じ版の中では、端末への保存が完了した未送信の記録を、タブを閉じる、再読み込み、送信の失敗によって失わない。
保存完了前に画面を離れた末尾の操作の扱いは[同期の設計](features/rounds/sync/design.md)に従う。
この保証は、以前の版で端末に保存した内容と記録には及ばず、未送信の変更を含む読み込み、表示、利用、保存、保持、送信を保証しない。
以前の版の内容が表示されないこと、消えること、送られないことも保証しない。
保存領域の版更新による作り直し、参照データの形の照合、読み込む値の形の確認は残し、それぞれの動きを定める現行の要件とテストは維持する。
保存領域の版更新は以前の内容を移行せずにstoreを作り直し、更新が塞がれている間の表示と再開を維持する。
参照データの形が取得項目と合わなければ保存を使わず、絞り込みやアカウント概要の値は現在の型と範囲に照らして読む。
これらの仕組みを残すことから、以前の版の内容全般への追加の保証を導かない。

新しい版へは、切替前の版の端末への保存が終わらない間は切り替えない。
有効化と保存の再確認は合計で最大1秒とし、上限内に終わらなければ旧版のまま遷移する。
この待機は切替前の書き込みを完了させる責務であり、切替後の版で読み込み、保持、送信できることを保証しない。

## 現在のデータの流れ

操作はハブから操作の保存へ追記し、同じ版の中で未送信を保持し、同期が現在のRPC契約で送る。
サーバーからの取得はベースへ反映し、反映済みの操作を整理する。
サーバーで対象が存在しないことを表す`base: null`は現在の契約として使うが、端末にはその印を保存せずベースの行を消す。
保存済みのベースの行は非nullである。
履歴RPCの成功応答は現在の返却型に写す。
通信失敗とDBのエラーの判定は維持する。
任意の履歴フィルターは指定された引数だけを送ることで通信量を抑え、DBの引数の既定値も維持する。

復元は、現在の取得処理が出力する`public`と`auth`のデータを、migration履歴の版が一致するDBへ投入し、全表の行数と外部キーを確認する。
