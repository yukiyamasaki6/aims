## 補足
- 検証コマンド: `pnpm exec biome check apps scripts supabase docs agents biome.json package.json .github` + `pnpm --filter web lint:text` + `lint:messages`(`pnpm lint` は `.agent-handoffs/` の図のJSONまで検査して落ちるため、同等の範囲を指定。`.agent-handoffs/` を除いた範囲は全て通る)、`pnpm typecheck`、`pnpm knip`、`pnpm test`(カバレッジの閾値込み)。
- 段階01の `supabase config push --dry-run` 相当は、認証情報が無く未実施。
- 設計との差異: 段階07で、設計に列挙が無い `reset-password/page.test.tsx` の14d相当2件(コード送信・確認の応答待ちで離れる)も、ガードの撤去で意味を失うため削除。段階05で `OtpCodeStep` の `idPrefix` prop(コードのエラー文のid専用だった)も削除。
- 段階10の解釈: 設計の「再送信の間のエラー表示」節・要件の削除に合わせ、開始(started)で以前の上部の理由と欄のエラーを消すようにした(設計は消す/残すを明記していないが、残す規則の削除とテスト削除の指定から読んだ)。
- 段階10の限界: 再送の不備は欄が1つ(`resend`)のため、待ち時間とチェック未完了が重なるときは待ち時間だけを示す。欄の整理は段階16。
- 段階12: 設計の「入力中もカウントダウンが進む」は、既存の「コード入力中に再描画されても、クールダウンの1秒の計時をやり直さない」(親の再描画を起こして残り秒数を確かめる)で満たすと判断し、新規には足していない。

- 段階15のリリース手順: 本番に出した後に、Vercelの本番・プレビューから SUPABASE_SECRET_KEY を削除する(ユーザー決定)。E2E・CIは残す。
