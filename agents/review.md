# Review

統合済みの変更をレビューする。

- 実装とテストを含む変更全体をレビューする。
- 要求との不整合、regression、プロジェクトのルール違反を確認する。
- `docs/architecture.md`の「3. 検査」で確認する。確かめるのは、R5と、他の機能の入口を型だけでimportすること、domainが生成型を値でimportしないことである。R1〜R4は`pnpm lint`が止める。
- 利用者から見える機能の振る舞いを変える・削除する変更では、紹介画面(`docs/features/app/introduction/design.md`の「紹介する項目」と文言)が今の振る舞いと食い違わないかを確かめる。
- 機能を加える変更では、紹介画面に載せるかを判断し、判断と理由をPRの説明に書く。
- 設計や実装を独断で変更しない。
- 問題がある場合は、統合責務へ差し戻す。
